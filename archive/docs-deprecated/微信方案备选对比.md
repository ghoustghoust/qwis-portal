# 微信情报接入 · 备选方案对比（主案的补充）

> 主案见《微信公众号接入与热榜方案.md》。本文回答"有没有别的路"——所有标注"实测"的结论均为 2026-08-27 本机真实探测结果。

## A. 公众号每日推送的替代路线

| 路线 | 形态 | 成本 | 实测状态（本机） | 适用场景 |
| --- | --- | --- | --- | --- |
| **wewe-rss 自建**（主案） | 开源自建，微信读书通道 | 免费 | 通道 weread 直连✓；无 Docker 需 SQLite 裸跑 | 默认推荐，可控性最高 |
| **wechat2rss.xlab.app 托管** | 付费 SaaS | 按源/年付 | ✅ 实测可直连（HTTP 200） | 最省事：买完导出 OPML 直接喂系统，零运维 |
| **rachelos/we-mp-rss 自建** | 开源自建（Python，4399★，2026-08 仍在更新） | 免费 | GitHub 元数据✅（README 细节未深测，以其仓库为准） | 不想走微信读书通道时的第二开源选项 |
| Feeddd 免费公共源 | 公共 SaaS | 免费 | ❌ 实测 502，基本不可依赖 | 不建议 |
| Pretzo / WeRSS 等其它托管 | 付费 SaaS | 付费 | 未逐一实测 | wechat2rss 出问题时横向替换 |
| 搜狗微信搜索 | 人工网页 | 免费 | ✅ 可达，但验证码频繁 | 仅人工补查，不做自动化 |

补充说明：

- **托管服务的本质优势**是它们维护了一批稳定的抓取账号池和对抗经验，你花钱买的是"不断供"。对自己时间贵、或订阅号很多的人是最优解。
- **rachelos/we-mp-rss** 与 wewe-rss 机制不同（走公众平台授权而非微信读书），部署形态偏传统 Python 栈；两条腿走路互为备份是进阶玩法。

## B. 微信热榜的替代路线

| 路线 | 形态 | 成本 | 实测状态 | 备注 |
| --- | --- | --- | --- | --- |
| **tophub + rebang 双源抓取**（主案） | 爬两个聚合站 | 免费 | ✅ tophub 代理下200 / rebang 直连200；tophub 无公开 RSS（404 实测） | 落地最快 |
| **DailyHotApi / NewsNow 自建** | 开源聚合 API | 免费 | ✅ 服务本身可部署，但**源码确认均无微信源** | 只适合顺带聚合微博/知乎等其它平台榜 |
| **聚合数据(juhe) 等商业热榜 API** | 付费 API | 按量 | 未实测（需注册拿 key） | 有"微信热搜榜"产品线，企业级稳定但要花钱 |
| **vikiboss/60s 自建** | 开源聚合 API（5680★，2026-08 更新） | 免费 | 公共实例本机❌；是否含微信榜未验证 | 备胎位 |
| **自有订阅池自算热度**（组合技） | 用现有事件聚合引擎 | 免费 | 你们八期 spec 已规划该引擎 | 把微信条目纳入聚类，得到"我的赛道热度榜"，比公域榜更贴合业务 |

要点：

- **没有任何主流开源热榜项目带微信榜**（DailyHotApi、NewsNow 已翻过源码确认），这不是部署姿势问题，是微信没有开放数据面。
- 所以现实的分叉只有三条：①爬聚合站（tophub/rebang，免费快）；②买商业 API（juhe 类，稳定要钱）；③自己算（组合技，最懂你但口径≠全网）。
- 组合技值得认真考虑：你们的 phase8 事件聚合引擎（Jaccard 相似度聚类 + 时间衰减热度）本来就是为"AIHOT 条目聚事件"设计的，把同一套函数跑在微信新文上，产出的"你的赛道热榜"对日报的价值可能高于泛全网榜。

## C. 决策指南

- **怕折腾、预算充足** → wechat2rss 托管（推送）+ juhe 商业API（热榜）：全程零运维，当天能用
- **免费可控**（主案）→ wewe-rss 自建 + OPML 接入 + tophub/rebang 双源爬榜：半天工作量，之后零成本
- **业务向最优** → 主案之上再叠"订阅池自算热度"：复用八期事件引擎，产出只属于你的赛道榜

## E. 深评：rachelos/we-mp-rss 与 vikiboss/60s（2026-08-27 源码级核实）

### E1. rachelos/we-mp-rss（Python/FastAPI，4399★，2025-05 创建，活跃维护中）

**结论：可行，且比 wewe-rss 功能面更宽，是真正的第一备选。**

| 维度 | 实测事实 |
| --- | --- |
| 抓取通道 | `core/wx/model/` 同存 weread（微信读书）、playwright_mp（浏览器抓取）、free_publish、web 多通道——不只依赖单一接口，抗断供性强于 wewe-rss |
| 运行环境 | 要求 Python≥3.13.1；本机 3.13.12 ✅；官方主打 Docker，但也给出裸跑步骤（clone→装依赖→`python main.py -job True -init True`） |
| 数据库 | SQLite 默认 / MySQL 可选 ✅ 与本机无 Docker 现状匹配 |
| 特色功能 | 文章转 Markdown/PDF 导出、HTML 过滤规则去广告、标签订阅、消息推送（`core/notice/`: bark/钉钉/企业微信 wechat.py）、Webhook/AI Agent 接入 |
| 许可证 | **NOASSERTION（自定义协议）**——个人自用没问题，商用前需读 LICENSE 条款 |
| 相对 wewe-rss | 功能超集（wewe-rss 只做 RSS 化）；但项目年轻约一年，代码量更大、组件更多 |

适配到本系统的方式与主案完全一致：它输出 RSS/OPML → 配置进 `opml.url`。额外福利：它自带的 notice 推送（企业微信/Bark）可能让主案第 4 步"推送到手"都不用自己写。

### E2. vikiboss/60s（NestJS/TS，5680★，2026-08 仍在更新）

**结论：解决不了微信热榜——全部模块逐一核对，无任何微信源。**

模块清单（36 个）：60s/-rss（每天60秒读懂世界）、ai-news、baidu、baike、bili、bing、changya、chemical、color、dongchedi、douban-weekly、douyin、epic、exchange-rate、gold-price、hacker-news、hash、health、ip、it-news、kfc、kuan、luck、lunar、lyric、maoyan、moyu、ncm、og、qq、quark、rednote（小红书）、today-in-history、toutiao、weather、weibo、whois、zhihu。

正确定位：它是"**时讯杂谈 API 盒子**"（60s日报 + 天气 + 汇率 + 金价 + 各平台热榜），把微博/知乎/B站/抖音/头条/小红书热搜一套搞定，作为你们热榜矩阵的**其它平台补充件**很划算；微信榜仍必须走 tophub/rebang 爬取或商业 API。

## F. 更新后的推荐组合

- 公众号推送首选二选一：**wewe-rss**（轻、专、成熟）或 **we-mp-rss**（全、多通道、自带推送）。想省心少运维选 we-mp-rss，想最小依赖选 wewe-rss。
- 热榜侧维持主案不变：tophub+rebang 双源爬取；如需其它平台榜单，加挂 60s 或 DailyHotApi 任一即可（互相冗余）。

## D. 可以立刻切换/叠加的动作

1. 若不想现在部署任何东西：先在 wechat2rss.xlab.app 买 3~5 个源的年付（成本低），导出 OPML 配置到系统 `opml.url`，链路当天打通——主系统的改造量为**零**。
2. 无论选哪条推送路线，`util/http.js` 的 proxy 小改造和 hotwx 采集器都不变（主案 P0.5/P1）。
3. 企微 Webhook / Server酱 的推送触达层与上面所有方案正交，随便组合。
