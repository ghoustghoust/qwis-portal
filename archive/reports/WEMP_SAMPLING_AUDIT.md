## 三、详细案例分析

### 3.1 ⚠️ **异常模式 1:Feed 篇数 > 主库篇数（系统性丢文）**

**现象**: 所有 6 个样本都存在 `feedEntries > dbArticles`，差异为 2-4 篇

**可能原因分析**:
1. **pubDate 过滤器丢弃** ✅ 已修复（P0-2）
   - 旧逻辑：`new Date(pubDate) > lastFetchAt` → 永久丢弃迟到文章
   - 新逻辑：`new Date(pubDate) > cutoff(14 天前)` + `INSERT OR IGNORE by url` 去重
   
2. **ETag/304 短路** ❌ 排除
   - 全部 87 个 wemp/rwss 源无 etag，`useConditional=false`，每次全量解析

3. **we-mp-rss feed 自身截断** ✅ 疑似
   - we-mp-rss cron `7 */2 * * *` 实际为每小时 `:23` 批次（修正自 REFRESH_MECHANISM_AUDIT）
   - `limit=20` 但最新文章可能 pubDate 早于本地上一轮 lastFetchAt → 被 pubDate 过滤器误伤

**证据**: 
- 极客公园：Feed 14 条最新文 → 主库仅入库 10 篇，4 篇缺失
- 最坏情况：机器之心 / 新智元 丢失 2 篇最新文（25% 缺失率）

**结论**: **系统性丢文存在**，主要根因是 `pubDate` 过滤器对"晚于 pubDate 才入库"的逻辑过于激进，导致：
- 如果某篇文章在 `pubDate: 10:23` 发布，但本地上一轮抓取是 `09:23`
- 该文章会在下一轮 `10:53` 本地抓取时因 `pubDate(10:23) < lastFetchAt(10:53)` 被丢弃
- **即：我们永远抓不到晚于自己发布时间的那轮文章**

## 五、根因诊断汇总

### 5.1 核心问题：pubDate 增量过滤器的"相对时间陷阱"

**代码位置**: `server/services/collectors/rss/index.js:326-353`（已修复为新逻辑）

**旧逻辑的问题**:
```js
// P0-2 修复前
if (!etag && lastFetchAt && feed.items.length > 0) {
  feed.items = feed.items.filter(item => {
    const pubDate = new Date(item.isoDate || item.pubDate);
    return pubDate > lastFetchAt;  // ❌ 如果文章 pubDate 晚于我们上一轮抓取时间，永远丢弃！
  });
}
```

**场景重现**:
1. 本地上一轮抓取：`lastFetchAt = 2026-09-03T10:53:00Z`
2. 公众号作者在 `11:00` 发布新文，`pubDate = 2026-09-03T11:00:00Z`
3. we-mp-rss 在 `11:23` 批次收录该文章
4. 本地下一轮抓取：`11:23`，检查 `pubDate(11:00) < lastFetchAt(10:53)?` NO → 保留？不对，应该是：
   - 更正：**正确的触发时机**
   - 本地本轮 `11:23` 抓取时，`lastFetchAt` 是 **上一轮 10:53**（还没更新）
   - 所以 `pubDate(11:00) > lastFetchAt(10:53)` → 应该保留
   - **等等，这里需要再核对真实时序...**

**重新推导（基于 wemp.log 和主库数据）**:
- wemp 源 `last_fetch_at` 更新时机：`fetchSource()` 成功/失败后写入（`store.js:91-93`）
- fetchSource() → rss collector → feed parser → filter → INSERT
- **所以在 filter 阶段，`lastFetchAt` 是上一轮的**

**正确场景**:
1. 本地第 N 轮：`10:53` 抓取，`lastFetchAt = 09:23`（第 N-1 轮）
2. 公众号作者在 `10:00` 发文（pubDate=10:00）
3. we-mp-rss 在 `10:23` 批次收录
4. 本地第 N 轮在 `10:53` filter: `pubDate(10:00) > lastFetchAt(09:23)` ✅ 保留
5. 公众号作者在 `10:30` 发第二篇（pubDate=10:30）
6. we-mp-rss 在 `11:23` 批次收录
7. 本地第 N+1 轮：`11:23`，此时 `lastFetchAt = 10:53`（第 N 轮刚写）
8. Filter: `pubDate(10:30) > lastFetchAt(10:53)` ❌ **丢弃！这就是"相对时间陷阱"**

**结论**: 只要公众号发文时间 > 我们上一轮抓取时间，就会被误杀。**这就是系统性丢文的根因**。

**P0-2 修复**改为宽松窗口（14 天截断）✅
