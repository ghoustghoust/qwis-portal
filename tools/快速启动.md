# 运维工具箱 - 快速启动指南（2 分钟上手）

> 适用于 ops-toolkit v2.0（2026-09-05 更新）
> we-mp-rss 已于 2026-09-04 退役，公众号改走 wechat2rss 托管 RSS

## 核心目标

让你**无需 AI 介入、无需查文档**，直接在终端完成所有熔断恢复与运维操作。

---

## 第一步：打开工具箱

### 方式 A: 双击运行（推荐）
```
双击 → tools/运维工具箱.bat
```

### 方式 B: PowerShell / CMD 命令
```powershell
cd d:\全网情报系统
node tools/ops-toolkit.js
```

**可用命令**：
```
全网情报系统运维工具箱 v2.0
用法: node tools/ops-toolkit.js <命令>
  check          系统健康总览（主服务 + 报警渠道）
  frozen         查看熔断源清单
  unfreeze       批量解冻所有熔断源（--yes 跳过确认）
  diagnose-bili  B 站专项诊断（WBI 密钥 + Cookie 登录态）
  export         导出错误报告 CSV 到 data/
```

---

## 第二步：按场景执行对应操作

### **场景 1：不知道哪些源有问题**

```powershell
# 先看整体健康状态
node tools/ops-toolkit.js check

# 再查熔断清单
node tools/ops-toolkit.js frozen
```

输出示例：
```
=== 熔断源清单（fail_count >= 3 且已停用） ===
  [132] 机器之心 (type=bilibili, 连失 4 次)
      最近错误: WBI signature failed
  [133] 极客公园 (type=rss, 连失 3 次)
      最近错误: timeout
```

**判断策略**：
- `type=bilibili` → 执行 `diagnose-bili` 诊断 Cookie/WBI
- `type=rss` → 通常是网络波动，可直接 `unfreeze`
- `type=wechat`（wechat2rss）→ 检查 wechat2rss.bestblogs.dev 是否可达

---

### **场景 2：B 站持续报错（WBI/signature 关键词）**

#### **诊断**
```powershell
node tools/ops-toolkit.js diagnose-bili
```

输出示例：
```
=== B 站专项诊断（WBI 密钥 + Cookie 登录态） ===
[OK] Cookie 已配置
[OK] WBI 密钥刷新成功
[FAIL] 登录态无效
原因分析：Cookie 中 SESSDATA 缺失或过期
```

#### **修复**
```
1. 浏览器打开 https://www.bilibili.com/ 并登录
2. F12 → Application → Cookies → bilibili.com
3. 复制 SESSDATA / bili_jct / buvid3 拼成完整 Cookie 串
4. 写入数据库：
   sqlite3 data/app.db "UPDATE credentials SET data='...' WHERE platform='bilibili'"
5. 解冻熔断源：
   node tools/ops-toolkit.js unfreeze
```

---

### **场景 3：多个源同时熔断（批量恢复）**

> 仅在你已解决根本问题（如更新了 Cookie）后使用！

```powershell
node tools/ops-toolkit.js unfreeze
```

交互确认：
```
=== 批量解冻所有熔断源 ===
检测到 15 个熔断源，此操作将清零失败计数并重新启用
确认执行？(y/N)：y
[OK] 已恢复 15 个熔断源（调度器下一轮 60s 内会自动重试抓取）
```

跳过确认（脚本/批处理场景）：
```powershell
node tools/ops-toolkit.js unfreeze --yes
```

**后续观察**：
- 前 5 分钟内应有部分源自动恢复为绿色
- 剩余红标源说明仍有问题，需单独处理

## 第三步：验证与监控

### **前端验证**
```
1. 打开 http://localhost:3000/admin/sources
```

## 常见故障速查表

| 症状 | 关键特征 | 对应命令 | 预计耗时 |
|-----|---------|---------|---------|
| B 站视频源持续报错 | lastError 含 `WBI/signature` | `diagnose-bili` → 更新 Cookie → `unfreeze` | 5-10 分钟 |
| RSS 源偶发报错 | lastError 含 `timeout/ECONNRESET` | `unfreeze` 或跳过 | 1 分钟 |
| 未知原因的批量熔断 | fail_count 均>=3 | `frozen` 查看 → `unfreeze` 恢复 | 3 分钟 |
| 报警不触发 | check 显示渠道数为 0 | 管理后台「报警管理」配置渠道 | 2 分钟 |

---

## 最佳实践建议

1. **每日晨检**：每天第一次开机时先执行 `check` + `frozen`
2. **变更即验**：任何配置修改后（如更新 .env），立即执行 `check` 验证
3. **周度清理**：每周日晚执行一次 `export`（CSV 归档）
4. **月度审计**：每月回顾 error-report，识别高频故障源并调整 intervalMin
