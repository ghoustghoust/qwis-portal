### #40 Windows 上 execSync 走 cmd.exe：`^ | & % < >` 会吃掉命令，取证方向能被静默反转（2026-09-19 实测）
- 症状：`tools/eval-f2p.cjs` 第一版用 `--base ca42cd5^` 取"改动前"基线，结果 base 侧 3/3 全绿、判成"这条锁是假的"。实际上它根本没回到父提交。
- 根因：Node 的 `execSync` 在 Windows 上经 **cmd.exe** 解释整条字符串，而 `^` 是 cmd 的转义符 → `ca42cd5^` 被剥成 `ca42cd5`。git 收到的是"改动本身"，于是"改前红"永远不成立。同一类静默篡改还发生过两次：commit message 里的反引号路径被命令替换掉（内容凭空消失）、`npm test | tail` 把退出码换成 `tail` 的 0。
- 规则：①凡是**带 ref、路径、外部输入**的子进程一律 `execFile`/`execFileSync`（数组参数，不经 shell），`execSync` 只用于完全静态的命令串；②git ref 显式写 `^{commit}` 而不是裸 `^`，并**先 `rev-parse` 成 sha 再用**，比较 `baseSha === headSha` 时直接拒绝取证；③任何"取证据"的工具都要有正向探针：本例是自检里那条「base 侧必须真的看见红」——如果 base 与 head 结果一样，判假而不是判过；④交付信息（commit message）里的路径/命令不许走 shell 插值，统一 `git commit -F <文件>`。
- 案例：`tools/eval-f2p.cjs` 的 `gitRaw/git` 改造；修好后同一命令正确报出 `base 2e2c757 红 3/3 → head 0/3`。

### #41 取证基线选错，会被判成"锁是假的"——而那份判据的下一步动作是删用例（2026-09-19 实测）
- 症状：`npm run eval:f2p -- --base 64124b7 --tests tests/regression-20260919c.test.js` 报「改前也全绿 —— 这条锁抓不到 bug，按 §6 应删掉或重写断言」，指向 8 条刚写完、明知能抓 bug 的锁。
- 根因：基线 sha 是我凭记忆挑的，`64124b7` 其实是修复提交 `5aa8118` 的**子孙**——那棵树里修复早就在，"改前红"在物理上不可能发生。工具没错，错在输入；但工具把"输入错了"和"锁假了"报成同一句话，而后者附带的动作是**删除测试**，等于让一次记错 sha 变成永久削弱回归网。
- 规则：①取证基线**不靠人记**：由"这条锁在哪个提交引入"（`git log -S<用例名> -- <文件>` 取最老一条）反查，工具提供 `--auto-base`；②显式给 `--base` 时先做**基线守卫**——base 若已包含目标锁的引入提交，退出码 2 并印出建议基线与"这是取证输入错了，不是锁假了，不要按 §6 删用例"；③"改前也全绿"只允许在守卫通过之后出现，此时才是真假锁；④守卫自身要有正向探针（同一批锁在 `intro^` 上必须放行），否则一个方向写反的守卫会把所有取证都拒死——本轮 `suggestBase` 的祖先判断就反过一次，症状正是"建议基线 = 最新提交"。
- 案例：`tools/eval-f2p.cjs` 的 `lockIntroCommit/baseIsStale/suggestBase` + 自检「base 已含该修复 → 判'基线选错'而不是'锁假了'」「自动基线取最老且与传入顺序无关」；同一轮另有一条相关判据：`Cannot find module` 要按**裸包名 vs 相对路径**分成 env 红与产品红（收敛型修复只有产品红这一种取证形态）。
- 另见：坑 #40（同一工具的 shell 元字符坑）、`docs/EVAL_GUIDE.md` §6。

### #43 检查器把"失败理由字符串"当成通过：`pass: !!verdict` 让云端巡检永远满分（2026-09-19 实测）
- 症状：`node tools/audit-cloud.js` 输出「通过 19/19」，但同一行里写着 `✅ 采集端点鉴权 405 应401实际405`、`✅ 源列表异常`、`✅ 文章列表去重 deduped 标记缺失`——**报告里带着失败理由，却按通过计数**。
- 根因：判据函数约定"返回 `true` 通过、返回字符串给出失败理由"，而汇总处写的是 `pass: !!verdict`。非空字符串是 truthy，于是每条失败理由都被判成通过，理由反倒降级成一条附注。叠加第二个坑：该脚本基址写死在 2026-09-11 就已下架的 `qwis-portal.vercel.app`（坑 #42 同源，全库第 5 份手写副本），所以它 8 天来打的都是 404。

### #44 分类器的正则跨行匹配会"造出"证据——一次合法取证被判成环境失败（2026-09-19 实测）
- 症状：给 41-8 的新文件出 F2P 证据时，工具拒绝：`base 侧有环境类失败（元凶：, ⏎ syscall: ）`。所谓"缺失路径"是两个换行之间的碎片，根本不存在这个文件。
- 根因：`/ENOENT[^\n]*?'([^']+)'/` 想抓 `ENOENT ... '路径'`，但 Node 抛出的对象 dump 长这样：`code: 'ENOENT',` 换行 `syscall: 'spawn python3',`。前缀 `[^\n]*?` 停在本行的引号上，捕获组 `[^']+` **却没禁换行**，于是跨过行首空白抓到 `,` + 换行 + `    syscall: ` 当作"路径"。分类器过宽时，它不是"漏判"而是**凭空造证据**。
- 规则：①抓路径/标识符的正则必须显式禁掉换行（`[^'\n]` 而不是 `[^']`），并用"必须同行出现"的结构锚定；②任何被分类器判成"环境红"的结果都要**点出原路径**（`envPaths`），报"有环境问题"而不给名字，等于让人瞎猜——这也是本轮加的要求；③分类器自身要同时有"树内=产品红 / 树外=环境红"两个方向的探针，以及一条"畸形输入不许产出结果"的探针（对象 dump 就是这类输入）；④同一套"树内/树外"判据要覆盖所有失败形态（`Cannot find module` 与 `ENOENT` 是同一件事的两种写法，只覆盖一种就是 #T3 的老坑）。
- 案例：`tools/eval-f2p.cjs` 的 `parseSummary(text, cwd)`/`repoRel()`；回归锁「41-3 ENOENT 按树内/树外分类，且正则不许跨行造出假路径」+ 取证器自检里「Node 的对象 dump 不许被当成缺失路径」。

### #45 "文件里有红"不等于"这条锁能抓 bug"：取证判据的循环论证 + 退出码混档（2026-09-19 独立对抗性审查查出）
- 症状：取证器对 5 个锁文件报 `✓ F2P 成立`，看起来每轮修复都有双证据。实际旧判据是 `if (!base.fail) → 假锁；否则成立` —— **改前只要有任意一条红就算成立**，红的是不是本轮那条锁根本不看；`--cases` 缺省时拿 `base.failedNames` 自己当目标集，等于"用结果证明结果"。另一条：head 侧解析不到汇总行时兜底成 `{fail:0}`，于是"没跑到"被打印成"改后 0 条全绿"。
- 根因：判据写成"有没有红"这种存在性检查，而不是"我点名的每条锁是否都改前红"；而用法/环境错误与"锁假了"共用退出码 1，1 的处置动作是**删用例**（与坑 #41 同一危险方向）。独立审查还并行查出同类 3 条：巡检全 SKIP 时退 0、评测器空 golden 退 0、"缺产物就 return"的单测（没断言也算通过）。
- 规则：①取证必须**逐条点名**：目标集内每条都要在改前红，缺一即 `state=product` 并列明"哪几条不红"；不给目标一律 `state=env` 拒判；②三态三码：`ok=0 / 锁抓不到 bug=1（允许删或重写）/ 未评测=2（禁止删用例）`，任何"没跑到/没产物/全 SKIP"都不许落到 0 或 1；③"没解析到结果"必须显式失败，**绝不允许兜底成 0**（兜底=无中生有）；④正向探针类断言（验证"检测器看得见坏形态"的）本来就不该在改前红 —— 它们属 P2P 守卫，取证时要显式排除，不要用整文件模式掩盖这个区别；⑤自我审查有天花板：这 5 条都是**独立 reviewer** 找出来的，我自己跑了 20 项自检仍没发现，所以"工具要有自检"不能替代"对抗性审查"这一步。

### #46 端到端"对账"对错了对象：拿剧本自己发的请求当页面的请求（2026-09-19 首轮实测）
- 症状：E5 报「筛选没退化成 all（article=0 all=0）」、E1 报「接口 200 但 items 为 0」——看着像一批前端缺陷，实际上页面好好的。
- 根因（三层，全是评测器自己的错）：①剧本先 `goto` 再自己 `fetch` 同参数接口，测的是"接口自己"而不是"这个页面"，页面用的参数、分页、缓存一概没参与；②新开的 page 停在 `about:blank` 时 `fetch('/api/...')` 没有同源 base，1ms 内 `status 0`，而 `status 0` 长得和"接口挂了"一模一样；③共用一个 page 时，前端 `api.js` 的 5s 内存缓存会让后一条剧本"页面根本没发请求"，于是对账拿不到数据。
- 规则：①**对账数据只能来自 `page.on('response')` 拦到的、页面自己发出的那次请求**，剧本另发的探针只用于"接口口径"这一类断言，并且必须在已有同源文档之后发（现在无同源直接抛 `TOOL:` 判 fail_env）；②按路径**拦截记录合并**（`collected()`）再比，列表页自己会追加请求（阅读器轮询、筛选重发），只拿某一条响应必然出现"DOM 比它多"的假红；③每轮剧本开新 page，别共用。
- **补刀（同日独立对抗审查查出）**：①里的"页面自己发出的"当时只是**口头**成立——响应事件与页面请求进的是同一个 store，而 `net.length = 0` 挡不住探针那条**晚到**的 push（记录要等 body 读完才进 store）。于是剧本发的请求会被当成"页面发过了"，`waitQuiet` 也会被它伪造成"页面已经静下来"。**方向要认清：这一类是假绿，比假红危险。** 现按 URL（`pathname + search` 全串，只比路径会把页面的同路径请求一起屏蔽）在事件回调里**同步**打 `by:'script'`，`collected/waitForApi/waitForApiWhere/waitQuiet` 一律只认 `byPage()`；探针在飞期间 body 未读完的记录也算"还在飞"，不许谎报安静。
- 案例：`tools/eval-e2e.cjs` 的 `attachNet/collected/api/scriptInflight/byPage` 四件套；回归锁 G5（每个 `file:line` 出处必须真指到含该 token 的那一行）、G6（剧本覆盖面不许缩水）。

### #47 选择器数错元素：一次"容差"其实是指错了节点（2026-09-19 实测）
- 症状：`/reader/` 文章行数量 34，接口给 30，差 4 → 我先加了 ±4 容差让它变绿。
- 根因：`div.cursor-pointer.flex.gap-2` 命中的是**侧栏源列表 34 项**，不是文章行；文章行实测是 `div.card.card-lift.p-3.cursor-pointer.relative`，与接口正好 30↔30。把"选错元素"包装成"容差"是端到端最隐蔽的一种假绿：数字看着合理，判据已经废了。同类还有 /hot/ 热搜事件视图——同一 class 既有含标题的外层也有只剩源芯片的内层，用"每行都出自响应"判会 100% 误报。
- 规则：①选择器必须实测，且**用零容差判据去验证它**（行数与接口条数相等、每行标题都能在响应里找到）；②给每条列表剧本加一条"选择器没落进侧栏/导航"的自检（`closest('aside')` 必须为 0）；③行结构有内外层之分时，判据换方向：文章卡视图判"渲染 ⊆ 响应"，事件榜判"响应 → 页面覆盖率"，别硬套一种；④页面会折叠（日报「展开剩余 N 条」）时，**总行数根本不适合当判据**，逐列 pill 才是。
- 案例：`tools/eval-e2e.cjs` 的 `SEL` 表（每条都带实测计数注释）、`subsetConsistency`/`responseCovered` 两个方向、E1 的"选择器不得落到侧栏"断言。

### #48 慢接口让 DOM 与响应错配：这不是竞态，是我读得太早（2026-09-19 实测，但**别拿这条掩盖真竞态**）
- 症状：E5 同一条判据三轮里两轮红——DOM 显示「全部 25150」，接口给的是 `counts.all=7291`。第一反应是"前端有竞态"。

- 案例：`tools/eval-e2e.cjs` E5 的 `waitForApiWhere` + `c.metrics.readingResponses`（把每轮 type/counts 都留档，红的时候能一眼看出是哪种）。

### #49 端到端引擎第一次抓到真缺陷：晚到的旧响应把筛选结果整屏覆盖（2026-09-19，B74）
- 症状：点「文章」后页面计数 pill 仍是「全部」的数字；点「视频」（云端收藏视频为 0）列表还挂着上一批 30 行。
- 根因：`MyReadingPage.fetchPage` 只有 `if (loadingRef.current) return` 一道闸。首屏 `type=all` 慢请求晚于用户筛选的快响应到达时，`setItems/setCounts` 无守卫地整体覆盖回去；而加载中点的筛选更会被直接吞掉。接口侧 counts 与列表是同一份表达式（B60 已修），所以这是**纯前端时序**缺陷——白盒与接口巡检都看不见，只有真点页面才看得见。
- 修法：每次请求领一个序号，成功与失败两条路径落地前都比对"我还是最新那次吗"；防重入只保留给翻页（`if (!reset && loadingRef.current) return`）。
- 规则：①凡是"筛选/搜索 + 分页"的列表，**响应落地必须有序号或 AbortController**，这是默认要求不是优化项；②这类缺陷只能由端到端层抓到，所以端到端必须真的点交互（只截图等于没测）；③锁要判行为数量：`seq !== seqRef.current` 必须**恰好两处**（成功+失败路径），只数一处就是恒真断言——G9 里配了"删掉任一守卫探针必须失败"的反向验证。
- 案例：`web/src/pages/MyReadingPage.jsx` 的 `seqRef`；回归锁 G9；端到端剧本 E5；`docs/ISSUES.md` B74。

### #50 永远不会红的判据就是假门禁：写死真、两侧恒等、读不到就返回空集（2026-09-19 独立对抗审查查出）
- 症状：三条看起来"有断言"的行，实际**任何产品状态下都绿**：①E7 `assert(c,'data','客户端路由…', nav1 === nav0)` ——`performance.getEntriesByType('navigation')` 在每个新 document 里长度都是 1，整页刷新与不刷新两侧恒等；②E10 `assert(c,'data','未知路径不返回 200 HTML 兜底', true, '只登记事实')` ——字面量 true；③`dictKeys()` 读不到 `i18n.jsx` 时 `catch { return [] }` ——空字典让 E8 的"无裸 key 上屏"永远满分。
- 根因：判据的**方向**写成了"记录一个事实"而不是"这件事可能不成立"。同一类还有把 `status 0`（fetch 根本没到服务端）当产品红报——那是环境不通，判错方向会逼人去找不存在的前端 bug。

### #51 跑过 ≠ 验收过：`--only E1 --fast` 全绿也会 exit 0（2026-09-19 独立对抗审查查出）
- 症状：端到端默认跑全剧本 ×3 轮 ×线上，但 `--only`/`--fast`/`--target 127.0.0.1` 三条路都能跑出一条"绿 + 退出码 0"的记录，而这句话一旦写进交付说明就等于用一条探针兑了"端到端已验收"。

- 案例：`tools/eval-e2e.cjs` 的 `acceptanceOf/gapIssues`；`docs/EVAL_GUIDE.md` §3.7；AGENTS.md §3 第 10 条子项。

### #52 回归测试写生产数据，留下的最坏形态不是"脏值"而是**悬空引用**（2026-09-19 线上实测，B78/B79）
- 症状：`GET /api/mybrief` 线上回 `{"ok":true,"empty":"no-subscription"}` —— 用户的「我的早报」整页退化成引导态，但库里 `settings.subscription.ids` 看着完全正常（`[2104]`，非空、类型对、能 JSON 解析）。

- 规则：①测试**不许**在生产库里"建实体 + 让别的表引用它"——要么全程本地文件库（H 组的做法：`file:` + 子进程冷缓存），要么引用只用到测试自己可见的临时键；②`after()` 的还原必须是"删掉我建的东西 + 把引用也清掉"，而不是"写回一个我快照来的值"（快照本身可能已经被上一次中断污染）；③凡是"id 列表"型设置，读层必须对**引用完整性**负责：全部落空要与空集合同等对待，部分落空要忽略坏 id（别让一个坏 id 打死整页）；④这类损伤**接口巡检看不出来**（`/api/mybrief` 回 200 且 `ok:true`），只有按用户语义断言"应该拿到 report 或明确的空态"才看得见。
