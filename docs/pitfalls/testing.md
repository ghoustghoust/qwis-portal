# 坑 · 测试（testing）

> 本域管「怎么证明」：回归锁怎么写、测试对生产库与凭据有什么影响、判据自身会不会假绿。
> 只装**仍约束现役东西**的规则。与 2026-10-01 整体摘除的那套装置（端到端/白盒/F2P/内容/过程）绑在一起的经验不在本文件——重建装置时该照的原则在 `docs/EVAL_GUIDE.md` §2，其余反查走 git。

### #13 smoke-test 跑的是生产库副本
- 规则：`smoke-test.js` 启动时 backup 到临时目录 + `APP_DATA_DIR` 注入，结束清理；任何测试文件 require `server/*` 前必须先 require `tests/helpers`（`APP_DATA_DIR` 隔离），**严禁直写 `data/app.db`**。

### #18 回归测试必须驱动真实路由
- 案例：2026-09-05 验收发现 3 例"手写与实现相同 SQL 再断言自己"的实现式测试——实现改了测试照样绿（空转）。
- 规则：路由行为测试一律起 express 实例打真实 HTTP（`tests/regression-sourcelib.test.js` 是样板：`app.listen(0)` + generateToken + fetch）；云端 handler 用 mock req/res 直打 `api/[...slug].js`（`tests/regression-cloud-settings.test.js` 的模式）。

### #27 云端回归测试写真实 Turso：全量替换语义必须先把整表原值取回来（2026-09-13 事故）
- 案例：`tests/regression-cloud-settings.test.js` 测 focus 订阅源的"全量替换"时，旧"恢复"只复位 2 个测试 id，而该语义是写**整表**的 `UPDATE ... CASE ... ELSE 0 END` → 跑一次测试把线上 8 个 focus 订阅源全部清零。
- 规则：①凡是"全量替换 / 整表 UPDATE"语义的测试，before 里取回该语义会触碰的**所有行的原值**，finally 里用同一条语句精确还原；②用"测试前后关键集合一致"断言自证；③知悉：`npm test` 对生产的接触只剩**只读**断言——写侧已被隔离（各测试把 `TURSO_DATABASE_URL` 指到 `file:` 临时库、`tests/helpers.js` 以 `APP_DATA_DIR` 隔离本地库），"npm test 会直打生产写"是过期警告，别再按它恐慌；跑全量前想一下此刻适不适合。

### #40 Windows 上 execSync 走 cmd.exe：`^ | & % < >` 会吃掉命令，取证方向能被静默反转
- 根因：Node 的 `execSync` 在 Windows 上经 **cmd.exe** 解释整条字符串，`^` 是 cmd 的转义符 → git ref `xxxx^` 被剥成 `xxxx`，"改动前"根本没回到父提交，取证方向被静默反转。同族两次：commit message 里的反引号路径被命令替换掉（内容凭空消失）、`npm test | tail` 把退出码换成 `tail` 的 0。
- 规则：①凡是**带 ref、路径、外部输入**的子进程一律 `execFile`/`execFileSync`（数组参数，不经 shell），`execSync` 只用于完全静态的命令串；②git ref 先 `rev-parse` 成 sha 再用，比较两侧 sha 时若相等直接拒绝取证；③任何取证据的工具都要有正向探针（base 侧必须真的看见它该看见的红）；④交付信息里的路径/命令不许走 shell 插值，统一 `git commit -F <文件>`；⑤看测试结果不许用管道（`| tail`、`| grep`）——管道的退出码是末端命令的，红色的套件会照样报 0。

### #42 探针 URL 凭印象写 → 把"我打错域名"报成"线上故障"
- 根因：仓库名与 Vercel 应用名同源不同物（`qwis-portal` 是 GitHub 仓库名，线上是 `qwis-intel.vercel.app`），凭印象必错；而 `DEPLOYMENT_NOT_FOUND` 长得极像"部署不存在"的真实故障。
- 规则：①任何外部探针（URL、参数名、字段名）必须**从仓库里抄**——`grep` 权威文档或代码，不许凭记忆；②探针失败先自查请求本身（换一个已知肯定存在的端点、看响应体是不是自家服务的错误页格式），再下"线上坏了"的结论；③"远端已部署"的唯一指纹是 `/api/meta` 回传的 `commit == origin/main`（权威域名与流程见 `docs/DELIVERY_VERIFICATION.md`）。

### #43 检查器把"失败理由字符串"当成通过：`pass: !!verdict` 让云端巡检永远满分
- 症状：`node tools/audit-cloud.js` 输出「通过 19/19」，同一行里却写着 `✅ 采集端点鉴权 405 应401实际405`——**报告带着失败理由，却按通过计数**；非空字符串是 truthy，于是每条失败理由都判成通过。
- 规则：①判据函数的返回类型必须**单一**：要么布尔，要么 `{pass, note}`，禁止"字符串=失败但用 truthy 判过"这种双关；②一律要求 `pass === true` 才算通过，任何 `!!x` 式宽判要写明为什么宽；③检查器自身必须有**退出码**（有失败即非 0），否则进不了任何门禁；④判据里的字段名、状态码、参数名一律**实测得来并写明出处**；⑤契约不存在的检查改成显式"未验收"第三态（`SKIP:理由`）——删除会让缺口消失，明说会让缺口进清单。

### #45 "文件里有红"不等于"这条锁能抓 bug"：判据的循环论证 + 退出码混档
- 根因：判据写成"有没有红"这种存在性检查，而不是"我点名的每条锁是否都改前红"；而用法错误与"锁假了"共用退出码 1，1 附带的处置动作是**删用例**——一次输入错误变成永久削弱回归网。
- 规则：①逐条点名：目标集内每条都要单独成立，不给目标就拒判；②**三态三码**：通过 / 判据抓不到 bug（允许改或删）/ 未评测（禁止据此删用例），任何"没跑到、缺产物、全 SKIP"都不许落到前两种；③"没解析到结果"必须显式失败，**绝不允许兜底成 0**（兜底=无中生有）；④自我审查有天花板：这类形态反复由独立 reviewer 找出来，"工具要有自检"不能替代 `AGENTS.md` §3 的对抗性审查那一步。

### #49 晚到的旧响应把筛选结果整屏覆盖（真产品缺陷，2026-09-19）
- 症状：点「文章」后计数 pill 仍是「全部」的数字；点「视频」（云端为 0）列表还挂着上一批的行。
- 根因：`web/src/pages/MyReadingPage.jsx` 的取数只有一道防重入闸。慢的首屏请求晚于用户筛选的快响应到达时，整体覆盖回去；加载中点的筛选更会被直接吞掉。接口侧 counts 与列表同源，所以这是**纯前端时序**缺陷。
- 规则：①凡是"筛选/搜索 + 分页"的列表，**响应落地必须有序号或 AbortController**，这是默认要求不是优化项；②这类缺陷只有真点交互才看得见，接口巡检与代码审查都看不见——别用"我等久一点"把真竞态调成绿。

### #50 永远不会红的判据就是假门禁
- 症状：三类"任何产品状态下都绿"的断言长得都像有断言——①字面量 `true` 当结论（附一句"只登记事实"）；②两侧恒等的观测量（拿一个每边必然同值的东西比两侧）；③读不到依据时 `catch { return [] }`，空集合让"0 命中"永远满分，而 `scanned=N` 照常打印，看起来完全像"扫了很多、一处没有"。
- 规则：①写判据前先问"什么情况下它会红"，答不出就删掉或换成**会翻转**的观测量；②机器扫判据源码禁止字面量真与两侧同值式，但**扫描区间要限定**——扫全文会让探针命中自己的源码，那本身就是一次踩坑；③工具侧"读不到依据"必须显式失败，**禁止用空集合或 0 兜底**把检查变成常绿（兜底=无中生有）；④**假绿比假红危险**：红会让人去查，绿不会——把"失败理由"记进通过计数、把"选错元素"包装成"容差"，都是让假绿显形的入口；⑤新判据先喂坏样本证明它会红，再谈它通过了几项。

### #52 回归测试写生产数据，留下的最坏形态不是"脏值"而是**悬空引用**
- 根因：测试在生产库里"建一个 TEST 源 + 让 `settings.subscription.ids` 引用它"，测后删源行、再把引用还原成"进测试前存下的原值"。只要某次运行在存原值之后、还原之前被打断，留下的就是**指向已删源行的 id**；读层对"键缺失/空数组"有兜底，对"声明了但全部落空"没有，于是整页退化成引导态——而接口照样回 200 且 `ok:true`。
- 规则：①测试**不许**在生产库里"建实体 + 让别的表引用它"，要么全程本地文件库，要么引用只用到测试自己可见的临时键；②`after()` 的还原必须是"删掉我建的东西 + 把引用也清掉"，而不是"写回一个我先存下来的值"；③凡是"id 列表"型设置，读层必须对**引用完整性**负责：全部落空要与空集合同等对待，部分落空要忽略坏 id；④这类损伤接口巡检看不出来，只有按用户语义断言"应该拿到结果或明确的空态"才看得见。现役兜底在 `lib/source-axes.js`，锁在 `tests/regression-20260919h.test.js`。

### #53 断言前清 store 等于扔掉自己要用的证据；绝对长度不能当渲染判据
- 规则：①需要"点击后新发的那条响应"时，按**参数**从整轮记录里筛，不要清空 store 再等——SPA 切回同一个视图不会重发请求，清完就永远拦不到；②涉及"渲染是否接住了数据"的长度类判据一律用**相对量**（面板 ≥ 正文明文的一半），绝对门槛必须先有"这一族条目实测长度分布"作依据，否则会把正常渲染判成缺陷；③失败信息里必须带上两侧读数，否则红一次就要重跑一轮才能定位。

### #57 仓库是 CRLF：文本型锁与注入型探针里的 `{\n` 永不命中，于是假绿
- 根因：`String.replace` 不报错——**"没匹配上"和"匹配上但结果一样"在返回值上无法区分**。探针往 CRLF 文件里注入 `'{\n'` 时模式永不命中，被测文件没变，测试当然绿，却被读成"锁没拦住"。
- 规则：①任何"改源码来验证锁会不会红"的探针，写回前必须断言改动真的落进了文件，不成立就报**探针自身失效**而不是报锁失效；②切函数/块边界禁止手写分隔符，统一用 `lib/src-spans.js`；③判据里凡出现 `\n` 字面量，先自问"这个文件是 CRLF 会怎样"；④负向自检必须逐条注入并逐条报结果，"三例两红"不叫证据。锁在 `tests/regression-20260919i.test.js`（同一份样例分别按 CRLF/LF 切，两侧清单必须逐字相等）。

### #58 "手工列清单"的判据必然漏
- 根因：三层叠加——清单靠人记，新增写入点不会通知清单；判据是**文件级**的，同文件的第二个函数天然被算成已接；没人拿产物反查生成者。
- 规则：①判据从**事实本身反查**（从写入语句的每一处出现反查宿主函数，再要求该函数体内有该行为），不维护文件清单；②反查结果必须**同时断言数量**，否则"扫不到东西"也算过；③判据文件必须**排除自身**；④凡"多份实现同一语义"的不变量（采集/清洗/门槛/栏目表），一律用这种扫真实调用点的写法——现役派生清单在 `lib/daily-writers.js`。

### #59 "从事实反查"仍然可以只覆盖一半事实
- 根因：**"反查"是一个方向，不是一种完成度。** 扫描范围写死成几个目录（那本身就是手写清单）、按函数名去重（同函数第二条写入被吞）、只看"名字出现过"（把返回值扔掉、或只在注释里留一句，都算接了）。
- 规则：①反查类判据必须**全仓扫**，排除项只允许"非运行代码"与"测试夹具"两类，且每条排除都写理由并反向断言；②同一函数内**每一条**写入语句单独判定；③判的是**行为后果**而不是名字存在；④**行尾注释也算注释**，剥注释用词法状态机而不是正则（`lib/src-spans.js`）；⑤残余面要明说不假装全覆盖——静态抓不到的（动态派发、运行时拼表名）由行为层兜。

### #63 剥注释的状态机不认正则字面量：注释没被剥净，"注释里写一句已接线"就又算接了
- 根因：**同一份词法判断写了两遍**（一份剥注释、一份直接吃源码），两边对"这是不是注释/字符串"的意见会分叉；而状态机若没有"正则 vs 除法"的判别，正则字面量里的引号会被当成字符串开头，之后整行行尾注释以"字符串内容"的身份留下。
- 规则：①词法判断只许有一份实现，需要不同视图就从同一次扫描派生（`lib/src-spans.js` 一次扫描出 code / masked / strings+comments）；②判"接没接线"要抹掉字符串内容，判 SQL 用字符串字面量清单而不是源码全文；③自检必须**双向**（抹完仍能通过语法检查=没吃代码；只在注释里出现的词确实消失=没留注释），只做一向等于没做；④需要按偏移互查的两个视图必须与原文**等长**（等距抹成占位符）——某一视图变成变长字符串后，所有基于偏移的区间全体错位，而错位的读数看着完全正常。

### #64 锁文件在顶层 require 本轮新建的模块 → 基线树上加载崩，被读成"锁是假的"
- 根因：判据按"用例名要出现在红清单里"取结果，而顶层依赖让**整份文件加载失败**，一个用例名都没产出，于是读成"改前不红"。同族触发形态还有"锁文件顶层读 `.env`"（`.env` 被 gitignore，基线树里根本没有）。
- 规则：①行为锁里**被测模块一律惰性取**，让每条用例各自报红；②新增门禁（基线上根本没有对应形态的判据）**不适用改前红取证**，它的证据是负向探针（把被禁写法喂给判据，必须逐个翻转），不许为了凑取证把断言写弱；③"跑不起来"和"跑出了红"必须分开报；④契约型锁（只读源码文本）不许 require 任何需要 `.env`/凭据的模块。

### #68 别的写入者产出的"正常行"，不是本次修复的证据
- 根因：`daily_reports` 是多写者共用表，**"最新一行"不等于"我改的那条路径产出的行"**——差点把一条规则版产出当成 AI 版生效证据。讽刺的是读侧早有形态指纹判据（`lib/brief-guards.js`），取证时没用它。
- 规则：任何"修复已在线生效"的断言必须同时给三样，缺一律写"未验证"：①**产出者的形态指纹**（按指纹认，不按时间取最新）；②**该产出来自哪次 run / 哪个 head_sha**；③**可见面读数**（页面实际渲染的计数）。
- 另：统计口径要**换一种写法再算一遍**——两个数不一致就是判据坏了、不是数据变了（实测过一次 `LIKE 'x%'` 前缀与 `LIKE '%x%'` 包含只差一个 %，让同一张表先得到 0 条、再得到 6 条）；并把**清单本身写进脚本**（数的是哪几个实体、用包含还是前缀），否则下次换个实体集又得到一个无人能复核的数。

### #69 一次性探针自写掩码，只掩顶层键 → 嵌套层的凭据明文进了会话输出
- 根因：掩码被当成"每次现写的一段代码"而不是**一份共享实现**。同一课已在读层修过（密钥在 `config` 嵌套层，只在顶层打码等于没打），换个宿主就重犯。
- 规则：①打印/落盘 settings、credentials、报警渠道前必须过 `lib/secrets.js#maskDeep`，且把"掩了几处、哪些路径"一起打出来——**静默少掩**比报错危险，因为它看起来像成功；②一次性脚本不许自写掩码；③凭据形态模式表要与扫描面一起扩（报警渠道的密钥长在 webhook 里）。锁在 `tests/regression-secrets.test.js`。

### #71 判据取错了视图字段 → 遍历一个字符串得到逐字符，`undefined` 一律 continue → 恒绿
- 根因：把字符串当数组遍历，循环体每次拿到一个字符，属性永远 `undefined`，全部 `continue` → 判据在任何输入上 0 命中，而"scanned=N"照常打印，看起来完全像"扫了很多、一处没有"。这条的方向是"命中 0 才算过"，**恒绿与真收口长得一模一样**。
- 规则：①接线前先拿"已知有 N 份副本"的老状态跑一次判据，红因必须是**能对上号的 N 处**；②要哪一视图就取哪一视图（字符串字面量清单 ≠ 抹掉注释后的源码）；③负向样本（塞一份坏的必须红）与反向样本（合法写法不许红）必须同批进锁，单向自证等于没自证。锁在 `tests/regression-ai-prompts.test.js`。

### #75 豁免名单只挡"今后新增"，不撤销历史
- 根因：豁免有两种语义，混用就出事——①**存量挂账**（这批历史项以后再说）只该挡"新增"；②**判据不适用**（这个文件天生归不到这条判据下）整块让路。用②的方式实现①，就是给自己开了"从此这文件再写什么都不判"的口子。
- 规则：①存量基线**单独成处**（机器生成的基线清单），判据只对基线之外新增红，棘轮的清除动作 = 基线少一项且与缺陷账同步；②**常驻判据要有自己的入口**（npm 子命令一类），禁止靠命名前缀把它和一次性脚本混在同一目录同一命名空间——混了之后没人知道哪个是天天跑的，于是一次性脚本被当门禁、门禁被当脚本；③按文件粒度豁免时要留一条负向样本（在这个文件里新写一个违规形态，判据必须还能抓到）。

### #T2 云端测试写生产 `settings` 且 `after()` 静默失败：报警链路被打死 2 天
- 症状：后台报警日志显示"已触发"，但审计里最近三条真实事件全是 `sent:0/total:1`；线上 `settings.alerts.channels` 只剩一个测试渠道，silence 里留着哨兵 id。根因是测试直连生产 Turso 写配置，`after()` 恢复未生效且无人断言。
- 规则：①写生产配置的测试必须**取原值 → 写入 → 还原 → 断言还原成功**，断言失败要让测试变红（不能只 catch）；②生产写路径要有"测试指纹守卫"（识别 `test-` 前缀 id、本机回调地址、哨兵值即拒绝写入并告警）；③报警/凭据这类"自证链路"的键，任何改动后必须跑一次真实投递验证（`POST /api/alerts/test` 收到消息才算完）；④**监控显示"已触发"不等于"已送达"**，UI 必须区分 dispatched 与 delivered。
