## T3-1 早报体系 v3：每日早报（公共版）+ 我的早报（个性化）（P0-需求）

> 进度（2026-09-13 深夜二）：R0/R0b/R4/R8 ✅（ea4f5d6）；R0c 主题全景 ✅ + R7 阅读足迹 ✅ + T4-3 视频入报 ✅（4aa76d2，今晚 21:30 首跑产出真实数据）；R5 行为画像加权与 R6 完整形态（Domain 篇数配额）→ T4-2 后继续

### 统一约定（两项共用）
- **R0 生成窗口**：每日早报与我的早报改为**晚间生成**（建议 21:30 北京，`collect.yml` 新增 cron），窗口=「前一天 00:00 ~ 当天 21:00」，实现"晚间整理，读前一天+白天"的自然日回顾；原 00:32 daily-ai 保留为补跑兜底。
- **R0b 配额调度优先级**：**早报/周报生成 > 翻译**。生成窗口前后 N 小时（可配，默认 ±3h）内 translate 批次自动缩小上限（TRANSLATE_LIMIT 环境或 settings 动态调低至 0），保证深析/导语/主题全景的配额；非窗口期恢复。
- **R0c 主题全景**：两类早报都新增「主题全景」区——把当日高评分碎片**按主题聚类**（跨源标题 Jaccard+AI 命名），每主题给四类视角标签：**事件 / 领域 / 人物 / 产品对比**，AI 生成一段主题综述（≤120字）。数据结构：sections 增 `themes: [{name, viewpoint, articleIds[], summary}]`。

### 每日早报（公共版）
- **R1 来源范围**：全部启用源（现走 settings daily.articleSourceIds，为空时=全部——用户指的"自己选的源定向分析"即此配置，云端当前为空走全量；管理台 T3-2 提供勾选）。
- **R2 推荐算法+破茧**：高评分（六维 totalScore）关注源文章正常入选；**破茧位**混入未订阅/低频源的高分内容（六维总分 ≥70），标注「探索」徽章（承接 T2-2 R3/R4 语义，落在每日早报）。
- **R3 六维评分**：选题/内容/深度/实用/创新/表达（管线已有），条目内联展示评分与理由。
- **R4 补充阅读 10 篇**：每日早报增设「补充阅读」栏，**固定 10 条**（我的早报同步改，见 R6）。

### 我的早报（个性化）
- **R5 兴趣驱动**：订阅集合 = `subscription.ids`（T2-1 落地后）+ **显式行为加权**：reading 表点击/收藏/稍后读行为 → 兴趣标签画像（复用 T2-2 R5），影响排序权重；「Domain 自定义篇数」= 每个兴趣域可配条数上限（settings `mybrief.domainQuotas`）。
- **R6 内容形态**：高评分关注文章（六维）+ **摘要 + 关键观点（points 已有）+ 金句（quote 已有）**，按主题全景分组呈现；**补充阅读固定 10 条**（现 rest 上限 3→10，取自非订阅源高分内容并标注来源）。
- **R7 阅读足迹回顾**：每天晚间生成「一天的阅读小结」回顾页（/mybrief/ 页内区块或独立 tab）：当日已读篇数、阅读时长分布、收藏/稍后读、top 来源，附一句 AI 总结。数据源 reading 表当日记录。

### 周报
- **R8 周刊 AI 总结注脚**：每周生成时附一段 AI 周总结（本周主线/趋势判断，≤200字），显示在 /weekly/ 页脚注；归档条目同步保存。

### 验收标准
- AC1 晚间 21:30 两报自动生成，覆盖窗口正确，飞书推送含主题全景
- AC2 生成窗口内 translate 上下限生效（日志可见），生成配额充足
- AC3 每日早报含探索位（≥1 条非订阅源高分带徽章）+ 补充阅读 10 条
- AC4 我的早报条目含摘要/观点/金句，主题全景四视角可见
- AC5 周刊页脚注出现 AI 周总结
- AC6 阅读小结与当日真实阅读记录一致

## T3-3 读层性能优化（P1-性能）

### 现状（2026-09-13 实测，Vercel 生产）
| 接口 | 耗时 | 主要开销 |
|---|---|---|
| `/api/reading?tab=all` | **11.2s** | UNION ALL（articles 4.3万×videos）全量聚合 + 多组 COUNT |
| `/api/status` | **6.1s** | overview 多组 COUNT/GROUP BY（今日/近7天/来源榜，排除热榜的 NOT IN 语义） |
| `/api/hot?tab=all` | 2.5s | 3 天窗口 + score 扫描 |
| `/api/articles` | 1.8s | 已有 idx_articles_pubco，尚可 |

### 需求
- **R1** reading：counts 与 items 拆分（前端首屏只要 items+粗计数）；聚合 SQL 走覆盖索引 `idx_articles_read(read_at, later)`；游标分页沿用。
- **R2** status：overview 拆成轻量核心（未读/今日新增，一次索引 COUNT）+ 慢速榜（来源榜/入早报统计，前端懒加载独立端点 `/api/status/overview`）。
- **R3** hot：`idx_articles_score` 表达式索引（score DESC NULLS LAST + published_at）。
- **R4** 前端：页面级 SWR 缓存（5min TTL）+ 骨架屏替代"加载中…"；hover 预取补 /reading/ /hot/。
- **验收**：三接口 P95 < 2s（线上实测），切换无"几秒加载中"。
