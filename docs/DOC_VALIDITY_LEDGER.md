# 文档有效性判定清单（裁决台账）

> 最后更新：2026-09-25
> 本文件**只做一件事**：把散在各活文档里的「约束 / 边界 / 口径 / 决策」逐条摊到可裁决粒度，标出它现在还会不会指挥人做错事。
> 裁决人是用户。Agent 不许在清单里给自己盖章「已确认」；每条 `裁决` 留空即为未决。
> 配套：模块与子模块的位置见 `docs/INDEX.md` 模块地图；本清单只装**结论与因果链**，不重复地图里的位置信息。

## 0. 三条准入门槛与一条单位规则（本轮判定用的尺）

一条东西**有资格留在活文档**，必须同时满足：

1. **已验收确认**——有线上实测、探针直读、或用户明确裁决其中之一；只有"文档写了"不算。
2. **会反复影响项目实现**——未来改动还会撞上它。一次性的验收流水、单轮排障过程不算。
3. **写清了为什么（因果链）**——只有"必须怎样"没有"因为会炸成什么"的，视为残缺，要么补因果要么出局。

**单位规则**：一条判定 = 一个「用户可改项」× 一条「可失效的因果断言」。
不以数值为门槛，也不以文件/章节为粒度。原因：**同一事实常有多段并存、尺度不唯一**，而数值本身会随版本漂移（这个文档要求 N 行、下个版本要求更多再验收）——拿数值当尺，尺会先坏。
数值在本清单里只有两种合法身份：**证据**（"实测得到 X"）或**失效信号**（"变成 Y 就说明这条已废"）。

条目写法固定五段：**是什么 / 为什么 / 要什么效果 / 边界 / 禁止什么**。

### V07 同一个"分钟数"在库里指三件不同的事，而且批次节奏的数值被抄进了不该抄的地方

### V23 我的早报的降级标记恒为假

- **是什么**：我的早报落库时把"降级"这个标记写死为否，所以前端那条降级提示永远不会出现；导语或主题全景没生成只写进生产日志，库里不留原因码。
- **为什么**：日报那条链路先做过原因码（有跳过原因字段），我的早报抄了形状没抄这一半。用户在页面上看到内容变少，系统告诉他"一切正常"。
- **要什么效果**：内容缺席必须能归因；不能归因的缺席要在文档里明确标为"当前不可观测"，而不是标为"正常"。
- **边界**：只判这一处的可观测性缺失；日报侧原因码机制可作改造基线。
- **禁止什么**：禁止在前端留一条结构上取不到真的提示分支——它是假的安全感，比没有提示更糟。
- **证据**：写死位置与日报侧对照见 `tools/collect-turso.js`；问题台账 H30/H35 已记同类归因缺口。
- **失效信号**：出现我的早报侧的原因码字段。
- **裁决**：☐ 接原因码 ☐ 摘掉死分支并写明不可观测 ☐ 待议

### V24 删哪些表声明在一份策略里，但云端那条路还自带一张自己的表清单

- **是什么**：内容清理"删哪张表、按什么条件"有一份唯一声明。但云端手动清理那条路径除了走这份策略删文章，还会遍历**本文件自带的另一张表清单**（含跳过位）直接拼删除语句执行。于是"系统会删哪些表"这个问题的答案分散在两处。
- **为什么**：各处历史独立长成——策略表是后来收口径时建的，云端那张清单更早就在，收口时没并进来。风险不是删错，而是**读策略文件的人会以为已经收口了**，据此判断"改保留天数不会影响别的表"，而实际那张清单里的表也按同一个截止时间在删。
- **要什么效果**：谁能删、删哪些表、过不过闸，一处说清；那张清单要么并进策略管辖，要么在策略里显式声明"这几张表归手动清理自己管"。
- **边界**：本条只判通路完整性与"读哪份才知道全貌"，不判保留期数值、也不判该不该删这些表。
- **禁止什么**：禁止新增删除路径时绕开策略声明；禁止让预览与实删查两套判定（此项待核，见 W06）。
- **证据（一手读原文）**：生产批次——先取闸再发两条删除，SQL 由策略派生（`tools/collect-turso.js:732` 取闸，`:775` 热榜轴，`:781` 保留轴）；云端手动——先过闸，不过则一条不删、返 409 并留审计行（`api/[...slug].js:2197-2201`），随后 `:2209-2211` 遍历本文件那张清单逐表拼 `DELETE FROM 表 WHERE 列 < 截止`；策略侧作用域与跳过理由在 `lib/retention.js:51` 起的表里。
  ⚠️ **更正我上一版**：我曾把本地维护模块算作"不过闸的旁路删除"。读原文后撤回——那两处一处是**注释里的历史说明**（`server/services/datamgr.js:13`，讲的正是旧版裸删被收口的经过），一处是**备份还原流程**（`:53`，还原前先清空目标表），都不是清理通路。
- **失效信号**：那张清单被并入策略、或策略出现"手动清理自管表"的显式声明。
- **裁决**：☐ 并入策略统一管 ☐ 策略里显式声明边界 ☐ 只画一张通路表进文档 ☐ 待议

### V25 采集语义三份实现，"同步"靠人自觉

- **是什么**：同一套过滤/清洗/熔断/去重逻辑在本地、云备份端、生产链路各有一份实现。项目规矩要求改一处查三处。
- **为什么**：三端演进不同步是既定架构代价，不是缺陷。但**文档里"已同步"的陈述大多是某一时刻的手工核对**，会随时间失真。
- **要什么效果**：讲采集语义时，写"哪几端各有一份、差异容忍是什么"，不写"已同步"这种会被历史打脸的状态。
- **边界**：已有白盒检查覆盖一部分一致性面；本条只管文档怎么写才不会腐烂。
- **禁止什么**：禁止用"三端一致"替代逐项比对；禁止把差异容忍当免检牌。
- **证据**：三份实现路径已在 `AGENTS.md` §1 与 `DEVELOPMENT_STANDARDS.md` §2 各写一遍（两处口径不完全相同）。
- **裁决**：☐ 只留一处讲、另一处指路 ☐ 待议
