## 背景：产物没有统一的"期"概念，所以后台必然乱

实测三报的存储形态完全不同：

| 产物 | 存储 | 期号 | 历史 | 档位 |
|---|---|---|---|---|
| 每日早报 | `daily_reports` 表（线上 **93 行**，真 7 天窗 27 行：AI 版 15 / 裸关键词版 11 / 降级 1） | 自增 id，无"第 N 期"语义 | 有 | `schemaVersion` |
| 我的早报 | `settings['mybrief.latest']` **单键覆盖写** | 无 | **无**（历史期直接丢失，= H13） | 无 |
| 精选周刊 | `settings['weekly.latest']` + `weekly.archive`（**107,918B / 5 期**，每期内嵌完整 report，items 又在 `storylines[].items` 重复一份） | `archive.length+1` | 有 | `degraded` |

由此产生的用户可见问题，逐条实测：

1. **生成历史"没反应"**（B39）：SQL 是 `ORDER BY id DESC LIMIT 7` —— **不是 7 天窗是 7 行**，20 行永久不可见；且不投影 `schemaVersion`、类型列硬编码「每日早报」（`BriefCenterTab.jsx:87`）→ 裸关键词版 `theme=null`、`degraded=false` 反而显示绿色「正常」。周刊 5 期完全不进这张表；我的早报只有单键 → **永远 1 行**；「阅读足迹」永不出现（云端 38 个 settings 键里没有 `reading.digest`）。
2. **周刊归档"信息太少"**（B40）：数据**在库里**（`coverTheme`/`editorNote`/`storylines` 齐全），前端只投影 6 字段、只渲染 5 个 → 最新最好的第 4/5 期反而显示「—」。第 2 期 theme 仍是 B16 污染串「我需要找到贯穿这些文章的核心主线。」，第 3 期是「19-20: 日本加息…」带 LLM 序号前缀 → **脏数据仍在归档**。更糟：期号 = `archive.length+1`，**同窗口重跑即算新期**（5 期里 4 期共用 09-11~09-18 同一范围）→ 调试产物无去重直接污染归档。
3. **「我的早报设置意味不明」**（B41/B42/B43）：4 项里 —— 探索强度 ✅ 生效（low2/mid4/high6，但 rest 固定 10 条，UI 无说明）；画像 ★ 加权 ✅ 生效；Domain 配额 ⚠️ **只裁订阅池，探索位完全绕过**，且键是主标签不是域名（命名误导）；飞书推送 ⚠️ 读得到开关但推不出去（真因是 B44 报警渠道被打坏）。而"订阅源在源库设置"的指路本身失效：线上 `subscription.ids=[]`，实际靠 54 个 ☆ 兜底 → **这现在根本不是"订阅"报**。
4. **卡顿**（B38）：早报中心 4 请求 ≈134KB / 两段瀑布，`/api/settings` 被调两次、`/api/settings/daily` 120KB（内嵌 1200 条 articleSources）；`/api/brief/history` 每次服务端解析 107,918B 换 6 字段（H11 同型）。
5. **栏目管理**（用户批注⑪）：设计停留在"关键词三栏"时代，与已上线的 AI 分领域聚类（T5-3）并存但用户看不出关系，且每个选项无功能说明。

## 目标

- G1 三报统一"产物 / 期 / 档位 / 历史"模型：任何一报都能回答"第几期、什么窗口、AI 还是降级、几条、能否重跑、能否预览上一期"。
- G2 期号有业务语义（窗口去重），**同窗口重跑覆盖当期而不是新增一期**。
- G3 后台"早报中心"拆成三块互不越界：产物历史 / 当期详情与预览 / 生成与推送设置（与 38-4 协同）。
- G4 归档瘦身 + 投影补齐：列表轻（一次解析换全量 → 分页或预投影），详情走已存在的 `/api/weekly?issue=N`。
- G5 每个设置项可验证生效：改了必须改变链路行为，否则从 UI 摘除（H12/H10 同族规则）。

## 边界

**不做**：不改早报的策展算法与评分口径（那是 35B/T5-3/B17/B20 的域）；不新增第四种报；不做定时生成的新调度（沿用 runner 现有 cron）；不在本域解决"周刊初筛预算不足"（B17 需单独拍板）。
**依赖**：40-1/40-2 是纯投影与读路径，可先做；40-3/40-4 涉及写生产数据与存储模型，必须在 37-1（报警恢复）之后——否则改坏了没人知道。

## 验收标准

- AC1（40-1）：生成历史显示 27 行（真 7 天窗）且能区分 AI 版/裸版/降级；周刊与我的早报出现在同一时间线。
- AC2（40-2）：归档列表能看到第 4/5 期的 `coverTheme` 与 storylines 数；打开 `/api/brief/history` 响应体 <20KB 且服务端不再全量解析 107KB。
- AC3（40-3）：同一窗口重跑周刊两次 → 归档仍只有 1 期且内容为后一次；历史伪期被清理（前后计数对比）。
- AC4（40-4）：我的早报有"第 N 期"且能翻回上一期（当前完全做不到）。
- AC5（40-5/40-6）：后台任何一项设置，文档里能写出"改前行为 → 改后行为"，并有对应回归测试；无测试的设置项不许存在。
- AC6（40-8）：`read_at='null'` 行数归零、周刊 theme 无第一人称串；未读角标与保留清理预览数字回到可信区间。
