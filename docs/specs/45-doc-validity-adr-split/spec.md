## 1. 为什么做（因果链）

上一轮把 `docs/features/`、模块地图、`ARCHITECTURE.md`、16 份 ADR 洗过了，**`docs/` 顶层那批操作性文档没洗**。它们的问题不是"写得不好"，而是**继续指挥人做错事**，四条一手证据：

| 证据 | 读数 | 后果 |
|---|---|---|
| 决策仍住在操作性文档里 | 全库提到 `ADR-` 的只有 3 份文件（架构文档、地图、ISSUES）。链路指南 / 功能矩阵 / 评测指南 / 运维手册 / 开发规范 / 上手指南 / 需求队列 **一份都没指 ADR** | 决策与实现细节同批过期；下一个动手的人把"当时的取舍"当"现状描述"改 |
| 决策形状陈述堆在操作文档 | 功能矩阵 27 处 · ISSUES 26 处 · 评测指南 25 处 · 链路指南 20 处「不做/禁止/不许/永不/不设」 | 同一取舍散在多份，互相矛盾时读者不知信哪份 |
| 写死接口 | 顶层文档 18 处 `file.js:123` 行号锚（功能矩阵 10 / ISSUES 5 / 治理 2 / 链路指南 1）；全库活锚点 59 条 | 重构后锚点失效或行号错位，读者按错坐标改代码 |
| 过期内容以现役身份挂第 1 必读 | 链路指南是 `AGENTS.md` §0 的第 1 必读，里面挂着「2026-09-11 实测审计」的章节；运维手册有「2026-09-11 方案A 后」；交付验证有「2026-09-11 实战案例（本文档的出处）」 | 17 天前的审计结论被当今天的现状引用 |

另有两处**凭证已销毁**：ADR-05 的依据栏指向已退役的判定台账（那份件本轮已删，此处不复述它的路径）；仓库根 README 的 11 条截图引用全部悬空，`npm run lint:docs` 现为 **11 错 27 警**（以重跑输出为准）。

## 2. 判据：一条陈述只有三种去处

判据不是字数，是**"删掉它会不会指挥人做错事"**。

| 类别 | 认法 | 去处 |
|---|---|---|
| **决策** | 短期不变的定位，或明确的"不做什么"，且**答得出为什么** | `docs/adr/` 续号件：是什么 / 为什么 / 边界与禁止 |
| **护栏** | 违反就停摆，但不涉及方向取舍（机制约束） | 留原文件，重写成"改了会怎样 + 现在读哪里能验" |
| **一次性读数 / 出土过程** | 每天变的数、"哪天被谁推翻、当时读到多少条" | **删**，不留指针，反查走 git |

**边界判据（本轮最容易判错的一刀）**：
- **"没做" ≠ "不做"**。排期里的需求、界面上根本没有控件的东西、结构性缺列，都不许写成决策件——那是现状，不是取舍。
- **"尺子的规则" ≠ "软件的方向"**。文档分层、归档处置、交付链步骤属治理，留在治理与验证文档，不进 `docs/adr/`。
- 一条陈述要进 ADR，必须填得出【为什么】。填不出 = 不是决策，或需用户补因；**不许由 agent 编造因果链**（因果链来源只有三种：文档/提交里的原文、现读得到的机制后果、用户口述）。

## 3. 有效性三态标记

顶层文档里被本轮读过的结论，只能是三种写法之一：

1. `现役（现读 X 可验）` —— X 是代码/配置/作业文件/库表现读字段/现役文档，不是一次性件。
2. `与实现相反 → 已按真值改掉（依据：X）` —— 当场改文，不改真值来源。
3. `待实测 + 怎么测` —— 离线判不了、必须打线上才能定的，就地写明测法，进 §9 的 B 清单。

**不许**出现的依据形态：某轮会话、某份已删台账、某轮交接件、"因为 09-XX 裁过"。

## 7. 本轮明确不做

1. **不改 `tools/` 与 `tests/` 任何文件**。含 `doc-lint`、`doc-stamp`、所有锁与判据。
2. **不自己消红**：若本轮文档改动让某枚锁变红（文档改动会牵动锚点类、登记类判据），**停下来报给用户三选一**（改代码 / 改锁 / 摘锁记理由）。这轮的冲突默认由用户裁决落哪边。
3. 不改 `DOC_GOVERNANCE.md` 的判据本体。它有两处与原则 1 冲突（归档五字段头注**要求**写 `file:line（函数名）`；门禁第 8 条把 59 条活锚点当合法物保护）——本轮**登记进 `ISSUES.md`**，标"改判据需与门禁同轮"，不动它。
4. 不新建目录；不动 `HANDOVER.md`、`STAMPS.md` 内容；不重写 `AGENTS.md`。
5. 不给已删文件补"已归档"标注，不写"原文见某归档件第几节"。
6. 不把 `docs/features/`、`docs/pitfalls/` 已洗过的内容再洗一遍（只在被顶层文档指路时核对指针是否还活着）。
7. 不为消长度警而压语义。

## 8. 写作规矩落到操作层

必须消失的形状（本轮判据）：`file.js:123` 行号锚 · 连排函数名/类名/字段名 · 复述代码结构（"某某文件里有几个写入函数、分别叫什么"）· 一次性读数（行数量级、秒数、篇数、源数、具体记录 id）· 章节标题里的日期与"取代旧表述"句式 · 指向已销毁件的依据。

允许且要求的形状：
- 叙述主轴 = **用户改了某项设置 → 数据经过哪些步骤、什么流向 → 最后产生什么结果**。
- 跨模块只记**接口契约**：调了什么、输入输出是什么、失败怎么处理；不写对面怎么实现。
- 关键链路只在**篇末保留少量源码入口**作索引（只给文件路径，不给行号、不给函数名）。
- 取值不写死：写"唯一承载处是哪份文件/哪个键"，或写"以命令输出为准"。
- 边界用"不能做什么"表达，必要时给输入输出示例。

## 9. B 清单（关键项云端实测，压到个位数）

离线判完后再打，代理与命令行口径见 `docs/DELIVERY_VERIFICATION.md`（本文件不复制端口与取值），候选四项（最终以波 1~2 结束时的实际存疑项为准）：

1. 功能矩阵里"云端有没有某功能"的逐格覆盖结论。
2. 采集双档触发现在还剩几档真在跑（现读库里的采集心跳归属，不看文档）。
3. 夜间预算那套常数是否真生效（三段耗时是否落库可读）。
4. 清理闸的实际状态（闸门是否挡住、当日有无心跳）。

代理或凭据不在位 → 按 A 案收口，这几项就地标 `待实测 + 怎么测` 并在需求队列挂号，**交付说明里明写"没测及原因"**。

## 11. 交付与回滚

每波验收链：`npm test`（不新增红）→ `git push origin main` → 查 `ci.yml` 与本波相关端点的线上实测 → `npm run lint:docs` 读数（**基线是 11 错 27 警；本轮只要求不新增错、且把本波涉及的悬空清零**，tools 不动则长度警与归档头注警会原样留着，如实报数）→ `node tools/doc-stamp.cjs` 刷 STAMPS → 文件清单交用户。

提交纪律：只 `git add` 本波真正改过的文件路径；用户工作树里那批未提交删除不碰、不复活、不代提交。

回滚点：波 0（地基）单独成一个提交，7 件新 ADR + 6 处边界增量各成独立提交；每波文档改动独立提交，便于单波退回。

## 12. 知情代价

- 一次性读数删掉后，要复核当时的现场只能回 git 翻提交；用户裁决是"这些每天都会发生变化"，接受。
- 治理文件的两处判据冲突仍在（§7 第 3 条），意味着 `docs/archive/` 的新头注下一轮仍可能被要求写行号锚。本轮只登记不修。
- `tools/` 不动，所以门禁仍会把"活锚点行号存在"当合法物校验；本轮把顶层 18 处锚点铲掉后，这部分判据对顶层文档变成空转（不报错，也不提供任何保护）。
