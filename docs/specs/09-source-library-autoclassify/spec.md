# 订阅源库管理 + 源自动分类 Spec

> 来源设计稿：`archive/样图/1.png`（订阅源库弹窗）、`2.png`（我的关注三栏，其「文件夹树 + 人工筛选精华源」理念作为设计指导）、`3.png`（源详情/文件夹下拉，仅参考手动改归交互）。
> 决策记录（2026-09-05 与用户确认）：关注=enabled + 特别关注=focus 两者都要；自动分类=OPML 原生分类+关键词兜底；存量 559 源回填=先预览再执行；页面形态=管理台新 Tab。

## 背景

系统已通过 bestblogs OPML 导入 559 个源（公众号 375 / YouTube 124 / 播客 60，另有 hotlist/bilibili/douyin/x 等），但：

1. **分类信息被浪费**：YouTube OPML 自带 8 个分类层级、播客 OPML 自带 7 个中文分类，当前导入工具只按文件粗分「公众号/YouTube/播客」三组；375 个公众号全部挤在一个组里。
2. **源规模增长后无法人工理清**：没有统一视图浏览"我们有哪些源、哪些可用、哪些熔断、属于什么分类"；现有 WechatTab/BilibiliTab/DouyinTab 按平台割裂，只覆盖部分类型。
3. **信息过载的根因是源未被筛选组织**（用户对 2.png 的澄清）：所有源都在更新，"全部文章"视图淹没有效内容；解法是先把源库管好（分类 + 关注/特别关注），feed 层的智能呈现留待后续迭代。

现有基础：`groups` 表 + `sources.group_id` + Sidebar 分组 CRUD/拖拽；`sources.enabled`、`sources.focus`、`fail_count` 熔断状态机；groups/sources 全套 CRUD API。

## 目标

- 在管理台提供一个**统一的订阅源库视图**：任何类型的源都可浏览、筛选、体检、批量管理。
- 提供**自动分类机制**：新源创建时自动归入合适的文件夹；存量源可预览式回填分类。
- 用户始终拥有最终决定权：手动改归优先于自动分类，自动分类永不覆盖人工调整。

## 功能需求

- **F1 源库浏览**：管理台新增「源库」Tab，以列表展示系统内全部源——含已停用、已熔断、已退役（wemp 等历史类型，以「已退役」徽章区分）及标记型源（marksFeatured，不进阅读器侧栏但属于管理视角）。每行展示：源名称、内容类型、所属文件夹、启用状态、特别关注标记、健康状态（正常 / 熔断中[含失败次数] / 已停用 / 已退役）、最近一次抓取时间、**累计已采集条目数**（文章源=累计文章数，视频源=累计视频数；注意区别于现有接口的"未读数"口径）。支持分页浏览。
- **F2 筛选与搜索**：支持按以下条件组合筛选：内容类型（全部 / 文章 / 播客 / 视频 / 推文 / 热榜；类型判定以源元数据为准，判定规则表在 plan.md 定义）、所属文件夹、状态（全部 / 仅未启用 / 仅熔断 / 仅特别关注）；支持按源名称关键词搜索。
- **F3 批量关注操作**：支持勾选多个源（含全选本页）后执行批量操作：批量启用（关注）、批量停用（取消关注）、批量设为特别关注、批量取消特别关注。**批量启用必须复用统一解冻语义**（清 fail_count + 清错误标记，与现有 toggle 一致），并对这批源的首次抓取时间做**随机错峰**（参考导入工具的 6 小时随机窗口），避免同一调度周期全部到期打爆采集队列。**批量特别关注只做增量更新**（按选中源逐个设置/清除），严禁使用全量替换语义——日报设置页的 focus 勾选是全量替换写法，两种写法并存会互相覆盖配置。批量操作完成后给出成功/失败计数反馈。
- **F4 手动调整分类**：单个源可通过下拉直接改属文件夹；勾选多个源可批量移动到指定文件夹。**文件夹选择范围受内容类型约束**——文章类源只能选择文章文件夹，视频类源只能选择视频文件夹（前端过滤 + 后端校验双保险，现有拖拽接口无此校验，会静默失效）。凡经用户手动改归的源被标记为「手动锁定」，锁定在**所有手动改归入口统一生效**（源库 Tab 的下拉/批量移动、阅读器 Sidebar 的拖拽），之后的自动分类（含存量回填）默认不再改动它。
- **F5 新源自动分类**：任何入口新建的源（管理台手动添加、OPML 同步新增、云端队列导入）在创建时自动执行一次分类，按优先级取第一个命中：
  1. 来源清单自带的分类层级 → 映射到内置分类目录（**适用范围**：解析本地 `opml/` 目录带层级的清单——YouTube 8 类、播客 7 类，用于存量回填；公众号 OPML 为扁平结构无层级，此条对其天然不生效）；
  2. 内置关键词规则（对源名称及描述做匹配）→ 内置分类目录；
  3. 均未命中 → **保持未分组**（沿用现有「未分组」语义，不新建实体「未分类」文件夹，避免双语义并存）。
  自动分类结果即新源的初始文件夹，用户可随时按 F4 手动改归。
  **破茧栏联动**：自动分类实际落组（含回填执行）时，所用的文件夹名需同步纳入日报「破茧栏」的域内分组名单（该名单当前为硬编码，本期改为可配置并把新组名并入），避免源搬家后破茧栏内容构成静默突变。
- **F6 存量回填（预览→执行）**：管理台可对存量源发起自动分类**预览**，逐条展示「当前文件夹 → 建议文件夹 + 命中依据（OPML 分类 / 关键词）」；**预览默认只列出建议发生变更的条目**（当前 ≠ 建议），可切换显示全部。用户确认后才批量写入。手动锁定的源默认跳过，预览中可勾选「包含手动锁定源」。
- **F7 内置分类目录**：自动分类使用一套内置分类目录（对齐 bestblogs OPML 的中英分类集：编程技术、人工智能、商业科技、金融经济、产品、效率成长、新闻媒体、生活方式与文化等），英文分类名映射到同一中文文件夹；**映射时优先复用系统中已存在的同名/同义文件夹**（如已有「科技」「AI」「财经」等），避免产生重复或近义文件夹；文件夹在首次被使用时按需自动创建（文章类源进文章文件夹，视频类源进视频文件夹）。
- **F8 视觉与设计集成**：「源库」Tab 在观感上与管理台现有页面融为一体，具体要求：
  1. 遵循管理台现有设计语言：主题变量（t-bg/t-surface/t-border/t-accent 等）取色，三套主题（暖色纸张/蓝白/深色）下均显示正常；复用现有按钮/徽章/输入控件样式与全局 toast 反馈；
  2. 图标统一使用现有图标集风格（icons.jsx），不足时按同风格补齐；
  3. 源行头像：源已有头像数据时展示圆形小头像（防盗链处理与现有列表一致）；无头像时用「类型图标 + 名称首字」的占位样式，全列表视觉整齐；
  4. 健康状态以带语义的彩色徽章呈现（正常 / 熔断 / 停用一目了然），特别关注有醒目的星标；
  5. 信息密度高的同时保持呼吸感：行高、间距、对齐与现有 SourceTable 同源； loading、空结果、批量操作进度均有明确界面反馈；
  6. 版心：源库 Tab 因列多（8 列+复选框）允许版心特例加宽（≈1160px），其余 Tab 维持 960px 不变；任何宽度下不出现横向滚动条；窄屏（≥1024px）下布局不破。

## 非功能需求

- **N1 仅本地主系统**：不改 portal 云端副本（冻结态）；不写 portal/ 下任何文件。
- **N2 性能**：600 源规模下源库 Tab 首屏加载 ≤1s；100 个源的批量操作 ≤3s 完成反馈。
- **N3 安全**：批量操作、自动分类执行/预览均为受保护写接口（沿用现有 Bearer JWT 鉴权，无新增公开面）。
- **N4 可测试**：自动分类规则为可独立测试的纯逻辑；新增接口有回归测试；`npm test` 全绿、`npm run build` 通过。
- **N5 兼容性**：不改动 ReaderPage/Sidebar 现有分组行为；`groups`/`sources` 表不加列（手动锁定标志存 `sources.extra`）；旧数据无需迁移即可运行。

## 不做的事

- ❌ 英文文档翻译功能（用户明确暂缓）
- ❌ 视频文案提取功能（用户明确暂缓）
- ❌ 「我的阅读」沉淀页（样图 4.png）——后续迭代
- ❌ 高级筛选面板 + 保存为视图（样图 3.png）——后续迭代
- ❌ 阅读器 feed 排序算法改造（智能排序/推荐，即"信息过载"的 feed 层解法）——确认问题存在，另立迭代
- ❌ portal 云端对应实现（冻结态）
- ❌ BestBlogs 平台侧数据（读者数、关注人数、「值得优先关注」徽章）——无数据源
- ❌ 分类关键词规则的用户可视化编辑器（规则内置，随版本更新）
- ❌ 新增源头像抓取渠道（有 avatar 字段则展示，无则用类型图标+首字占位，不为此新增网络抓取）

## 验收标准

- **AC1**（F1）：打开管理台「源库」Tab，能看到与数据库一致的全部源列表，每行包含名称/类型/文件夹/启用/特别关注/健康状态/最近抓取时间/条目数；翻页正常。
- **AC2**（F2）：组合使用类型+文件夹+状态筛选与名称搜索，列表结果与筛选条件一致（可对照数据库验证）。
- **AC3**（F3）：勾选若干源执行批量停用，这些源立即不再出现在阅读器且不再被调度采集；批量启用后恢复采集且 fail_count 已清零（熔断源不会因下一次失败立即再熔断），且这批源的首次抓取时间被打散（非全部立即到期，可对照数据库 next_fetch_at 验证）；批量设/取消特别关注后，对应源在日报候选中的 focus 行为随之变化。
- **AC4**（F4）：手动改归单个源后，阅读器 Sidebar 中该源出现在新文件夹下；批量移动同理；视频源的文件夹下拉中不出现文章文件夹（反之亦然），直接调用接口跨类型移动被拒绝；**在阅读器 Sidebar 拖拽改组的源同样被锁定**；被手动锁定的源在后续任何自动分类运行中保持不变。
- **AC5**（F5）：通过管理台手动添加一个新 RSS 源（名称命中关键词，如「××技术」），创建后其文件夹自动为「编程技术」；添加一个无任何命中的源，其保持未分组；存量回填中，带分类层级的来源（YouTube / 播客 OPML）按清单原生分类归档。
- **AC6**（F6）：发起存量回填预览，默认仅列出建议变更条目，每条含「当前 → 建议 + 依据」，可切换查看全部（总数与源数一致）；未确认前数据库无变化；确认执行后建议生效，且预览中显示的手动锁定源未被改动（除非勾选包含）。
- **AC7**（F7）：内置目录中的英文分类（如 Programming & Technology）与中文分类（编程技术）落到同一个文件夹，不产生重复文件夹。
- **AC8**（N3）：未登录状态下调用批量操作/自动分类接口返回 401。
- **AC9**（N4）：`npm test` 全绿（含新增回归测试），`npm run build` 通过。
- **AC10**（N5）：阅读器现有分组导航、拖拽入组、日报源勾选行为与改版前一致。
- **AC11**（F8）：三套主题逐一切换，源库 Tab 均无违和色值/对比度问题；列表中有头像的源显示圆形头像，无头像的源显示类型图标+首字占位且整列对齐；熔断/停用/特别关注徽章肉眼可辨；批量操作有进度与结果反馈；任何宽度下无横向滚动条；空筛选结果有明确空态提示。
- **AC12**（F3）：在源库批量设置特别关注后，日报设置页里未选中源的 focus 勾选保持不变（两个界面互不覆盖）。
- **AC13**（F5 破茧栏联动）：存量回填执行后，日报破茧栏的域内分组名单包含回填所用的全部分类文件夹名，日报生成时破茧栏正常产出且内容构成不因分组搬家而突变。
