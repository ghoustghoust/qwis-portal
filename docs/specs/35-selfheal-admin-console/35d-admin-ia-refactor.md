## 为什么它排在最后

1. 现状是 **2026-09-15 spec30 刚收敛过的 5 Tab**（源库 / 早报中心 / 热点榜策展 / AI 能力 / 系统，`web/src/pages/AdminPage.jsx:46-52`），9 个 Tab 组件挂在这 5 个壳上（`:11-19`）。三个月内二次大改布局的代价是丢掉刚建立的肌肉记忆与已写的对照卡（C1/C2）。
2. 35A/35B/35C 会**改变后台要显示的对象**（自愈事件、成功率、冷却队列）。先定布局再加数据 = 必然返工；先有数据语义再定布局 = 一次到位。
3. 后台已知问题里，多数是**行为缺陷**而不是布局缺陷（假开关 H10、改了不生效的周刊设置 H12、无期号无归档 H13、解冻无差别 H15、成功率假 B23、颜色坏 B22）。这些逐个修完，页面该长什么样会自己浮现出来。

## 拆板块预案（批准 D1~D5 后才写各自 spec.md）

- **35D-1 观测与运维面板**：健康度总览、自愈事件流、冷却/待人工队列、报警收件箱（承接 35A-F8、35C-F5）。
- **35D-2 源库工作台**：批量操作、四轴（上架/收录/订阅/重点/屏蔽）编辑、导入导出、探活与重试。
- **35D-3 编辑部**：三报（每日/我的/周刊）的期号、归档、重跑、预览对照（H13 的需求落点）。
- **35D-4 AI 能力台**：模型与配额、翻译管线、提示词版本与 A/B、真实输出抽样（去假开关）。
- **35D-5 系统台**：设置写、数据保留与备份、凭据状态（只显位置与指纹，永不显明文）、诊断自检。
- **35D-6 全局壳**：导航（含 B11 懒加载骨架屏）、错误边界、对照卡规范、深浅三主题一致性。
