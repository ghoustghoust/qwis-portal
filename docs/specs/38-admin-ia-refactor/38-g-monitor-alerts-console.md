## 背景：这一块的现状必须用实测数字说话

- **BL7（本轮重新量化，见 `docs/ISSUES.md`）**：`alerts.recentLog` 近 7 天 **33 条事件全部未送达**（`ok:false, error:"fetch failed"`，最后一条 2026-09-17T08:34）；生产库唯一渠道 `test-ch` 的回调是 `http://127.0.0.1:1`。
- **B67（本轮发现的检测器骗人）**：`eval-preflight` 原判据 `enabled && url.startsWith('http')` 把这个哨兵渠道显示成「1 个可用渠道 ✓」——**P0 在验收门禁里长期绿灯**。现已由 `lib/alert-channels.js` 修正，preflight 如实报红。
- **B45**：云端 `alerts.eventMeta` 实测是空对象，而前端渲染 4 个不存在的事件名（`fuse/stall/queue/error`）→ 事件勾选框看起来能配，实际配不到任何真实事件。
- **B46**：报警只有 7 类事件且 payload 无结构化字段（缺源 id / 参数 / 堆栈 / 代码位置 / 建议动作 / 自愈态）→ 自愈引擎想读也没得读。
- **B48（已闭合）**：全角括号被写成 JSX 文本转义 `\uff08`，界面显示字面串。

## 边界

- 本板块**不定义**事件模型与 payload 结构（37 域的事），也不定义熔断阈值（`lib/source-breaker.js` 的事）。
- 报警恢复（把生产渠道配回真 webhook）是**写生产**动作，用户已决定"先不写生产，等评测就位"→ 在授权前本板块只做"如实显示无出口"，不许偷偷塞一个测试渠道。
- 明文 webhook 地址（含 token）不落界面与日志；掩码同 `lib/alert-channels.js`（只 `scheme://host/…`）。

## 验收标准

- AC1：G1 三态在线上实测为红（当前 BL7 实况），恢复后为绿——同一条判据在两个状态下都要被验证过（负向 + 正向）。
- AC2：G2 的测试按钮必须有"回读 recentLog 且 `ok===true`"的锁；`dispatched:true, delivered:false` 必须判不过。
- AC3：G3 勾选项集合与后端 `eventMeta` 键集合**逐字相等**（回归锁，防 B45 复发）。
- AC4：G6 有 F2P 证据（本轮 F6-1/2/3 三条已出证，基线 `2e2c757`）。
- AC5：端到端剧本覆盖"制造一次采集失败 → 报警出现在列表 → 送达状态为真/为假都如实显示"。
