# 38-B · 后台首页（健康概览 + 待办）—— 板块小 Spec

> 总框架：`spec.md`（38）。状态：**待批准，未动工**。归属工作包：38-5（新页面）。
> 板块定位：**唯一入口**——"今天有没有事要处理"只在这里回答一次；它不修东西，只把人送到能修的地方。
> 关联现状代码：`web/src/components/MonitorTab.jsx`（155 行；端点 `api/health/status`、`api/health/source-stats`、`api/health/collect-history`、`api/queue/stats`）
> 叶子缺陷：B47（任务队列面板读数错误 → 本轮已下线）· 用户批注⑰（"进后台第一眼看不到该干什么"）
> 最后更新：2026-09-19

## 背景：现状是"把监控卡片堆成一页"，不是首页

- 「系统」Tab 实测 1251 行 / 3 Zone / ≈19 张卡（父 spec 定量表），进去先看到进程、队列、清理、快照、报警日志混在一屏——**没有"今天最该看的三件事"**。
- B26 实测：健康概览所依赖的 `/api/status` 是**双峰响应**（30.7s / 14.4s / 0.66s），首页若同步等它，最坏情况首屏 30 秒 → 首页必须分级装载（先缓存值后实数）。
- B47 的教训要写进本板块规则：`MonitorTab` 曾把后端 `{overall, byType}` 当扁平对象读，显示成"队列 0"，**读数错但界面不报错**。首页的每一张卡都必须能自证"这个数是从哪个字段来的"。
- **BL3（关键依赖）**：采集尝试流水不存在（B23 假成功率 / B24 心跳只 25 小时且无正样本），所以"每源成功抓取概率"现在**物理上算不出来**（`docs/ISSUES.md` BL3）。本板块不许先做界面再编数字。

## 目标

进后台 3 秒内回答三件事：**整体活着吗 → 哪里在坏 → 点一下就到**。

## 边界

- **只读板块**：本板块零写操作（不重启、不清理、不改配置），所有动作以深链交给业务板块——这是"一个板块只负责一件事"（G1）的样板。
- B4 在 BL3 未闭合前**不许上线**：宁可不显示，不许显示算不出来的数字（坑 #38/#43 同族：能力不用文案假装，数字不用旧值假装）。
- 不新造端点：首页只用现有健康端点；若要新字段，先改 37 域（链路与数据模型）再来这里显示。

## 验收标准

- AC1：首屏 3 秒内 B1 四卡出数（线上实测计时，含 `--ssl-no-revoke` + 代理）；每卡有出处标注。
- AC2：B2 四条深链逐个点到底（Playwright 剧本 + 截图）。
- AC3：断掉 `/api/status`（改端口或 mock 慢响应）时页面呈现"上次值 + 时间"，不出现假 0。
- AC4：F2P——B47 那类"读错字段但界面不报错"必须有回归锁（本轮已锁 `queueStats.overall`，首页新卡逐条同办）。
