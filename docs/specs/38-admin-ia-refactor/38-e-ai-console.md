## 背景：这里出过三种"界面骗人"

1. **假开关**（B51，已在 38-D 记录）：挂着 4 个复选框和"x/4 已启用功能"，实际摘要/分类/事件关联全是规则实现 → 本轮连后端读写面一起摘（`ai.features` 全库无人消费）。白盒因此新增 **W3b**（某 settings 键每一处 `getSetting` 都只用于回显 → 判假开关）。
2. **占位文案挡住 404**（B52）：前端请求 `GET /api/ai/translate/config`，云端路由表只有 `config/ping/chat` → 实测 404 被 `catch` 吞掉，而 `if (!config) return 加载中` 让页面**永远**显示"加载中"。修后：缺路由时显式报错并指向 39-6（占位文案不许冒充"还在忙"，坑 #43 的 SKIP 同族）。
3. **可写通道本身**（B50，P0）：后台「保存配置」把 `settings.ai.{enabled,apiKey,apiBase,model}` 写回线上，与 `CLOUD_PIPELINE_GUIDE.md` 旧的 env-only 声明冲突；这正是 09-11 全链路 401 停摆 2 天的合法复发通道。**用户 2026-09-19 裁决：保留可写 + 强制审计 + 变更告警 + 写后连通探测失败即回滚**（实施在 39-1/39-3，旧 env-only 表述已作废落档）。

另有 **BL8**：线上 `ai.minIntervalMs=0`（无间隔硬打 Agnes 免费池，45~60 分钟耗尽配额，坑 #A1）——本板块必须把这个数显示出来并挡住"0"。

## 边界

- 本板块不实现任何 AI 逻辑；供应商降级链、重试、缓存全在 39 域（三份实现的收敛由白盒 W1/W10 盯）。
- 不新增"看起来能开关但其实没人读"的控件：**加一个开关必须先指出哪段行为会读它**（W3b 的界面版）。
- 明文密钥、完整 webhook 地址一律不落界面与日志（掩码规则同 `lib/alert-channels.js` 与 `util/log.js`）。
