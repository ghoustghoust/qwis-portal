# 38-C · 源库（信源台账与四轴编辑）—— 板块小 Spec

> 总框架：`spec.md`（38）。状态：**待批准，未动工**。归属工作包：38-1（四轴入口收敛）+ 38-2（布局与刷新）。
> 板块定位：**唯一拥有"一个源是什么状态"的地方**。四轴的可写入口全后台只能在这一块（G2）。
> 关联现状代码：`web/src/components/SourceLibraryTab.jsx`（663 行）+ 平台接入（935 行）= **1598 行 / 51.1KB chunk**；端点面 `api/sources/library`、`api/sources/batch`、`api/sources/dedupe`、`api/groups`、`api/groups/move`、`api/opml/export`、`api/sources/`
> 轴语义唯一实现：`lib/source-axes.js`（上架 `enabled` / 收录 `reader_visible` / 订阅 `subscription.ids`（settings 键）/ 重点 `spotlight` / 屏蔽 `muted`；`focus` 已退役只许迁移函数读一次）
> 叶子缺陷：B33 组合视图无搜索 + 四轴入口割裂在 5 处 · B34 spotlight 双写冲突 · B41「订阅」名不副实
> 最后更新：2026-09-19

## 背景：三件实测事实

1. **轴入口割裂在 5 处**（B33）：`enabled` 三处可改、`reader_visible`/`muted` 只能批量或组卡改、`subscription` 只在源库、`spotlight` 却出现在早报中心 `DailySettingsTab.jsx:96`。同一件事有五个门，用户记不住哪个是真的。
2. **B34 是会丢数据的**：早报中心「保存」走 `PUT /api/settings/daily` **全量替换** spotlight，会把非六类型（wechat/rss/x/bili/douyin/youtube 之外）的重点源清掉。这不只是早报中心的 bug，它证明 **spotlight 的可写入口不该在早报中心**。
3. **B41 是语义问题不是显示问题**：线上 `subscription.ids = []`，而 `lib/source-axes.js` 的 `resolveSubscriptionIds` 在空数组时**兜底用 spotlight 集合**——所以"订阅"这个开关当前实际什么都没决定，界面上的"已订阅"是借来的。要么让用户真的订阅，要么把这个开关摘掉，不许继续显示借来的状态（坑 #38）。
4. **交互成本**：每次轴操作 `await load()` 全量重拉 `/api/sources/library`（`:137/205/217`），点一下约 4 秒且组卡按 issueN 重排跳位（实测）。

## 边界

- 本板块**不生成任何内容**：日报/周刊/热榜的产物归 40 域，本板块只决定"这个源参与不参与"。
- 不改采集链路口径；改阈值/间隔语义要走 35/37 域，且必须同步三端实现（AGENTS §1，`lib/` 单一实现）。
- 平台接入（抖音/B站/公众号，935 行）与本地专属能力（文件快照、抖音本地化）在 UI 上必须标注"仅本地"（云端无此能力，见 38-F 的能力位规则）。

## 验收标准

- AC1：`grep` 判据——五轴的可写调用（`PUT/PATCH` 到该轴）在全后台只出现在本板块组件内；早报中心不再出现 spotlight 写（对应父 spec AC1 + B34 前后对比 `SELECT COUNT(*) WHERE spotlight=1`）。
- AC2：改一个源的间隔，网络面板请求数从"全量重拉"降到 1 次局部写；组卡顺序不变（截图 + 请求计数）。
- AC3：C5 的文案与实际生效集合一致——用隔离库构造 `subscription.ids=[]` + `spotlight=3` 的场景，界面显示的数字必须等于 3 并说明是兜底（回归锁 + 端到端剧本）。
- AC4：F2P——B34/B41 各配一条锁：改前红（`PUT /api/settings/daily` 清掉非六类型 spotlight；订阅数显示与实际不符）→ 改后绿。
