## 背景：这不是"审美问题"，实测给了定量根因

spec30（2026-09-15）把 12 Tab 收成 5 Tab（源库/早报中心/热点榜策展/AI 能力/系统）。方向对，但**收敛成了"把旧页面堆进一个 Tab"**，于是用户看到的臃肿是真的：

| Tab | 体量（实测） |
|---|---|
| 源库 | `SourceLibraryTab` 663 行 + 平台接入 935 行 = **1598 行 / 51.1KB chunk** |
| 系统 | Data+Monitor+Alerts = **1251 行 / 3 Zone / ≈19 张卡 / 36.8KB**（最大） |
| 早报中心 | 552 行 / **9 个 section** / 16.5KB |
| AI 能力 | 488 行 / 2 Zone / 15.4KB |
| 热点榜策展 | 204 行 / 5.1KB |

用户观感的逐条定量：

- **「版面看着别扭」＝真 bug**：header 内层 `max-w-[1100px]` 且 padding 在内（`AdminPage.jsx:56-57`），main 的 padding 在外、内容宽 1160/960（`:83-84`）→ **左缘永久错位 54px（源库）/70px（其余 4 Tab）**，怎么调都调不齐。
- **「保存要浮动」＝现状确实没有**：全后台零 `sticky/fixed` 保存条（唯一 fixed 是弹窗遮罩）；保存语义三种并存（BriefCenter/Hot/Alerts/Data 即时写、DailySettings 四区共用底部一个按钮、AiSettings 两个按钮）；**无 dirty 未保存提示**（全库 grep 零命中）。
- **「组合层没有搜索」＝部分真实**：组合视图（`:301-376`）确无搜索框，但「检索」是同级常驻 pill 而非"点进文件夹才有"；真实痛点是**每次操作全量重拉 `/api/sources/library`**（`:137/205/217`）+ 组卡按 issueN 重排 → 点一下约 4s 且卡片跳位；调频/failover 用 `window.prompt`（3 prompt + 3 confirm）。
- **「我的早报要在源库设置」＝真实且更严重**：订阅轴唯一写入口在源库（组卡 `:329` / 批量条 `:532`），早报中心只有指路文字；**源库从不请求 `/api/settings`，而 `subscription.ids` 早已透出** → 界面看不到订阅现状；组卡「订阅」无计数、无退订分支；无「仅已订阅」筛选；线上 `ids:[]`，真生效靠 54 个 ☆ 兜底（→ 见 40 域）。
- **四轴编辑入口割裂在 5 处**：`enabled` 三处可改、`reader_visible`/`muted` 只能批量或组卡、`subscription` 只在源库、**`spotlight` 在早报中心 `DailySettingsTab.jsx:96` 会被 `PUT /api/settings/daily` 全量替换**（会清掉非六类型的重点源）→ 潜伏双写冲突（B34）。
- **「侧边栏」＝一致性收敛**：前台 5 页都用左栏 `IconRail`（`main.jsx:37-88`），admin 刻意不带（`AdminPage.jsx:41`）；且 `admin.jsx` 无 store/i18n Provider，需自建。Tab 态纯 `useState`，**刷新回源库、无深链**。

## 目标

- G1 **一个板块只负责一件事**：每个功能区能一句话说清它管哪个对象、写哪个键、影响前台哪块。
- G2 四轴有唯一归属：同一轴的编辑入口收敛到一处（其余处只读展示 + 跳转）。
- G3 导航可寻址：每个板块有 URL 深链，刷新/分享/回退不丢位置；左侧栏与前台同语言。
- G4 保存语义统一：要么全即时写（并显示"已保存"），要么草稿 + 浮动保存条 + dirty 提示；不许两种并存。
- G5 消除定量硬伤：左缘对齐、去 `window.prompt`、操作不再全量重拉。

## 边界

**不做**：不改任何生成链路与数据口径（那是 35/36/37/40 的事）；不新增后台功能种类（先隔离再增强）；不动读者端页面；不引入新 UI 库（沿用 Tailwind + 三主题 CSS 变量）。
**顺序约束**：38-3/38-4 必须在 35（自愈/健康度）与 37（报警）落地**之后**，否则新面板没有数据可放；38-1/38-2 可提前，因为它们修的是当前就在咬人的入口问题。

## 验收标准

- AC1（38-1）：任一轴在后台只有一个可写入口，其余入口显示只读并给出跳转；线上实测"在早报中心点保存"不再清空非六类型 spotlight 源（改前后对比 `SELECT COUNT(*) WHERE spotlight=1`）。
- AC2（38-2）：5 个 Tab 左缘与 header 对齐（截图量像素）；改一个源的刷新间隔不再触发 3~4s 全量重拉与卡片跳位。
- AC3（38-3）：`/admin/#/sources/issue` 之类深链可直接打开并停留在该板块；刷新不回源库。
- AC4（38-4）：任一板块首屏请求 ≤2 个、响应总量 ≤60KB（现状早报中心 4 请求 ≈134KB、热点页 451KB）。
- AC5（38-5）：后台首页 3 秒内呈现总源数/红档数/冷却中/未读报警，且每个数字可点进筛选后的列表。
- AC6（38-6）：功能区正文不再出现"手动生成命令"这类说明段（B43/B53 同族），改为 tips。
- AC7：spec 41 的端到端剧本覆盖"改一轴→前台可见效果"与"深链可达"两类场景。
