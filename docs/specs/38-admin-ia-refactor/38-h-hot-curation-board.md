## 背景：B58 是一次"三方各写一份"的典型

修之前三方各有意见：本地 `server/services/hot.js` 一份分类映射、云端 `handleHotCategories` 用 `Object.keys()` **把 map 丢了**、前端再自带一份 `DEFAULT_MAP`，并且 `.catch(() => {})` 静默吞错 → 界面永远显示内置默认，用户改了配置看起来"没生效"。

本轮的修法（已线上复测，见 `docs/ISSUES.md` B58 行）：接口返回 `{categories, map, categorySource}`，前端删掉自带默认，按 `categorySource` 显示**「线上生效配置 / 内置默认 / 读取失败」三态徽章**，读失败不再伪装成"没改"。

**B57 仍在**：热点回填（backfill）动作依赖 runner 与本地文件态，云端没有等价端点；当前界面把它当通用能力展示，且进度读数取 `d.progress`（实际响应里没有这个字段）→ 显示成空进度。修法是"标仅本地 + 修进度取值"，但真正要跑通需要在云端**新增一个会写库的回填端点**，属生产写动作 → 用户决定延后。

## 边界

- 不改热点榜的打分/排序算法（25/28 热榜重设计域）。
- 不新增云端写库端点（需用户授权，B57 卡在这）。
- 分类语义的唯一实现是 `lib/hot-categories.js`；任何"第六种分类""新 feed 名"只能加在这里，三端引用（AGENTS §1）。
