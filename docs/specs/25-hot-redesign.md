# 设计：热点榜重设计（2026-09-14，样图定稿）

> 样图：`archive/样图/热点榜/`（3 张 PNG）。
> 用户定性问题：现状热点榜 = 纯热搜聚合流（知乎/微博娱乐向占满、覆盖不全一天），
> 分类（模型/产品/行业/论文/教程/观点）无作用，「全部动态」不是全部动态——
> **需要贴合当前系统架构重设计：读我们自己的源（六维评分后的内容）呈现流式时间线**。

## 样图解读（BestBlogs 热点页形态）

1. **当前热点 Top5 卡**（页首）：排名 + 标题 + 热度值，右上「完整榜单 →」
2. **按日期分组的时间流**：日期分组（9月14日 星期一 · N 条 ▼ 可折叠）→ 每条 =
   时间点（左侧竖排）+ 来源（含「精选」徽章）+ 标题 + 摘要 + **推荐理由** + 右上 AI 评分/100
3. **分类 tabs**：全部 / 模型 / 产品 / 行业 / 论文 / 教程 / 观点（真实过滤）
4. **搜索框**：搜标题、摘要
5. 左侧栏保留系统导航（精选/全部动态/主题/收藏……）

## 与现状的差距（差距 → 改造点）

| # | 现状 | 目标 |
|---|---|---|
| G1 | 数据源 = 热榜聚合源（newsnow 热搜）为主 | **主数据源 = 我们自己源的高分内容**（score ≥ 阈值的六维评分文章 + 热榜聚合为辅）；时间线读 articles（评分/推荐理由字段已有） |
| G2 | 分类无作用（category 从未真实执行，P3-3） | 分类 = 真实过滤：复用六维评分的 tags / AI 分类字段（模型/产品/行业/论文/教程/观点 → 映射 tags 关键词组），服务端 WHERE 过滤 |
| G3 | 时间流只有热榜条目、无推荐理由/评分 | 时间线条目卡：来源+精选徽章+摘要+**推荐理由（reason 字段已有）**+AI 评分（score 已有） |
| G4 | 「精选」tab 与「全部动态」差异模糊（P0-3 修过 tab 参数但语义仍弱） | 精选 = score ≥ 70（六维高分）；全部动态 = 全部源全部内容（含热榜），按时间 |
| G5 | 覆盖不全一天 | 时间线回溯 7 天（数据在库），日期分组折叠 |
| G6 | 无搜索 | 标题/摘要 LIKE 搜索（服务端） |

## 技术方案

- **后端**：`handleHot` 重写为统一查询——
  `GET /api/hot?view=timeline|featured|all&category=&q=&cursor=`
  - timeline/featured/all 三视图共享一条 SQL 骨架（where 差异），游标分页沿用（坑 #25 规则：游标=原生列值）
  - 分类过滤：`a.tags LIKE '%"模型"%'` 类 JSON 串匹配（tags 已是 JSON 数组文本），或建 tags 展开表（量大后优化）
  - 排序：featured 按 score DESC；timeline/all 按 published_at DESC
  - 「当前热点 Top5」：复用 handleHotEvents（事件聚合）取 top5
- **前端**：HotPage 重排——Top5 卡 + 分类 tabs + 搜索框 + 日期分组时间线（竖线+时间点+条目卡，复用现有时间线样式）；骨架屏
- **降级**：热榜聚合源保留为「热搜」子视图（现有时间线数据不丢）
