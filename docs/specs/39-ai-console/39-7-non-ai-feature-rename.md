# 39-7 · 非 AI 功能正名：摘要/分类/事件关联 不该住在"AI 开关"里 —— 小 Spec

> 总框架：`spec.md`（39）。状态：**待批准，未动工**（语义归类问题，改动小但影响界面信息架构，需与 38 域对齐）。

## 现状

| 事实 | 证据 |
|---|---|
| `settings.ai` 线上实测只有 `enabled,apiKey,apiBase,model` 四键；**`features` 那组假开关已摘除**（H10/B51/39-2 已复核） | 只读实测 + `grep features web/src/components/AiSettingsTab.jsx` 0 命中 |
| 但"摘要 / 分类 / 事件关联"这三件事在**产品叙事里**仍常被当成"AI 功能"来开关，实际它们是各功能域的固有步骤：摘要属于早报/阅读器（`translated_content/summary` 分流，见 B8/B92），分类属于源治理（`autoClassifySourceId`，已进 `server/services/`），事件关联属于热点榜（`lib/hot-events.js`） | `docs/ISSUES.md` B8/B92；`server/routes/*` |
| 因此 `ai.enabled=false` 的语义边界**没有定义过**：关掉 AI 之后，摘要/分类/事件关联是照跑、降级、还是全停？现在只能靠"代码里恰好怎么调"回答 | 本文件结论（未定义即缺陷） |

## 目标

G1 定义 `ai.enabled=false` 的**确切降级语义**（每个功能一行：照跑 / 用规则版 / 停），并把它变成可测的判据。
G2 界面上把"AI 配置"（凭据/模型/限速）与"各功能是否用 AI"（早报增强、翻译、事件聚类）分层：后者留在各自域，不再挤进 AI 设置页。

## 改动点（批准后才写）

| # | 内容 |
|---|---|
| T1 | 一张**降级矩阵**（`ai.enabled` × {翻译, 深析六维, 早报增强, 周刊策展, 事件关联, 摘要}），每个格子写"关了以后走哪条路 + 用户看到什么"。矩阵落成文档 + 一条表驱动锁 |
| T2 | 关掉 AI 时的**用户可见信号**：日报/早报要标"本期为规则版（AI 已关闭）"，不许静默换成低质产物（这正是 B20/坑 #32「档位」那套的同一类问题） |
| T3 | AI 设置页只留凭据/模型/限速 + 探活（39-3/39-5 的范围）；"要不要用 AI 做 X"迁到对应板块（38 域的 F/D/G 各页） |

## 判据与验收

- AC1 降级矩阵每一格都要有**一条锁**：在 `ai.enabled=false` 的隔离环境里跑对应链路，断言产出符合该格定义（含"标了规则版徽标"这种可见信号）。
- AC2 `ai.enabled` 的读点必须唯一（同一份 `isAiEnabled()`），三端不许各写 `if (settings.ai.enabled)`（`server/services/ai/daily-ai.js` 与 `api/_ai.js` 历史上就各写各的，见 B20 的"本地灾备无六维分"分叉）。
- AC3 界面搬迁后，e2e 剧本要断言"AI 设置页不再有它管不着的开关"，且被迁走的开关在新位置可写可读（往返一次，值不变）。

## 边界

- 不改任何 AI 算法/prompt（39-6）。
- 不新增"AI 总开关"以外的开关（39-2 刚摘过一批，本包只搬位置，不扩面）。
- 与 38 域的信息架构冲突时**以 38 的板块划分为准**（后台 IA 已批准过），本包只声明归属。
