# 每日早报 v2（18-daily-ai-v2）Spec

## 背景

当前日报是关键词匹配版（候选 500 → 4 栏目 ~28 条），无 AI 判断，无推荐理由，无主题导语。用户已确认的决策（ROADMAP §6.2）：改名「每日早报」；窗口自然日整（昨 00:00~今 00:00）；AI 凌晨批处理、早 9:00 呈现；每篇产出六维评分（选题/内容/深度/实用/创新/表达）+ 推荐理由 + 精选摘要 + 金句 + 关键观点；顶部「今日主题」导语。

基础设施已就位：统一 AI 通道（16）、两阶段初筛器（16）、BestBlogs 六节点管线蓝本、降级链。

需求澄清结论：**无开放问题**——六维度/窗口/时间/导语形式均已由用户拍板。「我的早报」（订阅定制版）与「精选周刊」是独立后续项，不在本 spec。

## 目标

- 早报从"关键词聚合"升级为"AI 策展"：每条内容都有 AI 的判断与解释
- 每天 09:00 呈现一份带主题导语的策展早报，零人工参与

## 功能需求

- **F1**：AI 早报生成管线（runner `daily-ai` 模式）：自然日窗口取候选 → filterArticle 初筛（<30 分丢弃）→ 通过者逐篇深析（单次调用输出：六维分数 + 总分 + 推荐理由 ≤50 字 + 精选摘要 + 金句 + 关键观点 ≤3 条 + 标签 ≤4 个）→ 栏目组装（保留现有四栏目语义，AI 总分决定入选与排序）→ 生成「今日主题」导语（基于全部入选条目的一句话主线概括）→ 落库
- **F2**：报告数据结构 v2：条目含 `{id,title,url,source,published_at,totalScore,scores:{选题,内容,深度,实用,创新,表达},reason,summary,quote,points[],tags[],translated}`；报告级含 `{theme, generatedAt, stats}`
- **F3**：自然日窗口：候选窗口 = 昨天 00:00 ~ 今天 00:00（北京）；settings.daily.time 语义改为「呈现时间」（默认 09:00），批处理固定在 00:30（北京）启动
- **F4**：前端早报页：顶部主题导语区 + 卡片展示六维评分（星标+分数）、推荐理由、摘要、金句（引用块）、关键观点（bullets）、标签 pills、阅读全文；标题改名「每日早报」
- **F5**：降级链：AI 失败 → 现有关键词版 → 原始时间序列表；降级状态在报告 meta 中标记
- **F6**：黄金集评测：`tests/fixtures/daily-golden.json`（20 篇已知优劣标注的文章）+ 跑分脚本，prompt 调整后对比分数分布
- **F7**：配额保护：初筛与深析都走 16 统一通道（4s 间隔）；全程预算 ≤90 分钟

## 非功能需求

- N1：runner 批处理 00:30 启动，09:00 前必须完成（实测预算 45-90min，远小于窗口）
- N2：Agnes 故障时降级产出（F5），早报绝不断更
- N3：前端兼容旧格式报告（无 AI 字段时按旧卡片渲染）
- N4：AI 输出容错：单篇解析失败跳过该篇，不阻断整份早报

## 不做的事

- 我的早报（订阅定制）——下一项
- 精选周刊——独立项
- 早报推送渠道（飞书等推送早报本身——后续可做）
- 逐段中英对照

## 验收标准

- AC1：runner daily-ai 跑出的早报条目全部含六维分数+推荐理由+摘要+金句+关键观点
- AC2：报告顶部有「今日主题」导语且与当日内容相关
- AC3：前端早报页显示导语 + 评分卡片；标题为「每日早报」
- AC4：AI 关闭（settings 或故障）时自动降级关键词版，早报仍生成且 meta 标记降级
- AC5：黄金集评测脚本可跑，输出初筛/评分分布对比
- AC6：单篇 AI 解析失败不影响整份早报生成
- AC7：全程 ≤90min（runner 日志计时）
- AC8：回归测试全绿
