# 01 - 部署架构决策

> 类型：已确定（短期不变）
> 生效日期：2026-09-04
> 决策人：用户拍板

## 背景

项目需要确定长期部署形态。曾考虑 Vercel serverless、自建服务器、混合部署三种方案。

## 选项对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| Vercel serverless 全量 | 零运维、自动扩缩 | 不适合重前端、serverless 副本维护成本高、抖音 Playwright 无法运行 |
| 混合（Vercel + 本地） | 前端 CDN 加速 | 双端语义漂移、维护成本翻倍 |
| **宝塔/自有服务器全量** | 全功能、单点维护、抖音可用 | 需手动运维 |

## 最终选择

**宝塔/自有服务器全量部署**：Express + SQLite 主系统 + 抖音 Playwright 全部上服务器（PM2，ecosystem.config.js），本地机即生产机。

## 理由

1. Vercel 不适合承载重前端（抖音 Playwright 无法在 serverless 运行）
2. serverless 副本维护成本高（云端是本地代码的移植副本，非同步）
3. PM2 单 fork 模式足够（个人工具，无需分布式）
4. 公众号走 wechat2rss 托管 RSS，无需自建引擎

## 影响范围

- 所有采集功能仅本地/宝塔可用
- Vercel portal 进入冻结态（迁移完成前只修安全项）
- 迁移完成后 portal 仓库归档，Turso 退役
