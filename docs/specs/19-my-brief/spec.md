# 我的早报（19-my-brief）Spec

## 背景

每日早报 v2（18 项）已上线：全量源 AI 策展，含破圈内容。用户要的第二个产品是**我的早报**：AI 根据「我的订阅」专为我呈现（无破圈）、AI 晚间整理、早 9:00 呈现，UI 参考 archive/样图/new（大日期+编辑导语+关键词标签+分层「头条推荐 3/精选内容 7/补充阅读 N」+类型筛选+富卡片）。

**现状事实**：云端 focus（特别关注）源当前为 0 个。v1 订阅集合 = focus 源（后台源库已可标记）；为空时早报显示引导态而非空报告。

## 目标

- 每天一份只为「我」策展的早报：只来自我订阅的源，AI 精选 + AI 摘要 + 六维评分
- 与每日早报共用深析池：一次 AI 分析，两份报告（成本不翻倍）

## 功能需求

- **F1**：订阅集合 v1 = `sources.focus=1 AND enabled=1`；为空时 GET /api/mybrief 返回引导态（`{empty:'no-subscription'}`）
- **F2**：生成管线（runner daily-ai 批次内复用深析池）：从深析通过的文章中筛订阅源产出 → 按总分排序 → 分层组装：头条推荐 ≤3 / 精选内容 ≤7 / 补充阅读 其余（≤40）→ 生成编辑导语（复用 generateTheme，样式「今日聚焦…」）+ 关键词标签行（高频 tags ≤8）
- **F3**：报告结构 `{date, theme, keywords[], degraded, sections:{top[], featured[], rest[]}, generatedAt}`；条目含 AI 摘要/核心观点/金句/标签/六维评分/总分/来源/封面/url
- **F4**：存储 `settings['mybrief.latest']`；`GET /api/mybrief` 公开读（与 daily 同级）
- **F5**：前端 `/mybrief/` 页面（按样图）：大日期标题 + 编辑导语 + 关键词标签行 + 三层分区标题 + 内容类型筛选（全部/文章/播客/视频/推文——v1 仅有文章与视频源，筛选器保留结构）+ 富卡片（TOP 排名/「来自你的关注」/AI 摘要/核心观点 bullets/金句引用块/标签 pills/评分星/阅读全文/封面图）；导航加入口「我的早报」
- **F6**：早 9 点送达：页面呈现 + 飞书推送导语 + 头条 3 条标题（复用 15 项渠道；settings `mybrief.pushEnabled` 默认 true；推送失败不阻断）
- **F7**：降级：订阅源当日无深析内容 → 生成空态报告（导语说明 + 引导语），不发推送

## 非功能需求

- N1：与每日早报同批次生成（00:32 批处理后追加 ~2 分钟）
- N2：无破圈保证：fallback 栏目/热榜内容绝不进入我的早报
- N3：前端兼容空态/引导态/降级态三态渲染
- N4：推送文案不含未掩码信息

## 不做的事

- 独立订阅模型（P2-1：settings.subscribedSourceIds + 选择器 UI）——上线后切换订阅源取值
- 多份主题早报（BestBlogs 3.0 形态，P2-3）
- 播客/推文类型源（当前源库无此类型，筛选器仅为结构预留）

## 验收标准

- AC1：标记若干 focus 源后，次日 mybrief 报告只含这些源的内容，且分层（top≤3/featured≤7/rest≤40）
- AC2：报告含编辑导语 + 关键词标签；前端三态（正常/空态/引导态）渲染正确
- AC3：无破圈内容（抽查 rest 区无 fallback 栏来源）
- AC4：飞书收到导语 + 头条 3 条（开启推送时）
- AC5：focus=0 时 GET /api/mybrief 返回 no-subscription 引导态
- AC6：与每日早报共享深析池（runner 日志显示零额外深析调用）
- AC7：回归测试全绿
