# 翻译链完整上云（17-translate）Spec

## 背景

已有基础（实测确认）：runner translate 模式每轮自动精翻英文新文章（走 16 的统一通道+降级链+术语库）；阅读器文章详情的中英切换对照控件已存在（P0-4）；术语库自动生长已上线。

缺口：① 翻译是单轮直翻，没有"词库对照→精翻"的打磨轮次；② 未被自动翻译的文章无法手动触发；③ Agnes 翻全文需 5-60s，超 Vercel 10s 限制。

需求澄清结论：**一个关键取舍已定**——云端手动翻译走**异步入队**（点按钮→标记→runner 拾取→前端轮询出现），不做同步等待（Hobby 10s 物理限制）。

## 目标

- 翻译质量：多轮打磨（筛→初翻→词库对照→精翻）
- 用户控制：任何英文文章可手动触发翻译，翻译状态可见

## 功能需求

- **F1**：多轮翻译管线（runner translate 模式内）：
  - 轮 1 初翻（现有 translateText）
  - 轮 2 词库对照：用当前 glossary 检查初翻的术语一致性，不一致则给出修正指令重翻相关段落
  - 轮 3 精翻（仅长文/高分文章）：检查四类问题（术语/表达结构/文化适应/格式）后意译
  - 轮次策略：短文（<1500 字）轮 1+2；长文/入选日报候选加轮 3
- **F2**：手动翻译端点：`POST /api/articles/:id/translate` → 标记待翻译（settings 队列 `translate.queue` 存 id 列表）→ 返回「已入队」；`GET` 状态并入文章详情（translated_* 字段已有）
- **F3**：runner 每轮 translate 先消费 `translate.queue`（手动优先）再走自动增量
- **F4**：前端手动翻译按钮（ArticleView + QuickStudyModal）：未翻译的英文文章显示「翻译」按钮 → 点击入队 → 按钮变「翻译中」→ 60s 轮询 until 译文出现自动切换
- **F5**：翻译状态可读：文章 meta 行显示翻译来源（Agnes 精翻 / Bing / Google 机翻标记）

## 非功能需求

- N1：手动入队到译文可见 ≤ 20 分钟（runner 每 15min + 翻译 ~1min）
- N2：多轮管线串行受 16 统一通道限速约束，不额外突破
- N3：降级链产出的机翻结果必须带 provider 标记（不冒充精翻）
- N4：已翻译文章不重复翻译（现有增量选择器保证）

## 不做的事

- 全文对照逐段并排视图（当前是整体切换，逐段对照后续迭代）
- 其它语言（日/韩等）翻译
- QuickStudyModal 全文阅读改造（属 P1-7 阅读体验项）

## 验收标准

- AC1：新英文文章经 runner 翻译后，glossary 中已有术语在译文中一致使用
- AC2：线上对一篇未翻译英文文章 POST translate → ≤20min 后详情出现译文且前端自动切换
- AC3：机翻降级产出的文章详情显示来源标记（非 Agnes）
- AC4：重复 POST translate 不重复入队
- AC5：长文走轮 3 精翻（日志可见 refine 轮次）
- AC6：回归测试全绿
