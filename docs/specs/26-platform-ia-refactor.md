# 总 Spec：前后台信息架构与关联性重构（2026-09-14 商讨稿 v1）

> ⚠️ **状态：商讨稿，等用户确认后按 mew-spec 拆分实施**。
> 背景（用户定性）：管理后台的很多板块原本是前台功能的配置面，历史上被"移到后台"，
> 导致后台与前台功能**联系不起来**——管理者看不出"后台这个开关影响前台哪个页面"。
> 同时 1500+ 源已信息过载，需要「用户选择部分源 → 全链路生效」的一等公民机制。
> 本文档是**母文档**：定义整体架构与关联性；每个功能的修复/新增再立小 spec（mew-spec 四件套）。

---

## 1. 核心心智模型（重构的目标态）

把系统显式分为**三层**，每层职责单一、互相通过「源选择」与「评分」两个枢纽联动：

```
┌────────────────────────────────────────────────────────────┐
│  ① 消费面（前台）——读什么、怎么看                             │
│  阅读器（订阅流）/ 每日早报 / 我的早报 / 周刊 / 热点榜 / 我的阅读  │
└──────────────┬─────────────────────────────────────────────┘
               │ 消费「源选择 × 六维评分 × 画像」三个枢纽
┌──────────────▼─────────────────────────────────────────────┐
│  ② 策展面（半前台半后台）——筛选与排序的规则                     │
│  早报中心（订阅/配额/强度/画像）/ 热点榜设置 / 画像标签云         │
└──────────────┬─────────────────────────────────────────────┘
               │ 规则作用于「采集 → 评分 → 策展」管线
┌──────────────▼─────────────────────────────────────────────┐
│  ③ 运维面（后台）——源与系统的健康                              │
│  源库（增删改查/合并/分组/频率）/ 监控 / 报警 / 数据 / AI 能力    │
└────────────────────────────────────────────────────────────┘
```

**关联性原则（重构后每条必须成立）**：
- A1 后台每个设置项都在界面上标明「作用于前台哪个页面」（文案/图标链接）。
- A2 前台每个页面的内容范围可一键跳转到它的策展面（如阅读器「只看订阅」→ 源库订阅选择器）。
- A3 「源选择」是一等公民：一处选择（订阅集/屏蔽集），阅读器流、我的早报、热点榜过滤全链路一致生效。
- A4 六维评分是唯一排序货币：阅读器 smart 排序、早报入选、热点榜精选、周刊终选都消费它。

## 2. 源选择功能（用户的核心诉求，A3 的落地）

**需求**：1500+ 源过载——用户选择部分源，全链路只显示所选源的信息。

**设计（三档视图模式）**：
| 模式 | 行为 | 存储读取 |
|---|---|---|
| 全部（默认） | 现状不变，所有启用源 | `reader.viewMode = 'all'` |
| 聚焦 | 阅读器列表/计数只显示「订阅集 ∪ 手动勾选组」 | `reader.viewMode = 'focus'`，聚焦集 = `subscription.ids`（focus 源）+ 临时勾选 |
| 自定义 | 用户勾选任意源/分组组合，独立于订阅 | `reader.customSourceIds[]`（localStorage + settings 双存，跨端同步） |

- 生效点：`/api/articles` 增加 `view` 参数（all/focus/custom）服务端过滤（游标分页兼容，坑 #25 规则）；未读计数、侧栏分组树同口径。
- 早报/我的早报不受影响（它们有自己的订阅语义）——**A3 的"全链路"指消费面过滤一致性，不改变各早报的策展语义**。
- UI：阅读器侧栏顶部「视图」切换（全部/聚焦/自定义），自定义模式勾选即存。

## 3. 管理后台信息架构重组（后台板块 ↔ 前台功能对照）

| 后台板块（现） | 归属层 | 重构动作 |
|---|---|---|
| 源库 | ③ 运维 | 保留；增加「订阅/聚焦」批量操作入口（服务于 A3） |
| 公众号 RSS / B 站 / 抖音 | ③ 运维 | **抖音下架**（用户决策）；公众号/B站并入源库的类型筛选（减 Tab） |
| 日报设置 + 早报中心 | ② 策展 | 合并为「早报中心」单入口：每日早报（来源/栏目 AI 化/生成时间）+ 我的早报（订阅/画像/配额/强度/推送）+ 周刊（归档/时间）+ 生成历史 |
| AI 能力 / 翻译 Skill | ③ 运维 | 合并为「AI 能力」单 Tab（配置 + 翻译队列观测） |
| 数据 / 监控 / 报警管理 | ③ 运维 | 保留（数据饼图/监控折线/报警时间线已做） |
| 热点榜设置 | ② 策展 | 并入热点榜重设计后的策展面（specs/25） |

**目标 Tab 数**：源库 / 早报中心 / AI 能力 / 数据 / 监控 / 报警（6 个，从 11 收敛）。

## 5. 不做的事（边界）

- 不改早报/我的早报/周刊的策展语义（T3-1 已定稿）；本重构只动「消费过滤」与「后台信息架构」。
- 不引入新存储（源选择复用现有 settings/localStorage）。
- 抖音下架 = 移除 Tab 与入口，保留本地 Playwright 代码归档（永不云端化决策不变）。
