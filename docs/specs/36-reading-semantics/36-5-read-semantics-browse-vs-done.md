# 36-5 · 阅读语义定稿：「点开即已读」是否保留，要不要"读完" —— 小 Spec

> 总框架：`spec.md`（36，G3）。状态：**⏸ 需拍板，未动工**（这是产品语义决策，不是代码缺陷；本文件把选项与代价列清）。
> 最后更新：2026-09-19

## 现状（实测）

| 事实 | 证据 |
|---|---|
| "已读"= **GET 详情即写 `read_at`**（打开就算读过） | 云端 `api/[...slug].js:248`（`UPDATE articles SET read_at=COALESCE(read_at, ?) WHERE id=? AND read_at IS NULL`）、本地 `server/routes/articles.js:246` |
| 另有批量置已读入口（阅读足迹/一键已读） | `api/[...slug].js:1284`（`WHERE read_at IS NULL AND id IN (…)`）、`server/routes/reading.js:189`（反向：撤销已读） |
| 云端真已读仅 **287 条**，而 `read_at='null'` 脏值曾达 **24855 行** | B15（污染只在云端，本地干净） |
| **这件事同时决定删除语义**：`read_at` 是保留清理的**豁免条件** | `api/[...slug].js:2010` `ARTICLE_CLEAN_WHERE`；实测 09-19：>7 天的老日子 95%+ 都是"已读"，所以它们没被删（见 `docs/specs/43-collect-retention-safety/spec.md` §二 N1 附注） |

⚠️ 最后一行是本包真正的分量所在：**"点开即已读"等于"点开即免于被清理"**。语义一改，保留窗口的实际效果就变（D4/B101 未修之前删不了，但方向要先定）。

## 三个选项

| 方案 | 含义 | 代价 | 影响面 |
|---|---|---|---|
| A 保持现状 | GET 详情即已读 | 零改动；但"已读"虚高（误点、扫标题都算），豁免面被放大 | 未读角标 / 保留清理豁免 / 阅读足迹 |
| B 双态 | 加 `opened_at`（点开）与 `read_at`（读完）两列，"读完"才豁免 | 要 schema 变更 + 三端同步 + 前端停留/滚动信号 | 最大；但语义最诚实 |
| C 轻量启发 | 仍一列，但写回加门槛（停留 ≥N 秒或滚动 ≥X%） | 无 schema 变更；前端要加信号，云端要新增写端点（不能再用 GET 副作用） | 中；**GET 有副作用本身是要修的**（见下"边界"） |

**我的建议**：C。理由：不动 schema、能立刻把"误点即已读"的豁免面收住，而且顺带解决"GET 不该写库"这个更硬的问题（当前 `GET /api/articles/:id` 会写 `read_at`，与"读接口只读"的不变量冲突）。

## 判据（选定后补全，不许先写实现）

- 无论选哪种，都要一条**行为锁**而不是文本锁：模拟"打开后立刻离开"与"停留 N 秒"两种轨迹，断言 `read_at` 的写入结果不同（C 方案）或两列分别落值（B 方案）。
- 保留清理的豁免集必须随语义同步：给 `lib/retention.js`（spec 43 拟建）的谓词加一条"豁免依据 = 本包定稿的语义"，并让 F2P 锁覆盖它。
- 端到端：`/reader/` 与 `/reading/` 的 pill 数字必须与列表条数同源（沿用 B74 的 DOM↔响应对账路子）。

## 边界

- 不做阅读进度条、不做"收藏体系"新功能（36 的 §边界）。
- **GET 有副作用这件事本身要处理**（与 40/39 里同类问题一起收敛）：选定 B/C 后，写 `read_at` 必须走显式 POST 端点，本地/云端同一份实现。
- 本包与 B15/B101/D4 交叉：**先定语义、再定删不删、最后才动代码**，不许反过来用代码选择绑架语义。
