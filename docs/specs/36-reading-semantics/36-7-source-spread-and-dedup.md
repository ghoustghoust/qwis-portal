# 36-7 · 同源打散与噪声口径（含 H7 云端 dedup）—— 小 Spec

> 总框架：`spec.md`（36，G1/G5）。状态：**待批准，未动工**。
> 最后更新：2026-09-19

## 现状（实测）

| 事实 | 证据 |
|---|---|
| 排序确实是时间（不是"按源块"） | `api/[...slug].js` smart 表达式 = 时间戳 + `spotlight×3d`，`ORDER BY … DESC, a.id DESC`；无 source 分组 |
| 相邻同源的真正来源 | ①同源成批发文；②时间戳并列后按 `id DESC` → 同一次抓取天然连号（实测单刻最多 **132 条**同 `04:00:00.000Z`，跨 12 源）；③spotlight 加权把 31 个源整体置顶（今日 3234 条里 468 条来自它们） |
| 云端 `/api/articles` **没有 dedup 分支** | 挂案 **H7**：重复事件不折叠（本地有） |
| **噪声口径被手写复制 14 处** | `type!='hotlist' OR aggregator` 这类判定出现在 `api/[...slug].js`（135/219/406/527/696/927/949/1272）、`api/daily-generate.js:104`、`server/routes/articles.js:20`、`tools/collect-turso.js`（592/794/1032/1558）——**含 aggregator 变体共 20 处**，三端各写各的 |
| 「我的阅读」里 hotlist 占 **71%** | 上一轮实测：`type=all` 的 25,142 条中 17,860 条来自 hotlist 聚合源；且**阅读路径没套用上面的 NOISE 口径** |

## 目标

- G7a 「噪声」（热榜聚合源与 aggregator）判定**全库一份实现**，三端引用同一构造函数。
- G7b 阅读器"看起来同源扎堆"可解释、可调：给 smart 结果加"同源最小间隔"或事件折叠上云（H7）。
- G7c 「我的阅读」不再被热搜足迹淹没（是否排除噪声由用户拍板，见下）。

## 改动点（批准后才写）

1. 新建 `lib/noise.js`：`noiseCondSql(alias)` / `notNoiseJoin()` / `isNoiseSource(row)` 三件套，`api/`、`server/`、`tools/` 全部改为引用它（**删掉 14 处手写副本**，不是再加一层封装留着旧的）。
2. 白盒新增判据（拟 **W18**，与 spec 43 的 W17 同批评估）：从字符串字面量派生扫描"存在 ≥2 份噪声判定"即红。判据纪律按坑 #58/#59/#63：派生自事实、非空断言、排除自身、剥注释、只认字符串字面量。
3. 打散策略：默认窗口内同源 ≤1 条/间隔 K（K 可调），或直接上"事件折叠"（与 H7 合并）——两者都必须在同一份排序构造里实现，不许前端再排一次。

## 判据与验收

- AC1 `grep` 层面：噪声判定在 `api|server|tools` 里**只剩 `lib/noise.js` 一份**字面量（由 W18 机器判，不靠人眼）。
- AC2 负向自证：往任一端塞第二份手写噪声条件，W18 必须红且点名文件行号；把构造函数摘掉，AC1 也要红（防"恒真判据"）。
- AC3 行为锁：给定"同一秒 132 条同源"的构造样本，列表首屏同源占比 ≤ 阈值；同一份样本在本地与云端跑出**同一顺序**（跨端一致性用例，G5）。
- AC4 「我的阅读」的计数与列表在噪声开关两种状态下都自洽（沿用 `lib/reading-filters.js` 一份口径，配 F2P 锁）。

## 需要用户拍板

1. **「我的阅读」是否排除 hotlist/aggregator**（现状 71% 是热搜足迹；排除则足迹更纯，但会看不到"我扫过的热榜条目"）。
2. 打散走**同源最小间隔**还是**事件折叠上云**（后者改动大，与 H7 一并做才划算）。
3. 打散是否只对"未开 spotlight 加权"的普通视图生效（加权置顶与打散天然冲突）。
