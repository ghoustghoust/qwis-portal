# 热点榜重设计（28-hot-redesign）

> **状态：草案（未开工）**——总 spec 见 `../26-platform-ia-refactor.md`（四层信息金字塔/源四轴模型）。
> 确认后按 mew-spec 四件套（spec/plan/task/checklist）补全再实施。

## 开发什么

热点榜改为读自有评分源的时间流：当前热点 Top5 卡 + 日期分组时间线（来源/精选徽章/摘要/推荐理由/AI评分）+ 真实分类过滤（模型/产品/行业/论文/教程/观点）+ 搜索；热榜聚合降级为「热搜」子视图。

## 为什么需要

现状纯热搜聚合（娱乐向占满、覆盖不全、分类无作用）与系统架构脱节——应呈现我们自己六维评分后的内容。

## 实现目标

热点榜 = L2 脉搏层：扫一眼今天行业内发生了什么（我们源的高分内容+热搜辅助）。

## 验收效果

①时间流含推荐理由与评分 ②分类真实过滤 ③精选=score≥70 ④搜索可用 ⑤覆盖回溯7天 ⑥线上实测
