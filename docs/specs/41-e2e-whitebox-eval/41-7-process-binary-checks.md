# 41-7 · 过程性二值检查器（防"没真跑却算通过"）Spec

> 总框架：`spec.md`（41）。要求正文见 `docs/EVAL_GUIDE.md` §3.6。状态：**待开发**。mew-spec 阶段一（做什么）。
> 关联现状代码：`tools/eval-preflight.cjs`（环境前置，41-1 已交付）、`tools/eval-whitebox.cjs`（41-4 已交付）、
> `docs/DELIVERY_VERIFICATION.md`（人工实测流程，本工具要把它变成可重跑的）
> 最后更新：2026-09-19

## 背景：为什么先要这个，而不是先要端到端引擎

41-2（Playwright 剧本引擎）体量 M，而它最大的风险不是跑不起来，是**跑绿了却什么都没测**。
本轮实测里两类事故都真实发生过：

| 事故 | 现象 | 归因 |
|---|---|---|
| 探针参数猜错 | 用 `tab=article` 打云端接口（真参数是 `type=`），三个 Tab 返回同一批数据，一度被判"筛选仍失效" | 判据来自猜测，不是来自被检代码 |
| 管道吞退出码 | `npm test \| tail` 显示 exit 0，实际 4 条红 | shell 取到的是 `tail` 的码 |
| 占位文案冒充通过 | B52 翻译 Skill 永远停在「加载中…」，DOM 有元素 = 断言通过 | 只断言"元素存在" |

三者共同点：**结果层的布尔值不可信**。所以门禁顺序必须是"先能证明你真的跑了、真的断言了，再谈测得全不全"。
论文里同一立场（安装验证仅 14% 通过 → 先修最前段的证据链，不是先扩用例规模）。

## 目标

一组纯函数检查器，输入"一次评测运行的事件流 + 产物清单"，输出二值结果与不通过原因。
**任一不过 → 该次运行判 `fail_env`，不算交付失败，但绝不算通过。**

## 功能点

| # | 检查 | 判据（必须能从产物里客观算出来） |
|---|---|---|
| F1 | `check_screenshot_taken(events)` | 每条剧本至少 1 张截图落盘，且文件字节数 > 0、mtime 落在本次运行窗口内 |
| F2 | `check_report_generated(artifacts)` | 报告文件存在、能 JSON 解析、`cases.length` 与剧本清单条数一致（漏跑即红） |
| F3 | `check_assertions_executed` | 每条用例的 `assertions > 0`；0 断言用例 = 空跑，直接红（防自证式测试） |
| F4 | `check_no_stub_text` | 响应/渲染文本里不得出现占位串白名单外命中：`加载中`、`暂无数据`、`TODO`、`not implemented`、`xxx`（`xxx` 来自本轮文档自评的真实命中） |
| F5 | `check_evidence_paths_resolve` | 报告里引用的每个路径（截图/日志/响应 dump）在磁盘上真实存在——文档写"见截图"但截图不存在，就是 B50 那类"文档-实现漂移"的评测版 |
| F6 | `check_exit_code_honest` | 每个外部命令记录 `cmd` 与其**自身**退出码（禁止 `cmd \| tail` 形态），退出码来源与命令一同落盘 |
| F7 | `check_probe_params_sourced` | 剧本里每个请求参数必须带 `source: "file:line"` 指明参数名抄自哪一行代码；缺失即红（把本轮"猜参数"的教训变成机器约束） |

## 边界

- 不做：判定"业务对不对"（那是 41-2 的三类断言与 §5 内容质量层的活）。本层只回答"这次运行可信吗"。
- 不做：修复。检查器只报，不改产物。
- 事件流格式与 41-2 共用一份定义，放在本文件 F0 附录里先固化，避免两边各写一版（正是 B60 的成因）。

## 验收标准

- AC1：六个检查各有 1 条"故意做错"的负向用例并确实为红（未做负向验证的检查按假门禁处理，同 W10 口径）。
- AC2：拿本轮已经发生过的一次真实事故（F4 的「加载中」与 F7 的猜参数）回放，必须判 `fail_env`。
- AC3：`npm run eval:e2e`（41-2）退出码由本层结果与业务断言共同决定，任一不过不得为 0。
- AC4：产出报告 `docs/eval/runs/<时间戳>.json` 被 `npm run lint:docs` 认可（新产物目录先登记进 `docs/INDEX.md`）。
