# 02 - 不做云端采集决策

> 类型：不做（Negative Scope）
> 生效日期：2026-09-04
> 决策人：用户拍板

## 背景

Vercel portal 曾有 catch-all serverless 函数处理采集请求（GH Actions 每 15min 触发）。需要明确云端是否继续承担采集职责。

## 选项对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| 云端继续采集 | 多一层数据保障 | 语义漂移、抖音无法运行、维护两套代码 |
| **云端不采集** | 单一数据源、维护简单 | 完全依赖本地 |

## 最终决定

**云端（Vercel）不跑采集函数**。采集只在本地/宝塔执行。

## 理由

1. 抖音采集需要 Playwright 有头浏览器 + 登录态，serverless 无法运行
2. 云端采集代码是本地代码的移植副本（非同步），语义已漂移
3. 个人工具不需要多源冗余
4. 减少 GH Actions 调用量和 Turso 写入

## 影响范围

- GH Actions 定时触发云端采集的功能下线
- portal/api/_collect.js 不再维护
- 所有采集相关 bug 修复只需改本地代码
