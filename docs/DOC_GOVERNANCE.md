# 全网情报系统 · 文档清洁与归档规范（底层文档治理）

> **这份文档管什么**：什么时候必须清洁文档、清洁时留什么、剔出去的内容怎么判（搬新家 / 改指路 / 删）、搬走时要写下哪些出处、以及怎么让机器证明这些规矩还开着火。
> **它自己是底层文档**（`DEVELOPMENT_STANDARDS.md` §文档规则的可执行版本；两者冲突以本文为准并回改本文）。
> 最后更新：2026-10-01

## 1. 触发时机（满足任一即必须做清洁，不做等于欠债）

| 触发 | 说明 |
|---|---|
| 用户说「清洁文档」 | 全量走 §3 SOP，一次做完 |
| 一个功能批次交付完并**用户验收通过** | 只清这批：把流水账从活文档里按 §2.5 判去处（搬新家或就地删），**不再往归档层搬文字** |
| 活文档自相矛盾被抓到（头部范围 ≠ 正文范围、日期 ≠ git 日期、引用不存在） | 立即改，属**修正**不属归档，不需要等验收 |
| 单份活文档超阈值（见 §5 门禁） | 触发核销轮 |

> 关键区分：**修正（correction）** 随时可做；**出账清（closing out）** 必须等验收。
> 未验收就把修复记录删掉 = 掩盖现场；验收后还留着 = 污染活文档。这两条都算违规。

### 2.2 白名单之外的目录职责

- **作废 = 删，不是搬进目录养着**（用户 09-25 裁决「清除过去的文档，别让过时的文档影响判断」）。
  "不静默删除"由 **git** 承担，不由"文件还在原地"承担——养在归档目录里的作废件会被下一个人当现状干活。**删除批次的提交信息就是台账**（10-06 用户裁决：作废登记表不设——删除都是用户点单，提交信息里写清删了什么、为什么、内容去向，另立登记属重复记录），所以删除提交的信息必须把这三样写全。
- **整批删除必须同时满足两条，缺一即算静默删除**：
  1. **先确认可反查**：`git ls-files <目录>` 逐份确认已被跟踪、且工作树干净。被 `.gitignore` 或内容过滤器挡住的孤儿文件**先单独救出再删**——它们没有 git 可反查，唯一副本就是那个文件本身。
  2. **不可再生的内容先落新家再删**：裁决、边界与禁令、"某个键/某张表根本不存在"这类**只有探针或只有当事人查得出来**的事实，删前按 §2.5 逐条搬进活文档。搬完再数一遍：被删的每一份里还有没有没搬走的"仍然成立的话"。
  - **删完之后不要再回头给这些文件写指针**：现行文档里出现"原文见某归档件第几节"这类地址式描述，等于把过去的上下文重新引回现在（用户 09-25 明确禁止）。反查只走 git。
  - ⚠️ 已知副作用：删掉大批文档会**缩小文档门禁的扫描分母**，可能触发"分母过小 = 判据写空"那几把锁变红。这类红**不许靠下调阈值消音**——绝对下限锁的是语料规模，不是判据行为；收口方式见 `docs/ISSUES.md` 的对应裁定行。
  - **删完仍散落在各文档与代码注释里的历史编号**（形如"某批号-子号"）不逐条清理，本节统一声明：「**整批删除的历史编号，自此只作历史编号读，不得当"方案已存在"引用**」。但**指向已删文件的路径必须清**——路径查不到就是悬空引用，编号只是读不懂。
- `docs/archive/` —— **只放素材**（分析图片、设计样图、一次性脚本）。**不再收文字件**：核销出账的文字按 §2.2 搬完即删，反查走 git（2026-10-01 把这一层原有的 85 份文字件整批清掉，理由与过程见 `docs/archive/README.md`）。这一层始终**不作现状依据，也不在索引里逐篇登记**。
- 仓库根**只放那三份入口文档**（`README.md`、`AGENTS.md`、`ARCHITECTURE.md`，门禁的第 1、2 条按 §2.1 那份白名单扫），其余一律进 `docs/`。**本仓没有仓库根 `archive/` 这个目录**——历史上曾在这里挂过一条"与分析产物同级的仓库级归档"的规矩，那是写给一个从未稳定存在的目录，别照它去建。

### 2.3 各类内容的现役位与出账处置（**归档位这一列正在消失**）

清洁动作的本质是：**内容验收通过后，把它从现役位清出去**——仍成立的语义改写到它该住的那份活文档里，不成立的一次性读数与流水**直接删**（不再搬进目录养着）。现役位**只在该文件头部**用一句目录级说明交代"已核销的不进本文件"，不逐条留地址（09-25 裁决，见 §4.1 末段）。

| 类别 | 现役位（还在跟进的） | 归档位（已验收/已完结） | 收什么 |
|---|---|---|---|
| **决策** | `docs/adr/`（一主题一号，只写最新标准） | — | **被覆盖就地改写该件，不归档、不留"旧方案对比"**；查经过走 git |
| **开发功能规格** | `docs/specs/`（在途批次的工作文件） | **不设归档位** | 判完生死按 §2.2「作废即删」走——**不建状态头注、不搬进目录养着**，否则归档层会变成第二个事实源。持久部分先按 §2.5 搬走 |
| **功能** | `docs/features/`、`docs/NEXT-DEV-REQS.md` | **不收文字留底** | 已验收功能的交付说明、需求源头、外部产品范式借鉴清单：语义部分改写进 `docs/features/`，其余出账即删 |
| **优化** | `docs/ISSUES.md` 观察中、`FEATURE_MATRIX.md` | **不收文字留底** | 性能/感知/配额/成本类优化的前后对比与实测数据属一次性读数（§2.5 第三类），结论留在现役那份里，读数删 |
| **调试** | `docs/ISSUES.md` 活跃表 | **不收文字留底** | 单期修复流水、DELIVERY 类文档、已完结 `changes/*.md`：出账即删，反查走 git |
| **踩坑** | `docs/pitfalls/`（**只累积不归档**） | — | 症状/根因/规则/案例四段式，按域一文件：collection / backend / ai / frontend / deployment / testing |
| **对接** | `docs/RUNBOOK.md` §4（队列对端与同步入口）、`docs/features/collectors.md` | **不设归档位** | 已停用/已替换的第三方链路方案。**09-27 起这里不再有独立手册**：两份"平台对接指南"被删，因为它们描述的通路从未在当前真实环境跑起来，而手册把它们写成了现役。判死方案的原文（wemp 自建引擎、宝塔/PM2 那几代）也**不再留底**——10-01 随归档层文字件一起清除，要看原文走 git。**规划中的 `archive/integration/` 从未建起来**，别再往那个路径搬 |
| **研究/前瞻** | `docs/research/`（每份自陈身份） | **不设归档位** | 外部范式拆解与目标态框架。判断不再成立即删、反查走 git；已落地的部分改写进 `docs/features/`，不留"应然 vs 实然"两份并行 |
| **密钥管理** | `docs/HANDOVER.md` §1.5（本地）、`ARCHITECTURE.md` §6 | **不设归档位**（规划中的 `archive/credentials/` 从未建起来） | 凭据**轮换史与位置矩阵**（三处同步记录、失效事件）写在现役那两处；本仓不在 `docs/` 里堆凭据史副本——**归档层里放一份"位置矩阵"就等于公开仓里多一个可被扫描的靶子** |

> ⚠️ **密钥类硬规则**：任何入库的文档（含归档层）**只许出现凭据名、存放位置、轮换时间、掩码指纹（前 4 后 4）**，永不写完整明文密钥；也不要在归档层另存一份"位置矩阵"——那是把靶子复制进公开仓。真实值只在本地 `.env` / Vercel env / GitHub Secrets 三处（AGENTS §2.6），本地速查件 `docs/HANDOVER.md` 已 gitignore、永不提交。提交前 `git status` 复核不得含密钥泄漏（门禁的明文凭据扫描见 §5 第 6 条，它连"未跟踪但没被 ignore"的文件一起扫）。

### 2.4 搬走一段内容时必须写下的出处（五字段）

> 适用面已收窄：归档层不再收文字件（§2.2/§2.3），所以这套字段现在用于**取证产物**（`docs/eval/`）与任何确实要长期留存的文字；核销出账的流水与读数据不再需要"归档件"这个载体——删掉即可，出处由 git 承担。

```markdown
> 类别：调试 | 归档自：docs/ISSUES.md B14 / 本轮会话 2026-09-18
> 关联承载处：`tools/collect-turso.js`（生产链路那份作业）、`api/_alerts.js`（报警分发）
> 关联坑：docs/pitfalls/collection.md#33 | 关联决策：ADR-02 | 取代：无
> 状态：已验收（用户 2026-09-XX 确认）／待验证 —— 待验证不得出账
```

**「关联承载处」只许写到文件/模块，或"哪份文档的哪一节"——不写行号、不写函数名**（用户 09-30 裁定：判据统一到"确实不要"这一侧）。
理由不是"怕写错"，而是**写不完**：代码每次增删改查都会让行号漂、让函数改名，于是要么锚点全部腐烂、要么靠人手改锚点消红——
09-21 的门禁实测就是后一种：抓到的越界锚点**大多数是我自己的修复打断的**，不是自然腐烂。指路要指向**不会天天变的东西**。

**搬走内容时必须写出处**：五字段缺任一项 = 这次搬家无效（出了问题查不到是谁搬的、从哪儿搬的）。适用面见本节开头——文字留底已不进归档层，所以这条现在主要管 `docs/eval/` 的取证产物。
**归档层的文字件已整批清空**（2026-10-01，85 份；仍生效的部分逐条搬进 `adr/`、`features/`、`pitfalls/`、`RUNBOOK.md` 之后删除，反查走 git 删除批次提交信息）。所以"存量不追溯、只报数不判红"那套豁免一起作废——**这条判据现在反过来**：往 `docs/archive/` 放 `.md` 就是错（见 §5 第 4 条）。历史沿革里值得留的只有一句：这条判据当年曾因归档层 255 条头注错而把"零错"变成不可满足，连带让两枚借门禁退出码判成败的锁（密钥扫描 S6、裸文件名 L5）静默失声——**判据把交付物当嫌疑人扫，就会反噬真正的安全判据**（同族教训见 §5 末条与坑 #45/#64）。
反向也要登记，但**只登记一次、且不给地址**：活文档里被抽走的行**就地删掉**，在文件头部用**一句目录级说明**交代"已核销的不进本文件，反查走 git 与归档层"。
**不许逐条写"详见 `docs/archive/xxx.md` §几"**（用户 09-25：那是多此一举，且会把过去的上下文引回现在）。

### 2.5 一条陈述的三种去处（判"该留 / 该搬 / 该删"的尺子）

判据不是字数，是**"删掉它会不会指挥人做错事"**。任何一段现行文字只能落进三类之一：

| 类别 | 认法 | 去处 |
|---|---|---|
| **决策 / 边界** | 短期不变的定位，或明确的"不做什么"，且**答得出为什么** | `docs/adr/` 续号件：是什么 / 为什么 / 边界与禁止 |
| **护栏** | 违反就停摆，但不涉及方向取舍（机制约束） | 留原文件，重写成"改了会怎样 + 现在读哪里能验" |
| **一次性读数 / 出土过程** | 每天变的数、"哪天被谁推翻、当时读到多少条" | **删**，不留指针，反查走 git。实测教训：写进规格文件的"背景事实"会在同一轮里被后续实测推翻——**照它动工就是按假前提开工**，所以这类数只许出现在取证产物里，且取证产物不作现状依据 |

三条边界判据（最容易判错的地方）：

1. **"没做" ≠ "不做"**。排期里的需求、界面上根本没有控件的东西、结构性缺列，都不许写成决策件——那是现状，不是取舍。写进去会让下一个人以为"这是有意为之、别去补"。
2. **"尺子的规则" ≠ "软件的方向"**。文档分层、归档处置、交付链步骤、本表本身，都属治理，留在治理与验证文档，**不进 `docs/adr/`**。
3. **一条陈述要进 ADR，必须填得出【为什么】**。填不出 = 不是决策，或需用户补因。**因果链只有三个合法来源**：文档与提交里的原文、现读得到的机制后果、用户口述——**不许 agent 编造因果链**，编出来的"为什么"会让一条无主取舍变成不可质疑的决策。

### 2.6 文档改动戳 —— 谁改了、什么时候、哪个版本（2026-09-20 新增）

> 一句话：**改动史集中由机器写，头部只写"最后一次内容改动"**。戳不落进各文档正文，落进 `docs/STAMPS.md`。

| 项 | 规则 |
|---|---|
| 谁生成 | `node tools/doc-stamp.cjs` → 写 `docs/STAMPS.md`；`--check` 只比对不写（将来接门禁用，本轮未接入） |
| 装什么 | 全库每份 tracked `.md`：头部声明日期 + 判定 + **最近 2~3 次提交**（短号 · 日期 时:分 · 提交主题）。底层文档给 3 次，其余给 2 次 |
| 何时重跑 | 每次改完文档、提交之前跑一次，产物随同提交 |
| 为什么**不**把 commit 号写进各文档头部 | ① **自引用**：写戳那次提交本身即成为该文件的新提交，头部只能指上一条，永远滞后一格；② **`git log -1` 不等于"最后内容改动"**：只加头注、只改错别字的元提交会把日期顶新（2026-09-20 实测 4 例：`README.md`、`docs/DEV_GUIDE.md` 的"漂移"经对 `git show` 取证后确认头部是诚实的，`docs/DEVELOPMENT_STANDARDS.md` 那次只改了 `Agencs`→`Agnes`）。所以给的是**带主题的提交史**，元改动由读者按主题分辨，**机器不替人判** |
| 判定列怎么读 | `待判` ≠ 有错。它只说"头部比最近提交旧"，真过时还是元提交，看同一行的提交主题；`头部超前` = 头部写了尚未提交的日期，**提交前出现它是正常态**，只有"已 push 却仍超前"才是硬伤；`⚠` = 工作区还有未提交改动 |
| 设计内滞后 | 表读的是**已提交**历史，所以"正在提交的这一次"必然不进表：本轮改过的文档，其行落后一个提交，下一轮重跑即补上。这是**显式**滞后（配合 `⚠`），与"头部手写 commit 号"那种静默滞后不同类——前者读者看得见，后者看不见 |
| 头部 `> 最后更新：` 的新语义 | 收窄为"最后一次**内容**改动"，并保留必填的"改了什么"一句。**纯元改动（改头注、改错字、重排、搬家）不许顶日期** —— 这条正是上面 4 例的结论 |
| 不许做的事 | 不许手改 `docs/STAMPS.md`（改了下次就被覆盖）；不许为了"让判定变绿"去把头部日期抄成 git 日期 —— 那等于把元提交冒充内容改动，日期重新变成不可信读数 |

## 3. 清洁 SOP（照做，不要凭印象）

**Step 0 冻结验收**：列出本轮拟出账的条目，逐条问「用户验收了吗」。没有 → 留在活文档，进待验收队列（§4.1 那三类之外，未验收的一律不清）。

**Step 1 事实反向核对（先代码后文档）**——活文档里的每个易变事实都要回到代码/环境取真值：

```bash
grep -n "cron:" .github/workflows/collect.yml          # 调度频率唯一真值
grep -rn "intervalMin\|refreshInterval" server/services/collectors/ | head   # 采集间隔默认值
npm test > test.log 2>&1; echo "EXIT=$?"                # 测试数以命令输出为准，不写进文档
```
> ⚠️ **不许用 `npm test | tail`、`| grep` 这类管道看结果**：管道的退出码是末端命令的，红色的套件会照样报 0。本项目已两次因此把红读成绿（含本文件旧版这里写的 `| tail -5`）。要么重定向到文件再取 `$?`，要么直接看汇总行。落文件时**别用 `/tmp`**：Windows 上 Git Bash 的 `/tmp` 与 Node 的 `os.tmpdir()` 不是同一处。
逐项核对：调度频率 / 采集间隔 / 测试基线 / 域名 / 端口 / 代理端口 / 凭据位置 / 功能矩阵 / 表列清单。发现冲突 → 改文档，**不改真值来源**。

**Step 2 头部元信息核对**：跑 `node tools/doc-stamp.cjs` 看 `docs/STAMPS.md` 的判定列，**不要**再用 `git log -1 --format=%ad -- <file>` 当"最后内容改动日期"——元提交（改头注/改错字/搬家）会把该读数顶新，2026-09-20 实测 4 例，机制与口径见 §2.6。判定为 `待判` 的要逐条对着提交主题确认是真过时还是元改动；`头部超前` 一律改回。头部声明的范围（"B12~B19"、"H9~H13"）仍须与正文表格实际范围一致。

**Step 3 悬空引用扫描**：跑 `node tools/doc-lint.cjs`（§5）。文档里出现的每个路径/端点/表名/spec 编号都要验证存在；**指向已删除历史件的指针直接删句**（不给它补"已归档"标注——那等于继续为过去的文档占现在的上下文）。

**Step 4 出账清**：按 §2.5 判每段内容的去处（仍成立的语义改写到新家、一次性读数与流水就地删）；**活文档原位不留逐条指针**（去冗规则见 §4.1 末段：文件头一句目录级说明即可）。**不再往 `docs/archive/` 搬文字件**（门禁会判红，见 §5 第 4 条）。

**Step 5 重建索引**：`docs/INDEX.md` 必须覆盖 `docs/` 下全部**在用** `.md`（`adr/`、`changes/`、`contracts/`、`eval/`、`features/`、`pitfalls/` 各域）。**`specs/` 不在覆盖范围**——它是用完即清的工作文件，逐份登记会让在途规格变成第二个事实源（§2.1）。
**归档层是唯一的例外**：`docs/archive/` 只写一句"不作现状依据"，**不逐篇登记**（09-25 用户裁决；`doc-lint` 的登记豁免与此口径配套，别再往 INDEX 里补清单）。漏登记在用文档 = 下次没人能找到。

**Step 6 去重与 SSOT 收敛**：同一事实多处写死 → 保留权威那处，其它改「见 X」。已作废的结论**直接改掉或删掉**（§2.2 作废即删），现行件只写最新标准，不留"已作废 + 日期 + 链接"的头注。

**Step 7 交付**：`node tools/doc-lint.cjs` 0 错 + `npm test` 不新增红 + `git push origin main`（AGENTS §2.1）。文档改动也要推，否则下一个人读的是旧事实。

## 4. 写作红线（长期有效）

1. **易变事实不写死**：测试条数、坑条数、源数量、保留天数 → 写「以 `npm test` / `grep -c` / `settings.data` 为准」。
   **但"只许一份"防的是重复取值互相漂移，不是要文档看不见那个值**：线上域名、端点路径这类**可读标识**不是易变取值（几年不动一次），权威文档里就该写得出一次，让接手的人知道"到底是哪个网站"；它的风险由"全库不许出现第二个域名 + 文档写的必须等于代码用的"这类锁兜住。**把这类值从文档铲成"见代码"是读反了这条规矩**。
2. **单一事实源**：调度表只存在于 `collect.yml`；功能矩阵只存在于 `FEATURE_MATRIX.md`；凭据位置只存在于 `HANDOVER.md` §1.5。
3. **活文档只装"当前"**：ISSUES 只装未修复/观察中/挂案；已核销的**出账即删**（不再写 `ISSUES-resolved-<date>.md` 那种留底），反查走 git。
4. **文档只写现状，不写变更史**：不写"哪天改过、被哪次实测推翻、当时读到多少条"。一条陈述仍然有效的凭证是它的**编号与确认标记**（ADR 号、坑号、`核 <日期>：<依据类型>`），不是叙述长度；变更史交给 git 与 `docs/STAMPS.md`。**过期陈述比缺失更危险**——它会指挥下一个动手的人往错方向走。
5. **不写死接口**：任何活文档都不写行号、参数取值、函数签名，也不复述代码结构；只写输入输出示例与"不能做什么"。取值全库只许一份（上面第 1、2 条），其余写「见 X」。理由：接口在迭代里大概率还要变，写死等于给文档排个腐烂日期。
6. **凭证不许押在一次性件上**：长期陈述的依据只能是代码/配置本身、现役文档，或"现读哪个字段能验"的查法。**不许**写"因为某轮裁过所以成立"——裁决载体（会话记录、一次性判定清单、某轮交接件）注定要拆，把依据押在上面，拆那次就等于把凭证一起销毁。一条陈述仍然有效的凭证是它的**编号与确认标记**，不是"谁说过"。
7. **一个词只指一个东西**：同名多义（"快照"既指整库备份又指静态导出物、"队列"既指任务表又指待导入清单）一律拆名后重写；靠上下文区分不成立。
8. **指针式推荐**：`INDEX`/`RUNBOOK` 之类入口文档只指路，不复述内容。

### 4.1 洁净 = 精炼 + 去冗 + 出账清（三条都做才算做过洁净，2026-09-20 用户口径；"归档"一档于 2026-10-01 废止）

**出账清本身就是洁净的一环，而且是收尾那一环**——不是"有空再做的搬家"。一条修改**经人工确认无误**之后，跟着它的那段验证报告、短期状态、后续计划就该从活文档里**抽出来**：仍成立的语义改写到该住的那份（`adr/` / `features/` / `pitfalls/` / `RUNBOOK.md` / `NEXT-DEV-REQS.md`），剩下的**一次性读数与流水就地删**，原位只留文件头部那一句目录级说明。**不再"整理成新文档并归档"**——归档层就是这么长成第二个事实源的（它的 85 份文字件已于 10-01 整批清除，过程见 `docs/archive/README.md` 与 git 历史）。**过时的、不具参考性的文件同理**：删，不要留在原位占读者的注意力，也不要换个目录继续占。

**为什么必须清**：`ISSUES.md` 这类活文档在开发过程中会长出**三类根本不属于它的东西** ——

| 长出来的东西 | 为什么不属于活文档 | 去处 |
|---|---|---|
| **验证报告**（证据对账表、F2P/评测读数） | 它证明的是"过去某一轮做过什么"，不改变下一步决策 | 取证产物落 `docs/eval/`（那是它们的现役位）；账本里的段落删掉，**不建留底副本** |
| **短期报告**（某轮交付链状态、某轮处置表） | 一轮一表，表与表互相覆盖，读的人要横向比对才知道哪张是活的 | 收口即删；要回看某一轮跑没跑，读 `AGENTS.md` §3 那条链 + git |
| **未来计划**（下一步做什么、优化方向） | 排期入口是 `NEXT-DEV-REQS.md`，写在缺陷账本里等于两个事实源 | `docs/NEXT-DEV-REQS.md` |

这三类都在**影响 agent 和人的阅读**：读者打开账本要看的是"现在什么坏着、等什么决定"，不是读五份已完成工作的验收细节。**放行 / 待批队列留在 `ISSUES.md` 顶部** —— 那才是它该装的。

**精炼的对象就是这些累计出来的废话**：同一事实多处写死 → 只留权威那处，其它改「见 X」；已作废结论 → 直接改掉或删掉（不留一行指针，指针也会被当成"那份还在"）；复述代码行为的段落 → **删掉，不留**——要指路只指到承载它的那份文档，**不写行号、参数取值、函数签名，也不复述代码结构**（09-26 用户裁定原则 1；本文此前"改成 `file:符号` 锚点"的说法与之相反，已作废：锚点会被重构消哑、会随版本越界，且把文档绑死在代码形状上）。

**判据不是"最短"，是"不可再被误解的最短"**：当你删掉任何一个词、任何一步、任何一个条件都会让执行失败或让语义改变时，这段就到位了（柯氏复杂度式的"不可再压缩而不损失信息"）。

但**别把"最精炼"当静态终点**：无损压缩的极限是熵，而文档面向的不是随机信号，是**持续演变的任务分布**——今天压到极限的版本，明天来了新场景就是残缺。所以允许**有生命力的冗余**：高频路径的显式前置条件、边界示例、"什么情况下不要这么做"。

| 信号 | 怎么判 | 动作 |
|---|---|---|
| 🔴 停下 | 删掉一句后需要**另加注释**解释"这里原来写了什么" | 删过头了，补回来 |
| 🔴 停下 | 为了省两个词花五分钟斟酌 | 边际收益为负，收手 |
| 🔴 停下 | 内容从"描述如何执行"变成"需要解码的谜语" | 加回展开，或换抽象层级 |
| 🔴 停下 | 需要看三遍才懂（另一个人 / 三个月后的自己） | 同上 |
| 🔴 停下 | 精炼**改变了词的存在性或结构语义**：把"拟建 `x.js`，落在 `lib/` 下"压成路径 `lib/x.js`（读者以为文件已存在，`lint:docs` 也会报假悬空），或把单元里的裸竖线留着（整行破格、内容错位到别的列——样本 `docs/ISSUES.md` B126） | 停：还原状态词、竖线用反斜杠转义。**精炼只删字，不删语义**（本行末尾的 `doc-lint:ignore` 标记就是举反例时怎么豁免悬空判据的正确写法） | <!-- doc-lint:ignore -->
| ⛔ **硬性停下** | 为了精炼引入**隐式依赖**——要求执行者本来就知道没写出来的前提 | 立刻停，补回显式声明 |
| 🟢 继续 | 同一份文档在不同调用里因某段描述**产生不一致行为** | 那段就是歧义源，继续精炼到消除歧义 |
| 🟢 继续（前置） | 精炼动手前先备份原文件，事后跑**无损校验**：原文里每一行要么还在活文档，要么能在归档文件里**逐字**找到，二者皆否 = 吃掉语义了 | 校验不过就不落盘（替换脚本先写归档、再逐行反查，反查失败即退出） |

> 反复命中第 3、4 条时，结论通常不是"不该精炼"，而是**还没找对抽象层级**——换层级重写，别在词上做文章。

| 维度 | 该精炼 | 该保留 |
|---|---|---|
| 高频执行路径 | 主流程零废话 | 高频路径的显式前置条件 |
| 异常 / 边界 | 用标准化钩子（如 `fallback: escalate`）替代逐条展开 | 钩子内一句话说明触发条件，不许是黑盒 |
| 术语 | 领域内共识术语精确使用、不解释 | 跨领域或新造概念**首次必须展开** |
| 示例 / 样本 | 删掉"仅供参考"型示例 | 保留**约束性**示例（什么情况下不该这么做） |
| 迭代阶段 | V3+ 持续压缩已验证逻辑 | V1–V2 保留探索性描述，宁可多勿少 |

## 5. 门禁与自检

`node tools/doc-lint.cjs`（已接入 `npm run lint:docs`；只读检查，非零退出码=不通过）：
1. 底层文档缺 `> 最后更新：YYYY-MM-DD` 头注 → **错**
2. 相对路径引用不存在 → 底层文档/`features/`/`pitfalls/` 报**错**，历史 spec 与变更记录报**警**（那里的引用是"当时的事实"）；刻意引用已删路径的行加 `<!-- doc-lint:ignore -->` 豁免
3. `docs/` 下存在未被 `INDEX.md` 登记的 `.md`/`.json`（文件名或任一上级目录命中即算登记）→ 警
4. **`docs/archive/` 里出现 `.md` → 错**：归档层只放素材（图片/样图/一次性脚本），不收文字留底（§2.2/§2.3）。要留存就搬进 `adr/`、`features/`、`pitfalls/` 或 `docs/eval/`，否则出账即删、反查走 git。目录级 `README.md` 豁免——它只作目录级说明，不是留底文字（判据实现与此口径一致）。
5. 活文档超长（ISSUES > 130 行 / ARCHITECTURE > 400 行 / NEXT-DEV-REQS > 260 行 / FEATURE_MATRIX > 200 行）→ 警，提示核销轮
6. 明文凭据扫描（判据本体 `lib/secrets.js`）：`ghp_` 前缀、`sk-` 前缀、Turso 带口令的 libsql 连接串、`*.libsql.cloud` 主机名，
   **09-21 补三类 webhook（飞书/钉钉/企微）与长 Bearer 令牌** —— 报警渠道的密钥恰恰长在 webhook 里，原模式一类都不匹配。
   **扫描面两块**：① git 已跟踪文件；② **未跟踪且没被 ignore** 的文件（B113 的形状：一次 `git add` 就进历史）。
   本地设计内的凭据（`.env` / `docs/HANDOVER.md` / `data/`）由 `.gitignore` 挡在两面之外，不在此列。
   每次运行打印分母（`[密钥分母] 已跟踪 N + 未跟踪未 ignore M，命中 X 处`）→ **错**，禁止提交。
   配套纪律：探针打印 settings/credentials 前必须过 `lib/secrets.js#maskDeep`（坑 #69，锁 S1~S8）。
7. **表格超格**（B126）：markdown 表里某行的格数**多于**表头（内容里的裸竖线把行撑破）→ **错**。
   少一格是合法 markdown（缺的尾格渲染成空），**不判**；转义写法 `\|` 不算多格。豁免只在行内 `<!-- doc-lint:ignore -->` 生效。
   **7b 表格断裂**：表头与分隔行被并成同一行（`| 号 | 判据 ||---|---|`）→ **错**。这不是渲染问题，而是
   **整张表从此脱离 7 的格数判据**——09-21 一次 Edit 少写换行就真发生过，光靠格数判据永远看不见它。
8. **活文档不许出现行号锚**（09-30 裁定，取代原"越界才判错"的 B115①）：活文档层（底层件 + `features/` + `pitfalls/` + `adr/`）
   出现 `文件名:行号` 这种形态 → **错**，**不管行号指得准不准**——指得准也只是这一秒准，代码一改就漂，
   逼人反复手改锚点消红。历史层（归档件）**只进分母、不判红也不逐条提示**：那里的锚点是"当时那次取证"的一部分，
   追溯判红只会逼人删证据或整行加 ignore；逐条细节走 `npm run lint:cites` 那张取证台账。
   但仍必须区分"引用一个锚点"与"把锚点当反例讲"，否则天天误报、三天后就被 ignore 绕过 ——
   现用**死锚点/讲形态信号词**（已删/作废/反例/原写/曾写/越界/不许出现/这种形态…）与行内 ignore 两条豁免，
   并每次运行打印分母：`[锚点分母] 看到 N 条…其中 M 条按信号词放过`（"0 个错"必须同时报"看了多少条"）。
9. **F2P 条数必须带证据文件名**（B114②/B106 残余）：同句写了"改前红/改后绿 + `x/y`"却没带 `*.json` → **错**；
   明说"不套/不适用"（坑 #64 规则②的新增门禁）与"原文那句…判为不实"（引用被更正的旧写法）**放过**。
10. **同一张登记表内编号唯一**：一张表里两行同号（例如 09-21 实测两个 B128 并存：`lib/db.js` 少三列 与 零引用资产）
    → **错**。粒度是**单张表**：跨表/正文再写一遍同一个号是正常引用（第一版按整份文件判，立刻造出 21 条假红）。
11. **判据自身要能被证伪**：`npm run lint:docs:selftest`（同一份 `doc-lint` 的 `--self-test`）逐条喂
    坏样本与反例，**双向**（例数由本次运行打印，本文不复制；含"分母必须非空"与"不许有文件级 ignore 短路"两条，防判据被写成恒绿）。
    - **判据的判据对象消失了就要一起摘**，不许留着：留下的是"看起来有门禁、实际永远零命中"，比没有更坏（上面那条锁防的正是这个形状）。摘除记在当轮删除/修复批次的提交信息里。
人工复核项（脚本查不了的）：范围声明与正文是否一致、同类事实是否只剩一处、**现行文档是否又长出了指向归档件的逐条地址**（09-25 禁，`doc-lint` 只查文件级悬空、查不出"节级指向已改名/已删段"）、日期是否与内容改动相称。

## 7. 大改动的文档义务（管理后台类页面/功能重构）

管理后台属**大页面 + 大功能重构**区，默认最低优先级，且必须：
1. 先出**总 spec**（一份框架：目标/边界/分板块/验收口径/回滚点），进 `docs/specs/NN-<topic>/spec.md`；
2. 每个小功能/板块各出一份 **mew-spec 小框架**（同目录 `NN-<topic>-<sub>.md`），列改动点、影响面、验收；
3. **用户同意后才动代码**；动工即建四件套（spec/plan/task/checklist），验收证据写进 checklist；
4. 交付后按 §3 Step 4 出账清：功能语义进 `docs/features/`，坑进 `docs/pitfalls/`，交付流水与一次性读数**就地删**（不搬进归档层，见 §2.2/§4.1）；**这批规格文件本身也按 §2.2 整批删**——它的持久部分已经搬完，留着它就会出现"以过时规格引领开发方向"那种事故。
