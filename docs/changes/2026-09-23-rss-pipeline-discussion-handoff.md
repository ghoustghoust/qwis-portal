### P0-2 初筛间歇性失效（已讨论完）

**现象**：近 11 期有 `filterStats` 的日报，初筛剔除率在 **0% ↔ 13.8%** 之间随机跳：

```
id 54  09-20T18:26Z  候选500 通过488 剔 12  2.4%
id 55  09-20T20:27Z  候选500 通过500 剔  0  0.0%
id 57  09-21T20:23Z  候选500 通过431 剔 69 13.8%
id 58  09-21T22:00Z  候选500 通过500 剔  0  0.0%   ← 第 22 期（用户截图那期）
id 60  09-22T19:14Z  候选500 通过434 剔 66 13.2%
id 61  09-22T21:18Z  候选500 通过500 剔  0  0.0%
（另 6 期 candidates=0 或全 0；29 期无 filterStats 字段）
```

0 剔除那几期，`passed == candidates`，与"模型认为这 500 篇全都值得深析"**在数据上完全同形 → 不可判别**。

**机制：三个各自正确的决定合成一个静默失效**

| 环节 | 位置 | 本身对不对 |
|---|---|---|
| 预算给小 | `api/_ai.js:261` filter 用 `maxTokens: 128`；同文件 `:69` 注释写着「**推理模型必须给足（reasoning 烧 token）**」默认 512 | ❌ 违反本文件自己的规矩 |
| B19 修复 | `:82-88` 以前"只吐思考不吐正文"会把 `reasoning_content` 当正文返回，现改为**抛错** | ✅ 修得对 |
| 失败放行 | `:262` `!r.ok → {score:50, ignore:false}`，注释「宁多勿漏」 | ✅ 单看是对的（不让一次抖动毁掉早报） |

`agnes-2.5-flash` 是推理模型，128 token 全烧在思考上 → `finish_reason=length` → 无 content → 抛错 → 放行 50 分（>门槛 30）。
**间歇而非恒定**的原因：思考长度随题目变化，有时 128 够它憋出 JSON，有时不够。
对照：**`analyze` 用 768 → 失败率 1.8%**；`theme` 用 300/512 的那两处失败率 43%；`term-extract` 67%。

**第 22 期完整漏斗**：`候选 500 → 通过 500 → 深析 162 → 门槛剔 109 → 入报 46`，`elapsedMin 9.1`，`theme: null`（即 ISSUES B16/B121 待复验的那一期）。
