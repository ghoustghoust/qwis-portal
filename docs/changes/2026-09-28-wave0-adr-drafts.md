## 一、可直接放行的 6 件（因果链来自文档原文或可现读的机制后果）

### ADR-17 · 不做云 / 本地数据同步

- **出处**：模块地图「设置写入通道 · 生效档位」行现在只把它当现状陈述挂着（"写进哪个库决定谁能看见：本地一份、云库一份，互不同步"），没有承载件。
- **是什么**：本地端读写本地 SQLite，生产链路读写云库，两者之间**没有运行期同步通道**。跨库动作只剩一次性种子脚本；那份"统一异步数据访问层"的适配文件自陈是冻结态、schema 已与本地漂移，主进程从不加载它。
- **为什么**：数据只有一个落点，采集写入方只有 runner。再加一条同步通道等于多一个写入者、多一套冲突与配额开销；本地端只作开发与全功能灾备，不承担"改了要让生产看见"的责任。
- **边界与拒绝**：任何"给设置或内容加本地↔云同步"的提案，先推翻本件。唯一例外是文件型导入队列（ADR-10）——那是把外部文件单向投进云端的一张清单表，不是同步。**知情代价**：本地改的生产看不到，必须各自改一遍。
- **现读依据**：看本地主进程里有几家云库客户端（现读为 0 家在运行路径上）；看那份适配文件头部的自陈。

### ADR-18 · 定时只走 GitHub Actions，Vercel 不加 crons 块

- **出处**：链路指南 §2 不变量「vercel.json 不要加回 crons 那条」。
- **是什么**：所有周期任务由 runner 侧作业文件定时；托管平台的部署配置文件里不放定时块。
- **为什么**：托管平台的定时只发 GET 请求且不插值环境变量，而采集入口只收 POST —— 天然不兼容，历史上写了等于没写。
- **边界与拒绝**：任何"把定时搬回平台 cron"的提案先推翻本件。定时取值与作业清单的唯一承载处是作业文件，**文档只许指路、不许复制取值**。重开条件：采集入口改成能接住平台定时请求的形态、且平台会插值环境变量——那时改写本件，不留两份并存。

### ADR-19 · 不引入工作流编排平台

- **出处**：需求队列「明确不引入的东西」表第 2 行。
- **是什么**：内容管线（采集 → 清洗 → 评分 → 成栏 → 落库）用本仓代码实现，不交给外部编排器。
- **为什么**（文档原文）：编排器只会把评分口径变成别人的默认值。本系统的评分口径是自家定义、且要能被探针反查的（口径见 ADR-15）。
- **边界与拒绝**：任何"接一个外部编排/工作流服务来跑管线"的提案先推翻本件。**定时触发不算编排**（那是 ADR-13 的双档触发）。

### ADR-20 · 不引入搜索引擎栈（全文检索 / 向量库）

- **出处**：需求队列同表第 3 行。
- **是什么**：检索用 SQL 匹配 + 集合相似度，不接全文检索引擎、不建向量库。
- **为什么**（文档原文）：当前量级下够用；引入一套检索就得多维护一条数据通路。云侧配额是墙，多一条通路就多一处一致性负担。
- **边界与拒绝**：任何"给内容加向量索引/接检索服务"的提案先推翻本件。重开条件要能现读：检索在真实数据量上答不出（**必须给出可测判法**），并写明新通路的数据由谁写、失效谁负责。

### ADR-21 · runner 依赖面只许纯 JS

- **出处**：链路指南 §2 不变量「runner 脚本不许依赖 better-sqlite3 那条」。
- **是什么**：跑在 runner 上的采集与批处理脚本只依赖不需编译的包（托管库客户端、feed 解析、全局 fetch 及配套）。
- **为什么**：runner 上依赖安装不跑编译脚本，需编译的原生模块装不上；而 runner 是**唯一写入方**，装不上 = 整条数据链起不来。
- **边界与拒绝**：本地库驱动那类原生依赖只许留在本地端；跨端共用的语义要落 `lib/` 且必须是纯 JS 实现（ADR-14）。任何"给 runner 加原生模块"的提案先推翻本件。

### ADR-22 · 不做清理总开关

- **出处**：模块地图「数据保留与存储 · 保留天数」行的括注（"故意没有'清理开/关'这种总开关"）。
- **是什么**：内容保留只暴露"保留天数"一项；没有"启用/停用清理"这种总开关；热榜那一保留轴与豁免名单是代码写死的策略，界面控制不了。
- **为什么**：关掉清理等于放弃保留策略，而**库只涨不删会把行读单价与存储同向顶高**——托管库任一维度越限就整站封锁（本仓真被禁过六小时，见链路指南 Turso 单点那条护栏）。
- **边界与拒绝**：任何"加一键清理 / 停用清理开关"的提案先推翻本件。删除闸与转储的机制归护栏与功能文档；本件只钉"不提供总开关"这一个取舍。

## 二、等你补一句因的 1 件

### ADR-23 · 兴趣画像不作为用户可改项

- **出处**：模块地图「我的早报 · 兴趣画像」行（"画像是**系统产出，不是用户可改项**，不许列进设置栏"）。
- **是什么（我读到的形状）**：生产链路每天按行为重算一张标签权重表写进设置，读层取前几名给条目加权排序。输入只有两件事——**打开过（已读）** 和 **点了稍后读**；收藏进不了它（文章侧结构上没有那一列）。后台只读展示，**没有任何写入口**（我扫过云端写设置的通路，没有一条放行这个键）。它只改排序、不改收录。
- **为什么**：待你补一句。我能证的是形状与代价（每次批次都会整表覆盖，若界面上能填，用户填的下一次就被算没了 —— 这算不算你的理由，你定）。
- **边界与拒绝**：任何"让用户手填兴趣标签 / 给画像加写入口"的提案先推翻本件。
