# 功能矩阵 · 三端能力覆盖 · 缺口归属 · 工具链口径

> 最后更新：2026-09-30（本表只回答「哪端有什么能力、读数叫什么名字」。**问题与调查过程不在这里写**，去 `docs/ISSUES.md` 与 `docs/features/`；逐轮改了什么由 `docs/STAMPS.md` 自动记）
> **本文档是唯一权威的功能覆盖矩阵**（SSOT），一律**以真实环境逆向推导**：云端能力逐端点实测、本地能力以本地端代码为准，不从其它文档抄。其它文档不再各自维护矩阵，只写"见本文"。
> **✅ 的时效**：各格的实测时点不一样，且中途换过一次库（换库前后的读数不可比）。早于最近一次换库或部署的格**只按形状读**；要拿单格结论当准绳，先按 `docs/DELIVERY_VERIFICATION.md` 复测。逐格复测本轮挂在 `docs/specs/45-doc-validity-adr-split/spec.md` §9。
> 更新规则：任何端点增删改 → 先改本文，再改其它文档。每条功能改动必须云端实测后才允许把矩阵标为 ✅。

## 0. 三端定义（先建立正确脑图）

| 端 | 形态 | 职责 | 存储 |
|---|---|---|---|
| **本地**（`server/`，本机端口） | Express + 本地库驱动，PM2 或手动 | 全功能开发与灾备；**需登录态的采集（抖音）与整库文件备份/恢复只在这里** | 本地库文件 |
| **Vercel**（`api/`，https://qwis-intel.vercel.app） | Serverless 读层 + 管理后台 | 面向用户的阅读与管理界面 | Turso（东京） |
| **GH runner**（`tools/collect-turso.js` + `.github/workflows/collect.yml`） | 按固定节奏的定时任务 | 采集 / 早报（双档）/ 我的早报 / 周刊 / 翻译 / 静态导出物 / 清理，直写 Turso | Turso |

**B 站在 runner 上采，不是本地专属**（09-26 核·代码 + 线上源表）；逐项覆盖以 §1 为准，本表头不作穷举。
runner 依赖面只许纯 JS（ADR-21）；定时取值唯一承载处是作业文件，本表不复制取值。

**数据流**：runner 采集 → Turso ⇄ Vercel 读层 → 浏览器。本地与 Turso 之间**没有运行期同步**——手动迁移工具是一次性动作，不构成同步通道（这是一条边界决策，见 ADR-17）。

## 1. 功能覆盖矩阵（实测为准）

> 每格只回答三件事：**哪端有、缺哪个端点、现读哪里能验**。不写"哪年加的、当时怎么修的"——那些在 git 与 `docs/ISSUES.md`。
> 引用任何一格之前先按 `docs/DELIVERY_VERIFICATION.md` 复测；本表不保留历史读数。

### 1.1 阅读器

| 功能 | 本地 | Vercel | 口径 / 现读法 |
|---|---|---|---|
| 文章列表（时间序 / 筛选 / 搜索 / 游标分页） | ✅ | ✅ | 默认是"今日"滚动窗口；"全部"是检索模式——至少一个筛选条件才发请求。顶部有当日早报摘要卡 |
| 未读口径 | ✅ | ✅ | 只算近三天的未读（更早的自动归档）。数据不变，变的是计数口径 |
| 无感刷新 | ❌ 长连接已废 | ✅ | 固定周期拉增量端点（ADR-06） |
| 详情 / 已读 / 稍后读 / 全部已读 | ✅ | ✅ | "全部已读"与列表用同一套噪声口径；两端必须同判据（ADR-14） |
| 阅读沉淀（我的阅读 / 批量 / 导出） | ✅ | ✅ | 足迹默认排除热榜与聚合噪声；要把热榜放回来得显式带"含热榜"参数 |
| 保存视图 / 分组管理 / 拖拽移动 | ✅ | ✅ | 分组与订阅轴的语义见 `docs/features/source-library-autoclassify.md` |
| 单源手动刷新 | ✅ | ❌ | 云端的等价做法是"标记到期"，由下一轮采集补抓（不是立刻抓） |
| 视频列表（含播客） | ✅ | ✅ | 游标分页；播客作为音频条目并入同一列表 |
| 视频详情 / 收藏 / 播放 | ✅ | ✅ | 直链解析仍是本地专属（Cookie 风控），云端走官方内嵌播放器 |
| 热榜 / 事件榜 | ✅ | ✅ | 精选=自有源达门槛且与 AI 相关，**热榜源不入精选**；事件榜由采集端预聚合、云端直读（链路指南不变量 10） |
| 热榜英文原文抓取 | ✅ | ❌ | 依赖较重、可移植，未排期 |
| 播客音频播放 | ✅ | ✅ | 音频地址的归位由共用的媒体口径决定（不是各端自己兜） |
| 日报中英对照 | — | ✅ | 读层实时回填译文标题，并与原文标题并列显示 |

### 1.2 每日情报

| 功能 | 本地 | Vercel | 口径 / 现读法 |
|---|---|---|---|
| 日报阅读 | ✅ | ✅ | 生成时刻只写在作业文件里，本表不复制 |
| 手动重新生成 | ✅ 会先补抓到期源 | ⚠️ 不补抓、无 AI 增强 | 两端的"重新生成"不是同一件事，比较结果前先确认跑的是哪一端 |
| 日报设置（栏目 / 来源勾选 / 时间） | ✅ | ❌ 缺写端点 | 界面改了不生效的那一类；账在 `docs/ISSUES.md` 设置面那一族 |
| AI 增强（摘要 / 评分 / 标签） | ✅ | ⚠️ 链路已通，功能未齐 | 现状叙述在 `docs/features/daily-report.md` |
| 早报候选层的每源预配额 | ❌ 有意不接 | ✅ | **换的是源覆盖宽度，不是额度**，也不改进报门槛。形状：宽范围读轻量行（不含正文）→ 每源取前 N 篇 → 截断送模型；正文到深析阶段按条单取。取值、上限与"为什么本地不接"见 ADR-09、ADR-14 与链路指南不变量 20；生效与否现读当日早报统计里的配额计数 |

### 1.3 管理后台

后台收敛为五个区：源库（含平台接入）/ 早报中心（含日报设置）/ 热点榜策展 / AI 能力（含翻译）/ 系统（数据 + 监控 + 报警）。每个区顶部有"入口 + 当前生效配置 + 作用对象"的对照卡。

| 区 | 本地 | Vercel | 缺口 / 现读法 |
|---|---|---|---|
| 源库（组合 / 问题源 / 检索三视图 + 四轴批量） | ✅ | ✅ | 四轴的批量动作与组级单条 SQL 见 `docs/features/source-library-autoclassify.md` |
| 平台接入：公众号 RSS | ✅ | ⚠️ | 新增 / 删除 / 单源刷新在云端是 404；OPML 同步、配置备份、队列同步可用 |
| 平台接入：B 站 | ✅ | ✅ | 采集已在 runner 上跑；诊断端点可用 |
| 早报中心（生成历史 / 推送 / 周刊归档 / 画像与配额） | ❌ | ✅ | **周刊归档删除**这个动作此前恒 404，现已可达；"手动生成"目前只是提示文本，不是可执行入口 |
| 周刊归档与当期骨架 | ❌ | ⚠️ | 两道守卫都在共用实现里：**条数不足整期不发布**（保住上一期，只在作业心跳留痕、不进报警）；**骨架缺任一（导语 / 封面主题 / 主线条数不足）就把降级标记写为"是"并附缺件清单**，页面显示"本期骨架不全"。⚠️ "降级提示恒不亮"那句**只适用于我的早报**，周刊已按实现订正——引用时必须点名是哪个域。现读：当期报告的主题 / 封面主题 / 故事线三键与降级标记。语义叙述在 `docs/features/hot-and-weekly.md`，账在 `docs/ISSUES.md`（观察中那条骨架复验 + 归档体积） |
| 热点榜策展 | ✅ | ⚠️ | 富字段回填与补抓的控制缺 |
| AI 能力（配置 / 连通测试 / 对话） | ✅ | ✅ | 写入口径与审计要求见链路指南的 AI 配置一节；挂账 BL9 |
| 翻译 | ✅ | ⚠️ | 提示词只许一份实现（ADR-14）；自动翻译的优先级与"薄正文只按标题处理"的通道见 `docs/features/daily-report.md` |
| 系统 · 数据 | ✅ | ⚠️ | 统计与按天清理可用；**文件型整库备份 / 上传 / 恢复在云端返回 501**，用配置备份替代（内容表靠转储，见 `docs/RUNBOOK.md` §7） |
| 系统 · 报警 | ✅ | ✅ | 配置写、连通测试、清冷却都在云端；触发引擎跑在采集批次尾部 |
| 系统 · 监控 | ✅ | ⚠️ 近似值 | 没有历史队列数据，显示的是"当前状态"的近似，不能当趋势读 |

### 1.5 命令与工具链（命令的唯一清单，别处只写"见 §1.5"）

> **本节只回答三件事**：有哪些命令、各自判什么、怎么取它的读数。**不列实现文件名、不列内部项编号、不复述代码结构** —— 那些是 `tools/` 与 `tests/` 自己的事，写在这里就一定会和它们不一致，而读的人会照这份去改代码。
> **每轮交付的准绳只有一份**（`AGENTS.md` §3）。下面标「按需」的命令是取证工具，不是每轮必过的门；改到它守护的区域时运行。
> **取读数只看它自己**：任何一条命令的结果都不许从别的命令、别的文件或本表里的历史数字推算。想看测试条数与红绿，就跑 `npm test`；想看文档门禁，就跑 `npm run lint:docs`。

| 命令 | 判什么 | 怎么取它的读数 | 定位 |
|---|---|---|---|
| `npm test` | 回归网：线上修过的每个 bug 都有锁钉着 | `npm test > 文件 2>&1` 再取退出码。**不许用管道看结果**（管道的退出码是末端命令的，红色会读成绿色，本仓真读过错）。条数与红数只在复跑那一轮有效 | **每轮门** |
| `node smoke-test.js` | 冒烟：真实数据形态下主要路径能不能跑通，含对抗段（超长/特殊字符/空内容/并发/错误边界） | 在**生产库副本**上跑，零副作用；看它自己的通过/失败汇总 | **每轮门** |
| `npm run build:vercel` | 云端构建面能不能编译出来 | 看构建退出码；产物细节不在本文判 | **每轮门** |
| `npm run lint:docs` | 文档不腐烂：缺头注、悬空引用、未登记、表格破格、明文密钥等 | 只看它自己的输出（报"零错"必须同时报"看了多少条"）。**归档层的头注缺项已豁免判红、只报数** | **每轮门** |
| `node tools/doc-stamp.cjs` | 刷新每份文档的最近改动记录（改动戳由机器写，人不手写、不手写进各文档头部） | 每次改完 `.md`、提交之前跑一次，产物随同提交 | **每轮门** |
| `npm run lint:cites` | 清点每处 `文件:行号` 引用还指不指得对 | **报数给人判，不判红**（红线只有一条，两条抢着判红只会逼人造豁免）。本项目的方向是逐步铲掉这类锚点，所以它是**收尾清点工具**，不是维持清单 | 按需 |
| `npm run eval:preflight` | 环境前置：代理在不在位、线上部署的提交指纹等不等于 `origin/main`、凭据形态、隔离是否成立 | **判红之前先看它**。多数"端到端红"是判据自己的环境问题，不是产品的 | 按需 |
| `npm run eval:e2e` | 端到端：真浏览器打开线上站点，页面呈现 ↔ 页面自己发出的响应对账 | 只有满足"全部剧本 × 每剧本 ≥3 轮 × 真实云端"才算一次验收轮，否则即便全绿也应判**未验收**。口径见 `docs/EVAL_GUIDE.md` §3 | 按需 |
| `npm run eval:whitebox` | 三端一致性：跨端必须同规则的语义是不是只有一份实现、多写入者有没有漏接 | 判据是**归属**不是形状；每项查什么以工具自身输出为准。归属原则见 ADR-14 与 `docs/EVAL_GUIDE.md` §4 | 按需 |
| `npm run eval:f2p` | 「改前必红」取证：新用例必须先证明它能抓这个 bug | 基线要由"这批锁在哪个提交引入"反查，不靠人记 sha。**"基线里没有这个文件"属未跑到，判环境，不许据此删用例** | 按需 |
| `npm run eval:process` | 过程性二值检查：这一轮评测本身可不可信（证据齐不齐、退出码诚不诚实、有没有永远不红的判据） | 产物缺任何一项就等于这轮没做 | 按需 |
| `npm run eval:content` | 内容质量：AI 写的东西人读不读得下去、有没有编 | 五维加权分**只作趋势与复核触发，不作门禁**；阈值与升级规则见 `docs/EVAL_GUIDE.md` §5 | 按需 |
| `npm run eval:strip-selftest` | 判"代码里真写了这句话"的那套词法视图本身对不对（双向自证） | 判据改过时跑；口径见 `docs/EVAL_GUIDE.md` §4 | 按需 |
| `npm run check:retention` | 现在有多少条满足删除谓词、删除闸是什么状态（只读） | 动保留口径之前先看这个比例，**别只看"待删多少条"**（滞后入库的老文会被误判过期） | 按需 |
| `npm run dump:content` / `npm run dump:gate` | 内容级转储与删除前的"有底牌"判据 | 任何删除类改动之前：转储 → 校验 → 判闸；闸不放行就**一条都不许删**。口径见 `docs/RUNBOOK.md` §7 | 按需 |
| `node tools/audit-cloud.js` | 云端只读巡检（页面/接口/鉴权是否可达、慢接口分流是否生效） | 一条 HTTP 响应都没拿到时判**环境红**，不许伪装成"云端全挂"。**它是观察面，不替代云端实测那一步** | 按需 |

**两条长期有效的纪律**（都来自真实翻车，不是偏好）：

1. **一条命令的成败不许借另一条的退出码**。曾有两枚锁因为去读文档门禁的退出码，在门禁非零时直接失去发言权——安全判据静默失声比报错更危险。这条判据缺陷仍在账上（`docs/ISSUES.md`），修法属 `tools/` 与 `tests/` 的改动，按用户 09-28 裁决暂缓。
2. **本轮实测状态**（只在复跑那一轮有效，下轮不符即以新读数改本格）：`npm test` 648 条 / 5 红。5 红的成因与裁决记录在 `docs/specs/45-doc-validity-adr-split/spec.md` §10，不属本轮文档轮的责任，也不作为放行门槛。

## 2. 本表里的缺口对应什么（需求队列的 SSOT 是 `docs/NEXT-DEV-REQS.md`，本节不复制排期）

已完成项**不在本表**（活文档只写现状；要回看哪年做完的走 git）。这里只回答一件事：§1 里每个 ❌/⚠ 是不是有人管、管到哪。

| 缺口（§1 里的格） | 状态 | 去处 |
|---|---|---|
| 云端整库文件备份与恢复 | **永不做**（serverless 文件系统约束，不是待办） | 边界理由见 ADR-02 的那刀与 `docs/adr/` |
| 抖音采集、播放直链解析 | **永不做**（需登录态 / Cookie 风控） | ADR-02 |
| 公众号（wemp）云端采集 | **云端两份实现都显式排除**，本地是唯一能采的一端 | 后果与排查见 `docs/ISSUES.md`；不许写成"云端也有" |
| 单源手动刷新的云端等价 | 已用「标记到期 + runner 下轮补抓」替代 | 端点清单见 `docs/HANDOVER.md` §3 |
| 热榜英文原文抓取 | 在途，卡在依赖体积 | `docs/NEXT-DEV-REQS.md` |
| 全文补抓 / AIHOT 富字段回填 | 在途待移植 | 同上 |
| 设置写通路（部分门槛键没有写入口） | **缺陷**，不是设计 | `docs/ISSUES.md` H41 三型静默失真 |
| 云端手动清理未接删除闸 | **缺口**，与安全方向绑定，未擅定 | `docs/ISSUES.md`（清理闸那一族） |
