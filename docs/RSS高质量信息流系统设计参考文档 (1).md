# RSS 高质量信息流系统设计参考文档

> 场景：1500 个订阅源，日产出 ≥2000 篇文章，依赖无微调、无上下文、无知识库的通用大模型完成评分与摘要。
> 三大核心问题：① 高质量内容如何浮现；② 小源如何不被大源裹挟；③ 如何避免信息茧房。

---

## 一、总体架构原则

1. **先过滤，再排序。** 不将 2000 篇全排序后取前 20；先做零模型额度的预筛（做法见 1.6），再让模型处理筛后的小池子——既避免排序器偏差被放大，也避免宝贵的模型额度浪费在正则表达式就能做的事上。
2. **评分层与分配层正交隔离。** 评分只回答"这篇文章本身好不好"；分配回答"今天该不该推、以什么位置出现"。总分不得染指配额与探索位。
3. **评分管"好"，配额管"全"，探索管"意外"。** 三者互不替代。
4. **双轨制阅读流。** 必读层（每天 10–30 篇）+ 浏览层（按主题聚类扫读，重复报道合并，每事件读 2–3 个视角）。
5. **先跑两周只记录不干预**，看真实阅读分布（哪些源被读、读完率），再调配额参数。规则靠数据迭代，不一次设计到位。

### 1.6 粗筛怎么做：零模型额度预筛层

**总原则：模型额度只花在"非模型判断不了"的地方。** 语义级的信息增量、深度、创新需要模型；去重、合并、配额、结构特征、分组一律用普通代码完成，零 token。预筛阶梯按成本从低到高执行，每一级只处理上一级的幸存者：

| 级别 | 手段 | 成本 | 预期削减 |
| --- | --- | --- | --- |
| 1 | URL 归一化 + 精确去重（同一文章被多源转发，RSS 中大量重复链接） | ≈0 | 5–15% |
| 2 | 近重复合并：SimHash/MinHash 正文指纹，汉明距离达阈值即并为一个"报道簇"，只留最早/最完整的一篇为代表 | ≈0 | 30–50%（削减量最大的一级） |
| 3 | 每源预配额（硬规则）：每源每日最多送 2 篇进后续所有环节，选篇用零成本信号（最新 / 最长 / 标题含主题词） | ≈0 | 省额度最多的一刀：大源 30 篇/日 → 入口压到 ≤2 篇 |
| 4 | 规则过滤：标题党黑名单词（"重磅/震惊/官宣/全网首发"）、PR 通稿结构特征（品牌词频密度异常、"供稿/转载自"、文末联系方式）、语言检测、长度阈值（正文 <200 字、纯图集、视频页） | ≈0 | 10–20% |
| 5 | 主题分组：标题 + 前 200 字对主题组词典匹配，顺带完成拆组（呼应第五部分）；不落入任何组的进"边缘桶"——不送模型、不进日常流，低频人工翻看或作探索位候选 | ≈0 | 边缘文章不消耗日常额度 |

几个要点：

- **合并 ≠ 删除**：第 2 级被合并的通稿在簇内视角对比时仍可选用（立场不同的各留一篇），只是不再各占一个评估名额。
- **预配额是硬规则，不是评分**：选哪 2 篇由规则决定，评分系统此刻尚未启动，不构成"评分染指分配"。小源（日更 ≤2 篇）全额通过，不受影响。
- **量级效果**：五级过完，2000 → ~600–800 篇进入 Pass 1，模型日调用量约为全量处理的 1/3；摘要也只在入流文章上生成，不做全量摘要。
- **架构纪律**：每月拿真实 token 账单核对——预筛层任何一级出现模型调用即违例，那是用美元做正则表达式能做的事。

### 1.7 视频与播客：一套架构、两套参数、三个分叉点

**结论：不需要另一套系统。** 评分、配额、探索、闭环的纪律必须统一——否则媒体流会成为茧房的漏洞：文章层做了多样性治理，媒体层却全是大 V。但媒体与文本在三个点分叉：

**分叉 1：预筛层的"正文"对媒体不可用**

- RSS 对媒体只给元数据（标题、shownotes/简介、时长、enclosure 链接），第 2 级的正文指纹改为 shownotes + 标题指纹；shownotes 为空时退回标题相似度 + 时长 + 源近似度。
- 剪辑号去重：同一访谈被剪成多个视频，标题高相似，按标题相似度合并即可。
- 时长过滤按真实消费偏好设阈值（如 <5 分钟的短片进快速浏览桶，不走完整管线）。

**分叉 2：评分需要转写输入，转写是最贵环节——放配额之后、两段式**

- 媒体管线的成本大头是 ASR 转写，不是 LLM 评分。顺序：媒体预筛（元数据 + 规则，零模型）→ LLM 对 shownotes 跑二元三问（便宜）→ **先转前 5–10 分钟**做 triage → 通过再全量转写 → 六维评分。
- 红线：是否转写的决策不得调用转写——先花小钱判断值不值得花大钱。
- 能白嫖就不 ASR：优先用现成的平台自动字幕、播客 shownotes/时间戳；shownotes 显示无信息增量的条目直接沉底，不进转写。

**分叉 3：媒体是独立槽位，配额比文章更严**

- 消费时长决定媒体每日可消费条数远低于文章：设独立"媒体槽位"，每日入流 1–3 条，与文章必读层（10–30 篇）并行、互不抢位。
- 媒体源每源预配额更严：每日 ≤1–2 条送评估（大媒体源一日多更时）。
- 媒体领域头部集中度比文字更高（视频/播客的马太效应更强），探索位纪律只会有过之无不及：媒体槽位同样固定 15–25% 探索位，不可被挤占。
- 六维向量可复用，但 rubric 与锚点必须为媒体单独准备一套：表达 = 口条/剪辑/每分钟信息密度，深度 = 单位时长信息增量。**文章锚点不可跨媒体使用**——否则模型拿"文笔工整"的标准去评口播，评分系统会在媒体层重新引入口味单一化。

## 二、六维评分体系

### 2.1 维度定义与角色分类

| 维度 | 角色 | 处理方式 |
| --- | --- | --- |
| 表达 | 门槛维度 | 低于下限直接沉底（veto），不做加权救场；**只罚不奖**——过线后 6→9 几乎不加分 |
| 内容（完整性/真实性） | 门槛维度 | 同上；硬伤走二元判断（"是否存在硬伤：是/否"） |
| 选题 | 排序维度 | 加权求和 |
| 深度 | 排序维度 | 加权求和 |
| 创新 | 排序维度 | 加权求和 |
| 实用 | 排序维度 | **内禀属性**：定义为"该文结论/方法可迁移到多少人实际决策的半径"（如 Claude 工程论文），不依赖读者当下任务 |

### 2.2 组合方式：串联门槛 + 加权主体 + 短板惩罚

**禁止纯相加**：

- 掩盖短板（表达 9 分救不了内容 2 分；"全面平庸"赢过"长板突出"）；
- 相关性重复计权——先跑维度相关矩阵，任一对 r > 0.6（大概率是深度×创新、选题×创新）须合并或改几何平均。

**禁止纯并级**：六维全达标的只剩套路化"标准好文"，偏锋内容（表达粗糙但洞察极深）被一票否决——**并级本身制造同质化，多样性最先死**。

**正确公式**：

```javascript
若任一门槛维度 < 下限 → 沉底（veto，非线性，无救场）
否则：总分 = Σ wᵢ·dᵢ − λ·Σ max(0, tᵢ − dᵢ)
      └─ 槽位加权 ─┘   └── 短板惩罚：跌破及格线每低一分额外倒扣 ──┘
```

效果："长板很长、短板及格"的偏锋内容能活；"全面平庸"的内容上不来。

### 2.3 量表与输出规范

- 量表 **1–5 配 rubric 文字描述**（五档一致性远高于十档纯数字）。
- 门槛维度（表达/内容）走**二元判断**，不进量表——二元判断是模型最稳的判断形式。
- **保留六维向量作文章指纹，不压成标量**。标量化后"深度 9 创新 8 实用 2"与"全面 6 分"不可区分，而后面的槽位匹配恰恰需要区分。

## 三、槽位权重模板

四类视角 = 四种消费意图，各有理想文章画像，作为权重模板（运行期由槽位自动选择；人工维护表本身）：

| 槽位 | 选题 | 深度 | 创新 | 实用 | 表达 |
| --- | --- | --- | --- | --- | --- |
| 事件跟进 | 极高 | 中 | 低 | 中 | 中 |
| 领域全景 | 中 | 高 | 中 | 低 | 中 |
| 人物 | 中 | 高 | 中 | 低 | 高 |
| 产品对比 | 低 | 中 | 低 | 极高 | 中 |

文章指纹（归一化六维向量）与槽位画像算匹配度，匹配度 × 短板惩罚后本体分 = 槽位内排序分。**同一指纹在不同槽位得分不同**，避免"深度长文和快讯在同一池子比总分"。

## 四、AI 处理流水线（通用模型，无微调/无上下文/无知识库）

**核心原则：不给模型绝对评分任务，只给相对判断任务；不让它自由校准，用锚点替它校准。**

通用模型最可靠的是"同一上下文内相对比较"，最不可靠的是"跨批次绝对校准"。

### 4.1 完整流程

```javascript
⓪ 预筛层（零模型额度）：五级阶梯，2000 → ~600–800 篇（详见 1.6）
① 聚类：链接共引（引用了相同 URL）+ 实体重叠 + 标题相似度 → 20–50 个主题簇（无需模型）
② Pass 1（模型便宜档，仅处理⓪的幸存者）：二元三问——是否原创信息增量？是否纯复述已知新闻？是否有硬伤？
   → 再砍约一半，剩 ~300–500 篇。降噪主战场在⓪+②（去重合并 + triage），不在评分精细度
③ Pass 2（满配，幸存者）：六维评分——锚点 few-shot + 证据先行 + 1–5 量表 + 二元门槛判断
④ 门槛 veto：表达/内容低于下限 → 沉底（加权之前执行）
⑤ 批内排序 → 分位映射：簇内按各维度排序，名次映射分数（簇内第 1 ≈ 9 分，中位 ≈ 6 分）
   绝对分在⑤才诞生，语义由名次锁定；模型原始输出只用于簇内排序，不进跨批比较
⑥ 槽位匹配：按槽位权重模板加权求和
⑦ 短板惩罚：总分 = Σwᵢdᵢ − λ·Σmax(0, tᵢ − dᵢ)
⑧ 一致性复检：完整跑两遍③–⑦，对【最终总分/簇内名次】做分歧检验
   名次差 > 30% 分位 → 降级桶，不进阅读流
   （分数反复横跳的文章本身是低质信号；复检对象是最终排序而非原始分——非线性变换下中间步骤看着差不多、合成后可能分叉）
⑨ Pass 3（簇级）：模型一次读完整簇 → 主题全景 + 四类视角摘要 + 代表篇推荐 2–3 篇
⑩ 分配层：每源配额 + 探索位（探索位不由⑧⑨的分数填充）
```

### 4.2 Few-shot 锚点（人类判断力的注入点之一）

- 锚点 = **人工挑选的真实文章片段**，写死在提示词中，模型只是应用，**绝不让模型自己生成锚点**（未校准者不能校准他人）。
- 每维度 2–3 个锚点（深度 9 分样例 / 5 分样例 / 2 分样例）。
- **必须包含"表达粗糙但洞察深刻"的工程笔记作为深度高分样例**，否则模型把"深度"学成"文笔复杂"。
- 锚点文件独立维护、版本化管理、**每季度人工重审**。
- 无微调场景下，提示词就是微调——锚点把模型默认口味（工整媒体文风）替换成你的口味。

### 4.3 证据先行，分数后跟

每维度强制三段结构：

1. 先引用文中支撑判断的**原文摘录**；
2. 再基于证据给分（1–5 配 rubric）；
3. 分数与证据不符时以证据为准重评。

收益：分数可审计、可抽查；引用动作强迫模型真的读文章，幻觉分大幅减少。

## 五、分配层（与评分正交）

1. **每源每日入场上限 1–3 篇（hard cap）**：大源优势从"篇数多"变为"必须选它最好的那篇"。（该机制已在预筛层第 3 级前置执行——入口即压到每源 ≤2 篇送模型；此处的 cap 指最终进入阅读流的数量。）
2. **按主题拆组**：1500 源拆成若干组，每组 200–400 源，组内竞争、跨组配额。跨主题比排名无意义（数据库论文 vs 宏观评论），拆开后排序信号更干净。
3. **源先验分只影响组内排序，不决定能否入场**；先验分随时间衰减，旧信任不永续，小源有翻身窗口。
4. **每日固定 ~10% 席位**给"过去 30 天几乎没被读过、但持续产出"的源——对抗马太效应最笨但最有效的办法。
5. **大源内卷稀释治理**：按内容类型打标，"通稿/资讯搬运"类降权，大源也必须靠干货进场。
6. **观点配对**：热点议题强制至少呈现立场相反的各一篇。

## 六、信息茧房的机理与对策

**机理**：评分系统是自锁回路——评分模型从你的阅读历史学"什么是好" → 按分推送 → 你读到的反哺历史。六维越精细，回路拟合越紧，茧房越光滑。**精细评分不是解药，是放大器。**

**茧房不是"订阅少"造成的，是"反馈回路"造成的。** 纯并级评分本身也是同质化器。

**对策**：

- 排序只用"相关性"，把"我感兴趣"与"我认同"拆成两个独立信号；
- **探索配额（explore vs exploit）**：每天/每周阅读流固定 15–25% 探索区——低先验分源、久未触达源、主题边缘文章。这部分不追求命中率，追求方差；连续 miss 可收缩比例，但**永远不能归零**；探索位不由评分填充，否则只是评分系统给自己找的替罪羊；
- **主动订阅"对抗性源"**：大概率不同意但论证认真的源，给稳定入场配额，永不沉底到看不见；
- **枯竭信号自检**：必读层某主题连续两周都是已知结论的复述 → 该注入异质源了；
- 定期看入流文章的源分布与六维分分布：分布越集中（都 7 分上下），说明评分器在收敛同质化，需注入画像完全不同的源打断。

## 七、闭环：三个不可自动化的人工入口

| 周期 | 动作 | 作用 |
| --- | --- | --- |
| 每日 | 探索位（无评分通道，比例固定不可挤占） | 方差来源 |
| 每月 | 逆向抽查 ~20 条被杀内容（文章 + 媒体，分别看 Pass 1 误杀率与评分误杀率）+ token/转写账单核对（预筛层零模型、转写两段式） | 校准回路，没有它一切自动化都是开环 |
| 每季度 | 锚点样例 + 四张权重表人工重审 | 人类判断力注入 |

另：上线前**先跑两周只记录不干预**，再定配额参数。

## 八、关键纪律清单（Checklist）

- [ ] 维度相关矩阵已跑，r > 0.6 的维度对已合并或几何化
- [ ] 门槛维度（表达/内容）只罚不奖，二元判断，低于下限直接沉底
- [ ] 量表 1–5 配 rubric，非 1–10 裸数字
- [ ] 六维向量保留为指纹，未压成标量
- [ ] 锚点为人工挑选的真实片段（含"粗糙但深刻"样例），版本化，季度重审
- [ ] 评分为证据先行、分数后跟，可审计
- [ ] 批内排序→分位映射在加权之前；模型原始分不进跨批比较
- [ ] 一致性复检针对最终总分，两遍分歧 > 30% 分位进降级桶
- [ ] 每源每日 1–3 篇入场 cap；1500 源按主题拆组（每组 200–400）
- [ ] 探索位 15–25%，无评分通道，永不为零
- [ ] 每日 10% 席位给"30 天未被读但持续产出"的源
- [ ] 热点议题观点配对（正反各一）
- [ ] 每月逆向抽查、每季度锚点/权重表重审
- [ ] 总分不用于决定配额与探索位（评分层/分配层隔离）
- [ ] 预筛五级阶梯全部零模型调用（去重 / 指纹合并 / 每源预配额 / 规则过滤 / 主题分组）
- [ ] 每源预配额（每日 ≤2 篇送模型）为硬规则，选篇用规则不用评分
- [ ] 摘要只为入流文章生成，不做全量摘要
- [ ] 媒体走独立槽位：每日 1–3 条，与文章池互不抢位
- [ ] 转写两段式（先转前 5–10 分钟），"是否转写"的决策不花 ASR；优先用现成字幕/shownotes
- [ ] 媒体六维 rubric 与锚点单独准备，不套用文章锚点
- [ ] 媒体槽位探索位 15–25%，不因头部集中而缩水

## 九、一句话收束

**模型负责流水线中"算"的部分（聚类后 triage、六维评分、簇内排序、全景摘要），人负责"判"的部分（锚点、权重表、配额参数、三个回路入口）。前者全自动化，后者一个都不能自动化——这正是系统不会退化为信息茧房的原因。**
