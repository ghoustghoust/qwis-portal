## 0. 系统定位（一切设计的前提）

- **个人专属情报系统**。部署云端的目的 = 挂机自动采集 + 随时随地为自己服务，**不是多用户产品**。
- **前后台必须分割**：前台（阅读器/日报/热榜）是阅读界面；后台（管理台）是我的私人控制台。当前任何人知道网址就能读前台内容（GET 公开），写操作虽有 JWT，但"每个人都能改我的设置"的担忧需要重新审视权限模型。
- 前后台功能归属目前存在摇摆（"拆过去拆过来"），需要一次从使用者视角的系统性梳理。

## 1. 功能补齐：云端必须能用（全部上线）

以下功能本地有、云端缺，要求全部迁移到云端可用：

| 功能 | 现状 | 目标 |
|---|---|---|
| 源写操作（新增/删除/刷新/批量/自动分类/分组管理） | 云端只读 | 云端全可用 |
| 设置写（PUT /api/settings、日报设置） | 云端 404 | 云端可保存 |
| AI 翻译/摘要 | 云端无 | 云端可用（见 §3 约束） |
| 报警（写配置 + 触发引擎） | 云端只读、无引擎 | 云端有完整报警能力 |
| 视频详情/收藏、热榜原文、AIHOT enrich | 云端无 | 云端可用（播放直链除外，架构限制） |
| 源管理器 | 概念存在 | 能对源做完整处理（启停/分组/关注/修复） |

## 2. 报警系统升级（今天事故的直接教训）

**今天的实证**：本地报警引擎对 6 个 YouTube 源发出"熔断暂停"报警，随后安静——不是修好了，是**源被熔断后不再抓取、也就不再报警（拔电源式安静）**。且这些报警本身是**误报**（YouTube 反爬假 404/500，源是活的）。

需求：
1. **云端要有独立的检测与报警能力**（不依赖本地开机）：源出错、采集停滞、B站登录过期、日报失败 → 推送到钉钉/Bark 等渠道。
2. **报警准确性**：区分"反爬封锁（可自愈）"与"源真死"，避免误报轰炸。
3. **报警不沉默**：源被熔断属于"需要人工处置"状态，要有"已熔断待处理"的汇总提醒，而不是熔断即安静。
4. **报警文案可诊断**：不能只写"HTTP 404"，要给出最可能的原因和处置建议（如"YouTube 反爬，下一轮换 IP 自动重试"）。
5. **AI 链路失败也要报警**：翻译失败、Agnes 不可达等。

## 3. AI 体系（核心资产）

### 3.1 供应商策略
- **Agnes 免费，必须用起来**；但其约束要在架构里写死：**不支持思考模式、不支持并发、有限流** → 所有 AI 调用串行 + 限速 + 失败重试 + 失败报警。
- 备用：谷歌/Bing 翻译（效果差，仅兜底）。
- **术语对照库**：翻译前注入专业术语表（知识库），保证领域词汇一致。参考 [BestBlogs](https://github.com/ginobefun/BestBlogs) 的翻译与摘要思路。
- **增量翻译**：建立翻译缓存，只译新增内容，绝不全量重译。

### 3.2 AI 在日报中的角色（不只是翻译）
每日情报由 AI 生成，每篇入选条目要有：
- **推荐理由**（为什么这篇被推荐上来）
- **精选摘要、金句、关键观点**
- **权重判断：6 个维度**（具体维度待与用户确认细化）

### 3.3 日报节奏
- **凌晨 00:00 后开始处理**（AI 批处理昨天的内容，耗时长没关系）
- **早上 09:00 展示**：昨天 24h 信息的汇总 + AI 处理结果
- （现状：runner 09:03 生成、窗口为昨天 00:00~今天 06:00、纯关键词无 AI——需调整为 AI 版）

## 4. 信息源自选 + 推荐算法（防信息茧房）

1. **源自选**：现有 180+ 源（实际 638+ 含各类型），用户自选订阅子集接收推送，未选的不进主流。
2. **源管理器**：能对源做完整处理。
3. **推荐算法**（重点，要专门设计）：
   - 大信息（重大事件）不漏；
   - 小的关键信息不被淹没；
   - 即使用户只选了部分源，也要让他接触到未选源的重要内容（现有「破茧栏」是这个思路的雏形，需强化）；
   - 目标：自定义过滤的同时不形成新的信息茧房。
4. 可参考 BestBlogs 项目的文档思路。**（2026-09-11 已完成调研：`docs/BESTBLOGS_BORROW.md`——两阶段过滤/六节点分析管线/三段式翻译/可解释推荐/漂移检测等 10 项范式已映射进总 spec）**

## 已确认决策（2026-09-11 用户拍板）

1. **前台权限**：保持公开只读（GET 公开，写操作 JWT）。后台才是私人控制台。
2. **日报窗口**：自然日整（昨天 00:00 ~ 今天 00:00），凌晨开始 AI 批处理，早 09:00 呈现。
3. **AI 六维度权重**（用户亲自定，原文）：**选题 / 内容 / 深度 / 实用 / 创新 / 表达**。
4. **防茧房形式**：双管齐下——破茧栏强化（每天强制曝光未选源重要事件）**+** 主流按比例插入「探索位」。
