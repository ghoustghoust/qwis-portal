# 调度引擎

> ⚠️ 适用范围：本文描述本地 Express（server/）实现。云端对应物：采集 tools/collect-turso.js、API api/[...slug].js；差异与云端覆盖见 docs/FEATURE_MATRIX.md。**云端各档点位唯一事实源是作业文件**；本地调度器的各间隔/时刻取值读实现——本文一个都不复制。
> 补注：门户同步目标已随门户项目删除而失效，且**默认不注册**（要设置显式开启才挂上，开了也不会产出可用结果）。
> 承载实现：`server/services/scheduler/`
> 最后更新：2026-10-03（收敛轮：去实现化——删调用链/频率值/方法清单，门户四处重复收成一句）

## 设计目标

- **due 驱动**：定时扫描到期源（启用且到期时间已过），入队任务队列异步消费；队列关闭时回退串行抓（开关与取值读实现，队列语义见 `task-queue.md`）
- **防重入**：扫描有 ticking 守卫；调度器与日报 job **共用同一把锁**（共享对象引用，不是两把）
- **崩了能爬起来**：启动先做队列崩溃恢复；服务启动晚于日报定时点会自动补生成当天日报
- **可重排**：设置变更后清旧重建全部定时器，不用重启进程
- **门户同步默认关**：见头部补注

## Job 模块职责

| 模块 | 职责 | 触发方式 |
|------|------|---------|
| daily.js | 日报定时生成 + 日报前补抓 | node-cron（默认 08:00，**本地调度器专属**，与云端各档无关） |
| fulltext.js | 全文补抓（薄内容） | 周期 cron |
| opml.js | OPML 源清单同步 | 周期定时 |
| maintenance.js | 数据清理 + 报警清理 + 健康自检 | 各自独立的周期定时 |
| 门户同步 | （历史：向已下线的只读门户搬静态导出物） | **默认关闭**，需显式开设置 |
| recovery.js | 中断的 bilibili/douyin pending 恢复 | 启动时一次性 |

各间隔的具体取值读实现；本表只回答"谁管什么、大概多久一类"。

## 注意事项

1. **ticking 守卫是共享对象引用**，scheduler 和 daily job 必须共用同一把——各造一把等于没有守卫
2. **抖音串行限速**在适配器抓取内部实现，不在调度层（见 `collectors.md`）
3. **健康自检启动后要过一段静默期才生效**（取值读实现），避免启动期间误报
4. **队列开关** `QUEUE_ENABLED=false` 时走串行回退，不经任务队列
