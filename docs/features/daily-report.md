## 一、这个模块给用户什么

一个"今天该看的 46 条"。用户在早报页看到的是：期号、生成时刻、**档位标签**（这份是 AI 策展版还是关键词裸排版）、统计条（候选多少、公众号多少、视频多少、实际入报多少、窗口多长）、**主题全景卡**（把散在多源的同件事并成一张卡：主题名 + 视角 + 几家源 + 一句跨源综述）、有时还有开头一句**导语**。右上角有「重新生成」，可以直接重出一份。

## 二、用户改了设置之后，数据怎么走

以最常见的四个设置为例（都在管理后台早报设置里，**改完不是立刻变，要等下一个批次读到**）：

| 用户改的东西 | 写到哪里 | 谁在什么时候读它 | 最后看到的结果 |
|---|---|---|---|
| 统计窗口（24h / 自然日） | 配置存储的早报设置项 | runner 生成下一期时读 | 早报页顶部的窗口标注变化，入报条数随之变化 |
| 每源最多取几篇（配额，1~100） | 配置存储的预筛配额项 | 生成时的"取候选"这一步 | 覆盖面变化：配额越小、覆盖到的源越多 |
| 初筛剔除门槛（分数） | 配置存储的 AI 初筛阈值 | 初筛打分之后决定丢不丢 | 入报条数与"剔除数"变化。⚠️ 这个键目前**后台改不动**（见 H28） |
| AI 通道（密钥、模型、接口地址） | 配置存储的 AI 段（部分只能走环境变量） | 每一次 AI 调用 | 有 AI 才可能出档位 2、出导语与主题全景；改坏则整批降级为关键词版 |

**一条主流程**（一次生成从上到下经过的步骤，只列步骤与产物，不列内部实现）：

1. **取宽候选**：按时间窗取一批"轻量行"（标题/来源/摘要这类不含正文的列），池子有上限（取值读实现）。刻意不在这一步取正文——正文列是存储与读取成本的大头。
2. **每源配额**：每个源只留前 N 篇（N 可配，默认值读实现），保证少数刷屏源不能把整期占满。
3. **截断送模型**：按分数取前若干条进入 AI 环节（上限读实现）。
4. **初筛**：逐条问模型"这条值不值得看"。**只给标题、来源、摘要，不给正文**。失败或掏不出答案时按"宁多勿漏"放行（记一次失败）。
5. **深析**：对通过者逐条打分并要摘要/要点/金句/标签。**正文在这一步才按条单独取**（这是刻意的成本设计，也有专门的"取正文取空了"计数）。
6. **门槛与入栏**：按分数与栏目规则分栏、限流、出库安检（乱码标题与风控错误页不得入报）。
7. **主题全景与导语**：把标题相近的条目并簇，够格的簇（有最少条数门槛，取值读实现）按总分取前几个交给模型起名并写跨源综述；另发一次请求要一句导语。
8. **落库**：写一条日报记录，统计读数与栏目内容分别存两段。
9. **读层交付**：读者请求早报时，**优先给 AI 档**（按档位选，不是按"最新时间"选），响应形状见 `docs/contracts/daily-report.json`。

**定时与耗时**：各批点位以 `.github/workflows/collect.yml` 为唯一事实源（本文不复制）。三段（初筛/深析/媒体）的用时分开落库，三段上限与作业超时**必须自洽——任一被单独抬大都会把另一段挤掉**（有锁钉这个关系）；上限取值读实现与作业文件。

## 三、这一期到底筛没筛：现在能回答到什么程度

以前最常被问也最答不上来的三件事，现在都有读数（都存在每条日报的统计段里，可直读生产库）：

| 想问的 | 现在的读数 | 能不能回答 |
|---|---|---|
| 这一期一共尝试筛了多少条、筛掉多少 | 尝试数 / 通过数 / 剔除数 | ✅ 能。此前只有"通过"和"失败"两数，而失败是**放行**的，两数会重复计，"筛了多少"从库里算不出来 |
| 时间花在哪一段 | 初筛分钟 / 深析分钟 / 媒体分钟 + 两个预算上限 | ✅ 能，且要求"三段之和 ≤ 总耗时"（对不上就是计时器套错位置） |
| AI 调用失败了，是**哪一种**失败 | 失败总数 + 按九类分布的归因（推理模型只吐思考没吐正文 / 超时 / 限流 429 / 服务端 5xx / 客户端 4xx / 连不上 / 答了但掏不出 JSON / 没配密钥 / 认不出） | ✅ 本轮刚补。**这一条决定了该抬参数还是该换模型**——只有总数时拍不了 |
| 主题全景为什么是空的 | 聚出多少簇 / 够格命名的几簇 / 实际发起命名几簇 / 成功入库几簇 + 六个丢弃出口各自计数（整批候选太少、标题切不出词属于聚类前；调用失败、没吐 JSON、缺字段、解析抛属于命名环节） | ✅ 本轮刚补。以前只有一句"0 个主题"，看起来像"标题聚不到一起"，实际可能是命名环节整簇被丢掉 |
| 导语为什么没有 | 五种原因之一（模型没答 / 答了但每行都像污染元文本 / 挑出的那句被否决 / 调用抛错 / 未标注） | ✅ 能区分 |

**当下的真实状态（不要美化）**：导语缺位是常态、主题簇多数期为 0、初筛失败率偶发越过报警线——具体读数现读统计段（读之前先换尺子，见下节）。修法（重试、抬输出长度上限、换模型）都还**等你拍**，见 H33；这一期是否"筛得偏松"目前只有管理端报警知道，**前台读者看不出**。

## 三b、读这些读数时必须换三把尺子（H30 的教训）

同一句「多少期没有导语」，用三种分母算出来的答案完全不同，**历史上每次争论都是各自用了不同尺子**：

| 尺子 | 分母是什么 | 适合回答 |
|---|---|---|
| 按「期」 | 库里每一行 | 生成器这一发成没成 |
| 按「北京日」 | 同一天可能有多期，取当天最该给读者那一份 | 这一天有没有出过 |
| 按「读者实得」 | 读层实际会交付的那一份（按档位优先挑） | 用户到底看到没看到 |

**还有一条范围限定，别把读数当成全系统都接上了**：导语与主题的归因目前**只接在早报的 AI 档生成处**；
周刊与个人早报走的是另外的写入器，它们同样可能"静默没有"，但**库里没有原因码**。所以「导语 94% 缺失」这类数字
只在早报 AI 档这个范围内成立，不能外推成"整个系统的 AI 增强都不工作"。

## 四、与其它模块的接口（只记契约）

| 我要做什么 | 调它的什么 | 输入 | 输出 | 失败怎么办 |
|---|---|---|---|---|
| 拿一批候选 | 内容库读取 | 时间窗、需要的列（不含正文） | 轻量行列表 | 空列表 → 本期候选为 0，仍会落一条记录（可分辨"没内容"与"没跑"） |
| 判断一条值不值得看 | AI 通道·初筛 | 标题、来源、分类、摘要（限长读实现） | 分数 + 是否剔除 + 一句理由 | 放行并计一次失败，失败按九类归因；失败率超线发管理端报警 |
| 给一条内容打分写摘要 | AI 通道·深析 | 上述 + 按条取到的正文 | 六维分、总分、摘要、要点、金句、标签 | 连败到阈值则**整期降级为关键词版**（档位变 1；阈值读实现）；正文取空仍会打分并单独计数 |
| 起主题名并写跨源综述 | AI 通道·主题 | 同簇若干条的标题与摘要片段 | 主题名 + 视角 + 综述 | 逐簇跳过并计数，不阻断出报 |
| 要一句导语 | AI 通道·导语 | 入选列表 | 一句话或空 | 记原因码；不阻断出报 |
| 发异常提醒 | 报警通道 | 异常摘要文本（含失败率与前三类原因） | 无 | 发送失败不阻断主流程；只发管理端，不上前台 |
| 交付给读者 | 只读层 | 档位偏好、分页游标 | 一条日报（统计段 + 栏目段） | 库里没有当期时可即时生成一份**关键词裸报**顶上，响应里带档位，读者不会拿到空白页 |

## 五、子模块一览

- **候选与配额**：宽池读取、每源配额、送模型条数上限（这三者的取值口径在 `docs/FEATURE_MATRIX.md` 与 `docs/ISSUES.md` 的 H27-补 / H30 里，不在这里复制）。
- **初筛与深析**：失败放行策略、九类归因、按条取正文的成本设计。
- **主题全景与导语**：并簇→命名→综述；缺失时的原因码。
- **档位与读层选档**：两档共存时必须按档位优先，不能按"最新生成时间"。
- **落库形状**：同一档内不同写入器的扩展键并不完全相同，消费侧必须按"可能缺失"处理（唯一共有的是档位、候选数、文章数、栏目、总数这几个）。

## 六、已知会咬人的地方

1. **耗时读数有历史脏数据**：9-24 之前落库的"耗时分钟"是真实值的 1/10，旧行不重写——跨期比较要先排除。
2. **"0"经常是两种意思**：筛掉 0 条与初筛根本没工作过、主题为 0 与"聚不到簇"，在补上这些读数之前**数据上同形**。这就是上面那张读数表存在的理由。
3. **报警是否真送达目前没有证据**：作业日志接口在本机链路上持续取不到，报警渠道也没有只读查询口。
4. **本地端的同名日报功能不在部署面上**（本地专属），不要把本地行为当成线上行为来读。
