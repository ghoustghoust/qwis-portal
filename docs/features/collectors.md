# 采集层架构

> ⚠️ 适用范围：**采集语义全库有三份实现**——本地端 `server/services/collectors/`、云端读层的即时采集 `api/collect.js`、
> 主链路 runner `tools/collect-turso.js`（AGENTS §1：改任何一份的过滤/清洗/熔断/去重/UA/间隔，必须同步检查另外两份）。
> 本文写"怎么算"，**不复制易变数字，也不复述代码结构**——目录树、函数名、建表语句读仓库，本文只留语义与规矩。
> 最后更新：2026-10-03（收敛轮：去实现化——删调用链/签名块/表结构复述；youtube 别名身份写明）

## 设计目标

- **适配器模式**：6 种平台适配器（RSS/B站/抖音/热榜/微信/X）统一契约；YouTube 以独立 `type='youtube'` 存储、复用 RSS 适配器（别名登记），不单设适配器
- **职责分离**：原单体 store.js 按职责拆成一组高内聚模块
- **并发安全**：同源互斥锁，防止 tick/手动刷新/日报补抓并发冲突
- **向后兼容**：老 import 路径（store.js 的兼容 re-export）不变，新代码用精确模块

## 适配器契约（语义）

每个适配器**必须**提供三件：平台唯一标识（type）、URL 识别（给一个串判断是不是本平台）、按源拉内容（返回文章/视频两类产物）。**可选**提供：订阅源字段解析、默认刷新间隔、能力声明（文章/视频/全文补抓）、全文补抓、内容清洗。注册时校验必填项，缺了直接抛错——不带病上线。

## 核心流程（语义）

- **一次抓取**：拿同源互斥锁 → 找到适配器抓取 → 文章与视频分别落库 → 条件请求标记（ETag/Last-Modified）与时间字段写回 → 聚合类源再触发一次缺失字段的补抓。
- **同源互斥**：同一个源同时只允许一个抓取在跑；后来的调用直接跳过并标记 in-flight，**不排队**——排队会让"手动点刷新"看起来像卡死。
- **源错误状态机**：失败计数 +1、错误文本（脱敏）落 extra；计数达到**该类型的熔断阈值**就自动停用——阈值全库一份在 `lib/source-breaker.js`（视频类放宽，理由见坑 #29），不在本文写死。计数达到**报警计数点**则触发报警（异步、不阻塞批次）——计数点在 runner 与本地各自的采集实现里（两份，改要对齐），语义见 `events-alerts.md` 的升级阶梯。解冻 = 恢复启用 + 清计数 + 清最近错误，**保留**间隔与校验标记。

### 刷新间隔怎么算

**改频率立刻生效**：任何写频率的端点都在同一次写入里带上新到期时间（设值按新间隔重算，置 null 顶成立即到期由采集端写回真实值——判据全库一份在 `lib/source-axes.js`）。

优先级**不是**一条直线，且**按类型分岔**（这是 09-25 订正的旧错：本文原先写"RSS 兜底 8h"，实际差着 16 倍）：

1. 源级覆盖 `extra.intervalMin` —— 最高，单源可钉。
2. 全局配置 `settings.intervals[...]`。
3. **文字类那一族（rss / wechat / x / youtube）到此为止**：它们共用一个"文章刷新间隔"键，
   没配就用默认值（真值读实现，云端与本地是否同源见 `FEATURE_MATRIX.md` §1.4）——
   **这一族不查适配器默认值**，所以"改了适配器默认间隔想影响 RSS 源"是无效的。
4. **B站/抖音**：查适配器默认值，再不行才落各自的兜底数。
5. 其余（热榜/未知类型）：适配器默认 → 回落到文章族那个间隔。

## 注意事项

1. **`pending_items` 是"搬进来的待办"表，不是文章表**：它**没有源归属列（source_id）、也没有 created_at**——时间只有导入时刻（imported_at）；要按源归属得先解析出 url 再落 articles，想当然按文章表查它会查空
2. **异步回调内的 DB 操作必须 try/catch**，prepare 抛错可崩进程
3. **better-sqlite3 不支持编号参数 `?1`**，一律用匿名 `?`
4. **抖音串行限速**：fetch 内部经队列严格串行（间隔取值读实现），防平台按并发指纹封禁（坑 #6）
5. **ETag 304 短路**：RSS 适配器支持条件请求，notModified 时不更新数据
6. **字数一律取纯文本那一列，不许用正文源码长度**：正文里嵌着标记与图片地址，拿它算字数会**虚高几十倍**。前端优先取纯文本列，落库时也钉住了两者的大小关系。要改字数口径先读这两处，别只改一头
