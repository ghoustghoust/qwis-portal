# 事件聚合与报警

> ⚠️ 适用范围：**聚合参数的权威在共用实现 `lib/hot-events.js`**（部署面用它）；本地端 `server/services/` 下另有一份同逻辑实现，
> 报警侧本地与部署面（runner + `api/`）共用配置存储。本文只写"改了什么会看见什么"，不复制易变数字（AGENTS §2.5）。
> 最后更新：2026-10-03（收敛轮：去掉与"不列清单/不写死"自相矛盾的枚举与计数，坑引改指账本）

## 设计目标

- **事件聚合**：把近几天的全域条目跨平台聚成"事件"，供热点榜与探索位使用
- **纯函数共用**：与日报共用同一套标题归一化/相似度算法，避免两条链路算出不同结果
- **多渠道报警 + 防骚扰**：按"事件 + 源"冷却去重，失败计数到点才升级成熔断报警

## 事件聚合引擎

### 核心参数（**不在本文写死值**）

| 参数 | 干什么用 | 真值在哪 |
|------|---------|------|
| 聚合窗口 | 只采样这段时间内的条目 | `lib/hot-events.js`（注释里记着"窗口不能长，否则热榜事件那条 SQL 在云端超时"——这是 09-16 的实测教训，别随手加宽） |
| 热度半衰期 | 越早的条目权重越低 | 同上 |
| 相似度阈值 | 标题像到什么程度算同一事件 | 同上（比日报去重略宽，因为跨平台标题差异大） |
| 结果缓存时长 | 多久重算一次 | 本地实现各自一份 |

### 热度与状态标（语义，不是数值定义）

- 热度 = 条目自身权重（评分贡献很小，主要是"有没有被读过/精选"）× 时间衰减 × **参与源数量的加成**——多源同时报同一件事，热度明显抬升。
- 状态标（新 / 爆 / 发酵中 / 收尾）由"首发距今 + 最新距今 + 参与源数"三件事判定；具体小时数门槛看实现，本文不复制。

### 聚类流程

```
取窗口内的全域条目
  └ 贪心聚类：标题相似度达到阈值就并成一簇（阈值见上一节指针，不在此复制）
      └ 每簇产出：代表标题、参与源、成员条目、热度、首末时间
          └ 标状态（新 / 爆 / 发酵中 / 收尾）
```

⚠️ 窗口与阈值**不许在本文写死**：它们决定云端那次查询要扫多少行——窗口加长在 Turso 上是成本动作，不只是"看得更全"。

## 报警引擎

### 有哪些报警事件（09-25 按实现订正）

事件清单**全库只有一份**：声明在 `lib/alert-events.js`（含每个事件的默认开关与文案）。
本文原先只列 4 项、还列了一个**不存在**的 `system_error`，并把停滞事件的键名写错了一版——
这就是"文档自己造名字"会让后来者踩的雷，现改为**照能力读，不照本文抄名字**。

事件按能力分三组（类的总数与逐个开关以 `lib/alert-events.js` 为准，不在本文数）：

| 组 | 覆盖什么 | 触发时机（自然语言） |
|---|---|---|
| 源侧 | 单源抓取失败 / 单源被熔断停用 / 单源耗时过长 | 连续失败到计数点才报；熔断=达到该类型的熔断阈值；耗时=单次超过慢阈值 |
| 链路侧 | 采集停滞 / 一批源同时被冻结（系统性形态汇总） / 日报生成失败 | 停滞=一个窗口内 0 次成功刷新；冻结盘点=一次批里冻结数成串 |
| 产物侧 | AI 调用失败 / 「我的早报」定时推送 | AI 失败=摘要、翻译、周刊等任一 AI 出口报错 |

**报警是否真送达仍未证实**（见 `docs/ISSUES.md` H35 行）：作业日志接口取不到、报警渠道没有只读口，所以"已补归因"不等于"人已收到"。

### 报警渠道

配置形状：一组渠道（各自必填字段不同）+ 一个全局冷却时长。渠道类型与必填项以发送实现为准（本文不列清单）。

⚠️ **"配了渠道"不等于"有出口"**：全库有一份共用判据在判断某个回调地址是不是真能发出去的公网地址
（回环、内网、链路本地、元数据面、`test-/demo-` 这类占位 id 全部判否）。
这份判据存在的原因是它曾被真实坑过一次：检查器把"指向本机的哨兵地址"算成可用渠道，于是"报警链路没有出口"这种 P0 在门禁里显示绿灯。

**这一句现在成不成立，只能现读**：读生产配置里的渠道形状（不打印任何地址与密钥）→ 把每条回调地址喂给上面那份真出口判据 → 再看最近投递记录里有没有成功项。三步缺一步就不许说"报警发得出去"，也不许说"发不出去"——这是一次读数，不是常置状态。接哪条渠道、由谁填真地址 = 待你拍（账在 `docs/ISSUES.md` H35；接渠道是一次生产写）。

⚠️ **旧库里那份渠道配置曾是哨兵值**（本机回环那一类地址），而现役库当年是从本地灾备副本迁过来的、恰好带上了真渠道。所以"链路现在通"不是"旧库被修好"的证据：**任何"从旧库迁 settings"的动作都会把哨兵带回现役库**，而症状恰好是"渠道数量对、配置看着齐，但一条都发不出去"。同族教训：别把换库副产物或绕过当修好（账与三步判法见 `docs/ISSUES.md` H52）。
要堵这条路需要一条判"渠道回调不是哨兵"的白盒锁——**目前没有任何锁钉住它**，只能靠手工 preflight 发现（缺口登记在 `docs/ISSUES.md`）。

### 冷却机制（09-25 订正一处会误判的陈述）

- 冷却键 = 「事件 + 源」组合，同组合在一个冷却窗口内不重复发送。
- ⚠️ **冷却记录不是纯内存**：原文写"存储在内存 Map，重启即清空"——**错**。实际落在配置存储的
  `settings['alerts.cooldowns']`，内存只是缓存。**后果差别很大**：按旧陈述会以为重启能重置冷却、
  或以为换进程就没历史；排查"为什么没报警"时方向就错了。
- 因此**清冷却要两处一起清**（配置存储 + 内存缓存），实现里已写明这条注意事项。
- 已知缺陷（H24，未修）：`ai_failed` 用的是**单一全局冷却位**，不同子因互相吞掉告警、且不落正文。

### 升级阶梯

失败计数往上走：**首档不报 → 到计数点报"源失败" → 达到该类型熔断阈值时停用该源并报"源已熔断"**。
熔断阈值全库一份在 `lib/source-breaker.js`（视频类放宽、文字类更严）；**报警计数点不在那里面**——它在 runner 与本地端各自的采集实现里（两份，改动必须对齐）。两者都不在本文写死。

## 接口契约（其它模块怎么调它）

| 想要什么 | 输入 | 输出 | 失败怎么办 |
|---|---|---|---|
| 热点事件列表（跨源聚成"事件"） | 无参（内部按窗口取全域近期条目并缓存） | 事件数组：标题、参与源、成员条目、热度、首末时间、状态 | 聚合失败 → 返回上一份缓存/空列表，**不影响文章流** |
| 报一条源侧异常 | 源对象 +（失败次数、错误文本） | 无返回语义（发不发由冷却与开关决定） | 渠道全失败 → 记日志并**直连重试一次**，不抛出到调用方 |
| 报采集停滞 | 停滞的源清单 | 同上 | 同上 |
| 报 AI / 日报 / 周刊失败 | 失败摘要 | 同上 | 同上（⚠️ 冷却是全局位，见 H24） |

聚类的窗口长度、相似度阈值、缓存时长：**真值一份在 `lib/hot-events.js`**；
本地端 `server/services/events.js` 是**另一份实现**（未合并），改云端那侧参数时要记得两处会漂。

## 纯函数共用

事件聚合与日报共用同一套"标题归一化 + 分词 + 相似度"纯函数（`server/services/ai/_tokens.js`），
这样"两条链路算出来的相似度"才会一致——事件侧不许再依赖日报模块。

## 注意事项

1. **批量刷新静默**：refresh-all / opml 路径 `opts.silent=true`，逐源报警被跳过，由调用方结尾汇总
2. **代理失败直连重试**：报警发送走代理失败时，自动直连重试一次
3. **异步触发**：报警通过 setImmediate 异步触发，不阻塞调度主流程
4. **脱敏**：报警内容经 `log.mask()` 处理，Token/Cookie/API Key 不泄露
