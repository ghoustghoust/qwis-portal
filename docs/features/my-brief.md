# 我的早报 · 从勾选订阅到页面上那一份报

> 模块地图里「我的早报」那几行的承载文档。日报那一条链写在 `daily-report.md`，本文只写**个性化这一层**：选择集怎么定、批次什么时候跑、哪些设置真生效、缺东西的时候为什么不吭声。
> 一句话先说清部署面：**这一域只在生产链路里有实现，Vercel 读层只读产物，本地端整个不存在。**

## 一、选择集：哪批源进你的早报

判定只有一份实现（三端共用，ADR-14），规则是：

```
订阅集合键里有一串 id
   → 用之前先按"源还活着"过滤（只留启用的）
   → 过滤后还剩东西 → 就用它
   → 三种落空形态一律兜底：键缺失 / 空数组 / 声明的 id 全部指向已删或已停用的源 → 退到"重点标记"那批启用源
```

- **粒度只有源**。分组不参与筛选：界面上"把整组加入订阅"在点下去那一刻就被摊平成一串源 id 写进键里，**之后改组名、移组成员都不会回灌早报**。
- **策展决定只有一个入口：早报中心**。订阅、重点、栏内配额、探索强度都在那里改；源库那几根轴只做**状态展示与批量调整**，它写的是同一批键，但不承担"今天早报长什么样"的决定。这条职责线是刻意划的：两处都能改 → 两处都会漂，而"为什么我的早报变了"就要在两个界面之间来回猜。
- 第三种落空形态（悬空 id）不是理论问题：自家回归测试在生产库里留过一个不存在的源 id，把线上整个页面打死过。
- 判空有**两道独立的门**：生成侧取不到源就写一份"引导态"进产物键；读层返回前还会**当场重算一次**选择集。所以"库里那份报是旧集合生成的"与"今天按新集合已无源"是两件事，只有两边都空才回"你没订阅"。

## 二、什么时候生成：它没有自己的定时点位

日常出报**搭在每日早报那一批 AI 作业的尾部**，零额外深析——先复用当天已经深析过的订阅源条目，不够才补析一小批（补析有上限）。所以：**每日早报跑几趟，我的早报就出几趟**；早报那一批不跑，这里也不会有新内容。

另有一个"重生成"入口，只能人工触发。它和主批**不是同一个口径**，这是这一域最容易踩空的三条：

| 差异 | 主批（定时） | 人工重生成 |
|---|---|---|
| 取数窗口 | 晚间那趟是**滚动 24 小时** | 走**北京自然日**窗口（不带滚动参数），但日期标签仍写今天——同一个"今天"两边取到的内容可以不同 |
| 探索位 | 从当天共享深析池里补 | **必然 0 条**：它没有深析池可复用。想单独验证探索位，用这个入口是验不出来的 |
| 归档期号 | 同一北京日重跑**原地替换**，不新增一期 | 同 |

## 三、产物落在哪，以及一个会丢历史的决定

- 当期落在一个"最新"键里（整份覆盖），历史落在一个归档数组里（封顶若干期）。
- ⚠️ **空态也会覆盖"最新"那份**：某天判空，就把昨天那份有货的顶掉了，读者当天看到的是空态而不是"上一期仍可读"。周刊走的是另一种口径（不达条数不发布、保住上一期）。这个差异是现状，不是笔误——要改属于产品决定。
- 版面切成三段（头条 / 精选 / 补充阅读），各有固定条数上限；补充阅读那一段的总数恒定，是**订阅余量与探索位互相对切**（见第四节）。视频与播客单列一段、**不经 AI 直接列**，且只按"源启用"筛，**不限订阅源**（这一段的口径和其余三段不一样，别当成同一批候选）。各段条数现读生成器。

## 四、界面上那三个设置：谁真生效、生效到什么程度

| 设置 | 真被读吗 | 它到底改什么 | 界面看不全的地方 |
|---|---|---|---|
| 推送开关 | 是 | 只决定"要不要发"，见第六节 | —— |
| 探索强度 | 是 | 决定补充阅读里**几条来自未订阅源**（三档换算成固定条数，非法值回中档）；总条数恒定，是**订阅余量与探索位互相对切** | 头条与精选结构上不可能出现探索条目，探索只发生在补充阅读那一段 |
| Domain 配额 | 是 | 按条目的**主标签**（第一个标签）计数，超配额就**移出**——它改的是收录不是排序 | 界面只为画像前若干个标签渲染输入框；为它们之外的标签存过的配额**看不见但照样生效**。配额砍空 → 本期直接写"今天没有新内容" |

两条补充口径：没有标签或没被评分的条目**不受配额管**；配额判定发生在判空**之前**。

探索位的选法：候选 = 当天深析池里**非订阅源**、且分数过一道写死门槛的条目，再用标题相似度做一轮多样性挑选（避免十条说的是一回事）。

⚠️ 这道"分数门槛 + 按分数排"的实现与 **ADR-24** 的期望相反——那条决策明写探索位不该由评分填充。这笔账挂在需求队列 T3-7 第三节，属待修；**别把现在的实现读成"反茧房已经做到"**。

## 五、兴趣画像：系统产出，不是可改项

- 每批生成开始时**整表重算并覆盖**：只看「已读 + 稍后读」两种行为（回看窗口、聚合取前几名都是实现里的常数，本文不复制），按标签聚合成权重表入库。
- **只改排序、不改收录**：命中标签的条目加分上浮，有封顶；谁能不能进报由订阅、窗口和深析成败决定，画像碰不到。为什么不做成可配项见 ADR-23——每批都被重算覆盖，人工填了下一批就没了，那是"改了不生效还骗你一次"。
- 界面上它是**只读**的（后台那张卡只展示，标出真正参与加权的前几名）。
- 一句需要说准的话：**文章侧没有独立的"收藏"列**，阅读器、热点榜、快速学习弹窗上那颗"收藏"按钮写的就是"稍后读"那一列，所以它照样进画像；真正进不了画像的是**视频的收藏**，以及已读/稍后读之外的一切交互。
- 有一条反馈环是**知情接受的代价**，不是待修缺陷（ADR-16）：点一条探索条目 → 它算你已读 → 那个标签进画像 → 下一批让同标签的订阅源条目上浮。

## 六、推送：那个开关不等于"发给飞书"

- 配置里那个开关只写在一个设置对象里；真发的时候走的是**通用报警分发**，会发给**所有启用的渠道**，不是界面上写的那种单一渠道。
- 有**第二道闸**：报警的事件表里这一项也可以整体关掉——勾着推送开关同样一条不发。
- ⚠️ **被跳过的时候什么都不留**。以下四种早退都不写报警日志、不写审计、不打日志：事件被关、没有可用渠道、在冷却窗口内、被静默规则命中。而生成侧既不看返回值也吞掉异常。后果是：**主批之后不久做一次人工重生成，第二次推送必然静默不发**，事后从日志和库里都查不到这件事。
- 只有"真的对某个渠道发起过投递"的失败才留痕；"是否送达"另有一份判据（见 `docs/features/events-alerts.md`），别用"发出过"当"收到了"。

## 七、导语与主题全景：缺了为什么不吭声

- 导语和主题全景的依据**只取订阅池那批条目**——探索条目对导语、关键词行、主题全景三者都没有影响，只出现在补充阅读版面里。
- **归因没接到这一域**。日报那条写入器会在缺席时把"为什么没导语 / 少了几簇"落进库；我的早报走的是只返回一个字符串的老接口，原因只存在于作业日志，库里没有。所以"这期为什么没有全景"在数据上问不出答案（账在 `docs/ISSUES.md`）。
- 一个簇要进库得连过**六道不留痕的出口**：聚类前两道（批次太小、标题切不出词），命名环节四道（模型没答、没返回可解析结构、答案不完整、解析失败）——**命名失败就丢掉整簇**，哪怕那簇已经聚好了。更糟的是"聚出四簇只命名成功一簇"这种**部分丢失既不入库也不打日志**。
- ⚠️ **降级标记是写死的"否"**：前端有一条"今日为降级版"的提示，结构上永远取不到真值；而且这一域**根本没有**"AI 不可用就回退关键词策展"这条路径，那句文案连语义都不成立。比没有提示更糟的是假安全感——这条已记为现役缺陷。

## 八、读层与页面：哪些状态读者分得出来

- 端点回三种形态：有报 / 没订阅 / 当天判空（判空带一句人话）。
- ⚠️ **读者页把"当天生成但判空"和"从来没生成过"压成同一句文案**——只有后台的历史视图能区分。
- ⚠️ **没有新鲜度守卫**：这一层的产物键没有年龄判断，三天前那份今天照样当"今日早报"给出去；页头只显示日期，不显示生成时刻。所以"今天没生成"经常不呈为空态，而呈为一份旧报。
- 译文标题由读层实时回填，但**只覆盖三段文字版面，媒体那一段不在内**——播客条目换新译标题后，当期页面上仍是旧标题。
- 有一条断了的通路要知道：从我的早报页的快速学习弹窗里点"收藏"**打不到后端**（请求要的目标标识在这份产物的条目结构里根本没有）。因此"从这一页产生的行为会回流进画像"这句里，真实成立的只有"点开条目算已读"这一条。

## 九、本地端：整个域不存在

本地端没有这一域的生成器、端点与页面路由；它只参与"选择集"这一件事——能改订阅轴、能建出那个键，**但本地没有任何东西消费它**。

一个必须知道的连带后果：对着本地端提交这一域的配置，会**回成功而一个字都没写**（它的写入口没有接住这一段的分支）。这就是 `docs/features/settings-plane.md` 第二节那一行的实例。

## 十、不能做什么（改这一域之前必读）

- **探索位不许改写订阅集合**，也不许为了"更懂用户"把画像接进探索选取——边界与理由见 ADR-16，只管这一层，别向其它两级类推。
- **兴趣画像不作可改项**：不给它任何写入口，界面上不许做成可编辑控件（ADR-23）。要改它的输入面属于**改算法**，得另立决策并重读 ADR-16 的反馈环。
- **这一域的语义只许一份实现**：选择集解析、期号与发布守卫、报警事件表都在共用层（ADR-14）。在某一端"顺手再写一份"是这个项目反复出事的形状。
- **不许把"页面没提示"读成"没有降级"**，也不许把"当天判空"和"没生成"混读成同一件事；引用任何"缺位比例"之前先声明用的是哪把尺子（期 / 北京日 / 读者实得，见 `daily-report.md`）。
- **不要用人工重生成入口去验探索位或窗口口径**（第二节表里那两条差异会让读数骗人）。

## 十一、怎么验（现读法）

- 选择集到底有没有兜底：现读那个订阅键（缺 / 空 / 全部指向已停用源），再看一次端点返回的空态标识是哪一种。
- 当期到底是谁生成的：现读产物的生成时刻与作业心跳对表——**"有报"不等于"定时跑的"**，这一域的定时点位寄生在日报那一批上。
- 三个设置有没有生效：改值之后**等一次真实批次**，再现读当期条目构成（探索条数、被配额移出的条目日志），别看界面回显。
- 推送有没有出去：读报警日志与审计，**注意被跳过时那四处都不落痕**（第六节）——查不到记录不等于没发生过。
- 缺导语 / 缺主题全景：这一层库里没有原因码，只能读当期产物里那两个字段是否为空 + 作业日志；要可归因属待接线的活（`docs/ISSUES.md`）。
