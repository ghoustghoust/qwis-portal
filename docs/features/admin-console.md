# 管理后台 · 板块边界与职责线（后台域总规格）

> 模块地图里「管理后台」各行的承载文档，也是开发标准 §8（板块归属纪律）的落点：**界面缺陷一律挂后台域**，链路/数据模型域只拥有链路与数据模型，不得在两个域各立一份界面规格。
> 本文只写**已定型的板块边界、职责线与准入规则**；各板块的功能叶子与排期在 `docs/NEXT-DEV-REQS.md`（SSOT），逐板块小规格批准后落地，本文不复制。
> 后台是单用户运维面（ADR-11 不做多用户），一切设计判断以"一个操作者每天进来要回答什么、要做什么"为准。
> 最后更新：2026-10-04（板块边界初稿：五分区、三条准入规则、自愈与日志形状，均经用户拍板）

---

## 一、第一性：进后台是在回答五个问题

| 问题 | 对应分区 |
|---|---|
| 今天健康吗？ | 首页 |
| 喂进来的东西（源）怎么样了？ | 源 |
| 产出去的东西（报）怎么样了、怎么改？ | 报 |
| 花钱的部分（AI）跑在什么上、消耗多少？ | AI |
| 机器本身（报警/日志/监控/数据）出事了吗？ | 系统 |

每个板块、每张卡、每个控件都必须能指回其中一个问题；指不回来的，不进界面。

## 二、信息架构：左栏一级分区

所有板块放页面最左侧（用户标注原文），一级分区五块：

| 分区 | 职责线 | 收编什么 | 明确不管什么 |
|---|---|---|---|
| **首页** | 回答"今天怎么样" | 健康概览、源抓取成功率、报警时间线、生成历史（近 7 天成败/降级/耗时）。每张卡带口径标签且可跳转到对应板块——首屏不止两张卡，但**首页不承载操作**，操作在目标板块 | 不做任何写操作 |
| **源** | 喂进来的东西：库、接入、存活 | 源库三视图与四轴批量、平台接入、熔断与自愈状态、**热点榜策展（降级为源板块下的一个视图，用户 10-04 拍板，不再单独成区）** | 不管报的生成设置（那是"报"的） |
| **报** | 产出去的东西：三报各自的设置与历史 | 每日早报 / 我的早报 / 周刊**各自独立的设置页** + 各自生成历史与归档。不再挤成一长块 | 不管源本身的状态 |
| **AI** | 花钱的部分：供应商、模型、用量、各管线开关 | 供应商下拉可切、官方 API 自动列模型、模型旁延迟红黄绿、各 AI 环节（初筛/深析/翻译/导语）的可见控制。写入口径与审计按链路指南 AI 配置一节（BL9） | 不暴露机器自写键的输入框 |
| **系统** | 机器本身 | **报警、日志、监控三块各自独立**（用户标注原文"各归各"）、数据治理（清理/转储/库体积）、运维入口 | 不收业务配置 |

## 三、三条准入规则（治"没功能还摆着"的根源）

1. **设置项准入**：按 `settings-plane.md` 第五节的键三类判——只有"人可配且有写口"的键给输入框；"代码在读、没有写点"的要么开写口要么不显示（不许摆一个改了不生效的格子）；"机器自写、人只读"的只做只读展示并给生效证据（兴趣画像即样本，ADR-23）。
2. **功能准入**：每个控件在板块小规格里必须写清——**改了它，下一个批次或哪个读数会变**。写不出这句话的不上界面。提示一律收进功能名旁的圆圈问号悬浮，不在功能没做时预摆 tips 段。
3. **数字准入**：同屏每个数字带口径标签（哪个库、哪把尺子、窗口多长）；同屏数不出口径的多个"源数量"必然被读成矛盾（现读法见 `docs/ISSUES.md` H36）。

## 四、自愈的形状：批次尾部自动步骤，不做队列面板（用户 10-04 拍板）

- 源自愈是**采集批次尾部的自动步骤**（与报警引擎同位），不是常驻任务队列——runner 是批次模型，无编排平台（ADR-19）、依赖面纯 JS（ADR-21），常驻队列与系统形状冲突。
- 行为要素：退避按错误类别分级、解冻前先探活、判为解析器缺陷的一律不熔断（那是我们的 bug，锁源等于藏问题）、系统性故障先过坑 #39 三闸门再谈赦免。
- 界面呈现：源板块里的"自动恢复记录 + 当前退避状态"，**不出现"任务队列"面板**。
- 本地端补自动恢复属纯增量，不动云端语义（见优化方向 2）。

## 五、日志板块的形状

云端没有可持久化的文件系统，五类日志（作业 / 源熔断 / 服务器错误 / 部署失败 / 数据层失败）的落点只能是：**库内事件与心跳表 + 跳转 Actions 运行日志**。设计时必须一并定两件事：

- **保留窗口**：心跳保留时长是"上周跑没跑过"这类问题的天花板（H34）——日志板块落地时同步定窗口。
- **丢轮可见性**：一周只有一根 cron 的作业，丢轮必须在日志里可判（周刊触发门落地后由认领键与产物时刻承担，见 `hot-and-weekly.md` §八）。

## 六、实现约束（动代码前必读）

- 新增云端写端点 = 一次改齐三处（分发表 / 鉴权白名单 / 消费方）且必须真打线上（ADR-04）。
- 云端写路径只标记不等待，真执行在批次侧（ADR-35）。
- AI 配置写入口径：保留可写 + 审计 + 告警 + 写后探测失败即回滚（BL9），主设置端点对 AI 段继续拒写。
- 需登录态的平台不进云端（ADR-02）；整库文件备份恢复在云端是 501，用配置备份替代。
- 设置键的写通道规则与坏值回落见 `settings-plane.md`——**不许在某一端另起一套"什么算合法键"的判定**。

## 七、推进节奏

1. 总规格（本文）已立：板块边界与职责线经用户拍板。
2. 逐板块出小规格 → 逐板块批准 → **一板块一批**动代码；板块边界没定之前不开功能点（§8 纪律）。
3. **早报中心（T3-2）是第一个按新规格建的板块**：三报上前台后后台没有对应管理页，是当前后台侧最大缺口——它按"报"分区的形状新建，不先建旧版再拆。
4. 其余板块（源 / AI / 系统 / 首页）在新规格下逐个搬迁，搬迁批次与"行为与数据语义稳定"的次序由排期件定，本文不排期。
