# 部署面 · 一次推送与一趟批次各自经过哪些判定

> 模块地图里「推送与构建」「定时与补跑」这类行的语义承载处。**运维动作的顺序住 `docs/RUNBOOK.md`，不可破坏的不变量清单住 `docs/CLOUD_PIPELINE_GUIDE.md`，本文只写"一条链上的判定形状 + 什么会静默不发生 + 谁对什么负责"。**
> 所有取值（cron 点位、每批条数、保留天数、上限常数）的唯一事实源是作业文件与代码，本文一个都不复制。

## 一、触发：两档换可靠性，但门有三种写法

云端定时只有 GitHub Actions 这一处（ADR-18），可靠性用**两档触发**去换：仓库自带的定时 + 一个仓库之外的 HTTP 触发器（它定时调用手动触发接口）。两档各按自己的可靠性跑，**不声明谁主力谁备份**（ADR-13）。

每个作业的门是三种写法之一：只看定时事件里的串是否等于本作业声明的那条、只看手动触发选的档位、或两者并联。由此产生三条今天仍然指挥判断的后果：

1. **不带档位的手动触发只兑现采集那一步**。靠"点一下 Run workflow"补跑日报/周刊/清理，结构性做不到——要么选对应档位，要么那一档只认定时。
2. **档位清单与作业清单不全等**：有一档只能人工触发（没有定时线），另有几档只认定时（手动选项里根本没有它们）→ "我想现在补跑清理"这件事没有入口。
3. **一次定时投递只携带一条串**，而门按"串等值"判——实测发生过事件被归属到另一条串上：该跑的全跳过、只有一个不该在那个时刻跑的跑了，而那次运行显示成功、没有任何报警。这条判据不可信本身就是账（`docs/ISSUES.md` 定时投递那条），修法候选也在那条里。

⇒ 想知道"某一档现在还剩几档在跑"，**现读作业文件**；想知道"这一档上次跑没跑"，见第四节。

## 二、一趟批次内部：主流程、副件，以及被吞掉的那些

- 每个模式开跑前都先补一轮库结构兜底（缺列、缺索引就建，失败全部吞掉）。原因是读层与生产链路谁先启动不确定，谁先跑谁补。
- 主流程之外挂着一串**副件**：事件预聚合、评分补齐、阅读小结、画像重算、推送、报警、心跳。它们**绝大多数包在"吞异常"里**——于是两个方向的误判都要防：
  - **批次绿不等于副件成功**（"不阻断 / 已隔离"字样的那一族）；
  - 个别副件反而能**把整档打死**：它的抛出点在心跳之前，所以表现为"这档红了，而且心跳里根本没有这一档"。
- **影响退出码的只有主流程**；且只有那四个产出报告的模式在抛错时发报警。**采集、清理、翻译抛错时一条报警都不发**。
- 收尾刻意不强行终止进程（会撞上运行时的关闭断言），但**失败路径也必须在退出前留下"待删量"那条读数**——批次失败时更要留。

## 三、一次采集里数据流向上的判定（顺序即因果）

```
到期判定（只取启用的、且到点的，有每批上限）
  → 同一故障转移组只采主源（备源本轮跳过，省重复抓取）；主源失败才顺序试备源
  → 指向本机的源在 runner 上直接跳过、不计失败（防把结构上不可达的源判成坏源）
  → 落库用"地址唯一 + 忽略重复"（⇒ 重复投递不会产生两份）
  → 逐源失败计数，过阈值才冻结；判为系统性故障时本轮不熔断不计数
  → 尾部副件事，先问"是否处在报告生成的保护窗内"（在窗内就主动让路）
```

最后那一格的读数是 `skipped` 而不是失败——**"跑空"是设计行为**，别当故障查。

单源级失败全部被隔离：一次代理故障不该把几百个活源集体关进牢房（这条判据是事故换来的，坑库有登记）。

## 四、"这一批到底跑没跑"：心跳这把尺子的三条边界

判据是生产链路每批写入的一把心跳键。它有三个必须知道的形状：

1. **所有档位共用一把键**：顶层永远是"最近一次任意档"，会被下一档整体覆盖；能回看的历史是一个**追加式定长数组**（瘦身过——原始失败明细内嵌整行源数据，不裁会把这把键撑爆）。
2. **上限是条数、不是时间** ⇒ 回看跨度由**写得最快的那档**决定，低频档的记录会被高频档挤出去。代码注释里那句"约相当于多少天"与实现频率不自洽，**不要按它推算**；由此产生的真实缺口是"任何'上周跑没跑过'现在都答不了"（账在 `docs/ISSUES.md`，加长留否是个待决项）。
3. **有一档不写心跳** ⇒ "看心跳里有没有那个 mode"这条判据对它**结构性失效**，只能改读它自己产物的生成时刻。

通用设置读写接口拿不到这把键（它在保留键清单里）；有两个健康类端点读它，管理台的监控折线用的是其中一个。

## 五、幂等：产物层有，触发层没有

| 动作 | 重跑会产出两份吗 | 靠什么 |
|---|---|---|
| 采集 | 不会 | 地址唯一 + 忽略重复插入 |
| 每日早报（裸版与 AI 版） | **会**——写入器是纯追加，既无期号也无认领键 | 只能靠**读层按档位择优**遮着（AI 档优先于"更新的裸报告"）；期号是**读时算出来的**，不是存下来的 |
| 我的早报 | 不会 | 期号 + 同一自然日原地替换；空态不占期号 |
| 精选周刊 | 不会 | 期号按**内容窗口**定；同一窗口补跑=替换 |
| 清理 | 无副作用 | 幂等来自"按谓词删除" |

两点结论：**"跑过就跳过"的那道认领键目前不存在**（它只活在待拍修法提案里），补跑一律真跑、真花 AI 调用与配额；周刊的"同一窗口"判据意味着**换一天补跑会多出一期**，不是重出同一期。

## 六、推送与构建：三道门互不绑定

```
git push main ─┬─→ 平台读 Git 集成 → 构建（跑仓库里那条构建命令）→ 上线
               └─→ push-CI → 只跑测试与文档门禁
```

- **CI 红不挡部署**：仓库里没有任何把两者绑起来的配置（不产出制品、不调平台接口、不是任何环境的必需检查）。"CI 必须绿"是**人的交付链纪律**，不是平台的门。
- **前端产物不进仓库**，由平台构建；本地跑那条构建命令只为"云端编得出来吗"，它顺带把仓库里已入库的静态数据拷进产物目录——所以那条命令依赖工作树里有那份数据目录。
- **两套依赖面不对称**：CI 用较新的 node 且正常装依赖；runner 用另一档 node 且**不跑编译脚本**（runner 依赖面只许纯 JS，ADR-21）。后果是"CI 绿"既不证明 runner 装得上，也不证明前端编得出来；runner 依赖装不上时**不是少一个功能，而是整条数据链静默无数据**。
- **线上是不是最新，只有一个指纹**：那个元数据端点回传的提交号必须等于 `origin/main`。push 的输出、CI 的绿、部署列表里有新记录，都不能替代它（历史上出现过"CI 绿但线上停在几十分钟前那一份"）。
- 静态导出物那一档会**回写仓库**（自动提交产物），于是它自己再触发一次部署；冲突时重试若干次仍失败就退出，**只留作业日志，没有报警**。

## 七、凭据在部署面：出现 ≠ 消费，三处同步不完整

- 作业文件里一律是平台密文引用，没有内嵌值。但要注意两件事：
  1. **同一作业内不同步骤的环境变量是独立的挂载面**——新增任何要调模型的动作，先确认它所在那一步挂了密钥；日志里出现"未配置密钥"时先查这里的挂载面，不是查代码。
  2. 有一个密钥名在作业里被声明却**没有任何步骤消费**（它是给读层的备份端点用的）。别按"文件里出现 = 这条链在用"读。
- **"本地 / 平台环境变量 / 仓库密文"三处同步这句话不完整**：还有第四处持有方——**仓库之外那个定时触发器内嵌的凭据**。漏改它的表现是触发器静默连跪、而链路上没有任何报错（本项目为此整链停摆过）。它的标识与管理密钥只登记在本地那份凭据速查件（`docs/HANDOVER.md`，永不提交），本文不复制任何值；轮换清单见 ADR-12。

## 八、删除闸：为什么"库只涨不删"是设计缺口的必然结果

清理这条链要"证据"才肯删，证据有两条腿：

| 腿 | 成立条件 | 在 runner 上 |
|---|---|---|
| 本地盘上有一份校验全过的内容转储 | 磁盘上找得到清单与分片 | **结构性永不成立**（作业跑在临时文件系统，转储是本地盘产物且不进仓库） |
| 库里有一张人工签发的转储凭证 | 由人在本地跑一次转储命令写入，有有效期 | 唯一实际生效的那条腿 |

于是：**人的那一次动作一旦断供超过凭证有效期，清理就必然进入"每天照跑、一条都不删"**，而今天**被挡与当日根本没跑到这两件事都没有报警**（账在 `docs/ISSUES.md`，含两条待接报警与续期路径二选一）。

其余口径：待删量的**计数与删除共用同一条谓词**（所以"看着会删多少"与"真删多少"是一回事）；被挡时的读数（闸状态 + 待删量）落在配置表里，**管理台没有这个读数的出口**；云端手动清理那条路走凭证腿，不过闸就返回 409 并留审计行。

## 九、这一层的"看起来在跑"清单（判错方向最贵的一类）

1. 定时投递归属到别的串 → **整趟运行显示成功、其余步骤全 skipped**（第一节 3）。
2. 不带档位的手动触发 → 只有采集在跑，你以为补了日报。
3. 保护窗内的让路 → 心跳/日志里是 `skipped`，不是失败。
4. 副件被吞 → 批次绿，但事件缓存/画像/推送里某一件没做。
5. 读层返回旧缓存 + 陈旧标记，**而前端不消费那个标记**（页面永远看不出新不新）。
6. 上一期的报告顶着"本期"的名号被给出（周刊与我的早报**都没有新鲜度守卫**）。
7. 静态导出物每天生成、每天回写 commit，**而读层与前端都没有取用方**——它是导出物，不是兜底路径（ADR-05），别把它当"链路还活着"的证据。
8. 托管库配额封锁时**零部署**：代码没动、平台没更新，恰恰是这种时候必须主动测线上。
9. CI 绿 ≠ 云端被测过：依赖生产凭据的用例在 CI 里按标记跳过。

## 十、不能做什么

- **不许复制取值**：cron 点位、作业清单、每批上限、保留天数，一律"见作业文件/见代码"。抄一次就多一处会漂的副本（这条已经在文档里破过例，见 `docs/ISSUES.md`）。
- **不许把人去点一次 Run workflow 当验收步骤**（交付链里的验收按档位与心跳读数判）。
- **不许声明两档触发谁主力谁备份**（ADR-13）。
- **不许把静态导出物写成降级兜底**（ADR-05）。
- **不许在 Vercel 侧加平台定时**（ADR-18，写过、从未生效）。
- **不许在 runner 引入需要编译的依赖**（ADR-21）。
- **不许在某一端另写一份"能不能删/删哪些"的谓词**：保留与删除只许一份共用实现（ADR-14），云端手动那条路自带的第二张表清单是已知违反项（账在 `docs/ISSUES.md`）。

## 十一、怎么验（现读法）

| 想知道 | 读哪里 |
|---|---|
| 某一档现在有没有定时入口 | 作业文件的门与档位选项 |
| 这一档上次跑没跑、跑成什么 | 心跳历史里该 mode 的条目；**不写心跳那一档改读它的产物生成时刻** |
| 线上是不是这一版 | 元数据端点回传的提交号 == `origin/main`，再逐 sha 回读检查结论 |
| 批次是真跑还是让路 | 心跳里的 stats（区分成功 / `skipped` / 被挡） |
| 清理有没有真删 | 待删量读数 + 闸状态 + 心跳里的实删行数三个数一起看（**别看单一布尔**） |
| 前端能不能编出来 | 本地跑那条构建命令的退出码（CI 不覆盖它） |
