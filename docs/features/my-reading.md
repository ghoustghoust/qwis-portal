# 我的阅读 · 决策与流向

> 最后更新：2026-09-25
> 本文件是**一个决策**：「我的阅读」按什么口径认定"我读过、我留着、我交互过"，以及这些认定会喂给谁。
> 内部按**用户改什么 → 数据经过哪些步骤 → 最后产生什么结果**展开；边界与禁止写在它们所属的那一步上。
> 不写接口形状、入参出参、返回字段、页面文案——那些由代码自己说。未裁决的在 `docs/DOC_VALIDITY_LEDGER.md`。

## 01 这个决策定的是什么

把"我读过的 / 稍后读的 / 收藏的"并成一个可回顾、可批量收拾的沉淀面，并且**让这个面干净到能被下游当作用户偏好使用**。

第二条是本模块存在的真正理由：足迹不只是给人看的列表，它同时是**个人版早报行为画像的输入源**。所以下游一旦要拿"我读过什么"做推断，这个口径就必须可靠——这是后面所有规则的来源。

## 02 用户改什么（输入面）

| 用户动作 | 这一动作的语义 | 不可逆吗 |
|---|---|---|
| 在阅读器打开一篇文章 | 产生"已读"时间戳 | **是**，反向操作会真删它（见 03 第 4 步） |
| 点"稍后读" | 打一个可反复的标记 | 否 |
| 收藏一条视频 | 打收藏标记（**只有视频有这一列**） | 否 |
| 批量取消稍后读 / 移除已读 | 反向清理 | 「移除已读」不可逆 |
| 浏览时选"全部 / 稍后读 / 已读"、选内容形态、搜索 | 只读，不改数据 | —— |

**边界**：本模块**没有任何配置项**。用户在这里能做的事全是行为，不是设置；"每页多少条"这类东西界面和接口都不给（见 05）。
**禁止**：禁止把本模块产出的东西（足迹、画像）列进"用户可改项"——那是最容易长出假开关的地方。

## 03 数据经过哪些步骤

### 第 1 步 · 判定这条内容是什么形态

文章 / 播客 / 视频三类，由**全库唯一一份判定**给出，本地端、云端读层、生产链路都从它取。

- **为什么只许一份**：09-19 之前这四处各手写一遍，三处漂移。最重一次是"文章"那一族漏了公众号类型，同一批数据两端算出的文章数**差 869 条**——列表与计数对不上，且不报错。这类偏差只在数据里显形，靠读代码读不出来。
- **播客没有独立源类型**，只能靠"封面是音频外壳"这个特征认——是权宜口径，正式方案随 09-23 那批 spec 一起作废了，别指望它变精确。
- **禁止**：在任何消费点重新手写一次判定；用注释写"与某处同口径"（注释不会被继承，只有能被机器验证的引用才算）。

### 第 2 步 · 排除噪声

默认把**热榜类与聚合类**条目从足迹里剔掉，要它们回来必须显式要求。口径由用户 09-21 批准（B107/B134）。

- **为什么**：热榜条目天天重复出现。计入足迹后，"我读过什么"实际记录的是"平台推了几次"，不是我的行为——第 01 节那条下游理由会直接崩掉。
- **边界**：只管足迹面；榜单页照常显示热榜内容，那是另一个消费点。
- **禁止**：下游想要"干净足迹"时各自重写一遍排除条件（回到第 1 步的病）；用这个开关去控制与足迹无关的查询。

### 第 3 步 · 两张表并成一个视图

文章与视频分别落在两张表，取回时并成统一形状给前端一套卡片。两表字段不通用，由此两个口径必须分开读：

- **视频"交互过"** = 收藏过 **或** 观看过（二者之一）。只认收藏会让这一档恒空——线上收藏常年为 0，入口藏得深。
- **文章"读过"** = 已读时间戳 **或** 稍后读。
- **「已读」这一档对视频恒为空是设计如此**，不是 bug：视频没有"读"这个动作。
- 观看时间戳目前**只有本地端写回**，云端那一半是准备动作，当下不改变任何可见行为。
- **禁止**：用视频侧的"交互"定义去解释文章侧（文章表没有收藏那一列，这种解释结构上不成立）；反过来用文章口径把视频从交互档里剔掉。

### 第 4 步 · 同一份过滤条件同时供列表与计数

取列表和取计数**必须走同一份判定**。

- **为什么**：真出现过"列表有行、计数显示 0"的自相矛盾页面——两边各自决定要不要排除热榜。
- **禁止**：新增筛选轴时只改列表不改计数；把排除开关只在一侧传。

### 第 5 步 · 痕迹喂给下游

已读与稍后读会被**个人版早报的行为画像**读取（权重不同、按固定时间窗滚动重算）。

- **由此得出的硬约束**：「移除已读」是**真删时间戳**，不是打标记屏蔽。用户点它时通常以为"只是从列表消失"，实际是在删自己的偏好证据，且没有回收站。界面提示必须挨着按钮，不藏在帮助里；这个动作**不许做成默认行为或批量预选项**。
- **画像侧的口径**：画像只认已读与稍后读，**收藏不进**（收藏列只长在视频表上，文章侧结构上不可能）；画像**只由生产链路写、后台只读**，用户改不了，要改只能改自己的阅读行为并等下一批。
- **禁止**：为界面完整而暴露一个写入端不存在的画像编辑口。

## 04 最后产生什么结果（用户看到什么）

- 沉淀页三个视图档（全部 / 稍后读 / 已读）各自计数，内容与本模块判定的口径一致。
- 可以导出成 Markdown 回顾，可以批量收拾。
- **看不到"配置"这一栏，也不该看到**：这个模块没有可调项，它的行为完全由用户行为塑造。
- 想让个人版早报更贴合自己：靠多读、多标稍后读，改完要等下一批生成才算，且**只影响排序，不影响哪些条目进池**。

## 05 边界之外 · 已知不成立的东西

写出来，防止有人去找不存在的东西：

- **「每页条数」参数不存在**：条数写死在两端各一份，传了也不报错。要改接口先读台账 H31，别以为是自己的请求没生效。
- **本模块不是本地专属**：列表 / 批量 / 导出三个端点云端都已上线。早期文档写成"本地才有"是错的，别照它做部署假设。
- 收藏该不该进画像：**未决**。现状是进不了——文章侧结构上没有收藏列。
- 本地端设置保存会静默假成功（与我的早报同族）：**代码缺陷，未修**——认不出的键照样回"成功"。
