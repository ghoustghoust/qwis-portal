## 设计目标

- **阅读沉淀**：把"我读过的 / 稍后读的 / 收藏的"并成一个可回顾的列表，不再散在阅读器里
- **三档视图**：全部 / 稍后读 / 已读，各档独立计数
- **按内容形态筛**：文章 / 播客 / 视频
- **批量收拾 + 导出**：取消稍后读、取消收藏、抹掉已读痕迹；导出成 Markdown

## 用户在页面上改什么 → 数据怎么走

| 用户动作 | 写到哪 | 谁读它 | 什么时候看见结果 |
|---|---|---|---|
| 打开阅读器某篇（产生"已读"） | 文章的阅读时间戳 | 本页列表与计数、"我的早报"的行为画像 | 立刻（本页刷新） |
| 点"稍后读" | 文章的稍后读标记 | 同上 | 立刻 |
| 收藏一条视频 | 视频表的收藏标记 | 本页"视频"档 | 立刻 |
| 批量取消 / 移除已读 | 同上（反向） | 同上 | 立刻；**移除已读不可撤销**（痕迹一没，行为画像就少一条） |

## 接口清单（列表 / 批量 / 导出）

列表入参：**视图档**（全部/稍后读/已读）、**内容形态**、**关键词**、**游标**。
还有一个容易漏看的开关：**要不要把热榜与聚合类条目带回来**——默认**不带**（09-21 定的足迹口径：
热榜条目天天重复，留着会把"我读过什么"算脏），只有显式要求时才纳入。**列表与计数必须同一个开关**，
否则会出现"列表有行、计数显示 0"那种自相矛盾（历史上真出现过）。

- 响应给：条目数组、下一页游标、三档各自计数。
- 条目是文章表与视频表**并起来**的统一形状（同一套字段名），前端一套卡片渲染两类东西。
- 分页每页固定条数（写死在两端各一份，**没有"每页条数"参数、传了也不报错**——这是 H31，改接口前先读那条）。

批量与导出：入参都是"动作 + 一组（类型, id）"；导出返回拼好的 Markdown 文本与条数，
格式为标题 + 形态/来源/日期/链接/摘要（摘要截断），按日期降序。

## 类型口径（为什么只有一份实现）

| 形态 | 判定依据（语义） | 注意 |
|---|---|---|
| 文章 | 文字类源类型那一族，**含公众号类** | 旧文档漏了公众号那一类，导致计数比真实少 869 条——这就是收敛成一份的原因 |
| 播客 | **没有独立的源类型**，只能靠"封面是音频外壳"这个特征识别 | 权宜口径；正式方案随 09-23 那批 spec 作废，别再指望它变精确。旧文档写"播客=抖音"，与实现相反 |
| 视频 | 走视频表，且**"交互过"= 收藏过 或 观看过**（两条件之一即入档） | 与文章表分家，所以"已读"档对视频为空是**设计如此**，不是 bug。⚠️ 只认收藏会让视频区恒空（线上收藏常年为 0），所以加了"观看过"这一半；**观看时间戳目前只有本地端写回**，云端那一半是前置修正、当下无行为变化 |
