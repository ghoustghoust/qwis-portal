# 测试地基与打桩（模块功能文档）

> **在模块地图中的位置**：`测试地基与打桩`。相关问题编号：H37（隔离只挡了一跳）、H38（三套出网实现）、H39（"零真实出口"目前没有能证实的装置）。
> 这份文档回答一件事：**测试声称"没碰生产、没打外网"，凭什么信、什么时候不可信。**

## 一、这个模块给谁用、解决什么

回归测试里有两类必须"真跑"：跑生产主链脚本、跑真读层接口。它们默认会碰两样危险东西——**生产数据库**和**外部 AI 网络**。这个模块的职责就是把这两样关进笼子，让"真跑一次"变成可以天天做的事。

## 二、一次"真跑"是怎么被隔离的

| 要隔离的东西 | 做法 | 生效条件 | 失败（没隔离住）会怎样 |
|---|---|---|---|
| 生产库 | 把数据库地址指到一个临时本地文件库；凭据项留**非空哑值** | 脚本的配置加载是"只填空缺"，所以已经设好的值不会被 `.env` 里的真凭据灌回来 | 直接往生产库写数据。**这一条最隐蔽的坑是"哑值设成空串"**：空值等于没设，会被真凭据覆盖 |
| AI 出口（本机桩） | 把 AI 接口地址指到测试自己起的一个本地桩服务 | 桩必须是**另一个进程**：真跑用的是同步等待的子进程，同进程起服务会被事件循环占死，表现成"一次都没调用 + 超时"，看起来像产品坏了 | 打到真实模型、烧配额、结果不可复现 |
| AI 出口（供应商链内部） | 用一个只给测试用的注入点替换掉整个供应商调用 | 见下方"为什么包全局 fetch 不够" | 同上，且**测试自己不会红**，只会静默打外网 |
| 报警出口 | 报警通道配置读的是**库里的设置**，临时库里不塞 webhook 就无处可发 | 依赖第一行"库被隔离"这一条成立 | 真发一条飞书给管理者（内容还是假数据） |

## 三、"零真实出口"这句话现在能证明到哪一步（本轮实测）

- **不可用的装置**：只在测试进程里包一层"全局 fetch"来数出网次数——**看不见产品的真实 AI 流量**。实测表现：计数报 0，而同一跑的日志显示确实发了 12 次 AI 请求。
- **可用的装置（本机桩层）**：让被测进程把"代理"指向**桩自己**。这样任何目标都会先落到桩手上，桩能记一行台账再把请求拒掉。台账为空 = 本跑没去别处；台账非空 = 抓到现行。
- **仍然没被证明的部分**：走加密地址（HTTPS）的目标，桩是以"隧道请求"的形式收到的，本模块当前的记账**没能覆盖这一路**（实测：注入一次访问外部加密地址，请求确实发生并失败，台账却 0 行）。所以：
  - ✅ 可以主张：本跑没有以明文 HTTP 形式访问过非本机目标；
  - ⛔ 不可以主张：本跑绝对没有任何形式的外网访问。
- 另有一条更省事的路线**尚未采纳**（等拍板，H39 的选项③）：既然存在"只给测试用的供应商注入点"，直接用它替换供应商，就绕开了整套代理/隧道问题——代价是真跑脚本不再经过网络层，隔离强度换成另一种。

**教训（写死）**：安全装置的证据必须装在**必经之路**上；装在"我以为的唯一通路"上等于没装。而它报出来的"0 次"看起来正好像好消息，这是这类装置最危险的失效方式。

## 四、本仓有三种出网实现，别按一种来想（H38）

| 跑在哪 | 走哪条路 | 会不会被"包一层全局 fetch"看见 |
|---|---|---|
| 云端采集作业 | 有自己的代理库与代理分派器，配置了代理时**用它自己的取回函数** | ❌ 看不见 |
| 本地 Express 服务 | 在进程启动时设置全局代理分派器 | ✅ 看得见 |
| 云端读层调线上接口 | 每次现造一个带代理的调用 | ❌ 看不见 |

⇒ 任何"我拦住了所有出站"的说法，都要先说清拦的是哪一条；跨端复用同一个装置是无效的。

## 五、判据自己的可信度（这套地基怎么防自己说谎）

1. **每条锁都要有坏样本**：新增判据必须先证明"把它想拦的东西真造出来一次，它会红"。本轮多次出现"加了更严的判据但其实恒绿"，唯一有效的防线是当场喂坏样本。
2. **下限检查**：判据里凡"数为 0 也算通过"的，都要加一条"分母必须非空"。典型例子：某条链路的读数全为 0 时，一堆"自洽、单调、闭合"的断言会全部成立，而那正是功能坏掉的样子。
3. **名单不手抄**：测试里要用枚举（比如"失败有几种"）时，从契约文件读，不复制粘贴。抄来的名单漏一项就会把合法数据判成违规（本轮真发生了一次）。
4. **枚举要按写法列全**：同一语义可能有多种代码写法，只扫一种就是给未来留恒绿洞。
5. **别拿漏检装置的"0"当证据**：见第三节。
