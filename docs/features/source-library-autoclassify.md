## 一、用户在这里改什么（输入面）

管理台「源库」是全类型源的统一管理面（置各 Tab 首位）。用户能做的动作按"轴"分——**同一个源在好几根轴上各有独立状态，互不代表**：

| 用户动作 | 改完会发生什么 | 落在哪 |
|---|---|---|
| 标/撤"特别关注" | 该源的内容在早报里优先 / 不再优先 | 源的"聚光灯"标记（旧称"重点"已退役，旧写法仅作兼容别名接收） |
| 静音 / 放出 | 在列表里屏蔽或恢复该源 | 源上的可见性状态 |
| 订阅 / 退订 | 决定它进不进「我的早报」的选择集 | **只写订阅名单那个配置键，不动源表任何列**——订了 ≠ 聚光灯，屏蔽 ≠ 退订 |
| 改抓取间隔 | 这个源多久采一次；整组一起调时一条语句完成，不逐行循环 | 源级间隔覆盖 |
| 标备用组 | 声明它与哪组互为备用（主源失败时顶上） | 源上的备用组标记 |
| 启用 / 停用 | 启用 = 解冻、失败计数清零并随机错峰排开（跨度取值读实现）；停用 = 直接停 | 启停状态 + 失败计数 |
| 移动到分组 | 归类；**并顺手把该源的自动分类锁上**（见第二节） | 分组归属 + 分类锁 |

批量操作带"组范围"时作用于整组成员。

## 二、自动分类：新源进来时系统替用户做的事

- **内置分类目录**：若干个大类（中英别名归一 + 关键词兜底），目录顺序即优先级——越具体的越先命中。逐类关键词清单现读实现，本文不复制。
- **判定顺序**：先看 OPML 清单里源自带的分类层级（经别名归一匹配）→ 再把源的名称与简介拼起来扫关键词 → 都不命中就**保持未分组**，不乱塞。
- **落组**：精确同名且同内容形态（文章 / 视频）就复用已有分组，否则新建。
- **三个挂接点**：手动添加源、OPML 同步、队列导入——新源在这三处都会被自动归类；**分类失败只降级、不阻断建源**。
- **手动锁定**：锁定标记存在源的扩展字段里；一旦锁上，自动分类永远不再动它。⚠️ **写锁的入口有两处**：单条改分组，和批量操作里的"移动到分组"——两条都置锁。旧文档只写了一个入口，按它理解会以为"批量移动的源会被下次自动分类悄悄改回去"，事实相反。
- **破茧栏联动**：分类结果自动并入破茧栏的"熟悉领域"名单（一个可配的设置数组，键名 `daily.cocoonFamiliar`；默认域内分组名现读实现）。这份名单由**每日早报**的"茧房外"栏目读取；它与「我的早报」的探索位是两码事（探索位的候选口径见 `features/my-brief.md`）。

## 三、最后产生什么结果（界面与读数）

- **源库列表**：全类型源统一浏览 / 筛选 / 搜索 / 批量管理；其中拉取列表的接口是**公开只读**的，每条源带文章与视频计数、内容形态。源的扩展字段只按**白名单**回给前端（原始串不外泄）——白名单里漏一个键，运维要看的字段就被藏掉；完整清单现读实现。
- **自动分类预览 / 执行**：预览默认只回"建议 ≠ 当前"的条目，可要求返回全量；判定不出建议的条目不混进变更清单、单独计数。执行时跳过已锁定的源，缺的分组顺手建。
- **破茧栏**：联动与消费方见第二节末条。

## 四、刻意不做（别当缺陷去补）

- **分类关键词规则不做成用户可编辑的界面**。规则内置、随版本走：开放成可编辑等于让每个人维护一套私有分类口径，而分类结果还要参与自动归组与破茧栏——两三年后没人记得当年为什么把某个词加进去，规则本身就成了第二个真相源。要改规则就改代码（顺带能被测试钉住）。
- **不新增头像抓取渠道**。源上已有头像数据就显示，没有就用"类型图标 + 名称首字"占位。**禁止**为了几个像素再开一条出网抓取——多一个抓取就多一套反爬与一份无人值守的故障面，而收益是装饰性的。

## 五、不能做什么（改这一域之前必读）

- **不许只改一端的分类判据**：两份实现对同一批源必须分出同一批组，改一处忘另一处就是漂移（篇首警示）。
- **源库路由必须挂在单源路由之前**：否则批量操作的路径会被按"单个源"理解的子路由截胡（实现里有注释标注）。
- **不许只写一个锁定写入点**：两个入口都必须置锁（第二节）。
- **白名单只许一份**：要新暴露扩展键，加进实现里那份白名单；别在文档或前端另抄一份清单。

## 六、怎么验（现读法）

- 两端分类是否一致：同一批源在本地端与云端各跑一次分类预览，对结果。
- 某个扩展键前端看不看得到：读实现里那份白名单，别读文档。
- 锁定生没生效：锁一个源后跑自动分类预览，它不该出现在变更清单里。
