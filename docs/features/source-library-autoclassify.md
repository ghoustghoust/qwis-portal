# 源库管理与自动分类

> ⚠️ 适用范围：**不是本地专属**——源库四轴与自动分类在云端读层同样上线。
> **注意分类逻辑有两份实现**（本地 `server/services/classify.js`、云端 `api/_classify.js`），二者不共用代码：
> 改判据必须两处一起改并各自带锁，否则会出现"同一批源在两端被分成不同组"（这是本项目最常见的漂移形态，AGENTS §1）。
> 本文只写"改了什么、锁会在什么时候咬人"，不复制实现清单。
> 最后更新：2026-10-03（收敛轮：删除两处悬空编号引用与行数读数）

## 设计目标

- **统一源管理**：管理台「源库」Tab 置首位，统一浏览/筛选/批量管理全类型源
- **自动分类**：内置 8 类目录（中英别名归一 + 关键词兜底），新源三挂接点自动入组
- **手动锁定**：`extra.categoryLocked=1` 标记的源不受自动分类覆盖
- **破茧栏联动**：分类结果自动并入 `daily.cocoonFamiliar` 设置

两条**刻意不做**（别当缺陷去补）：

- **分类关键词规则不做成用户可编辑的界面**。规则内置、随版本走：把它开放成可编辑，等于让每个人维护一套私有分类口径，而分类结果还要参与自动归组与破茧栏——两三年后没人记得自己当年为什么把某个词加进去，规则本身也就成了第二个真相源。要改规则得改代码（顺带能被测试钉住）。
- **不新增头像抓取渠道**。源上已有头像数据就显示，没有就用"类型图标 + 名称首字"占位。**禁止**为了几个像素再开一条出网抓取——多一个抓取就多一套反爬与一份无人值守的故障面，而收益是装饰性的。

## 源库 API（sourcelib.js）

### 路由挂载顺序

**必须挂在 `sources.js` 路由之前**，避免 `/batch` 被子路由截胡。`index.js` 有注释标注。

### GET /api/sources/library

全量源列表（公开只读），含 `itemCount`（文章/视频计数）+ `contentKind`（article/video）。

- extra 白名单重建：只回白名单键（含源级间隔、最后错误、是否聚合源、域名、缓存标签、**分类已锁定**、来源、**备用组标记**——
  完整清单以 `server/routes/sourcelib.js` 里那份白名单为准，本文不复制，漏一个键就会把运维要看的字段藏掉）
- 脱敏：原 extra 串不外泄，仅返回白名单键

### POST /api/sources/batch（27b 起是"四轴 + 组级"，不是一列动作）

**本文旧版只列了 5 个动作、还写着已退役的"重点=focus"，与实现差一整版**。现在按轴读：

| 轴 | 用户意图（改完会发生什么） | 落在哪 |
|---|---|---|
| 列轴·特别关注 | 该源的内容在早报里优先/不再优先 | 源的"聚光灯"标记（旧"重点"列 27b 已退役，旧写法仅作兼容别名接收） |
| 列轴·静音 / 可见性 | 在列表里屏蔽或放出该源 | 源上对应两列 |
| 订阅轴 | 我订不订这个源 | **只写订阅名单这个配置键，不动源表任何列**（两件事分开：订了≠聚光灯，屏蔽≠退订） |
| 参数轴·间隔 | 这个（组）多久采一次 | 源级间隔覆盖；整组一起调时是一条 SQL，不逐行循环 |
| 参数轴·备用组 | 标它属于哪组互为备用 | extra 的备用组标记 |
| 启用 / 停用 | 解冻并随机错峰排到 6 小时内 / 直接停 | 启停列 + 失败计数清零 |
| 移动到分组 | 归类 | 分组外键，**并顺手把分类锁上**（见下方"两处写锁定"） |

组级快路径：带"组范围 id"时动作作用于整组成员，单条语句完成。

> **两处会写"分类已锁定"**：单条改分组与批量移动**都会**置锁——一旦锁上，自动分类就不再动它。
> 旧文档只写了一个入口，按它理解会以为"批量移动可以悄悄被下次自动分类改回去"，事实相反。

### POST /api/sources/autoclassify

自动分类预览/执行：

| 模式 | body | 返回 |
|------|------|------|
| 预览 | `{ dryRun: true, includeLocked?, showAll? }` | `{ items, total, changed, skippedLocked, noSuggestion }` |
| 执行 | `{ apply: true, ids: [...] }` | `{ applied, skippedLocked, groupsCreated }` |

- 预览默认只返回「建议≠当前」的条目；`showAll=true` 返回全部
- 无建议（`suggested=null`）的条目默认不计入变更清单，单独计数 `noSuggestion`
- 执行时跳过 `categoryLocked` 的源

## 分类引擎（classify.js）

### 内置分类目录（8 类）

数组顺序即优先级，前面的更具体优先命中：

| key | 中文名 | 关键词示例 |
|-----|--------|-----------|
| `programming` | 编程技术 | 技术/开发/编程/前端/后端/开源/dev/github |
| `ai` | 人工智能 | ai/大模型/llm/gpt/深度学习/机器学习 |
| `business` | 商业科技 | 商业/创业/科技/创投/融资/财经 |
| `finance` | 金融经济 | 金融/经济/投资/股票/基金/macro |
| `product` | 产品 | 产品/产品经理/设计/ux/交互 |
| `growth` | 效率成长 | 效率/成长/学习/阅读/写作/自律 |
| `news` | 新闻媒体 | 新闻/资讯/日报/早报/晚报/媒体 |
| `life` | 生活方式与文化 | 生活/文化/艺术/旅行/美食/书 |

### 分类优先级

1. **OPML 原生分类**：`buildOpmlCategoryMap()` 解析 `opml/*.opml` 的 outline 层级，经 `aliases` 归一匹配
2. **关键词匹配**：`name + description` 拼接后逐目录扫描关键词
3. **均未命中**：返回 `null`，保持未分组

### 落组规则

`getOrCreateGroupId(zh, kind)`：精确同名 + 同 kind（article/video）复用已有分组，否则新建。

### 三个挂接点

新源自动分类在以下三点触发（全部 try/catch 降级不阻断建源）：

1. **手动添加**：`routes/sources.js` POST 端点
2. **OPML 同步**：`wechat syncOpml` 流程
3. **队列导入**：`poller.resolvePending` 流程

### 破茧栏名单

`mergeCocoonFamiliar(zh)`：分类结果自动并入 `settings['daily.cocoonFamiliar']`（可配 JSON 数组）。默认域内分组名：

```
AI / 科技 / 科技热榜 / 国际科技 / AI 模型 / AI 产品 / 技巧观点 / 行业动态 / 公众号 / 播客 / YouTube
```

### 手动锁定

- 写入点**两处**（旧文档只写了一处）：单条改分组的入口，以及批量操作里的"移动到分组"——两条都会置锁
- 判断：`json_extract(COALESCE(extra,'{}'),'$.categoryLocked')` 或 `JSON.parse` 后读键
- 自动分类永不覆盖锁定源
