# 云端实时信息流 · 交付文档（下一个 Agent 必读）

> **这份文档的目的**：让任何接手的 Agent 在改代码之前，先理解"网页数据为什么会自动更新"，
> 避免改功能时把采集/调度链路碰断而又不自知（本系统已经因此静默停摆过 2 天）。
> 最后更新：2026-09-28
> 验收与交付链以 `AGENTS.md` §3 为唯一准绳；`eval:*` 那批命令是按需工具，不是每轮必过的门。
> 档位与 cron 取值一律以 `.github/workflows/collect.yml` 为唯一事实源，本文只画形状、不复制取值。判"这一轮到底跑没跑"的硬证据是采集心跳里有没有那一档的 mode（云库设置项 `cloud.collect` 的历史记录），**不是本文的任何陈述**。
> **方向性取舍与"不做什么"不在本文**：住 `docs/adr/` 的编号件（索引见 `ARCHITECTURE.md` §3.8）。本文只留两类东西——链路形状，和"违反就会静默停摆"的护栏。
> 外置触发器与 GH schedule 是**双档**：两档各自按自己的可靠性跑，本文不声明谁主力谁备份——那样一句话每轮换一次实测就会被写成本文最大的坑（停摆 2 天那次就是这么来的）。

## 1. 一张图看懂实时链路

```
┌─────────────────────────────────────────────────────────────┐
│ GitHub Actions（.github/workflows/collect.yml）              │
│                                                             │
│  采集档：按固定节奏跑一轮，尾部带热搜事件预聚合与即时补分      │
│  生成档：日报 / 早报（晚间主批 + 夜间备跑）/ 周刊 /            │
│          静态导出物 / 清理                                    │
│  ⚠ 我的早报没有定时档——只能手动触发                          │
│  各档具体时刻、以及"哪档认 schedule、哪档认手动触发"          │
│  只写在作业文件里，本文不放取值（北京时间见其注释）             │
│                                                             │
│  触发双档：GH schedule + 外置 HTTP 触发器                     │
│  （任务标识与凭据见 docs/HANDOVER.md §1.5）；两档各按自己的    │
│  可靠性跑，本文不判主次                                      │
└──────────────────────────┬──────────────────────────────────┘
                           │ 托管库客户端直写（不经任何 Vercel 函数）
                           ▼
                     Turso（东京）  ← 唯一云数据源
                           │ 读（无缓存，写入即所见）
                           ▼
        Vercel 读层（push 自动部署）：读者前端 + 管理后台
```

**关键认知**：Vercel 函数**不参与**定时采集。Vercel 只是读层。数据新不新，取决于"Actions → 云库"这条链，和 Vercel 部署本身无关。

> ⚠️ 「清理」是**两件事**，别混成一个布尔：**跑没跑** —— 该档只认 schedule，手动触发选不到它，所以判它跑没跑只能现读采集心跳里有没有那个 mode（"有 cron 表达式" ≠ "它会执行"）；**删没删** —— 跑到不等于删到，删除闸在没有内容转储凭证时必定挡住，同一格读数里的实删行数才是结果。这两个数本文不写结论。

## 2. 不可破坏的不变量（动了就会"不更新"）

改任何代码前对照此表。违反任意一条 = 信息流停摆，且**没有任何报警**。

编号是长期标识（跨文档按号引用），**不重排、不回收**；一条归给决策件之后，原位只留一行现状 + 件号，理由与边界去那件读。

### 2.A 已归决策件的

| 号 | 现状一句话 | 承载件 |
|---|---|---|
| 1 | 同一把采集/库凭据同时活在本地环境、云平台环境变量、仓库密文三处，改一边不改其余 = 静默 403 | ADR-12（含"外置触发器里内嵌那份也要同批改"）+ `AGENTS.md` §2.6 |
| 4 | runner 上装不了需要编译的原生模块，而 runner 是唯一写入方 | ADR-21 |
| 6 | 托管平台的定时块写过但从未生效（它只发 GET，采集入口只收 POST），所以定时全在 Actions | ADR-18 |
| 9 | 触发是双档，且**不带 mode 的手动触发只跑采集那一步**——日报/周刊/清理都不会被这一次点出来 | ADR-13（操作细节见 §3、§4） |
| 14 | 新增一个云端只读端点必须同一次改齐三处，且本地测不到鉴权这一层 | ADR-04（对应坑 #56） |
| 19 | 云库是链路的单点，且没有读路径兜底 | ADR-05（三条推论已并入其边界） |

### 2.B 护栏（改了会怎样 + 现在读哪里能验）

**2 · 采集必须带浏览器 UA。** 热榜聚合端点对自定义 UA 一律 403。UA 在本地、云端读层、runner 三份实现里各有一份，改要同步。
现读：热榜档抓回 0 条且日志是 403，第一嫌疑就是这里。

**3 · 熔断阈值按类型分档，视频类必须比别的高。** 视频站点的反爬会掷出假 404/500 误杀活源；把那一档改回统一小阈值 = 一批源被集体停掉。取值唯一承载处在共用实现里，本文不写数值。

**5 · 作业必须有仓库写权限。** 静态导出物那一档要往仓库回写提交，权限缺了它静默不产出。

**7 · 脚本末尾用退出码自然结束，不要强制终止进程。** 强制退出在 Windows 上会撞到运行时句柄断言、返回一个非零码，看起来像"跑挂了"。

**8 · 走代理时，发请求的函数必须与代理客户端配套。** 把外部的代理分派器喂给运行时内置的请求函数会全部失败（符号不兼容），症状是每一条出网都报网络错。

**10 · 热搜事件是预聚合 + 直读。** 那段聚合在冷启动的函数里跑不完（一定超时），所以由采集批次尾部预算好写进设置项，读层直读；只有缓存陈旧到一定程度才允许现场算一次兜底。聚合语义有且仅有一份实现，runner 与云端兜底共用它——**别写第三份**。
现读：热榜事件页内容与那份缓存的产出时间。

**11 · 白天新入库的文章靠即时补分才有分。** 六维评分原本只在早报批次跑，白天进的内容分数为空，热点榜"AI 精选"就一整天没有今日内容。现在采集批次尾部会补一批（可调，且在生成保护窗内主动让路）。
现读：白天入库条目有没有分数。

**12 · 日报的写入者不止一个，读层择优必须按档次。** 各写入者生成的报告档次不同（AI 增强版与裸报告都在写同一张表）；若按生成时间取最新，裸报告每天会把增强版整体遮蔽。守卫有且仅有一份实现，runner 与读层共用，**任何一端都不许重写这条规则**；入报门槛要**逐个接到每一个写入者**身上——漏一个的表现是"大部分天正常、个别天混进低质条目"，而来源往往是最后才补上门槛的那一支（读层内联兜底）。
统计口径也要统一：候选数记的是**进门前的条数**，被门槛剔掉的条数另记一个键；同一个键名在两份写入者里是两种群体，统计卡就会说谎。
周刊侧同源：条数不足一律不发布，**不许用空或降级产物覆盖上一期**（宁缺毋滥）。
现读：某天早报的档次、门槛剔除计数、周刊是否被覆盖。（对应坑 #32）

**13 · 「视频与播客」这一栏有三份产出实现，字段必须一起改。** 云端日报、runner 日报批、runner 我的早报批各写一份，形状由共用的媒体口径决定（播客与视频在封面、音频地址上的取法不同）；显示层的兜底头像是同一栏的一部分。**加字段或改口径时漏一处，表现是"某些天有图标某些天没有"，看不出是没同步。**
本地灾备端这一栏结构性缺失（它同样带着兜底头像，补齐时别再分叉）。
现读：同一栏位在不同天的产出字段是否齐。

**15 · 日报栏目表只许一份实现。** 三端生成器与读层的默认栏目都引用它。曾经有多份副本，而读层那份会被后台"恢复默认栏目"**写进库**——副本一漂，脏默认值就落进生产库。栏目的描述文字不许复述它的关键词。（对应坑 #55）

**16 · 实体解码只许一份实现，且只作用于标题类字段。** 曾经各处各自解码、每处抄的映射表都少几个实体，症状是源名和标题带着转义符号上屏。两条硬边界：**只解一次**（双重转义留给数据订正，不在采集层连解两次）；**正文与摘要故意不解**——那里被转义的标签文本一旦解开就成真标签，会被"像不像 HTML"的分流判据误判，等于用一个 bug 换另一个 bug。

**17 · 日界只许一份实现，全站产品语义是北京日。** 云端容器是 UTC、本地开发机恰好是东八区，所以任何"各自算一下今天"的写法都会在云端错位八小时；**日期串是标签不是时刻**，把它拼成零点时刻就是那族 bug。日报窗口是"北京昨日 00:00 → 今日 06:00"，各写入器共用这一份口径。前端不能引用后端那份，因此有一份对端实现，它的正确性靠**逐时刻跑数**比对，不是比文本。
故意保留的一处例外：本地灾备端判断"到没到点"用的是这台机器的墙上时间——那是本地调度触发器，跨时区部署才需要换。

**18 · 判"代码里真写了这句话"的扫描只许一份词法实现。** 注释与字符串内容要能分别处理；用只去注释的那条路径判"已接线"，会把注释里的名字算成实现了。自检必须**双向**（抹完好、只在注释里的词确实消失、字符串内容不许丢）。派生清单类判据一律从**事实**反查（例如从插入语句反查写入者），不靠人记清单——清单会被删空，删空后判据静默变绿。（对应坑 #63）

**20 · 早报候选层的每源配额只许一份实现，且必须落一个可判别的计数。** 这一刀换的是**覆盖宽度**（让高频源别把坑位占满），不改进报门槛，也不是额度削减。配额值只有一处写死，坏值回落默认并出声。
两条附带硬约束：宽范围读**不许携带正文列**（正文一律到深析阶段按条单取；带正文的宽读曾被连接层掐断），行数上限是唯一取值处；配额是否生效必须**落库可判别**，否则"生效没有"又变成靠人猜。
本地灾备端不在这条部署面内，但入报门槛照旧必接。
现读：当天早报统计里的配额计数。

**夜间预算（从不变量 9 移出来的操作事实）。** 一次夜间生成同时跑着初筛、深析、媒体三段，三段各自的耗时上限与作业超时必须**自洽**——只抬一边会让另一段被静默截断。三段各自的用时现在分开落库，预算够不够只有拆开才答得出；取值与作业超时的对应关系以代码与作业文件为准，本文不写数值。**"哪些语义只许一份实现"（12/13/15/16/17/20 这一族）归 ADR-14 的边界。**

**配额的另一半是自己（清理侧）。** 删除需要一次**人工内容转储**才能拿到的凭证，而它的有效期比最短保留窗口短得多——**闸开着的时候几乎没得删，等有得删了闸已经关**；runner 的临时文件系统又让转储那条腿结构性跑不通。人工一断，清理就变成"跑到也被挡、一条都不删"，而库只涨不删会把行读单价与存储同向顶高（任一维度越限即整站封锁）。
所以"闸门挡住"与"当日无清理心跳"都**必须出声**——这两条目前都未接，账在 `docs/ISSUES.md` H29。
顺带一句量具的真相：真正吃行读的界面入口是几个大范围扫描（精选栏裸扫、正文模糊搜索、日报一次搬多份），不是逐条读。

## 3. 改代码时的检查清单

- [ ] 改了采集语义（过滤/清洗/去重/熔断/UA）？→ **三份独立实现都要对**：本地采集器、云端读层备份、runner 主链路。它们会漂移（归属规则见 ADR-14）。
- [ ] 改了日报逻辑？→ 本地灾备端、云端手动生成端点、runner 生成批、读层内联兜底都要检查；**档位守卫只有一份实现，勿在任一端重写**（不变量 12）。
- [ ] 改了库结构？→ 三份采集实现 + 静态导出物生成 + 读层全部要对齐。
- [ ] 改了作业里的定时？→ Actions 用 **UTC**，且整点拥挤，用错峰分钟。
- [ ] 改完必须跑：`npm test`（**条数以命令输出为准，本档不写死**；基线状态见 `docs/FEATURE_MATRIX.md` §1.5），不许新增失败；push 后查 `ci.yml` 是否绿（判某一次运行的成败要带凭据查——匿名配额会把"没有 check"伪装成状态）。
- [ ] 涉及云端的改动 → 部署后**验你改的那一步**：不带 mode 的手动触发只会跑采集那一步（不变量 9），其余档位要么要选对应 mode、要么只认 schedule，**一次点选不出全流程**。判某一档真跑没跑，现读采集心跳里的 mode。
  ⚠️ **不许把"人去 GitHub 点一次 Run workflow"当验收步骤**（用户 09-27 裁：这条通路他从未手动用过，即使功能存在也不在他的操作面里）。要补跑就写清是谁跑、跑完现读哪个字段自证。

## 3.1 部署方式

✅ **Vercel 已连接 GitHub 集成**（productionBranch=main）：**`git push origin main` → 自动构建部署**，静态导出物那一档的每日回写也随推随上线。

CLI 手动部署仍可用作兜底，但有两条红线：**禁止拉取平台环境变量**（会覆盖本地 `.env`、丢掉端口与代理这些只在本地有效的变量），**禁止交互式登录流程**。

```bash
# ④ 手动触发采集（不带 mode 只跑采集那一步；清理档在这里选不到）
#    GitHub → Actions → collect → Run workflow

# ⑤ 看外置触发器这一档是否在准点敲门（另一档是 GH schedule）
#    控制台 https://console.cron-job.org/dashboard → 该 job 的执行历史
#    任务标识与管理用 Key 见 docs/HANDOVER.md §1.5
#    近轮返回无内容(204) 且间隔符合节奏 = 正常；GH 侧对应的是手动触发事件
```

## 5. 故障决策树

```
网页数据不更新
  ├─ 最新一条数据的创建时间是旧的？
  │    ├─ 是 → 采集链断：查 GH Actions 是否全红
  │    │    ├─ 403 → 凭据三处不一致（不变量 1）
  │    │    ├─ 热榜 403 → UA 被改回去了（不变量 2）
  │    │    └─ 其他 → 看那一轮作业日志里采集脚本的输出
  │    └─ 否 → 数据是新的但页面旧 → 前端/缓存问题，与采集无关
  ├─ 日报没生成 → 查日报档的作业日志；窗口是"北京昨日 00:00 → 今日 06:00"（口径见不变量 17）
  ├─ 某源不更新 → 查源表的启用位/失败计数/最近错误；视频类间歇失败属正常（反爬掷骰，见不变量 3）
  └─ Actions 绿但数据旧 → 查采集心跳的统计字段
```

| AI 对话 / 摘要 | ✅ | Vercel | 配置写入口径见 §6.1 |
| YouTube / X | ⚠ 间歇 | GH runner | 反爬掷骰，阈值已放宽（不变量 3） |
| B 站 | ✅ | GH runner | 签名主链 + 两类兜底；**播放直链仍本地** |
| 抖音 | ❌ | 仅本地 | 需登录态，永不上云（ADR-02） |
| 云端队列取件（手机提交链接） | ⚠ 手动 | Vercel 手动 / 本地自动 | 自动轮询仍在本地调度器 |
| OPML 源清单同步 | ⚠ 手动 | Vercel 手动 / 本地自动 | 自动同步仍本地 |
| 采集停滞报警 | ✅ | runner + 本地 | 心跳埋点在采集档；报警引擎两端都有出口 |
| 页面内自动刷新 | ✅ | Vercel | 固定周期拉增量端点（ADR-06，不做长连接） |

> 结论：**本地关机，信息流、日报、翻译、阅读正常运转**；依赖本地开机的只有抖音采集、手机提交队列的自动轮询、OPML 自动同步这几项（B 站在 runner 上采，**不属本地专属**）。
> ⚠ 本表每一格"云端到底有没有"都属**易漂事实**：本轮只按代码与作业文件核过形状，线上逐格实测在 B 清单里（`docs/specs/45-doc-validity-adr-split/spec.md` §9）。

## 6.1 AI 配置写入口径

现行口径（用户 09-19 拍板：保留可写 + 强制审计 + 变更告警 + 写后探测失败即回滚）：

1. 优先级：设置项里的 AI 配置**高于**环境变量。改环境变量永远修不好"被设置项覆盖"的问题——排查顺序仍是先查库里那个键。
2. 允许从后台写模型、接口地址、密钥，但每次写必须同时做到：写审计记录（何时、改了哪几项、旧值指纹→新值指纹，**不落明文**）；推一条变更告警到报警渠道；写后立即做一次轻量连通探测，失败即回滚并在界面报错（防止把线上打成鉴权失败）。
3. 读侧永不回显明文密钥，只回显指纹。
4. 通用设置端点对 AI 键的拒写拦截**保留**——两个写入口只留一个真写入口，避免绕过审计。
5. 上述四条**不等于已落地**：四项各自到哪一步需重新对代码核，挂账在 `docs/ISSUES.md` BL9；其中"变更告警"这条还依赖报警出口可用（同账）。

> 曾经有一份"云端 AI 配置只能来自环境变量、设置项已清空"的纸面禁令，它与实际实现不一致过——纸面禁令挡不住真实通道。现在按上面五条走，别再回到"禁令 + 无人核对"的形态。
