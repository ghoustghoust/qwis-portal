## 二、我在这条上一分钟内造出的两处假读数（记此防复犯，同坑 #41/#45 族）

1. **把 `read_at='null'` 的 0 命中直接读成"已经干净了"**：第一版探针用三个 `CASE` 分支相加，
   结果 `真值=214 / 字面'null'=0 / NULL=0`，加总 214 ≠ 59,832。**判据自己漏了 58,217 行**，
   而"0 命中"恰好落在我预期的方向上，所以第一反应是"污染没了"——方向对了，推理是错的。
2. **`row.isnull ?? 0` 把"没读到"抹成"读到 0"**：`NULL` 那一列在结果里是 `undefined`
   （别名与聚合返回形态的问题），`?? 0` 静默把它变成 0，于是"真 NULL = 0 行"看着像事实。
   这正是坑 #41 的形状：**探针取不到值必须报错，不许兜底成 0**——同一族错误在 B106 里刚立过判据。
   改成 `typeof` 分组后，`null` 这一类被显式数出来 59,618 行，三分支才加总闭合。
