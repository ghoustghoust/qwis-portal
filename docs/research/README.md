# docs/research/ · 研究性与前瞻设计参考

装**外部世界的做法与目标态设计**：长篇研究笔记、同类产品的范式拆解、"这套系统将来该长成什么样"的框架文档。

**它和邻居的区别**（别放错，放错就会互相污染）：

| 目录 | 装什么 | 时间方向 |
|---|---|---|
| `docs/research/` | 别人怎么做的、我们**打算**怎么做的 | 未来 |
| `docs/features/` | 某个模块**现在**干什么、改它会怎样 | 现在 |
| `docs/adr/` | 已经拍板的方向性取舍与"不做什么" | 已定 |
| `docs/specs/` | 某个功能拆几步、什么算做完 | 在途 |
| `docs/archive/` | 判完生死的过去件，只作反查 | 过去 |

**三条准入规矩**：

1. **每份文件头部必须自陈身份**：写清它是"目标态/外部参考"还是"已验收的现状依据"。没标身份的一律按"未验收的外部想法"读——**不许拿它当现状引用**。
2. **落地了就搬空它**：某条设计接进生产链路之后，把"现在怎么跑、改它会怎样"写进 `docs/features/` 对应模块那份，本目录这份**只留还没做的部分**。一份文件长期同时承载"应然"和"实然"，就会开始自我矛盾。
3. **作废即删，不养**：判断不再成立的，直接删，反查走 git。**不许**在这里堆"当年考虑过但没做"的件——那是这个目录最容易变成的样子（本仓已经有一份这样的沉积目录叫 `docs/archive/`，它不参与决策）。
