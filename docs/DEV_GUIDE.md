# 全网情报系统 · 开发者上手指南

> 最后更新：2026-09-29
> 这份只管"我今天要动手，先去哪儿"。**系统形状、目录职责、阅读顺序、交付链都不在这里复制**——它们各有一份权威承载处，复制过一次就已经不一致过一次了。

---

## 一、这是什么

私人 AI 情报阅读器：聚合多源信息（RSS、公众号托管 feed、B站、热榜聚合、播客等），每天生成 AI 策展的早报与日报，支持检索、热榜与事件聚合、异常推送报警。

跑在哪三端、各自职责与数据落点：`ARCHITECTURE.md` §0/§2（方向性理由在 `docs/adr/` 01、02、13、14、17）。

## 二、我今天要改东西，按这个顺序

| 场景 | 先去 |
|---|---|
| 接手项目、第一次读 | `AGENTS.md` §0 那份**固定顺序**（唯一一份，别处不复制） |
| 定位"用户改的是哪个模块的哪个子模块" | `docs/INDEX.md` 模块地图（禁止绕过它做全仓关键词匹配） |
| 这个模块现在到底怎么跑 | `docs/features/` 对应那份 |
| 云端 / 本地 / runner 谁有这个能力 | `docs/FEATURE_MATRIX.md`（唯一矩阵） |
| 这事是不是已经定过方向 | `docs/adr/`（索引在 `ARCHITECTURE.md` §3.8） |
| 改采集链会碰什么不能碰的 | `docs/CLOUD_PIPELINE_GUIDE.md` §2 不变量 |
| 线上不更新了怎么查 | `docs/RUNBOOK.md` §11 与 §10 |
| 改完怎么算交付 | `AGENTS.md` §3 |

## 三、本地跑起来

1. 装依赖，配本地环境文件（要哪些变量见 `ARCHITECTURE.md` §6；凭据位置矩阵在本地件 `docs/HANDOVER.md` §1.5）。
2. `start-all.bat` 一键起（含健康检查、自动开浏览器）；只改后端要重启用 `restart-server.bat`。
3. 前端：阅读器 `http://localhost:<端口>/reader/`，管理台 `/admin/`。改了 `web/src/` **必须** `npm run build` 再强刷——前端产物旧于源码是本项目反复踩的"我改了页面没变"。
4. 改云端：改 `api/` 后 `git push` 即自动部署（Git 集成已连）；**推完必须验部署**（先打线上 meta 比对提交指纹，见 `AGENTS.md` §3 第 5 步）。
5. 门户（`portal/`）**已退役**：它的同步通道默认关闭，别再按"门户也在跑"改行为。

## 四、动手前要知道的四条约定

1. **改采集语义要看那三份实现**；改共用语义只改唯一那份。细则与归属：`docs/DEVELOPMENT_STANDARDS.md` §2 + ADR-14。
2. **本地与云互不同步**（ADR-17）：本地改了生产看不到，是设计代价。
3. **新增云端端点必须同一次改三处、且真打线上**（ADR-04）：本地是单用户放行，测不到鉴权那层。
4. **云端巡检工具** `node tools/audit-cloud.js`（只读）帮你看线上形状，但**不替代**云端实测那一步。

## 五、文档落点（写什么去哪儿）

- 新决策（方向性取舍、"不做什么"）→ `docs/adr/` 一个编号件：是什么 / 为什么 / 边界与禁止。同主题被改判时**就地改写那件**，不新开"取代件"、不留旧方案叙述。
- 做一个新功能（拆几步、什么算完）→ `docs/specs/` 走规格件。
- 模块行为变了 → 改 `docs/features/` 那份；能力覆盖变了 → 改矩阵。
- 完整的对应表与清洁规矩 → `docs/DEVELOPMENT_STANDARDS.md` §4 与 `docs/DOC_GOVERNANCE.md`。

## 六、坑库

`docs/pitfalls/` 按域一文件，**条数不写死**，域索引见 `docs/pitfalls/README.md`。本指南**不列"精选坑"**——列了就会和坑库各自过期，而且挑哪几条本身就是偏见。接手时按你要改的域整份读。
