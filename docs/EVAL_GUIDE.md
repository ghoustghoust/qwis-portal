## 1. 为什么要加这一层（本项目自己的理由，不是照抄论文）

本项目的故障形态决定了单测不够用：

- **纸面不变量与实现长期不一致**：文档写「云端 AI 配置 env-only」，而 `PUT /api/ai/config` 一直在写 `settings.ai`（B50，8 天才被发现）；文档写「心跳保留 7 天」，实测只有 25 小时（B24）。`npm test` 对这两条全都绿。
- **三端各写一份语义**：同一个源在本地永不自动恢复、在云端 48h 后恢复（H14）；`/api/reading` 云端漏 `date` 而本地有（B27）；类型筛选云端 SQL 少括号而本地正确（B28）。单测各测各的，谁都不红。
- **测试自己就是事故源**：回归测试直连生产 Turso 把报警渠道写坏，报警链路哑了 2 天（B44/坑 #T2）。
- **用户可见 ≠ 代码正确**：翻译 Skill 恒「加载中」（404 被 catch 后挡在渲染前，B52）、任务队列恒 0（字段形状不匹配，B47）、成功率整屏 0%（`slice(0,50)` 只取最坏 50 个，B23）——这些在单测里全都"通过"。

所以要两层新评测：**端到端**证明"用户点得到、看得见"，**白盒**证明"三端与不变量真的一致"。

## 3. 端到端评测（E2E）

### 3.1 环境前置检查（先跑，不通过就中止）

论文实测"安装验证"仅 14% 通过是全链瓶颈；我们最脆的是**本机代理 + 三端凭据**。所以评测第一步不是点页面，而是：

| 检查 | 判据 | 不通过时的分类 |
|---|---|---|
| 代理可达 | `GET https://github.com` 经 `http://127.0.0.1:12000` 返回 2xx/3xx | `fail_env`（不是产品缺陷） |
| 远端已部署 | `origin/main` HEAD == Vercel 生产部署 commit | `fail_env`（部署未完成/未推送） |
| 凭据三处一致 | `.env` / Vercel env / GH Secrets 的 `COLLECT_KEY`、`TURSO_*` 指纹一致 | `fail_env` + 立即报警 |
| Turso 可读 | `SELECT 1` 通过 | `fail_env` |
| 测试隔离就绪 | `APP_DATA_DIR` 指向副本而非生产；`settings.alerts` 未被写路径污染 | **`fail_env` 且拒绝继续**（防 B44 重演） |

> 规则：**环境不通不许折算成"产品失败"**，也不许跳过检查直接跑剧本。

### 3.2 剧本清单（页面 × 关键交互，逐条可断言）

前台：`/reader/`（今日流、翻页、点开详情、中英对照、搜索）、`/daily/`（AI 版档位、栏目、星级）、`/mybrief/`（订阅集、探索位）、`/weekly/`（期号、storylines、导语无污染串）、`/hot/`（三视图）、`/reading/`（三 tab × 三类型矩阵、日期分组无「未知日期」）。
后台：8 个板块（源库 / 后台首页 / 早报中心 / AI 能力 / 系统·数据 / 监控·报警 / 热点榜策展 / 全局壳导航），每板块至少一条"改一个设置 → 前台或链路真的变了"的闭环剧本。

每条剧本必须产出：截图、网络请求清单（含体积与耗时）、断言结果、`env_lock`。

### 3.3 断言分三类，缺一不算覆盖

1. **渲染断言**：目标元素存在且文本非占位（**禁止**只断言"元素存在"——B52 的「加载中…」正是占位）。
2. **接口断言**：响应字段齐且形状匹配（B27 漏 `date`、B47 形状不匹配都属此类，肉眼看不出来）。
3. **数据断言**：写操作后回读库/端点确认落地（改设置后必须回读，对应 B54「改了不保存」）。

### 3.4 结果四分类与 flaky

`pass / fail_product / fail_env / fail_flaky`。同一剧本**连跑 3 次**：3 次全过才算 `pass`；偶发失败标 `fail_flaky` 并进 ISSUES，**不得作为通过依据**。
> 门禁口径必须是"每次都过"。论文用 pass@5（5 次中 1 次即算），那是给模型排名用的，不是交付标准。

### 3.5 性能预算（端到端顺带量，超预算即 `fail_product`）

| 目标 | 预算 | 当前实测 |
|---|---|---|
| `/api/articles?sort=smart` | P95 < 2s | **11.4 / 13.6 / 15.3s**（B31） |
| `/api/status` | P95 < 5s | 26.1s 且出现 `FUNCTION_INVOCATION_TIMEOUT`（B26） |
| 后台任一板块首屏 | ≤2 请求、≤60KB | 早报中心 4 请求 ≈134KB；热点页 451KB（B38） |
| 点开一篇文章 | 不触发 >100KB 重拉 | 重拉 545KB sources（B31） |

## 4. 白盒评测（代码不变量与三端一致性）

不做静态风格检查，只检查**本项目真踩过、且肉眼 review 抓不到的**结构不变量。每条都要能写成断言：

| 组 | 检查 | 依据（事故） |
|---|---|---|
| **W1 三端常量 diff** | 熔断阈值（3 / YouTube 10）、冷却时长、退避节奏、UA、RSS 间隔、清洗规则、去重键，在 `server/services/collectors/`、`api/collect.js`、`tools/collect-turso.js` 三处逐项对齐；不一致即红 | H14/H15、坑 #35 |
| **W2 产物档位** | 凡"多写者 + 单读者取最新"的表，读侧必须按 `schemaVersion` 档位优先而非时间优先（`lib/brief-guards.js` 是唯一实现，禁止任一端自写） | 坑 #32 |
| **W3 配置优先级** | `settings` 高于 env 的键清单必须显式列出并逐项断言；新增 `settings.*` 键若无人读 → 报"假开关" | 坑 #24、B50/H10/H12 |
| **W4 序列化陷阱** | 任何"值→存储字符串"路径禁止用 `typeof v === 'object'` 判类型；`NULL` 不得变成 `'null'` 字面串；字符串列不得与 ISO 时间做大小数比较 | 坑 #36（B15 误诊根因） |
| **W5 表达式与查询预算** | OR 链深度上限、无索引排序表达式、单次响应体积上限（防 H11/B26/B31 类慢性 504） | 坑 #31、B26 |
| **W6 SQL 组合正确性** | 动态 WHERE 片段拼接必须整体加括号；同一响应的 counts 与列表必须出自同一条件 | B28 |
| **W7 鉴权与路由** | 中间件注册顺序、写端点鉴权覆盖、云端路由表 ⊇ 前端所请求路径（防 B52/B57 类"端点只在本地存在"） | 坑（鉴权顺序）、B52 |
| **W8 文档-实现一致** | 活文档声明的不变量必须能在代码里找到对应实现或断言（如"env-only"这类声明） | B50 |
| **W9 坑↔测试对账** | 每条 `docs/pitfalls/*` 编号必须被至少一个测试引用；新增坑无测试 → 红 | 坑 #13/#T2 反复复发 |

白盒结果同样四分类；`fail_product` 必须给出**文件:行号 + 期望值/实际值**，否则视为检查写得不合格。

## 5. F2P / P2P 双集合与「改前必红」

- **P2P（回归集）**：§3.2 全部剧本 + §4 全部不变量，每轮全跑，必须全绿。
- **F2P（本轮集）**：本轮每个被修缺陷对应一条断言。**新用例必须先证明它能抓 bug**：在不含该改动的分支/worktree 上跑，必须红；抓不到就删掉这条用例。
  ```bash
  git worktree add ../.wt-eval HEAD~1        # 或对应改动前的 commit
  node tools/eval-e2e.cjs --only B28 --worktree ../.wt-eval   # 期望：红 <!-- doc-lint:ignore：该工具是 41-2 的待建交付物 -->
  git worktree remove ../.wt-eval
  ```
- 报告里每条 F2P 必须同时给出"改前红"与"改后绿"两份证据，缺一不记为已修。

## 6. 去污染：防止"实现者自己出题、只测顺手写对的路径"

论文用时间切割 + 显式标记做去污染；我们的等价污染是**自证**。四条硬规则：

1. **`self_authored` 标记**：用例记录 `scenario_added_at` 与 commit；与所验实现同出处 → 报告标 `self_authored=true`，**不得单独作为验收依据**（必须配 §5 的改前必红）。
2. **覆盖分母机械化**：以 `docs/FEATURE_MATRIX.md` 的「页面 × 功能」格子为分母，未覆盖格子自动生成「已知空洞」清单进 `docs/ISSUES.md`。覆盖率是算出来的，不是感觉出来的。
3. **题源限定**：只从 ①`ISSUES.md`/用户批注 ②`/api/health/status` 与 `audit_log` 实发故障 ③`docs/pitfalls/` 事故 出题；每轮额外随机抽 1 个未覆盖格子做异常组合（空数据、档位切换、settings 覆盖 env、熔断中恢复）。
4. **饱和换题**：长期全绿的用例归档换题，避免剧本退化成"永远正确的仪式"。

## 8. 产物与门禁

- 命令：`npm run eval:e2e`、`npm run eval:whitebox`、`npm run eval:preflight`（§3.1）。
- 报告：`docs/eval/YYYY-MM-DD-<轮次>/{report.json, screenshots/, env_lock.json}`；`env_lock` 含部署 commit、Turso 快照标识、`APP_DATA_DIR` 副本路径、settings 键指纹、代理端口。报告目录**只进 git 的 `report.json` 与摘要**，截图走 `.gitignore`（避免仓库膨胀）。
- 退出码：0=全绿；1=有 `fail_product`；2=有 `fail_env`（视为未评测，不许交付）。
