# 全网情报系统 · 评测口径

> 最后更新：2026-09-29
> **这份只写"怎么判"，不写"谁实现了什么"**。哪些命令、脚本里有哪几项检查、内部叫什么名字，都是 `tools/` 与 `tests/` 自己的事，本文不复述——复述过一次，它就和代码各自过期一次，而读的人会照这份改代码。
> **定位**：本文描述的工具是**按需工具**，不是每轮交付必过的门。每轮交付的准绳只有一份：`AGENTS.md` §3。
> **现行有效性**（用户 09-28 裁）：功能尚未完全稳定，`tests/`、`tools/` 里的判据**目前不具参考性**，不随本轮文档轮修改；系统稳定后按这份口径重建正式验收测试，从行为锁里长，不从产品意图锁里长。

---

## 1. 为什么要加这一层

本项目自己的理由，不是照抄论文：

- 回归测试只能证明"这次改的东西没把已知功能碰坏"，它证明不了两件更要紧的事——**线上真的在产出吗**，以及**产出的文本有人愿意读吗**。
- 本项目过去两周最贵的几个缺陷，全都不在"功能坏没坏"这一层：热榜数据停在旧时段、早报条目长期没有封面、导语里混进模型的自陈句、生成结果大部分天正常个别天混进低质内容。**这些用接口状态码看不出来**，接口全都 200，页面全都"正常"。
- 因此分三层取证：**页面呈现**（读者看到什么）、**数据与内容**（落库的东西对不对、写得好不好）、**执行过程**（这一次评测本身可不可信）。每层各有各的判据，互不替代。

## 2. 分层与各自回答的问题

| 层 | 回答的问题 | 什么时候用 |
|---|---|---|
| 端到端 | 真浏览器打开线上站点，读者看到的和接口发出的是不是同一件事 | 改到前台页面、读层输出、日报/周刊/热榜呈现时 |
| 白盒一致性 | 同一语义是不是只有一份实现；跨端会不会各漂各的 | 改采集/清洗/去重/熔断/保留/日界这类共用语义时 |
| 内容质量 | AI 写的东西人读不读得下去、有没有编 | 改到摘要、导语、翻译、评分口径时 |
| 过程与产物 | 这一轮评测本身可不可信（证据齐不齐、退出码诚不诚实） | 每次跑评测都要落产物，否则等于没跑 |
| 环境前置 | 代理、线上版本、凭据形态这些"外部条件"到位了没有 | 判红之前先看它——多数"端到端红"是判据自己的环境问题 |

## 3. 端到端

**先决条件**：目标必须是真实线上站点（打本地端口不算）；代理与证书口径见 `docs/DELIVERY_VERIFICATION.md`；先核对线上部署的提交指纹 == `origin/main`（`AGENTS.md` §3 第 5 步），否则你验的是旧产物。

**判据的三条纪律**（每条都来自真实翻车）：

1. **断言要分三类各至少一条**：页面呈现（DOM 上看得见的）、接口发出（页面自己请求到的数据）、数据落库（现读某个字段）。只断言 DOM 会漏掉"前端兜底冒充后端产出"；只断言接口会漏掉"接口有但页面没渲染"。
2. **不许有永远不红的判据**：写死的真值、两侧恒等的比较、"文档里没提到就算通过"——这类断言比没有更坏，它给出绿灯。每条新判据交付前要做**负向验证**：手工塞一个坏样本，确认它会红；塞不红就是假门禁。
3. **探针拿到的响应不算页面自己发出的**：用来对账的响应必须只包含页面真实发起的请求，否则是自我循环取证。

**四分类与处置**（判红之后先分类，再动手）：

- **产品红** = 改动真的坏了 → 修代码，或按第 6 节先补"改前会红"的取证。
- **环境红** = 代理/凭据/部署没到位 → 判**未评测**，不许交付，更不许去删用例或放宽判据。
- **判据红**（旧称"flaky/工具红"）= 判据自身有缺陷 → 报给用户三选一（改代码 / 改锁 / 摘锁记理由），**agent 不许自己改锁消红**。
- **缺口** = 这条路径根本没有剧本覆盖 → 记进 `docs/ISSUES.md`，不许把"没覆盖"写成"通过"。

**验收轮 vs 探针轮**：跑过 ≠ 验收过。算一次验收轮必须同时满足三条，否则即便全绿也应主动判"未验收"：① 跑的是全部剧本（挑子集不算）；② 每条剧本连跑 ≥3 轮（单轮判不出抖动）；③ 目标是真实云端（本地不算）。

**覆盖率的诚实说法**：`已知缺口=0` 只表示"没有剧本级摘出的缺口"，`每条剧本三类断言齐` 只表示形状齐——**两者都不等于功能覆盖全**。覆盖率要靠人工对表，别拿这两个字段当证据。

## 4. 白盒一致性

判的是**归属**，不是形状。这一层的不变量都是同一句话的具体化：

- **跨端必须同规则的语义，只许有一份实现**：熔断阈值、内容保留与删除谓词、源状态各轴、早报候选的每源配额、噪声判定、北京日界、标题类字段的实体解码、日报栏目表、报警事件表、翻译提示词。归属与拒绝边界见 **ADR-14**。
- **入口完整性**：同一件事有多个写入者时（日报就有不止一个），门槛/守卫必须逐个接到每一个写入者身上。漏一个的表现是"大部分天正常、个别天混进低质"，而不是当场报错。
- **派生清单不许靠人记**：需要"列出所有写入点/所有消费点"的判据，必须从事实反查（从语句本身找），而不是维护一份手写名单——名单会被删空，删空后判据静默变绿。所以派生判据要带"分母过小=判据写空"这一腿。
- **文本型判据要能区分注释、字符串和代码**：判"代码里真写了这句话"必须用同一套词法视图，且**双向自证**（抹完代码仍可解析、只在注释里的词确实消失、字符串内容不许丢）。只去注释的那条路径会把注释里的名字算成"已接线"。
- **不许反向迁就现状**：判据不能因为"现在就是这样"就把自己改绿。锁的口径与实现不一致时，红了才对，红了就要报。

## 5. 内容质量评测（LLM-as-a-Judge 五维）

前三层只能证明"功能活着"，证明不了"AI 写得好不好"——而本项目的产品就是文本。指标为**五维度评分（1~5 分制）**，外加可选总体分与反馈文字。每一轴都锚在一次真实缺陷上，不做空泛打分：

| 轴 | 中文含义 | 评什么 | 起因 |
|---|---|---|---|
| `clarity` | 表达清晰度 | 推荐理由、摘要、编者注是否一读就知道在说什么 | 用户原话"有的文章不知道在说什么" |
| `factual_correctness` | 事实正确性 | 译文标题/摘要与原文是否一致、有无编造；引文是否真出自原文 | AI 编造标题与占位金句 |
| `consistency` | 前后一致性 | 标题↔正文↔栏目↔星级是否自洽；主题导语与实际条目是否对得上；档位声明与内容是否一致 | 低质条目混进高档报告 |
| `redundancy` | 简洁度 | 元评论、重复导语、同义堆叠、思维链残留、"我需要找到…"类自陈句 | 周刊导语污染多次复现 |
| `readability` | 易读性 | 排版是否保住加粗/重点、行内代码、分段；纯文本糊墙即低分 | 综述与详情无排版 |

**计分口径**（改动要与实现同时核，两处各改一遍就会漂）：

- 每轴 `v ∈ [1,5]`，归一化 **`norm(v) = (v - 1) / 4`** → `[0,1]`。
- 加权总分 `score = Σ weight[a] · norm(v_a) / Σ weight[a]`。
- 默认权重（可调，改动必须记进本轮环境快照）：`factual_correctness 0.30 · consistency 0.25 · clarity 0.20 · redundancy 0.15 · readability 0.10`。**事实正确性权重最高**，因为这个产品的底线是不编。
- **自动分只作趋势与复核触发，不作门禁**：论文的自动校验准确率有限，所以我们定死——白盒硬不变量不过 = 直接红；内容分低于阈值 = 进 `docs/ISSUES.md` 等人工复核；**同一轴连续多轮低分才升级**成待修项。单轮低分不判红，避免拿一个不靠谱的数字当门。
- **对齐抽检**：每轮随机若干条由人与 judge 同时打分，记一致率；一致率过低时本轮 judge 结果只作参考，不许据此改产品阈值。

## 6. 「改前必红」与回归集

- **回归集**：本文 §3 全部剧本 + §4 全部不变量 + §5 全量样本。**这是"跑这套工具时"的完整口径**，不是每轮交付必过的门。
- **本轮集（改前必红）**：本轮每个被修的缺陷对应一条断言，且**新用例必须先证明它能抓这个 bug**——在不含该改动的基线上跑，必须红。
- 三条纪律（都是踩出来的）：
  1. **"基线里没有这个文件" ≠ "改前红"**。文件不存在时测试根本没执行，判**环境**（未评测），不许判成产品红，更不许据此删用例。
  2. **别让锁直接读本轮新建的实现文件**。在"基线=改动前"的构造下它永远不可能红；要出证就得把修复点回退或注入桩，而不是让文件消失。
  3. **参数不许静默截断**。指定用例时多出来或写错的名字必须直接判错，不能"少跑了几条还打勾"。
- **取证要留文件**：每轮的取证必须指向一个具体的证据产物文件名；文档里只写一句"已出证"而没有产物落盘，不算出证。

## 7. 去污染：防止实现者自己出题只测顺手的路径

1. 判据必须来自**缺陷与用户裁决**，不能来自实现细节。
2. 每条锁的改动都要带"为什么"——指到用户的一句话或一个实测数字；指不到就是这条锁该重审。
3. 覆盖要有**负向样本**：坏样本必须被抓到，反例不许误伤。
4. 文档改动是交付物、不是嫌疑人；被审的只有锁。判卷权不能落在写代码的一方——每轮至少一个独立视角复审这批改动。

## 8. 明确不照搬外部蓝本的哪些部分

不搬规模与方法论外壳，只借机制：任务量级与语料爬取、自建分布式容器/镜像/临时文件系统跑评测、微调大模型给产物打质量标签、公开榜单与 leaderboard、统一超长上下文与固定 agent 模板、**把自动通过率当门禁**。理由一句：本项目是单人系统、真实量级小、自动判分准确率有限，把它当门会制造假红并逼人加豁免。蓝本条目与取舍见 `docs/eval/` 的提炼件。

## 9. 产物与退出码

- 每轮必须留下：结果报告（含逐条判定与分类）、环境快照（部署提交指纹、代理与凭据形态、判分模型与权重）、截图、过程检查结论。**缺任何一项 = 本轮不算做过**。
- 退出码三档，处置各不相同：**0** 全绿；**1** 有产品红（去修）；**2** 有环境红或未验收（视为未评测，不许交付）。把"未评测"和"失败"混成同一个码，等于授权人删用例。
- 交付口径只有一份，见 `AGENTS.md` §3；本文不复述那份序列。
