## 1. 现状

每轮交付的准绳只有一份：`AGENTS.md` §3 的固定交付链（其中每轮必过的门以 `docs/FEATURE_MATRIX.md` §1.5 的标记为准，本文件不数门）。现役 harness 三件：

- `npm test` —— `tests/` 的行为锁：钉现役功能的既定行为与修过的线上事故；
- `node smoke-test.js` —— 冒烟：生产库副本上跑主要路径，零副作用；
- `npm run lint:docs` + `node tools/doc-stamp.cjs` —— 文档门禁与改动戳。

上面只点名三件现役装置是哪些；各命令的用法与读数口径的唯一清单在 `docs/FEATURE_MATRIX.md` §1.5，本文不复制用法。

端到端 / 白盒一致性 / F2P 改前红取证 / 内容质量 / 过程检查 / 环境前置那套评测装置（`tools/eval-*` 及给它上的锁）**当前不在仓内**：功能尚未稳定，那批判据多与未稳定的产品意图绑定，与迭代天天对抗、诱发"改锁消红"。用户 09-28 裁"判据目前不具参考性"，10-01 裁整体摘除——装置、装置锁、一次性探针脚本一并删除，原文在摘除提交之前的 git 历史里，可反查（摘除提交即边界，`git log` 可查）。

仍保留的取证方式：**一次性只读探针**——数据链路改动时新写探针直读生产真值，产物落 `docs/eval/`；探针脚本一次性，跑完即删、不入库。

## 2. 重建原则（系统稳定后重建正式验收测试时照此）

1. **从行为锁里长，不从产品意图锁里长**。每条锁必须指到一个已发生的事故或一句用户裁决，指不到不立锁；迭代中的功能不提前上锁。
2. **判据不许读另一条门禁的退出码**判成败（安全判据会在门禁非零时静默失声）；不许写永远不红的判据；每条新判据先喂坏样本证明它会红。
3. **锁红了 = 报用户三选一**（修代码 / 修锁 / 摘锁记理由），agent 不许自己改锁消红；每条锁的 diff 必须带"为什么"。
4. **判红先分族再动手**：产品红（改动真坏了）/ 环境红（代理、凭据、部署没到位，判未评测）/ 判据红（锁自身有缺陷）/ 装置红（锁读了已删路径， ENOENT——让装置不再指向消失的目录，属 `tools/`/`tests/` 的活）。
5. 云端实测仍是唯一验收标准：先 `/api/meta` 的 `commit == origin/main`，再按 `docs/DELIVERY_VERIFICATION.md` 打真实端点。
