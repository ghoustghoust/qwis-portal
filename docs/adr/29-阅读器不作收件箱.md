# ADR-29 · 阅读器不作收件箱：全量时间线这个形态已被否决

- Status: active
- 拍板：用户 09-14 立项、09-15 落地，09-30 自开发记录中确认为现行决策
- 依据：现读阅读器默认视图与未读口径；源数量随时间单调增长这一事实可现读

【是什么】
系统按"用户每天实际投入的注意力"分四层：**策展层**（每日早报 / 我的早报 / 周刊——AI 已替读者读完并评分）、**脉搏层**（热点榜，扫一眼在发生什么）、**检索层**（阅读器按需查：带条件地找某个源/关键词/时间段）、**存档层**（读过的都在，要时能翻）。
阅读器**不是收件箱**：默认只看得到"今天"这一小片，未读数只算近几天，"全部"降级成必须带条件的检索入口，侧栏不再挂一个巨大的未读总数。

【为什么】
源数量持续增长、每个源各自更新，"全部内容的无限时间线"里的信息量是**只涨不跌**的：任何一个时间点都存在几万条没读的内容。把这件事摆成待办清单，得到一个焦虑数字和一个真实的使用结果——**没人读得完，于是谁都不读**。用户实际的使用方式是象征性地看最新、精读已策展的内容。
所以产品形态必须承认"看不完"这个事实，把"替你选好了"放在第一层，把"我想查"放在第三层。把这两层反过来，等于要求读者自己完成系统本该做的工作。

【边界】
- **禁止**把默认入口改回"全源无限流 + 全量未读计数"。任何形式的"其实加个开关就能回到收件箱"都算违反本件（要开的是版面偏好，不是产品形态）。
- **禁止**为了"看起来内容丰富"扩大默认视图的时间窗或条数——那只是把焦虑数字变大，判据是"打开后三秒内能不能决定今天看什么"。
- **允许并且要求**：全部内容永远可检索回来。降级的是入口，不是可及性；**不许**因"默认看不见"就把旧内容判成可删（数据面的规矩见 ADR-30 与 ADR-22）。
- 各层的具体窗口长度、条数上限、排序权重属易变参数，不在本件写死。
- 本件钉的是**阅读入口的形态**，不钉早报的策展目标（那条是 ADR-24）。
