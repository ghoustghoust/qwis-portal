# ADR-30 · 用户的选择只过滤消费端，永不反向减少采集或删除数据

- Status: active
- 拍板：用户 09-30 自开发记录中确认为现行决策（原文："采集层永远全量；用户选择只过滤消费端、永不删除数据"）
- 依据：现读各消费端对源状态轴的取用位置；采集候选面的取数条件

【是什么】
"我不想看哪些源 / 哪些进我的早报 / 哪些从热点榜排除"这类选择，**只作用于消费端**：它决定某个界面给这个人看什么。它**不减少采集面、不删已入库内容**。
方向是单向的：采集广度 → 各消费端按轴过滤 → 界面。反过来的箭头都不允许存在。

【为什么】
这个系统的价值来自"全都在，随时查得到"。一旦"不想看"变成"不采"或"删掉"，三件事同时坏：
① 检索层承诺的"任何源都能回看"当场不成立；② 收缩是不可逆的——没采的内容不会补采，删掉的行不会因为"我又想看了"回来；③ 最隐蔽的一条，**用户的界面偏好会悄悄改写策展的输入面**，于是"我为什么看不到 X"变成要查三层的问题。
把选择限制在消费端，人的情绪只影响版面，不影响数据资产。

【边界】
- **禁止**用订阅集、屏蔽、收录、分组这些消费端的选择去过滤采集候选、缩小采集范围，或作为删除依据。**唯一能减少采集的是"这个源死了/换源"（ADR-25）与显式的下架轴**。
- **禁止**"隐藏即删除"：界面不显示不等于数据可清理。清理判据只有保留策略那一条路（ADR-22）。
- 消费端各自声明自己消费哪些轴（ADR-08），**不许**在读侧临时发明新的过滤含义；加一条过滤等于给"为什么看不到"新增一个原因，要连带更新模块地图。
- 本件不写"当前有几条轴、各轴叫什么字段名"——那是 ADR-08 与实现的范围。
