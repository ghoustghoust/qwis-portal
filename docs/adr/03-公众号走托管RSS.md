# ADR-03 · 公众号走托管 RSS，不自建引擎

- Status: active
- 拍板：用户 09-26 复核确认
- 依据：本地库逐行普查（非抽样）+ 现役源类型实测

【是什么】
公众号内容统一走第三方托管 RSS 取。不为公众号自建采集引擎、不再维护任何需要微信读书 Cookie 的本地子进程。

【为什么】
自建引擎要养 Python 子进程、独立进程守护、Cookie 续期与人工扫码，成本压在个人系统上；托管方案把这部分换成"改一行源地址"的维护成本。

【边界】
- **接受**图片单点依赖：现役公众号文章的正文图片地址存的就是托管方域名（逐行普查：基本一个域名，微信原站仅个位数例外）。对方域名或代理策略一变，封面与正文图一起受影响，这已是知情代价，不再重评。
- **禁止**绕过自家的 `/api/img` 代理把图片地址原样交回原站域名——微信 CDN 有防盗链，直挂必失；也**禁止**另写第二份图片代理实现（双端同语义由锁 B18 钉着，规则见 `docs/pitfalls/frontend.md` 坑 #1）。
- 退役引擎遗留的源行以关闭状态保留，只作源列表里的历史归属；不再采集，也不再为它补凭据。
- 图片域名分布与遗留文章条数属一次性读数，**不写进本件**，要读就跑普查（`docs/eval/`）。
