# ADR-26 · AI 与其它增强环节失败绝不阻断主链路：内容先入库，增强可以缺

- Status: active
- 拍板：用户 09-30 自开发记录中确认为现行决策（原始口径来自 AI 基础设施与日报两轮的验收要求）
- 依据：现读采集与成报流程对"增强调用失败"的分支处理（条目照常落库、缺的部分留标记）

【是什么】
内容能不能进库、能不能被读到，只取决于**采集与落库这一步成没成**。评分、摘要、翻译、主题归类、导语这些**增强环节失败时，主链路必须继续走完**：条目照常入库、照常可读，只是那一层是空的或降级的，并且**如实留下"这一层没做成"的标记**。

【为什么】
增强环节依赖外部模型服务，那是本系统唯一不受自己控制的一段：限流、超时、返回脏数据、配额按时间耗尽，都是常态而不是异常。如果这些失败能阻断主链路，结果就是"上游模型抖一下，用户今天没有内容读"——而**内容采集才是这个产品的承诺**。
反过来，缺标记更糟：一条没有译文的英文文章和一篇翻译失败的文章长得一样，人就会去查"翻译为什么坏了"，而真相是那篇本来就没翻。

【边界】
- **禁止**让任何增强环节的失败改变两件事：这条内容进不进库、它在阅读器可不可读。
- **禁止**把"增强层没做成"表达成空值之外的一切形态——不许用默认分、占位文案或上一次的结果去填空。缺就是缺，且要能被现读查出来（哪一层缺、缺多少）。
- 批量任务里**单条失败不许终止整批**：整批中断会把"一条脏数据"放大成"今天没有报"。
- 本件只规定"不能阻断"，不规定重试次数、超时数值与退避形状——那些是易变参数，读实现。
- 报警要不要为"某一层大面积缺"发声，属护栏与缺陷范围，账在 `docs/ISSUES.md`，不因本件视为已解决。
