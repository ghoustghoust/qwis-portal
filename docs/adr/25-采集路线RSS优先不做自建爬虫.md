# ADR-25 · 采集路线是 RSS 优先：不为平台自建爬虫，例外是显式清单

- Status: active
- 拍板：用户 09-13 定调，09-30 自开发记录中确认为现行决策
- 依据：现读各平台采集实现与源表（每个平台走哪条路可逐个查出）；早期"扫码拿 Cookie 自建采集"路线的失败原因仍在代码注释与坑库里

【是什么】
任何平台的内容获取，**第一步永远找现成稳定的 RSS 源**（官方 feed、第三方桥接、聚合器）。RSS 出问题时的处理路径是**换一个 RSS 源**，不是自己写爬虫。
自建采集只保留**点名的存量例外**（一份逐个有理由的清单，本件不复制份数与平台名——逐项现状以 `docs/FEATURE_MATRIX.md` 的源类型面为准）。它们是历史包袱，**不是可类推的先例**。

【为什么】
自建采集的真实成本不是写那几百行代码，是**长期养登录态与风控**：Cookie 会过期、要人工扫码续、反爬策略随时变，而这套系统是个人维护、无人值守的。换 RSS 的成本是改一行源地址。
把这条立成决策而不是习惯，是因为它会反复被"这个平台没有 RSS，那我们爬吧"重新提出——每一次都要重新付一遍养登录态的代价，而代价落在无人值守的夜里。

【边界】
- **禁止**为新平台新增自建爬虫作为首选方案。要越过本条，先推翻本件，并说明"这个源为什么换不掉"。
- **RSS 故障的处理路径 = 换源，不是为单源修管线**。源健康由熔断与报警兜底；"这个源死了"是换源或放弃，不是给它写一套定制抓取。
- **例外清单不许类推**：每个被点名保留的例外各有各的原因（一类是登录态依赖因此永不云端化，一类是纯签名直连、无登录态且已稳定），把它们当成"爬虫也可以"的先例是本件最常见的误读。逐项现状以 `docs/FEATURE_MATRIX.md` 的源类型面为准。
- **调第三方聚合端点不算自建爬虫**：热榜那一类走的是别人维护的聚合接口，本件禁的是"自己去爬某个平台"。区别在**谁承担风控与登录态**——聚合端点坏了照样是换源，不是接手维护。
- 本件不管"某个具体源现在通不通"——那是现场读数，现读方法看源健康状态与最近抓取时间。
