# ADR-19 · 不引入工作流编排平台

- Status: active
- 拍板：用户 09-28 放行（自 `docs/NEXT-DEV-REQS.md`「明确不引入的东西」表拆出）
- 依据：该表原文 + 现读管线全部为本仓代码实现

【是什么】
内容管线（采集 → 清洗 → 评分 → 成栏 → 落库）用本仓代码实现，不交给外部工作流 / AI 编排器。

【为什么】
编排器只会把评分口径变成别人的默认值。本系统的评分口径是自家定义、且要能被探针反查的（口径见 ADR-15）——交给编排器，口径的解释权就外流，出问题也无法在自家代码里定位。

【边界】
- **不接外部编排服务跑管线**。任何"用某编排平台串起采集与 AI 分析"的提案，先推翻本件。
- **定时触发不算编排**：那是作业文件与外置触发器的事（ADR-13），不因本件被否。
- 本件不禁止在单次任务内部调用模型供应商接口——那是 ADR-15 的范围。
