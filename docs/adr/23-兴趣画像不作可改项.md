# ADR-23 · 兴趣画像不作为用户可改项

- Status: active
- 拍板：用户 09-28 放行并补因（自 `docs/INDEX.md` 模块地图「我的早报 · 兴趣画像」行拆出）
- 依据：现读生产链路里画像的算法与写入方式；现读云端写设置通路放行过哪些键

【是什么】
「我的早报」用的兴趣画像，是系统按用户行为算出来的一张标签权重表：每天扫一段窗口内**打开过**（已读）和**标了稍后读**的文章，把它们带的标签按权重排，取前若干名整表写入设置。生成个人版早报时读它，用它给条目**加权排序**。

它是**系统产出，不是用户可改项**：后台只读展示，界面上没有、也不提供填写入口；收藏进不了它（文章侧结构上不存在收藏这一列）。

【为什么】
**这张表每批次都被整表重算覆盖。** 做成可配置项的结局必然是：界面上让你填，提示"已保存"、回显也显示你填的，而下一次生成用的是刚重算出来的那张——**你填的已经被算没了**。那是"改了不生效还骗你一次"的形状，比根本不提供入口更糟。与其加一个说明去解释这件事，不如不提供这个入口。

【边界】
- **不做"用户自己填兴趣标签"，也不给这张表加任何写入口。** 任何"让画像可配 / 加一栏兴趣设置"的提案，先推翻本件。
- **不许把它列进设置栏**：它出现在界面上只能是只读展示（"系统现在认为你偏好这些"），不能是可编辑控件——可编辑控件本身就是那个假承诺。
- 它**只改排序，不改收录**：任何"按画像过滤/门槛化"的改法都会改变进报集合，与本件的定位不同，要另立决策。
- 输入只有已读与稍后读这两个行为。要扩大输入（例如把某种交互算进画像）属改算法，不属开配置口——改之前先回来看这条边界。
