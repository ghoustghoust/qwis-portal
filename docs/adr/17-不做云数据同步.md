# ADR-17 · 不做云 / 本地数据同步

- Status: active
- 拍板：用户 09-28 放行（自 `docs/INDEX.md` 模块地图的现状陈述拆出）
- 依据：现读本地服务代码里没有运行期云库写入路径；跨库动作只有一份一次性种子脚本；那份"统一异步数据访问层"自陈冻结态、schema 已与本地漂移且主进程从不加载

【是什么】
本地端读写本地 SQLite，生产链路读写云库，两者之间**没有运行期同步通道**。设置项写进哪份库决定谁能看见它；两份库各有一份，互不同步。跨库动作只剩一次性灌库的种子脚本，那不算同步。

【为什么】
数据只有一个落点（Turso），采集写入方只有 runner。再加一条同步通道等于多一个写入者、多一套冲突判定与配额开销——而配额是这个系统的真实墙（任一维度越限即整站封锁）。本地端只作开发与全功能灾备，不承担"改了要让生产看见"的责任。

【边界】
- **不做本地↔云的数据或配置同步**。任何"给设置项或内容加一条双向同步"的提案，先推翻本件。
- 唯一例外是文件型导入队列（ADR-10）：那是把外部文件**单向投料**进云端的一张待导入清单，不是同步，也不许被写成同步的证据。
- 知情代价（已接受）：**本地改的生产看不到，必须各自改一遍**。据此产生的"我在后台改了但线上没变"不是缺陷，是本件的代价；要报缺陷先得证明两端都改过。
- 本件不约束"读"：本地端可以读云库排障，约束的是**写入路径不新增**。
