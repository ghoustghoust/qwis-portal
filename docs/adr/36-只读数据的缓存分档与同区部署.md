# ADR-36 只读数据的缓存分档与同区部署

日期：2026-10-07（性能批，实测前后对比见 `docs/eval/2026-10-07-perf-baseline.md`）

## 是什么

云端读层的响应分三档，档位只由**路径与鉴权头**决定，不逐端点配置：

1. **公开 GET（`PUBLIC_GET_PATHS` 成员 + 条目正则）**：出口设 `Cache-Control: public, s-maxage=<TTL>, stale-while-revalidate`，进 Vercel CDN。TTL 只有三档：`/api/articles/since` 10s、`/api/meta` 与 `/api/hot/categories` 300s、其余 30s。错误响应（非 200）不设缓存头。
2. **鉴权 GET / 写操作**：不设缓存头，直达函数，写入即所见。
3. **图片代理 `/api/img`**：按 URL 不可变资源给长缓存（浏览器 1 天 + CDN 7 天）。

函数（`api/*.js` 全部三个）pin 到 `hnd1`（东京，与 Turso 同区）。前端 `web/src/api.js` 对公开 GET **不附带 `Authorization` 头**——Vercel CDN 对带鉴权头的请求一律不缓存，这是第 1 档生效的前提。

## 为什么

实测基线（2026-10-06，线上带 token 直打函数）：`/api/videos` 10-17s、`/api/articles` 3.2s、`/api/meta` 2.7s；整条链零 HTTP 缓存，每次跳转/轮询都打穿函数 + Turso。跨洲 RTT（函数区域未定，实测常落美区）给每次 Turso 往返加 ~200ms，串行查询端点被乘法放大。修后同端点 0.4-0.9s，CDN 命中 ~350ms（含本机代理 RTT）。

## 边界与禁止

- **前端公开端点清单必须是后端 `PUBLIC_GET_PATHS` 的子集**（当前取等）。后端给公开清单加端点时前端不同步，该端点会继续带 token、CDN 静默失效——不报错，容易漏，改公开面时两处一起动。
- **带鉴权头的响应不允许进 CDN**。任何端点若开始按 token 返回不同内容，必须先离开公开清单再谈缓存。
- 管理台写设置后的回显有最长约 2.5 分钟 CDN 旧读窗口（30s s-maxage + SWR），知情接受；要求立即可见的读走带 token 请求。
- `/api/articles/since` 轮询端点**同时绕过前端内存缓存**（URL 里 ts 基线不变，吃 TTL 会把新文章提示拖到 TTL 量级）。
- 内存缓存（hot 家族 60s、status 30s、settings 30s）是 serverless 实例内的，随实例回收失效，不构成契约。
- 部分索引 `idx_articles_audio` 的 WHERE 谓词文本被 `lib/media.js` 三个常量固化——改常量必须 DROP + 重建索引（三端），否则播客分支静默退回全表扫，约定写在 `lib/media.js` 函数注释上。
