# ADR-18 · 定时只走 GitHub Actions，Vercel 不加 crons 块

- Status: active
- 拍板：用户 09-28 放行（自 `docs/CLOUD_PIPELINE_GUIDE.md` §2 不变量拆出）
- 依据：现读部署配置文件里没有定时块；采集入口只接受带凭据的 POST

【是什么】
所有周期任务由 runner 侧的作业文件定时触发。Vercel 的部署配置文件里**不放 crons 块**，托管平台的定时能力不用。

【为什么】
托管平台的 cron 只会发 GET 请求，且不插值环境变量，而采集入口只收 POST——天然不兼容。历史上写过 crons 块，**等于没写**：它静默不生效，看配置的人会以为定时在那儿。

【边界】
- **不做平台侧定时**。任何"把日报/采集/清理的定时搬回 Vercel crons"的提案，先推翻本件。
- 定时的取值（几点跑、多久一次）与作业清单的**唯一承载处是作业文件**；文档只许指路，不许复制取值（与 AGENTS §2.5 单一事实源同轴）。
- 重开条件：采集入口改成能接住平台定时请求的形态，**且**平台会插值环境变量——满足后改写本件，不留两份并存。
- 双档触发（平台 schedule + 外置 HTTP 触发器）是另一件事，见 ADR-13；本件只禁平台自带的 crons 声明。
