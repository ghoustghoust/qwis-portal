# ADR-01 · 部署方向：Vercel 读层 + runner 采集

- Status: active
- 拍板：用户 09-26 复核确认
- 依据：作业文件与 `vercel.json` 实测；本仓推 GitHub，push 即触发 Vercel 部署

【是什么】
读层与管理后台跑在 Vercel；采集与批处理跑在 GitHub Actions runner，直写 Turso。本地 Express 只作开发与全功能灾备，不在部署面。

【为什么】
平台免费档的函数存活时长只够处理极少数源，把采集放进函数等于把整条数据链卡在平台配额上。runner 是长驻进程、能带节流与重试、网络位置也适合连境外源。

【边界】
- **不做自有服务器全量部署**：主系统不再往"某台服务器"整体迁移，也不为迁移预留实现。任何"把整套搬到自有服务器"的提案，先推翻本件。
- 唯一的例外是文件型导入队列那半边的 PHP 件，它本来就跑在仓外的独立站点上（见 ADR-10）。
- 数据只有一个落点（Turso）。三端共享语义不共享进程。
