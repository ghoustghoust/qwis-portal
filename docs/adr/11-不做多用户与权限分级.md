# ADR-11 · 不做多用户与权限分级

- Status: active
- 拍板：用户（系统定位，09-26 复核确认）
- 依据：定位文档 + 单一管理账号实现

【是什么】
这是一个人的情报系统。云端常驻的目的 = 挂机采集 + 随时随地为自己服务，不是多用户产品。

【为什么】
多用户会连带带来账号体系、配额、隔离、审计、内容可见性分级——每一项都会改写现在按"只有一个主人"设计的读层与设置面。把它当"以后再加"的选项，等于让今天的每个功能都替明天的产品形态付设计税。

【边界】
- **禁止**引入用户表、角色、成员、协作、分享链接这类形态。
- 凭据只用于"是我自己 + 防误改"，不承担租户隔离（见 ADR-12）。
- 任何"给家人/同事开一个账号"的提案，先推翻本件。
- 公开只读接口是**有意**开放的（内容本身是已公开来源的聚合），这不是待补的安全缺陷；写与敏感读必须凭据。
