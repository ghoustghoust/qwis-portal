# ADR-22 · 不做清理总开关

- Status: active
- 拍板：用户 09-28 放行（自 `docs/INDEX.md` 模块地图「数据保留与存储」行拆出）
- 依据：现读保留策略只暴露保留天数一项，没有启停位；热榜轴与豁免名单在代码里写死

【是什么】
内容保留只有"保留天数"一个可改项。**不提供"启用 / 停用清理"这种总开关**；热榜那一保留轴与豁免名单是代码写死的策略，界面控制不了（域 3）。

【为什么】
关掉清理等于放弃保留策略，而**库只涨不删会把行读单价与存储同向顶高**——托管库任一维度越限就是整站封锁，本仓被禁过六小时。给一个"停用清理"的开关，等于提供一个把系统推向已知故障形态的按钮。

【边界】
- **不加一键清理 / 停用清理这类总开关**。任何"给清理加个开关"的提案，先推翻本件。
- 界面上只许改保留天数；任何"把热榜轴/豁免名单做成可配"的提案，先推翻本件（那会把代码写死的策略变成第二个可漂的真相源）。
- 本件不管删除闸的机制与转储凭证的形态——那是护栏与功能文档的范围（现读：`npm run check:retention`）。
- **但"两端的放行不是同一个条件"属取舍，登记在此**：删除闸有两条腿——有转储目录可量的那一端量磁盘上的全量校验结果，跑在托管 CI 上的那一端量不到目录，改判库里的转储凭证（而那份凭证只能由"本地校验全过的转储"写进去）。两腿都没有 = 挡下。
  - **禁止**只改一条腿就交付：改完必须在两端各读一次"闸现在放不放行、凭什么放行"，判据里要能看到它是走哪条腿过的。
  - **禁止**把"闸恒挡"当安全：目录指错位置会让闸永远判"没有转储"，界面上一切正常，实际是**库只涨不删**——而本件立论的那个故障（任一维度越限即整站封锁）恰恰就是这么来的。
- **闸门挡住与当日无清理心跳都必须出声**：出声机制是否接好属缺陷，账在 `docs/ISSUES.md`，不因本件视为已解决。
