# ADR-20 · 不引入搜索引擎栈（全文检索 / 向量库）

- Status: active
- 拍板：用户 09-28 放行（自 `docs/NEXT-DEV-REQS.md`「明确不引入的东西」表拆出）
- 依据：该表原文 + 现读检索实现为 SQL 匹配与集合相似度

【是什么】
内容检索用 SQL 条件匹配加集合相似度（事件聚合那类），**不接全文检索引擎、不建向量库**。

【为什么】
当前量级下这套够用；引入一套检索就得多维护一条数据通路——多一份索引、多一处与主库的一致性负担，还要多一个写入时机。而这个系统的云侧配额是墙（任一维度越限整站封锁）。

【边界】
- **不给内容加向量索引、不接检索服务**。任何"上 embedding / 上 ES / 上向量库"的提案，先推翻本件。
- 重开条件必须**能现读、能测**：检索在真实数据量上答不出，并且给出可复现的判法（例如某类查询在现有数据上的实测下场）。只凭"以后量大了"不成立。
- 若真重开，必须先写清这条新通路的数据由谁写、失效谁负责、与主库的一致性怎么保——否则等于把本件的代价换个名字请回来。
