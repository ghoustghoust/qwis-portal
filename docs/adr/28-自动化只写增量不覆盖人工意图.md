# ADR-28 · 自动化只写增量与初始值，永不覆盖人工意图；不做模糊自动合并

- Status: active
- 拍板：用户 09-30 自开发记录中确认为现行决策（原文两条：手动改归优先于自动分类；近义不合组，留给用户手动并）
- 依据：现读自动归类与批量回填对"人工已改过"的对象的跳过行为；查重/合并类的候选处理形状

【是什么】
系统里所有"机器替人整理"的能力（源自动归类、批量回填、健康自愈、查重建议）都遵守同一条：**自动化只负责把东西放到一个可用的初始位置，以及补上人没空补的增量；人手动改过的地方，自动化默认不再碰。**
合并类动作只在**完全确定**时自动执行；"看起来像同一个"不自动合，只出候选给人点。

【为什么】
自动化的价值是省人力，一旦它能覆盖人工选择，价值就反转成"人得先把被改回去的东西再改一遍"——而它是在人不在场时改的，人只会觉得系统在乱动。**人工意图必须是这套流程里的最高优先级**，否则没人敢真的去手动整理。
合并方向同理：误合并比重复更难收拾。重复是两件独立的事，谁都能看出来；误合并是**把两个不同对象的历史搅在一起**，而且界面上一切正常。所以宁可留重复给人自己并。

【边界】
- **禁止**让任何自动流程改写"人显式设置过"的值。要么跳过（默认），要么在预览里点名要求人勾选同意；**禁止**静默覆盖。
- **禁止**批量写入使用"全量替换"语义。人工增量与自动增量并存时，全量替换会让两条路径互相抹掉对方的配置。
- **禁止**用模糊相似度自动合并实体（源、分组、主题）。相似度只用于**排序建议**，落地要人确认。近义命名（中文全称与英文缩写这类）也**不自动复用同一个对象**，宁可新建再由人合并。
- 自动动作必须"预览 → 人确认 → 执行"，且预览里能看出**每条改动的依据**（凭什么建议这么放）。
- 本件不管具体规则表、阈值与映射字典内容——那是实现与现场读数；也不管"某次回填影响了几条"——那是一次性读数，反查走 git。
