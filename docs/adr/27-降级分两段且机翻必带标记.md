# ADR-27 · 降级分两段：判断类只在模型之间换，机翻只服务翻译且必带来源标记

- Status: active
- 拍板：用户 09-30 自开发记录中确认为现行决策（降级链选型与"评分/摘要不降级到机器翻译""机翻结果不冒充精翻"均为原文明确）
- 依据：现读统一调用通道的供应商链（判断类）与翻译专用的机翻兜底段；译文行上持久化的来源字段与阅读器界面按该字段显示的标记

【是什么】
系统里的"降级"是**两段，不是一个开关**：

1. **判断类调用**（评分 / 摘要 / 主题归类 / 导语）——模型不可用时，只能换到**另一家有判断力的模型供应商**。（本件的"判断类"＝这些要产出语义内容的调用；ADR-15 里的"判断类"专指削减层的二元判问，**不是同一组**，引用时点名是哪件。）
2. **翻译**——除了上面那条链，还额外允许落到**免费机翻端点**作最后兜底；这条兜底**只服务翻译**。

任何经兜底产出的译文，**必须带上它真正来自哪个提供方的标记**：这个标记存在条目上，并且阅读器界面按它显示，人眼能分清这条是精翻还是机翻。

【为什么】
翻译要的是"能读懂"，机翻在多数场景够用，落到机翻是有意义的退让。
评分要的是"替读者取舍"。把判断交给机翻端点，等于让早报的门槛由一个没有判断力的通道决定——**那比没有分更糟**，因为它看起来像一个分。所以判断类调用的降级面只到"换一个会判断的模型"为止。
"必带标记"是同一件事的另一半：如果精翻与机翻在库里、在界面上长得一样，读者会把机翻当精读结果来信任，策展的可信度就靠伪装撑着。

【边界】
- **禁止**把机翻端点接进评分、摘要、主题归类等判断类调用；**禁止**新增第二套降级链实现（同一件事只许一处定义）。
- **禁止**产出无来源标记的译文，也**禁止**把兜底来源标成主力模型。验收判据是"人眼在界面上能分清这条是谁翻的"。
- 免费机翻端点**只作兜底**，**禁止**当常态主力以省额度：它们没有一致性保证，术语库对它们不起作用。
- 具体供应商名单、顺序、重试次数与超时数值不在本件写死（读实现）；本件钉的是"哪一段允许降级到哪里"和"降级必须可辨"。
- 与 ADR-26 的分工：那条管"失败不许阻断主链路"（内容照常入库、缺的层留空并标出），本条管"允许换实现的那一段换到哪、换完怎么标"。
