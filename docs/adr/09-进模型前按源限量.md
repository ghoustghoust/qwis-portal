# ADR-09 · 进模型之前先按源限量

- Status: active
- 拍板：用户 09-26 复核确认
- 依据：预配额实现与执行锁实测（不配额时坑位被少数高频源的后续文章占满）

【是什么】
候选池进模型前，先给每个源限量、再按时间截断。这条换的是**源覆盖**，不是调用量。

【为什么】
只按时间排序截断时，坑位会被同一批高频源的"第 3 篇以后"占满——一天的池子来自几百个源，截断后只剩几十个源。**按调用量评估这条会得出"没用"的错误结论**，它本来就是拿覆盖换的。

【边界】
- 每源配额是**策略参数**（设置里可改），值不可用时回默认并出声；**禁止**静默降级。
- 宽池读取**一律不带正文**，需要正文的深析按 id 单取：一次拉回大结果集会把 HTTP 数据库链路掐断。
- 本地灾备端**有意不接**这一层。入报门槛是**安全阀**（漏一份就出垃圾），预配额是**策展策略**（改的是版面构成），两类风险不共用同一个"逐个接线"的面。这个前提有锁守着：本地端一旦回到部署面，判据自动红。
- 各部署面写入器必须同值；两份云端实现不许各写一份常数（漂移只在"抬一半"时发生）。
