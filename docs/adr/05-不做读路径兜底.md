# ADR-05 · 不做读路径兜底，静态导出物只是导出物

- Status: active
- 拍板：用户 09-26
- 依据：全仓引用实测（读层与前端均无取用方）

【是什么】
读层只有一个数据来源。每天导出的静态 JSON 是**导出物**，不是数据库不可用时的降级路径——本系统不承诺任何读路径兜底。

【为什么】
用户裁定原话：可能有快照，但**绝对没有让它来兜底**，所以这个功能不存在。把"生成物"写成"兜底"最坏的地方在于：真出故障时人会去查兜底为什么没生效，而不是去修读层。

【边界】
- **禁止**在任何文档或代码里把这些导出物描述成 fallback / 兜底 / 降级路径。
- **禁止**在前端接线去"补全"这个兜底——它不是待实现的意图（写成待办会诱使下一个人去接线）。
- 这条链本身要不要继续每天跑（每天一次导出加一次提交）待裁，见 `docs/DOC_VALIDITY_LEDGER.md` V37；裁"停"时两个双写目录要一起处理。
- 与本地端的"整库文件备份/恢复"不是一回事，两件事不许共用"快照"这个词。
