# ADR-10 · 三套"队列"不并成一套

- Status: active
- 拍板：用户 09-26
- 依据：代码实测 + 本地库只读探针

【是什么】
系统里有三件都被叫作"队列"的东西，各自服务不同目的，**不合并**：
1. **本地调度器的任务队列**——只管本地进程里的采集派发。
2. **待导入清单**——两端都有这张表，装"等着被解析成正式内容或订阅"的条目。
3. **文件型导入队列**——清单的上游，服务端半边是 PHP 件（仓内有一份源码副本 + 两份活消费方），对端跑在仓外的独立站点上。

【为什么】
第一件是"活儿怎么排"，第二件是"什么东西等着入库"，第三件是"外部设备怎么把链接递进来"。三者共用一张表会让"清理已完成任务"和"清空待导入"互相误伤。

【边界】
- **禁止**把三者并成一套表或一套端点；**禁止**拿两侧的计数互相对账（本地有任务队列，云端那个接口返回的是清单加零值占位，对不上是设计如此，不是故障）。
- 第三件通不通取决于三件事：对端站点在跑、设置里的队列基址与凭据有效、轮询开关打开。**本件不写"它通/它不通"**——那是每次要重读的读数；现读方法看设置里队列项的最近同步时间与末次错误，或打云端队列统计接口。
- `cloud/` 目录**不是死副本**：端到端测试拿它当 PHP 服务的 docroot 源，客户侧部署工具往里生成凭据文件。删它等于拆测试依赖。
- 这条链算不算现役待裁（V40）。
- **第一件（本地调度器那套任务派发）的实现是"同一个库里的一张表 + 进程内消费"，不引入外部队列中间件**。理由不是"外部中间件不好"，是这套系统只有一个消费者：分布式能力一个都用不上，而多一个常驻依赖就多一份要人照看的故障面（进程重启不丢任务由库的持久化承担，不靠队列）。
  - **禁止**以"以后要横向扩展"为理由先把中间件引进来。真要横向扩展那天，先推翻本件。
  - 本条只管第一件的实现选型，**不改变**"三件不许合并"这条主判据。
