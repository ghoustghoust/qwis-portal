# ADR-14 · 三端共享语义，不共享进程

- Status: active
- 拍板：用户 09-26（本轮复核确认）
- 依据：三份采集实现与共用 `lib/` 的实际边界实测

【是什么】
本地、云端读层、runner 是三份独立实现，**共享的是语义不是代码**。真正需要一份的只有跨端都得同规则的那几件事，它们住在 `lib/` 里（熔断、保留、四轴、预配额、噪声、密钥掩码、图片安全取回）。其余各端按自己的运行环境写自己的那份。

【为什么】
三端的运行约束根本不同：本地能跑无头浏览器和同步阻塞、runner 有长驻进程、读层有存活时长与函数配额。强行一份代码跑三端，等于把最弱那个环境的限制乘到全部三端上；而语义不分叉才是用户能感知的正确性（同一个源在两端不该给出不同的入报结果）。

【边界】
- **禁止**把"共享语义"实现成"同一份代码三端 require"——那会把不可移植的依赖带进 serverless。
- **禁止**在只改一端的实现里顺手改掉共同语义（过滤、清洗、去重、UA、间隔、熔断口径）；改这些必须对另外两份。
- **禁止**再用"两套部署同构同码"这类说法描述两端关系——语义一致、代码独立，是这个项目的既有形态。
- **不要求**"每个功能本地 + 云端各写一遍"：那是门户时代的旧默认，已废。顺序规则见 `AGENTS.md` §1。
- 哪些键真的被共用、哪些已经各自漂移，属现场读数，不写进本件。
