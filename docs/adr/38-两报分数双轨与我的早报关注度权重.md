# ADR-38 两报分数双轨与我的早报关注度权重

日期：2026-10-07（用户拍板 A+B 组合："每日早报和我的早报的评分和内容生成应该有细微差别，比如他们的关注度不一样"）

## 是什么

两份早报的分数从此是**两个视角的两个数**：

1. **每日早报**显示全局原始分（AI 六维深析分，未加权），入报线 60 分（ADR-37 编辑线）。
2. **我的早报**显示"关注分"= 全局分 + 关注加成，加成拆成三件随条目落库，前端可见：
   - `baseScore`：加权前的全局分；
   - `boost`：关注加成合计（订阅源固定 +`subBoost`，兴趣画像每命中一个 Top5 标签 +8，合计不超过 `boostCap`）；
   - `boostWhy`：加成依据（命中的画像标签，或"订阅源"）。前端以"关注 +N"角标与悬浮拆解展示。
3. 三个权重键都在 `settings['mybrief']` 开放集合，管理后台「我的早报」页可调：`subBoost`（默认 6）、`boostCap`（默认 30）、`minScore`（默认 50）。
4. **我的早报有独立入报线**：订阅源条目加成后数字分仍低于 `minScore` 的不进当期；未评分（深析失败）不误杀。探索位维持 ≥70 全局分不变。

## 为什么

两报的候选池早已分视角（我的早报只取订阅源 + 探索位），但分数是同一份全局分且加权（原行为画像 +8~24）不落库、不可见——订阅源一篇 55 分的文加成到 79 上来，页面只显示 79，"因为关注"这件事完全不可感知，同一篇文章两报分数不同还像 bug。用户拍板把"关注度"显性化并给订阅源独立的权重通道与更低的入报线：编辑视角 60 分不够格的内容，关注视角可能够格——这正是两报"细微差别"的本体。

## 边界与禁止

- **每日早报的全局分不许被关注加成污染**：加成只发生在我的早报生成段（runMyBrief 的 minePool 内），不得回写 articles.score（深析回写的是全局分，此口径不变）。
- 旧期归档条目没有 `baseScore/boost/boostWhy` 字段——前端一律 `boost > 0` 判定渲染，不许假设字段存在。
- 权重键坏值（空串/越界/非数字）回默认值，不许静默读成 0（"配置缺失 ≠ 故意设为 0"，坑 #38 同族）。
- `minScore` 只作用于订阅源条目；探索位条目不许用它放低标准（探索位本义是"破茧"，标准反而更高）。
