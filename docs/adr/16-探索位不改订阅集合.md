# ADR-16 · 探索位不改订阅集合

- Status: active
- 拍板：用户 09-27
- 依据：生产链路取数与写库路径实测（订阅集合在该流程内只读；行为画像按标签聚合、不筛来源）

【是什么】
我的早报有一段「补充阅读」，其中**探索位**从用户没有订阅的源里挑高分内容补若干条，并给这些条目打一个「探索」标记，前端如实显示。

它是**版面构成的一层**：让一个人看到自己订阅范围之外的高分内容。它不改变"这个人的早报由哪些源构成"。

【为什么】
订阅集合同时是两件事：用户的显式选择，以及我的早报取数的**输入面**。如果探索位把补进来的源写回订阅集合，"我看到过什么"就会变成"我选了哪些源"——输入退化成输出，"按我的订阅生成个人版"这个功能定义当场不成立。

这条边界的价值在于它是**单向的**：订阅集合决定探索位从哪些源之外挑，反过来不成立。

【边界】
- **禁止**探索位写回订阅集合、源分组或订阅轴。它的存在只落进当期归档的补充阅读段。
- 探索位的选取**不经过行为画像**（按条目自身分数、加上与已选条目的相似度做多样性控制）。**禁止**为了"让探索更懂我"把画像接进这一层——那会把下面那条反馈环整个放大一圈。
- **知情接受的代价，现状如此、不是待修缺陷**：用户点开探索位条目 → 该条目的标签**会进**行为画像（画像按标签聚合阅读与稍后读痕迹，不区分来源是不是探索位）→ 画像再让带同标签的**订阅源**条目在早报里排序上浮。
  即探索影响的是"**圈内怎么排**"，不是"**圈里有哪些源**"。这条反馈环正是防茧房起作用的机制。改画像的输入面时，必须连带重读本件。
- 探索强度（补几条）在设置面上可改；相似度权重与分数门槛是写死取值，不在本件。
- 本件只管**我的早报**这一层。其它两级产品要不要有同类补足，是各自的功能口径，不从本件类推。
- **我的早报道入面只有一条：订阅集本身**（订阅源在窗口内的内容，自己补齐分析）。**禁止**新增第二条入口——尤其**禁止**"从每日早报的栏目或补位结果里回落几篇进来"。
  理由与上面同构：一旦版面能借条目，"我的早报 = 我选的源"这个定义就不再成立，而且它会让**两级产品互相掩盖故障**（日报少了一栏，个人早报跟着少几篇，而两边看起来都"正常"）。
  现状确实复用了同一批已分析结果以省调用，那是**取数复用**，不是版面借用：候选仍按订阅集筛。
