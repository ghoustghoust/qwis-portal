# ADR-24 · 早报策展的四个目标不可拆，不接受"先保一个后补一个"

- Status: active
- 拍板：用户 09-29 放行（自 `docs/NEXT-DEV-REQS.md` T3-7 第一节抽出；原话"任一被牺牲都算失败"）
- 依据：需求定义原文 + 现读候选池与栏目构成可复现"只优化其一会发生什么"

【是什么】
早报策展同时追求四件事，缺一即判失败：

1. 高质量内容浮得上来；
2. 真正有质量的小源不被淹没；
3. 反茧房（读者会看到的不是同一类东西）；
4. 系统负荷扛得住（时间与配额）。

这四条是**同一套设计的四个约束**，不是四个可以分批交付的目标。

【为什么】
每一条都可以被单独"做到"，代价都由别的条承担：只追 1 就是把池子交给少数高频源与高分口径，2 和 3 当场失守；只追 2 会给小源发保底位，1 与 4 变差；只追 3 靠随机探索位，读者拿到的质量下限塌；只追 4 就是少读少算，1/2/3 一起没。所以"先保浮现、多样性后补"这种拆法不是保守，是**把三条悄悄放弃**——而它看起来像在完成工作。

【边界】
- **禁止**以任何"这一期先把质量做出来，多样性下一轮再补"的口径立项或验收。任何改动候选、排序、栏目分配的提案，必须同时说明它对四条各自的影响与判据。
- **禁止**用单一指标（覆盖率、平均分、调用量下降幅度）证明策展改动成功。四条各有一个可现读的判据，验收要四条都报。
- 覆盖宽度与调用量是**一对交换关系**，不是同一个优化目标：见 ADR-09（每源限量换的是覆盖，不是额度）。
- 反茧房的探索位**不由评分填充**，否则它只是评分系统给自己找的替罪羊（这条现状仍不符，账在需求队列 T3-7 第三节，属待修，不因本件视为已解决）。
- 负荷扛不住时**优先削的是取数形状（不带正文、按条单取），不是候选多样性**。
