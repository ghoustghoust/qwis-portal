# BestBlogs 调研与功能借鉴清单（2026-09-11）

> 调研对象：[ginobefun/BestBlogs](https://github.com/ginobefun/BestBlogs)（AI 策展阅读器，Dify 工作流 + OpenAPI + Skills）
> 目的：为本项目（ROADMAP-2026-09）的功能开发提供已验证的实现范式。
> 结论摘要：BestBlogs 把「AI 策展」工业化踩过的坑（成本、评分稳定性、术语一致性、可解释推荐）都留下了成熟方案，**我们的 AI 日报 v2、翻译链、推荐算法、源自选四块可以直接站在他们肩上**。

---

## 1. 直接要抄的（进 spec，阻塞级提升）

### 1.1 两阶段过滤架构 → 进 P1-2（AI 基础设施）
BestBlogs 的 Issue #564 决策：**初筛只传标题+元信息+200 字符摘要**（不传全文），输出 `{ignore, reason, value(0-100), summary}`，阈值 30 才放行进入昂贵的深度分析。
**对我们的价值**：Agnes 免费池只有 20 RPM——初筛便宜、深析昂贵，这个架构是把 20 RPM 用出 200 RPM 效果的关键。我们的日报候选每天 500 篇，先初筛杀掉 80%，深析只跑 ~100 篇。

### 1.2 六节点分析管线 → 进 P1-4（AI 日报 v2）
`分段（Markdown 结构感知切分，≤3000字/段）→ 段落精要 → 汇总综合 → 领域标签 → 评分 → 反思改进`。
关键细节：**反思节点每处改动必须带 UpdateReason，只删重要性 <3 分的信息**——防止 LLM 越改越烂。
评分用「维度分 + 加减分项」：内容深度 30 / 相关性 30 / 写作质量 20 / 实用创新 20 / 综合调整 ±10（营销过多 -3、稀缺性 +3……）。我们已定用户六维（选题/内容/深度/实用/创新/表达），实现时内部可以用他们这套更可操作的打分细则，最后映射到用户六维展示。

### 1.3 三段式翻译 + 混合术语库 → 进 P1-3（翻译链）
他们的翻译流：`术语识别（本篇即时生成对照表）→ 初译 → 检查（四类问题找茬）→ 意译`。
用户要求的「术语对照库」落地为**双层**：全局静态术语表（settings 维护，AI/LLM/Agent 类领域词固定译法）+ 每篇即时识别补充。注意：他们翻译的是**分析结果 JSON**（标题/摘要/观点/金句）而非全文——摘要先译、全文按需译，这正是我们成本结构该抄的。

### 1.4 推荐可解释四件套 → 进 P2-2（推荐算法）
每条候选内联 `candidateSource（召回来源）/ selectionReason（一句话理由 ≤50字）/ personalized / fallbackApplied`。
直接满足用户「为什么这篇被推荐上来」的要求，也是防茧房的信任基础。**articles 表加字段**：`selection_reason`、`candidate_source`。

### 1.5 行为画像 + 漂移检测 → 进 P2-2
画像 = 显式兴趣（用户选的源/标签）+ 隐式兴趣（阅读/收藏/稍后读行为学习，我们已有 reading 表）+ 近期活跃主题 + **driftDetected（兴趣漂移检测）**——检测到画像漂移主动提示，这是防茧房的自动哨兵。

## 2. 产品形态借鉴（进 ROADMAP 后续迭代）

### 2.1 主题早报（他们 3.0 方向）→ 我们的日报演进方向
用户自然语言定制多份早报（"每天早上给我 AI Agent 简报，只看英文一手源，过滤营销稿"）→ 系统转成 来源+关键词+实体+排除条件。比我们现在的固定四栏目更进一步，且天然多视角防茧房。**建议列为 P2-3**。

### 2.2 源洞察报告 → 源管理器的高级形态
`posts/source_insights/` 模板：标签热力 + 洞察卡片（类型标签/⭑×N 多篇佐证/可行动性/出处带分数）+ 双轨汇总。我们的「源管理器」可以加「这个源最近都在讲什么、值不值得继续订」的一键洞察。

### 2.3 标题双层存储 → 阅读器
`originalTitle`（原文可溯）与 AI 优化 `title`（去标题党）分离。我们热榜/公众号标题党不少，值得加。

### 2.4 质量分暴露为过滤参数 → 阅读器筛选
他们的 RSS 支持 `?minScore=90`。我们的 /api/articles 已有 score_min 参数（本地），上云后可直接把六维总分当过滤器暴露。

## 3. 工程范式借鉴（文档/流程级）

| 他们的实践 | 我们怎么用 |
|---|---|
| 提示词与流程定义分离维护（prompts/ 独立文件） | AI prompt 全部落 `server/services/ai/prompts/`，可版本管理可 A/B |
| 废弃表达对照表（旧术语→替代，防漂移） | 我们 ARCHITECTURE 已有「决策作废标注」规则，术语层面同样适用 |
| 降级链设计（my_brief → for_you → public 兜底） | 推荐/日报生成都设计降级链：AI 失败 → 关键词版 → 原始列表 |
| Skill 化封装（每功能一份 SKILL.md + 稳定 JSON 契约） | 我们系统正在被 Agent 重度使用，后期可把「日报/热榜/阅读」封装成 skills |
| 北极星指标选「每日打开」而非「时长」 | 我们的健康目标同样是「读得更少但更重要」 |

## 4. 明确不抄的

- **多用户/Pro 付费体系**：我们是个人系统（已确认前台公开只读）。
- **Dify 工作流平台**：我们用代码实现同样的管线（Agnes 直调），不引入 Dify 依赖。
- **音频早报/海报多形态**：暂不需要。
- **ES BM25 + 向量混合检索**：我们数据量级用 SQL LIKE + Jaccard 足够，不引入搜索引擎。
