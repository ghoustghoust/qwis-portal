# 全网情报系统（私人 AI 情报阅读器）复刻 Spec

> 依据：课程视频 8/17/18/19 的 61 张关键帧截图分析 + 用户口述补充。
> 本文档只描述「做什么」，不涉及具体技术实现（留给 plan.md）。

## 背景

复刻对象是一套「私人 AI 情报阅读器」：本地运行的 Web 服务（原作为 Node.js，入口 `server.js`，三页面路由 `/reader/`、`/daily/`、`/wechat/`），配合云端 PHP 队列文件（`wechat-rss-queue.php`、`bilibili-video-queue.php`、`douyin-video-queue.php`）接收手机端提交的链接，实现「公众号 RSS + B站 + 抖音」三源聚合阅读，DeepSeek 提供 AI 速览与每日情报日报。

与原作的差异约束：
- 开发与运行在 **Windows**（原视频为 macOS）；手机端为**安卓**——原作的「Mac 签名 .shortcut + iPhone 快捷指令」链路整体替换为「安卓 HTTP Shortcuts 提交配置 + Windows 提交工具」（云端 PHP 队列协议不变，仅客户端不同）
- 需要扩展接入 **X（Twitter）、YouTube、Claude/OpenAI 等海外官网一手信息源**，且架构要支持后续接入更多网页类型
- 任务量大，**分五期交付**，每期独立可用、独立验收

## 目标

- 本地一键启动的全网情报聚合阅读系统：公众号文章 + B站/抖音视频 + 海外信息源
- AI 加持：单篇 AI 速览 + 每日定时情报日报（DeepSeek）
- 随时提交：安卓分享菜单 / Windows 提交工具 → 云端队列 → 本地自动拉取入库
- 可扩展：新信息源类型以低成本接入

## 图中出现的全部功能（功能需求）

### A. 阅读器页（/reader/）

- F1: 文章 / 视频 双 Tab 切换，共用左侧导航栏
- F2: 左侧导航（文章态）：全部、稍后阅读、历史存档（均带计数）；分组区（可新建分组，把订阅源拖入分组）；订阅源列表（favicon、名称、未读数）+ 手动刷新按钮 + 上次/下次抓取时间
- F3: 左侧导航（视频态）：全部视频、收藏、历史存档（带计数）；视频分组（同上）；视频订阅列表（UP 主头像、名称、视频数）+ 刷新按钮
- F4: 文章列表栏：来源名、标题、两行摘要、右侧方形缩略图、相对时间（8h/1天）、未读蓝点、选中高亮
- F5: 文章阅读栏：来源、大标题、发布日期时间、正文完整渲染（公众号排版：图片、小标题、加粗）；顶部工具条：AI 速览、稍后阅读（心形，激活变紫色填充）、打开原文（↗）、更多（⋯）；上一篇/下一篇/关闭（X）；全部标为已读（✓）
- F6: 阅读状态流转：读过的文章自动进入历史存档；历史存档视图带「搜索历史标题和内容」搜索框
- F7: 稍后阅读：阅读栏心形按钮加入/取消，左侧「稍后阅读」视图聚合
- F8: 视频网格：多列卡片（封面图 + 右下角时长角标、两行标题、UP 主头像+名称+N天前）
- F9: 视频详情页：返回视频列表；内嵌 HTML5 播放器（默认用本机 B站播放 Cookie 解析直链播放，可「切回官方播放器」）；标题、UP 主+时间、视频简介；底部「收藏」「在原平台打开」按钮
- F10: AI 速览：阅读栏星星按钮展开速览面板，调 DeepSeek 生成单篇摘要；面板含设置齿轮与复制按钮；失败时展示错误原因（如 `DeepSeek API HTTP 402`）；激活后星星变紫色
- F11: AI 速览设置弹窗：自定义摘要提示词（多行文本框，仅保存提示词不加载正文）、恢复默认按钮；速览时间范围三选一（最近48小时 / 最近7天 / 全系统）；保存提示词
- F12: 主题切换：左下角主题按钮，至少支持暖色纸张（米色底+棕色按钮）、蓝白、深色三套主题，全局生效

### B. 每日情报日报页（/daily/）

- F13: 报纸风格页头：「48 小时订阅情报」标签 + 衬线超大标题「每日情报」+ 生成时间 · 排序方式（关键词规则排序 / AI 智能排序）· 统计区间；右上「重新生成」按钮与设置齿轮
- F14: 统计卡片行：候选内容数、公众号文章数、视频数、统计窗口（48h）
- F15: 日报栏目为可配置规则（栏目因人而异）：每个栏目 = 名称 + 说明文字 + 命中关键词列表，用户可增删改；另有两类特殊机制栏目——「重点更新」（重点关照来源，按时间倒序不限数量）与「其它重要」（兜底，收录未命中任何栏目的入选内容）；默认内置原作四栏目（培训课程发布：课程/训练营/社群招募/项目培训/技术培训发布或预告；重点更新；AI技术：Codex、Claude、豆包、Agent、模型、自动化、RAG、MCP 等动向；其它重要），不同领域用户可整体换成自己的栏目与关键词（如经济、管理）；每栏右侧附说明文字；空栏显示「这一栏暂时没有命中内容」
- F16: 日报卡片：封面大图 + 「AI简介」标签 + 标题 + AI 生成摘要段落；AI 排序时卡片体现「重要度」评分
- F17: 快速学习弹窗（QUICK STUDY）：点击日报卡片打开，含内容类型标签（公众号文章/视频）、大标题、来源+时间、「加入收藏」「复制链接」「打开原文」按钮、AI 总结卡片（绿色标识，标注「DeepSeek · 重要度 N」）、正文内容
- F18: 日报设置弹窗（DAILY SETTINGS）：统计窗口（小时，默认48）、每日生成时间（默认08:00，时间选择器）；公众号文章来源勾选列表（全选）+ 每个来源「重点关照」开关（激活显示红色「已重点关照」徽章）；视频订阅勾选列表（全选）+ 重点关照；「启用 DeepSeek 智能分析」开关；API 地址（默认 https://api.deepseek.com/chat/completions）；模型（默认 deepseek-v4-flash）；API Key（留空保留已保存 Key）；栏目管理（增删改栏目：名称、说明、关键词列表）；保存设置
- F19: 按「每日生成时间」定时自动生成日报；生成后页面顶部显示「已生成 DeepSeek 智能日报。」提示
- F20: 日报卡片/摘要内容可复制（操作后 toast「已添加到剪贴板」）

### C. 订阅源设置页（/wechat/，三 Tab）

公众号 RSS Tab：
- F21: OPML 配置：OPML 同步间隔（小时，默认12）+ 启用 OPML 自动同步开关 + 保存 OPML 设置 + 同步 OPML 按钮；显示本地记录数/当前订阅数/最后同步时间
- F22: RSS 配置：RSS 文章刷新间隔（小时，默认8）+ 启用 RSS 自动刷新 + 保存 RSS 设置 + 同步 RSS 按钮；显示最近刷新/下次刷新/文章缓存数/刷新异常数
- F23: 状态卡片区：OPML 状态（空闲/同步中）、OPML 最近同步、OPML 下次同步、OPML 最近结果（新增 N，恢复 N，更新 N）、RSS 最近刷新、RSS 下次刷新、文章缓存、刷新异常
- F24: 待提交公众号信息区：手机提交的公众号仅保存在本地供手动复制（不自动提交到第三方网页）；点「同步队列」拉取后出现「复制链接 / 复制名称」按钮；同步失败展示错误详情
- F25: 公众号队列 API 折叠区：队列 API 地址（如 https://api.qianmeng.news/wechat-rss-queue.php）、Token（留空保存不覆盖已保存 token）、轮询间隔（分钟，默认10）、启用公众号队列同步开关、保存队列设置；显示已保存 Token 状态与上次/下次同步时间
- F26: 数据备份区：立即备份（生成 subscriptions-yyyymmdd-hhmmss.json）、恢复最新备份；显示最新备份文件名/时间/订阅源条数
- F27: 公众号订阅列表表格：头像（微信图标）、公众号昵称、状态（订阅中 绿色徽章）、新增时间、完整 RSS 链接

B站 Tab：
- F28: 状态卡：运行模式（本机模式）、订阅源数、视频数；「B站订阅已就绪，本机模式无需 RSSHub」提示；刷新 B站按钮
- F29: 自动刷新：内容刷新间隔（分钟，默认60）+ 启用自动刷新 + 保存设置；说明「B站不依赖 RSSHub；有 Cookie 时优先用本机链路」
- F30: 添加 B站 UP 主：粘贴 B站主页、视频链接或 uid + 显示名称（可留空）+ 添加按钮；链接识别失败时提示「添加失败：没有识别到 B站 up，请粘贴 space.bilibili.com 的主页链接或直接填写数字 uid」
- F31: B站队列同步：队列 API 地址（bilibili-video-queue.php）、Token、轮询间隔（分钟，默认10）、启用队列同步、保存队列、同步队列按钮；同步结果显示「导入 N 个，更新 N 个，清空云端 N 个；本地后台正在解析订阅」；说明「云端任务会先导入本地待处理区，再立即清空云端；失败重试只在本机追踪」
- F32: 本地待处理订阅列表：名称、待处理状态、导入时间、原始链接
- F33: 已订阅 UP 主列表：头像、名称、平台徽章（B站）、条数、上次刷新时间；状态（状态正常）、最近刷新/下次刷新、启用开关、刷新按钮、删除按钮；重新读取按钮
- F34: 高级与诊断折叠区
- F35: B站播放 Cookie 配置：有 Cookie 时视频详情页可解析直链内嵌播放（对应 F9）

抖音 Tab：
- F36: 状态卡：运行模式（本机模式）、订阅源数、视频数；「抖音订阅已就绪，本机模式无需 RSSHub」；刷新抖音按钮
- F37: 抖音登录状态卡：未登录显示「未添加抖音订阅/需要时再扫码登录」+ 重新扫码按钮；已登录显示「已保存登录态；添加抖音订阅后会低频使用」
- F38: 扫码登录流程：弹窗「需要重新登录抖音」，说明点击后打开本机浏览器抖音登录页，扫码或确认登录成功后自动保存 Cookie 和浏览器登录态，检测到有效登录态自动关闭窗口；按钮「打开抖音登录窗口 / 稍后处理」
- F39: 自动刷新：内容刷新间隔（分钟，默认360）+ 启用自动刷新；说明「抖音刷新严格串行，任意两个主页访问之间固定等待 10 秒」
- F40: 添加抖音作者：粘贴抖音主页、分享链接或 sec_uid + 显示名称（可留空）+ 添加；失败提示「添加失败：没有识别到抖音 uid/sec_uid，请粘贴抖音用户主页链接或直接填写 sec_uid」；成功提示「抖音订阅已添加」
- F41: 抖音队列同步：同 F31 结构（douyin-video-queue.php）；说明「导入本地后清空云端；处理和刷新都按 10 秒间隔串行」
- F42: 本地待处理订阅、已订阅作者列表（名称未解析时显示原始 sec_uid）、高级与诊断折叠区

### D. 云端队列与快捷提交链路

- F43: 三个云端队列端点（PHP 文件部署在网站根目录，Token 鉴权）：接收 POST 提交的链接/名称/类型 → 存入队列；响应本地轮询 GET 返回队列内容（JSON：`ok=true, count=N`）；本地拉取后清空云端
- F44: 本地队列轮询：按配置的轮询间隔（默认10分钟）自动拉取三个云端队列，导入本地待处理区后通知云端清空；失败重试只在本机追踪
- F45: 安卓快捷提交配置生成：部署时生成 HTTP Shortcuts 导入配置（JSON 文件）+ 图文配置指南；安卓系统分享菜单接收链接 → 自动识别平台（B站→bilibili 队列、抖音→douyin 队列、公众号→wechat 队列）→ 确认弹窗「识别到XX/类型/确认加入订阅队列」→ POST 到对应云端队列
- F46: Windows 端快捷提交工具（替代 Mac 快捷指令链路）：复制链接后一键提交到对应云端队列（全局快捷键读取剪贴板 / 托盘工具形态，自动识别平台 + 提交确认）

### E. 海外源与扩展（用户新增需求）

- F47: 通用 RSS/Atom 源接入：任意 RSS 地址可直接添加为订阅源（覆盖 YouTube 频道官方 RSS、Claude/OpenAI 官网博客等提供 RSS 的站点）
- F48: X（Twitter）接入：通过 RSSHub / 第三方 RSS 服务（如 TodayRSS）将 X 账号时间线转为 RSS 订阅
- F49: 订阅源类型扩展框架：新网页类型以「适配器」方式登记接入（解析规则独立成模块，不改主流程）

### F. 配置与部署

- F50: 客户化配置文件 config/customer-config.json：公众号 OPML 地址、云端 API 域名、API Token（可自动生成随机长 Token）、DeepSeek API Key（可留空，留空则 AI 功能关闭）、B站 Cookie（可留空）、抖音登录方式（扫码/Cookie）、各源刷新间隔（OPML 12h / 公众号 RSS 8h / B站 60min / 抖音 360min / 队列 10min）、是否生成提交客户端配置（安卓/Windows）
- F51: 一键配置脚本（setup:customer）：依配置生成 .env、写入三个队列 Token、初始化本地数据、生成安卓提交配置文件与 Windows 提交工具
- F52: 本地服务启动后三页面可访问：/reader/（阅读器）、/daily/（日报）、/wechat/（设置），均返回 200

## 非功能需求

- N1: Windows 10/11 可完整开发与运行（不依赖 macOS 专属能力；快捷指令签名等 Mac 链路用 F46 替代）
- N2: 数据全部本地存储；敏感信息（Token、API Key、Cookie）只写入本地配置/数据文件，不在界面回显、不进日志
- N3: 单用户系统；云端队列端点以长随机 Token 鉴权，不建账号体系
- N4: 外部请求限速：抖音任意两次主页访问间隔 ≥10 秒且严格串行；其余源按各自刷新间隔执行
- N5: 千级内容量下界面流畅（视频 1000+ 时网格列表不卡顿）
- N6: 全部页面支持深色模式；主题切换即时生效无需重启
- N7: AI 功能可整体降级：DeepSeek Key 未配置或调用失败时，阅读器/日报其余功能正常，仅 AI 区域展示错误原因

## 技术栈约束

（选型理由详见 plan.md 技术决策表；本节为硬性约束，实现不得偏离）

- 前端：React 18 + Vite + Tailwind CSS（三页面 SPA，由后端静态托管）
- 后端：Node.js 20 + Express 4（本地单进程服务）
- 数据库：SQLite（better-sqlite3，单文件存于 data/）
- 云端队列：PHP 单文件 + JSON 文件存储（上传宝塔站点即用，免数据库）
- 采集：rss-parser（公众号 OPML/通用 RSS）、fetch + B站官方 API（B站）、Playwright 拉起本机浏览器（抖音扫码登录与抓取）
- AI：DeepSeek API（OpenAI 兼容协议，fetch 直连，无 SDK 依赖）
- 定时调度：node-cron（日报定时）+ setInterval（轮询类）
- 提交端：安卓 HTTP Shortcuts（生成 JSON 导入配置）、Windows PowerShell 提交脚本 + 快捷键
- 测试：Node 内置 test runner

## 不做的事（边界）

- 不做多用户/账号权限体系
- 不做移动端原生 App（手机端靠快捷指令分享表单 + 浏览器）
- 不自建公众号 RSS 源（依赖「今天看啥」等第三方服务，经 OPML 导入）
- 不自建 X 爬取（依赖 RSSHub/第三方 RSS 服务）
- 不做视频下载、无水印下载
- 不做 iPhone 快捷指令（用户手机为安卓，HTTP Shortcuts 覆盖同一场景且云端协议相同；iOS 客户端留作后续扩展）
- 服务器购买、域名备案、宝塔建站等运维操作不含在开发范围（仅保证交付物可上传到 PHP 站点根目录运行）
- 不实现原视频中的 bug（AI 速览 402 错误属原作的欠费问题，非功能需求）

## 验收标准

- AC1（F1~F7）: 添加公众号 OPML 后，文章 Tab 三栏界面可浏览文章列表、打开阅读、稍后阅读、全部已读、历史存档搜索均生效
- AC2（F8~F9）: 添加 B站 UP 主后，视频 Tab 网格展示封面/时长/标题；点击进入详情页可内嵌播放，可切官方播放器，可收藏、可跳转原平台
- AC3（F10~F11）: 配置 DeepSeek Key 后，文章 AI 速览返回摘要并可复制；提示词与时间范围可改可保存；Key 无效时显示错误原因
- AC4（F12）: 三套主题可切换，刷新页面后主题保持
- AC5（F13~F20）: 点「重新生成」产出日报：统计卡数字正确、栏目分组展示、卡片可点开快速学习弹窗（含 AI 总结与重要度）、可收藏/复制链接/打开原文；到达每日生成时间自动生成；修改栏目名称/关键词后重新生成，内容按新规则归类
- AC6（F21~F27）: 公众号 Tab 各保存/同步按钮生效，状态卡时间与结果正确；备份生成 JSON 文件且可恢复；订阅表格展示完整
