# 批量恢复熔断源 - 一键故障恢复解决方案

> **版本**: v2.0  
> **修复时间**: 2026-09-02  
> **状态**: ✅ 已部署（需重启服务）  
> **适用场景**: B 站/抖音/公众号大规模账号批量熔断恢复

---

## 🎯 问题分析与解决方案

### **问题 1 - 错误现象诊断**
从截图可知当前有 **86 个源处于熔断状态**（`fail_count ≥ 3, enabled=0`），表现为：
- ❌ "全部刷新"仅刷新已启用的源，对熔断源无响应
- ❌ 手动逐个启用 + 刷新耗时极长
- ❌ 管理者无法快速恢复大量失效账号

**根本原因**: 旧版 `refresh-all` 仅处理 `enabled=1` 的源，缺少针对熔断源的自动化恢复逻辑。

---

### **问题 2 - 缺失的状态流转逻辑**

**期望流程**:
```
enabled=0 (停用) 
  ↓ [批量解冻 API]
enabled=1, fail_count=0, status='ok'
  ↓ [立即刷新 API]
抓取成功 / 失败但不重新熔断
```

**旧版实现缺陷**: 无此一体化链路，导致用户必须分两步操作且存在二次熔断风险。

---

### **问题 3 - B 站/抖音批量恢复机制缺失**

**原有方案痛点**:
1. 需逐个点击「启用」按钮
2. 需再次手动触发刷新请求
3. 连续失败仍会触发熔断

**新方案设计原则**:
- ✅ 一体化操作：一次点击完成解冻 + 刷新
- ✅ 防二次熔断：刚解冻的源即使刷新失败也不启用自动暂停
- ✅ 类型过滤：支持按平台隔离（bilibili/douyin/wemp/rss）
- ✅ 结果反馈：清晰展示恢复/刷新成功数和失败明细

## 🔧 实施细节

### **后端修复清单**

#### 1. 新增专用恢复接口
**文件**: `server/routes/restore-all.js` (新建)

**API 定义**:
```javascript
POST /api/sources/restore-all
Content-Type: application/json

{
  type: 'bilibili' | 'douyin' | null,  // 可选，按类型过滤
  refreshImmediately: true              // 是否立即启动串行刷新
}
```

**核心逻辑**:
```javascript
// Step 1: SELECT * FROM sources WHERE fail_count >= 3 AND enabled=0 [AND type=?]
const frozenSources = db.prepare(...).all(type);

// Step 2: UPDATE sources SET enabled=1, fail_count=0, status='ok', extra={} WHERE id=?
for (const s of frozenSources) {
  stmt.run(stripErrorMarkers(s.extra), s.id);
}

// Step 3: if (refreshImmediately) { for (...) await fetchSource(source); }
```

**安全特性**:
- 使用参数绑定防止 SQL 注入
- 清除错误标记防止重复报警
- 即使刷新失败也不重新熔断（因为是刚解冻的）

## 🔍 故障排查

### Q1: 按钮未显示

**可能原因**: 前端缓存未更新

**解决方案**:
```bash
# 强制清除浏览器缓存
Ctrl + Shift + Delete → 清除缓存
或 Ctrl + F5 硬刷新

# 开发模式下重新构建前端
cd d:\全网情报系统\web
npm run build
```

---

### Q2: 恢复失败，返回 404

**可能原因**: 后端服务未重启或未挂载路由

**检查命令**:
```powershell
# 验证进程运行中
netstat -ano | findstr :3000

# 查看日志头几行
Get-Content _phase7-server.log -Tail 50 | Select-String "批量恢复"
```

**预期输出**:
```
[批量恢复] 路由加载完成
```

如果无此日志，说明服务器未重启。

---

### Q3: 批量恢复后部分源仍熔断

**可能原因**:
1. 这些源在刚解冻后立即又连续失败 3 次
2. 网络问题导致批量刷新超时

**解决方案**:
```bash
# 查看具体失败源列表
node -e "
const {db} = require('./server/db');
const err = db.prepare('SELECT name, extra FROM sources WHERE extra LIKE \"%lastError%\" ORDER BY lastErrorAt DESC LIMIT 10').all();
err.forEach(e => { let j = JSON.parse(e.extra || '{}'); console.log(\`\${e.name}: \${j.lastError}\`); });
"
```

根据错误信息针对性处理（如 Cookie 过期、目标网站变更等）。

---

### Q4: 刷新速度过慢

**正常现象**: 为防止风控平台封禁，批量刷新采用**串行模式**（每间隔 10 秒请求一次）

**预计时间**:
- 10 个源 ≈ 2 分钟
- 50 个源 ≈ 8 分钟
- 100 个源 ≈ 16 分钟

**加速方案**（谨慎使用）:
如需并行刷新，修改 `fetchSource` 调用处移除串行等待（可能导致 IP 被封）。
