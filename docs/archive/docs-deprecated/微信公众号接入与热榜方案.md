# 微信公众号推送 + 微信热榜 接入方案

> 目标：在 `D:\全网情报系统` 内实现两件事——①收到所关注微信公众号的每日推送；②拿到"微信每日公众号热榜"。本文基于 2026-08-27 对该机器的实际探测结果编写，所有连通性结论均已验证。

## 0. 结论先行

- **公众号每日推送**：微信公众平台没有对外的"读取别人公众号文章"的官方 API，唯一可持续路线是**公众号 → RSS**。推荐自建开源项目 **wewe-rss**（走微信读书通道，v2.x 接口较稳；支持 SQLite 且官方给出无 Docker 的本地部署步骤，与本机"没有 Docker"的现状匹配）。产出的 RSS 通过**你系统里现成的 OPML 同步机制**导入，抓取、调度、AI 日报链路零改动复用。
- **微信热榜**：已逐一核实——DailyHotApi（80+ 平台榜单）与 NewsNow 的源码里**都没有微信源**；公共聚合 API（vvhan、60s 等）从本机均不可达。可行且已实测打通的是抓取两个聚合站的微信板块：**tophub.today「微信24h热文榜」**（走本机代理可访问，返回完整榜单 HTML）和 **rebang.today/weixin**（直连即可）。做成双源互备的小采集器，每小时入库，既可单独出榜，也能拼进现有 AI 日报。
- **推送到手**：站内已有 node-cron 定时日报；若要把摘要主动推进微信，首选**企业微信群机器人 Webhook**（免费、消息落在微信里）或 Server酱·Turbo，邮件作保底。

## 1. 机器环境实测（决定方案形态）

| 探测项 | 结果 | 对方案的影响 |
| --- | --- | --- |
| Docker | 未安装 | wewe-rss 必须用 SQLite + Node 裸跑，或改云端一键部署 |
| Node / git | v22.22.0 / 2.53 ✓ | 满足 wewe-rss 与本系统要求 |
| mp.weixin.qq.com 直连 | 超时 ✗（走代理 ✓） | 不能直爬公众号页面，也不必要 |
| weread.qq.com | 直连 ✓ / 代理 ✓ | wewe-rss 运行期无需代理 |
| github.com / npm registry | 直连超时 ✗；走代理 ✓ | 克隆与安装需代理（本项目 .env 已配 127.0.0.1:7890） |
| registry.npmmirror.com | 超时 ✗ | npm 走官方源+代理 |
| tophub.today | 直连超时 ✗；代理 ✓ (200) | 热榜抓取请求需挂 undici ProxyAgent |
| rebang.today/weixin | 直连 ✓ (200) | 第二热榜源，直连抓取 |
| api.vvhan.com / api-hot.imsyy.top | DNS/连接失败 | 公共热榜 API 不可作为依赖 |
| weixin.sogou.com | 直连 ✓ | 搜狗微信搜索仅作人工补查，验证码频繁不适合自动化 |

关键代码事实：`server/util/http.js` 的 fetch 封装目前**不带代理**（Node 22 的 fetch 默认忽略系统代理），而项目已依赖 undici——热榜抓 tophub 时用 `new ProxyAgent('http://127.0.0.1:7890')` 作为 `dispatcher` 传入即可，属小改造。

## 2. 公众号订阅：内容源头

### 2.1 路线对比

| 路线 | 成本 | 稳定性 | 备注 |
| --- | --- | --- | --- |
| **wewe-rss 自建**（推荐） | 免费 | 较高，支持多账号轮换 | 基于微信读书接口；输出 atom/rss/json + OPML 导出 |
| wechat2rss / Pretzo 等托管 | 付费 | 高 | 零部署，购买后导出 OPML 直接喂本系统，可作为懒人/兜底路线 |
| Feeddd 等免费公共源 | 免费 | 中 | 公共实例负载波动，接口随公告变动 |
| 搜狗微信搜索爬虫 | 免费 | 低 | 只有最近文章、验证码拦截频繁，不建议 |

### 2.2 wewe-rss 本地部署（SQLite，无 Docker，照官方步骤）

```powershell
# ① 安装与克隆（需代理）
npm i -g pnpm
git clone https://github.com/cooderl/wewe-rss.git D:\tools\wewe-rss
cd D:\tools\wewe-rss

# ② SQLite 环境（按官方 README 的本地部署步骤）
$env:DATABASE_URL  = "file:../data/wewe-rss.db"
$env:DATABASE_TYPE = "sqlite"
# 删除 mysql 相关 prisma 文件，换用 prisma-sqlite
Remove-Item -Recurse -Force apps\server\prisma
Move-Item apps\server\prisma-sqlite apps\server\prisma
npx prisma generate --schema apps/server/prisma/schema.prisma
npx prisma migrate deploy --schema apps/server/prisma/schema.prisma

# ③ 构建并启动（建议用 pm2 / NSSM 注册为开机服务）
pnpm run -r build
pnpm run start:server   # 默认端口 4000，注意避开主系统 3000
```

首次使用：

1. 浏览器打开 `http://127.0.0.1:4000`，输入环境变量 `AUTH_CODE` 设定的授权码；
2. 「账号管理 → 添加账号」用**微信读书**扫码（别勾选“24小时后自动退出”）；
3. 「公众号源 → 添加」，粘贴目标公众号任意一篇文章的分享链接，自动识别 feed id；
4. 把想订阅的公众号逐个加入。

使用纪律（降低风控概率）：单账号订阅 ≤ 50 个源；每个源的更新间隔 ≥ 60 分钟（系统当前默认 480 分钟没问题）；token 失效时回到账号管理重新扫码即可；不要用主力个人微信号当读书小号。

### 2.3 与情报系统对接（几乎零改动）

你系统现有的链路是：`scheduler` 每 12h 读 `opml.url` 同步 → 每个 type='wechat' 的源是一条 RSS 地址 → 到期由 `due` 驱动、复用 rssAdapter 抓文章 → 进库供 AI 日报使用。因此只需：

1. 在 wewe-rss 后台**导出 OPML**（它原生支持全量导出所有订阅）；
2. 将该 OPML 的 URL 配置为系统设置的 `opml.url`（本机文件可临时起一个静态目录服务，或放到自己的gist/对象存储生成只读链接）;
3. 我们建议把每个源的地址统一换成全文格式：
   `http://127.0.0.1:4000/feeds/<feedId>.atom?limit=20&update=true&mode=fulltext`
   （`update=true` 还能在被抓取时顺手触发 wewe-rss 单源立即更新，和系统的到期调度天然契合）；
4. 完成——之后每天的文章会自动进入 `articles` 表并参与 AI 日报生成，不再需要动任何调度代码。

## 3. 微信热榜：双源互备采集

### 3.1 数据源结论（均已实测）

| 来源 | 实测状态 | 内容 | 接入方式 |
| --- | --- | --- | --- |
| tophub.today `/n/WnBe01o371` 微信24h热文榜 | 代理下 HTTP 200，78KB 页面 | 近24h热文 Top100（标题+原文链接） | HTML 解析，建议每小时 |
| rebang.today `/weixin` | 直连 HTTP 200，133KB 页面 | 微信热点/在看榜等多板 | HTML 解析，第二来源 |
| DailyHotApi（自建可选） | 源码确认无微信源 | 80+ 其它平台榜单 | 仅当你还想顺带聚合微博/知乎等其它榜时部署 |
| NewsNow（自建可选） | 源码确认无微信源（其 aihot 源正是你现在用的上游之一） | 其它平台 | 同上 |
| vvhan / 60s 公共 API | 本机不可达 | — | 不依赖 |

### 3.2 实现要点（贴现有代码风格）

新增 `server/services/hotwx/`（独立于 sources 表，不影响五类适配器契约）：

```js
// server/services/hotwx/index.js —— 微信热榜双源采集
const { ProxyAgent } = require('undici');
const { JSDOM } = require('jsdom');
const PROXY = new ProxyAgent('http://127.0.0.1:7890'); // tophub 必须走代理

async function fetchTophub() {
  const res = await fetch('https://tophub.today/n/WnBe01o371', {
    dispatcher: PROXY,
    headers: { 'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64)' },
  });
  const dom = new JSDOM(await res.text());
  // tophub 榜单行为 tr，标题在 a.link；选择器上线前以实际 DOM 校准一次
  return [...dom.window.document.querySelectorAll('table tbody tr')].map((tr, i) => ({
    rank: i + 1,
    title: tr.querySelector('a')?.textContent.trim() || '',
    url: tr.querySelector('a')?.href || '',
    provider: 'tophub',
  })).filter(x => x.title);
}

async function fetchRebang() { /* rebang.today/weixin，直连，同样 jsdom 提取，略 */ }

// 入库表：hot_wx(id, provider, rank, title, url, fetched_at)
// 以 (provider, rank, 当日小时) 幂等覆盖；node-cron '15 * * * *' 错峰执行
```

配套：

- **查询 API**：在 `routes/hot.js` 增加 `GET /api/hot/wx?provider=tophub&hours=24`，前端热榜页加一个「微信」分组；
- **进日报**：日报生成时取当下 Top10 + 各条一句话摘要（DeepSeek 已配好），作为日报固定栏目「微信热度」；
- **可靠性**：tophub 失败自动切 rebang，双双失败只在日报中留空并在日志 warn，绝不让热榜故障拖垮整份日报。

## 4. 推送触达

- **站内**：沿用现有日报 cron（打开网页即看），成本为零；
- **推进微信（推荐体验）**：企业微信群机器人 Webhook，每日 08:00 日报生成后推送一条 Markdown：`昨日公众号新文 Top5 + 微信热榜 Top10 + AI 一句话综述`。注意 `qyapi.weixin.qq.com` 的连通性未在本机实测，不通就走代理；Server酱·Turbo 是更简单的替代（免费档每天几条，直接弹到你微信）；邮件作最终保底；
- **不推荐**自己长期去爬 mp.weixin.qq.com：需要登录态与加密参数，维护成本远高于上面两条正道。

## 5. 风险与边界

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 微信读书通道属非官方接口 | token 偶发失效、极少数情况下风控 | 小号专用、低频（源间隔≥60min）、重新扫码即恢复；可随时切付费托管兜底 |
| tophub 页面结构变更 | 解析失败 | 双源切换 + 选择器集中在单文件便于修补 |
| 合规/版权 | 全文入库仅供本人阅读 | 不对外分发；对外只出标题+链接 |
